# 多人空间架构与协议 v1

2026-09-16 既有 Journey 实现的协议与持久化记录。当前玩法与分期以[玩法方案 v2](../product/gameplay-plan-v2-2026-10-02.md)为准；本文用于维护现有技术，不表示 P0 已接入本页全部多人玩法。

## 进程与状态

`OnlineGateway` 接收同源 WebSocket 和队伍 HTTP 请求，`Room` 是每个空间的串行权威执行器。
街区键为地区/蓝图/修订/线路，农场键为 farm_id/线路，矿井键为独立 UUID。
默认地下城模板 ID 为 `starter_mine`；实例 UUID 由服务器创建，客户端不能指定他人的 UUID 进入。
同一账号仅保留一个空间连接，新连接替换旧连接，旧连接的关闭回调不能删除新角色。
离开后实体 ID 可回收，避免常驻空间经过大量进出后耗尽编号。

房间 20 Hz 固定步长验证装备移速、导航碰撞、怪物 AI、朝向/攻击扇形、距离、冷却和伤害。
角色输入超出 350 ms 未更新即停止移动；断线立即移除，不让幽灵角色继续受击。
Godot 预测本地移动，按输入序号与服务器位置校正；其他角色按接收间隔插值。
矿井中的暂停/背包只停止本人输入，共享世界继续运行。原 HTTP `mine_combat` 仅供旧个人矿井，
联机矿井既不调用它，也不接受客户端的命中、伤害或掉落字段。

导航由 `tools/dev/export_online_navigation.tscn` 从 Godot 的 `FarmInterior`、`JourneyStreets`
导出为 `assets/farm/data/online_navigation.json`。修改空间布局后重新导出并同时更新客户端与服务端。
默认合作矿井使用统一的六岩石模板，第五层无岩石；服务器下发每层岩石和导航。
旧个人矿井继续使用原随机布局与存档，不从旧档创建奖励。

## 持久化与恢复

- `online_rooms` 保存实例、共享进度、怪物 HP/参与者、提交序号与最后提交 ID；
  `online_players` 保存各人的实例入口与队伍；`online_parties` 保存队长、邀请码及成员。
- 实例键锁、版本比较和农场行锁串行结算。一个事务提交共享状态与所有参与者的独立物品/生命。
  多人奖励通过一条批量 UPDATE 写入，避免每位参与者一次网络往返。
- 相同提交 ID 的不确定重试读取上次提交结果，不重新扣血或发奖；旧版本的新提交失败。
  掉落按实例/轮次/楼层/目标/玩家确定随机结果，种子归 bound，满包使用现有暂存。
- 血量和死亡在农场行锁内用最新装备与生命结算，避免与 HTTP 吃饭/换装覆盖。
  实时角色使用新的农场版本，客户端收到 `farm_changed` 后通过原串行会话刷新库存。
- 写库期间移动模拟和快照仍继续，后续战斗等待这批提交完成。未提交击杀不广播为已完成。
  连续写入失败关闭该房间连接；重连从已提交状态恢复，怪物从安全 AI 阶段继续。
- 每次有效伤害/采矿保存关键进度；移动不逐帧落库。新个人实例从第一层入口进入，跟随矿内队长
  的主动重新入场使用队长当前楼层入口。短暂断线通过
  HMAC 恢复凭据回到原实例原楼层的安全入口，避免组队后的网络抖动偷偷换绑。
  凭据绑定账号、实例、楼层、连接 nonce，120 秒有效并随心跳续期；主动离开使其失效。
  超时要求主动重新进入。空的内存房间一分钟后释放，持久实例保留到主动重置。
- 重置必须队长/单人确认且成员都在矿外；旧实例标记 retired，不能用旧入口复活旧进度。
  已入袋奖励和永久电梯保留。实例记录保留供审计，生产长期运行需定期归档 retired 且无活跃引用的记录。

生产 `src/index.ts` 持有 PostgreSQL 会话锁 `735920160`。第二个实时进程启动失败，
锁连接失效立即关闭服务。HTTP 可独立扩容并关闭实时功能，Caddy 原配置可直接转发 WebSocket。
需要多台实时节点时，应先增加显式实例分片/路由及租约交接；本实现不声称已提供跨节点自动迁移。

## 通信

先用原匿名账户取得 token，连接 `wss://<API 的 v1 前缀>/online`。
首包 `{t:"auth",token:"..."}`，鉴权成功再发 `{t:"join",kind:"street"|"farm"|"mine",channel?:1..100,farm_id?:"..."}`。
农场/访客街区校验公开权限或主人授予本队的访问权限；矿井加入只读取服务端的队伍和绑定关系。
跨区旅行可在 `join` 中附带服务器签发的 `travel_ticket`，客户端不能直接指定任意私有实例。

| 客户端包 | 含义 |
| --- | --- |
| `input`：seq、epoch、x、z、yaw、action | 目标位置和动作意图，20 Hz；不含已确认位置或伤害 |
| `act`：seq、epoch、action、node? | attack / dig / up / down / elevator；每人最多一条待处理交互 |
| `leave` | 等待当前房间结算后离开，返回 `departed`，组队关系保留 |
| `ping` | 心跳；30 秒无活动断开 |

`joined` 返回自身实体 ID、实例键、楼层、epoch 和出生点。
`world` 返回当前导航及共享资源/清层状态；`roster` 为当前层初始名单，`peer`/`left` 增量维护名单。
`floor` 增加 epoch 并更换位置，旧楼层输入/快照失效。`enemies` 返回同层怪物位置、HP、阶段与朝向。
`result` 确认交互，`farm_changed` 通知刷新个人存档，`rescued` 驱动原农场救援页。
人员跨层互不可见，但实例总人数按五层合计，最多 300 人。

位置帧为小端二进制：12 字节头（u16 协议、u32 tick、u32 epoch、u16 数量），
每实体 26 字节（u16 id；f32 x/z/yaw；u16 hp/max_hp；u8 动作/楼层；u32 已处理输入序号；u16 攻击序号）。
本人和最近 64 人 10 Hz，其余同层成员 2 Hz。攻击序号让短挥砍不会因低频位置更新而消失。
所有角色都保持在客户端名单中；最近 8 人使用完整动画骨架，其余用 MultiMesh 简化人物和动作，
避免 300 套骨骼更新。0.10.2 起，近处完整角色使用对方实际保存的整套装扮；远处仍使用简化人形，
进入近处动画名额时按最新外观装配。装扮在本机衣柜保存，连接时重新发布；本轮没有增加跨设备云衣柜。

鉴权响应 `appearance_version:1` 后，客户端在 `join.appearance` 发送
`{version:1,slots:{body,eyes,hairHat,cloth,shoes,...}}`。14 个槽位只包含部件 ID，服务端使用
与客户端相同的 manifest 和 denylist 校验部件/槽位，不接受资源路径、变形参数或属性。
没有该字段的旧客户端使用默认外观。`roster` 和 `peer.member.appearance` 携带最新完整装扮，
覆盖后来加入、换层和重新连接；不增加逐帧二进制包大小。

保存换装后使用 `t:appearance` 更新本人，服务器同连接最多每 500 ms 接受一次，客户端合并到每秒最多一次。
相同外观不重复广播，非法更新不改变当前外观或战斗状态；`appearance_result` 单独返回结果。
远端角色池按玩家身份和外观内容去重；复用时取消旧部件请求、清除空的可选槽，装配期间不展示上一个人的服装。
本人的场景角色跟随成功保存的衣柜变更，编辑草稿与其他玩家外观不写入本机衣柜。

连接消息限 4 KiB、30 包/秒（60 包突发），未鉴权连接有 5 秒期限和 64 个名额。
出站积压超过 64 KiB 跳过位置帧，超过 256 KiB 断开；单进程上限 256 个活跃房间、10000 个连接。
令牌不出现在 URL。HTTP 撤销立即关闭对应连接，后台每分钟重新验证令牌。
共享 NAT 下允许 300 个不同安装同时登录/组队：登录按 IP 600 次/小时、按安装 10 次/小时双重限流；
队伍写操作按 IP 600 次/分钟、按认证会话 20 次/分钟限流。非法登录仍按 IP 10 次/小时限流，
仅信任配置过的反向代理提供的客户端 IP，伪造转发头不能绕过配额。

## 队伍接口

- `GET /v1/online/status`：协议/容量、模板 ID、自己的绑定和队伍；`travel_version:1`、
  `roster` 包含成员在线状态、场景、地区/蓝图、线路和矿井楼层，`farm_access` 为自己的本队访问开关。
- `POST /v1/online/party`：`action=create|join|leave|kick|leader|disband|farm_access`，`value` 为邀请码、目标成员或 `allow|deny`。
  队长离队自动转给第一位剩余成员；踢人、转让、解散需要队长身份。
- `POST /v1/online/reset`：`{confirm:true}`，有成员在矿内时拒绝。
- `POST /v1/online/travel`：`mode=leader|follow|farm`，可指定队员；`leader` 始终解析当前队长。
  返回目标布局、访客快照、线路/楼层及 60 秒 HMAC 入场票据。入场时重新校验队伍、队长、
  目标连接 nonce/epoch/楼层、权限和容量，目标已变化时拒绝旧票据。

`online_players.party_farm_access` 保存获准访问的当前队伍 ID，离队、踢人或解散清空。
撤销权限后关闭不再获准的私有农场访客连接，客户端返回原场景。公开访问独立存在。
街区旅行快照不包含作物/背包，农场只返回既有访客 DTO；旅客保留自己的身份、库存与家乡设置。
客户端先等待未确认操作、刷新存档并收到 `departed`，再加载目标场景；替换原矿井入口需要明确确认。
拜访场景替换前一个拜访场景并保留最初返回点，避免反复汇合堆积场景。

邀请码是随机 12 位十六进制值；队伍写请求受 HTTP 频率限制。队伍关系变化不会修改现存实例或位置，
入口绑定只在下一次进矿决定。断线队长不算正在矿内，不向新进队员提供其历史进度。

```sh
pnpm --filter farm-server typecheck
node server/tools/test_online_isolated.mjs test/realtime
pnpm --filter farm-server exec tsx tools/online_load.ts
pnpm --filter farm-server exec tsx tools/online_pg_capacity.ts
godot --headless --path . res://tools/dev/export_online_navigation.tscn
```

`online_qa_server.ts` 仅是本地内存夹具，可用 `ONLINE_QA_CROWD=298` 增加真实机器人连接，
供一台 Godot 与一台 Android 客户端一起验证 300 人；其测试账号文件和 APK 不用于生产。
