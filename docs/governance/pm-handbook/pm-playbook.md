## 3. 核心工作流

### 3.1 规则 / 文案改动：q 行（全部要用户批）
1. 任何会改变玩家看到或能做的事的口径（规则、数值、文案、按钮样式、可走范围、落点规则……）都要成为一条 **q 行**，写在 `docs/product/gameplay-plan-v2-2026-10-02.md`（.md + .html），由**李白**写成一个独立提交（叠在最新 farm-dev 上）。
2. **所有 q 行先交不知火舞审**（包括无画面的）。界面 / 文案类：不知火舞定规格 → 安其拉出帧 → 不知火舞验收 → 才能报批。
3. 李白在 **SGODOT-302**（q 行台账二，q(158) 起；210 存 q(1)–q(157)）挂【待批】：说明 + **改前 / 改后真实截图**（不要抽象示意图）+ Figma 帧链接 + 不知火舞结论 + 影响与实现人 + 提交号。纯规则标「无画面」。没有图的界面类 q 行退回。
4. 奕星报用户，用户回 `N ok` 才推。推送步骤（自己做）：
   ```bash
   git fetch -q origin farm-dev
   WT=〔私有路径〕
   git worktree add -q --detach $WT origin/farm-dev && cd $WT
   git cherry-pick -x <sha>
   diff <(git show <sha> --format= | grep -v '^index ' | grep -v '^@@') <(git show HEAD --format= | grep -v '^index ' | grep -v '^@@')   # 必须无输出
   git fetch -q origin farm-dev && test "$(git rev-parse origin/farm-dev)" = "$(git rev-parse HEAD~1)"   # farm-dev 没动
   git push -q origin HEAD:refs/heads/farm-dev
   cd - && git worktree remove --force $WT
   ```
   冲突（多条 q 行改同两个文件很常见）就请李白重叠到最新 farm-dev 发新提交号，不要自己解冲突。推完告诉李白在 210 记【已批·已推 <sha>】。
5. **开发 PR 里涉及新规则的部分，q 行没批不能合**（"规则口径先有 q 行再合"）。会话里临时定给开发的口径也要同轮补 q 行。
6. 锁定组件（SGODOT-197 清单）要改，先在 197 发复议，随 q 行一起报用户；不知火舞维护 197 增补。
7. **数值 / 规则复核（10-13 用户定，暂用子代理）**：李白的 q 行凡涉及数值、经济、节奏、规则联动，奕星报用户前开一个只读子代理独立复核（和方案其他章节是否矛盾、数字能否推出、和已定规则 / 模拟器是否冲突、实现可行性），结论随报批一起给用户；挡批的问题退回李白。纯界面 / 文案只由不知火舞审。以后若改为增设虚拟员工，再更新此条。

### 3.4 代码 PR
- 作者：测试全过 + 截图 / 短视频传到对应 Plane 卡（节奏类改动必须附几秒视频），开 PR 时直接 @ 审核人。
- 审核：交叉审核（GitHub 同账号不能 Approve，结论写在 comments 或 Reviews）；UI 改动还要不知火舞走查；3D 接入要上官婉儿技术检查。
- **已审过的 PR 要再推，先在 PR 写"还有增量，先别合"**，推完报新头。
- **奕星合并**：
  ```bash
  gh pr view N --json headRefOid,mergeable --jq '"\(.headRefOid) \(.mergeable)"'
  gh pr view N --json comments --jq '.comments[-3:][]|...'    # 看有没有"先别合"
  gh pr view N --json reviews  --jq '.reviews[-2:][]|...'     # 审核也可能交在 Reviews
  gh pr merge N --merge --match-head-commit <完整 sha>
  ```
  只按审过的头合。审后若多了小增量（如只改 README 一行），用 `git fetch origin pull/N/head:refs〔私有路径〕` + `git diff <审过的头> refs〔私有路径〕` 确认只是那一处再合，否则请审核人复看。`mergeable` 为 UNKNOWN 时等几秒再查；GraphQL EOF 就重查状态后重试。
- 合完回作者一句（提交号、进哪个版本）。

### 3.9 重启恢复（10-12 事故后）
- 〔机器名〕 重启后，herdr 只把窗格恢复成空 shell，不会自动启动会话。**不要在窗格里按「↑ 回车」恢复**：各窗格共用 zsh 历史，会把所有窗格恢复进同一个会话（10-12 就这样让 14 个窗格进了奕星会话）。
- 正确做法：用 `herdr agent list` 或 `〔私有路径〕` 里每个窗格的 `agent_session`，逐个窗格运行 `<启动命令别名> --resume <会话编号>`，或 `herdr agent start <名字> --kind claude --pane <窗格> -- --resume <编号>`。
- 恢复后核对：每个窗格的会话编号互不重复，没有残留的重复进程；然后 ListAgents，广播全员新会话名。
- 恢复失败就新开会话，靠本手册、最新 status 文档和 Plane 卡接上。
