# 合伙人演示 Runbook（3–5 分钟）

适用版本：2026-09-01 内部 Demo ｜ 主设备：Android 真机 ｜ 目标：在最短时间内证明
“地图探索 → 形象编辑 → 保存 → 地图同步”已经形成完整产品闭环。

> 演示原则：只走一条主路径，不现场解释工程菜单。性能监视仅在被问到承载能力时打开；
> 无障碍只陈述已经实现和验证的边界。

## 1. 演示前检查

### T-15 分钟：走一遍闭环

- 使用本次汇报对应的 debug 包，不在现场临时安装或更新。
- 打开应用并处理定位权限。推荐提前选择“使用 App 时允许”；只给大致位置也可以继续。
- 确认地图底图可见且地图标签为英文；顶部状态不再长时间停在 `Locating...`，角色计数
  `N people` 不为 0。
  定位不可用时，3 秒后显示 `Demo Area / Demo location` 也可以走完整主线。
- 确认顶部先显示 `Loading map...` 和 24 步细进度条；进度条至少停留 1800ms，并且只在
  Mapbox ready、23 个角色全部完成且队列清空后自动隐藏。
- 确认右侧窄工具栏从上到下依次显示单个 `3D` switch、`Explore LA`、小型 `Edit` 和
  48dp `↻`。点一次 `↻` 应把地图旋转 30°；如果旅行按钮显示 `Back Nearby`，先点一次回到
  `Nearby`。
- 点一个珊瑚色圆形 `!`，确认英文留言气泡可展开，再点一次收起。
- 进入 `Edit Avatar`，确认 `Hair` 中存在 `Chestnut Long`，并完整走一次
  `Done → map sync`。
- 为了让现场变化明显，演示前把自己的发型保存为 `Silver Crop`，再回到 `Nearby`。
- 准备一段已跑通主路径的短录屏，以及一张性能监视截图，作为断网或投屏故障兜底。

### T-2 分钟：保持可演示状态

- 打开勿扰模式，锁定竖屏，亮度调到投屏可读，关闭省电模式并保持设备电量充足。
- 应用停在 `Nearby`；等待顶部进度条隐藏、角色和 `N people` 数量稳定后再开始投屏。
- 不清除应用数据，不停留在权限弹窗、`Los Angeles` 或 `Edit Avatar`。
- 备用终端可提前停在下方性能页启动命令处，但不要执行。

性能监视是 debug-only 页面，正式 UI 没有入口。需要时用：

```bash
adb shell am start -S -W \
  -n com.sensen.avatarphase1/com.godot.game.GodotAppLauncher \
  --es com.sensen.qa.SCENE stress
```

## 2. 主路径（约 3 分 30 秒）

| 时间 | 演示操作 | 建议讲法 | 通过信号 |
|---|---|---|---|
| 0:00–0:40 | 从 `Nearby` 开始，等细进度条隐藏后轻拖地图；点右侧 `↻` 旋转一次；点一个 `!` 展开英文留言，再点一次收起 | “首页把真实地图、附近的人和自己的 3D 形象放在同一个探索界面里；社交内容直接锚定在地点上。” | 地图可拖动且点击 `↻` 后旋转 30°，角色正常显示；顶部为 `Nearby / Near You / Demo Area` 之一，计数为 `N people`；`!` 气泡可开合 |
| 0:40–1:15 | 点右侧 `Explore LA`，再用同一个 switch 切到 `2D`，随后切回 `3D` | “地点切换和视角切换都留在地图上下文内；一个 switch 清楚表达当前模式，不再用两枚并列按钮占空间。” | 标题为 `Los Angeles`，状态为 `Exploring`，旅行按钮变为 `Back Nearby`；switch 在 `2D / 3D` 间同步切换 |
| 1:15–1:40 | 点右侧栏的小按钮 `Edit`，等待角色和选项稳定 | “形象编辑是主流程的一部分，不是独立的工程工具；预览阶段不会立即覆盖用户已保存的搭配。” | 进入 `Edit Avatar`，底部显示分类和款式 |
| 1:40–2:25 | 点 `Hair` → `Chestnut Long`；等待 `Selected: Chestnut Long`，可轻拖角色展示侧面 | “换装即时预览，异步加载期间保留完整角色，不用空白或半成品画面打断体验。” | 发型可见变化（银色短发 → 深棕长发，投屏上一眼可辨），状态从 `Trying on: Chestnut Long` 变为 `Selected: Chestnut Long` |
| 2:25–2:50 | 只点一次 `Done` 并等待 | “只有完成才提交；保存期间按钮和返回都被保护，避免重复提交或中途离开造成状态错乱。” | 按钮短暂显示 `Saving...`，随后自动返回地图 |
| 2:50–3:30 | 等待地图重载时的 `Loading map...` 和细进度条隐藏，确认 switch 为 `3D` 并展示自己的长发造型 | “同一份形象配置已经回写到地图中的自己，编辑、持久化和多人地图展示形成闭环。” | 进度条至少显示 1800ms，并在 Mapbox ready、23 个角色全部完成且队列清空后隐藏；地图中的自己显示 `Chestnut Long`，重新进入 `Edit Avatar` 仍保持该选择 |

收尾一句：**“今天展示的重点不是三个孤立页面，而是一条已经连通、能保存、能回到核心场景的
用户路径；接下来会把这条路径扩展到社交互动和正式内容。”**

## 3. 性能页备用（额外 45–60 秒）

不要主动切到性能页。合伙人追问“多角色是否扛得住”或“合并装配有什么收益”时再展示：

1. 执行上面的 debug 启动命令，确认页面标题为 `Performance Monitor`，并带有
   `INTERNAL` 标记。
2. 把 `Characters` 滑到 `15`，确认按钮显示 `Assembly: Merged`。
3. 等待 3–5 秒，等加载抖动结束后，再读出当前设备上的 FPS、帧时、绘制调用和显存。
4. 只有对方追问对比时，点一次切为 `Assembly: Direct`，再次等待稳定后比较绘制调用和帧时。
5. 点 `Back to Map` 结束，不把这个页面描述成面向用户的正式功能。

对外口径：**这是当前真机的现场采样和装配策略对比，不是所有机型的 60 FPS 承诺。**

## 4. 失败恢复

| 现场情况 | 立即处理 | 不要做 |
|---|---|---|
| 顶部停在 `Locating...` | 等 3 秒；进入 `Demo Area / Demo location` 后照常演示 | 现场进入系统设置反复改权限 |
| 定位权限弹窗意外出现 | 选择“使用 App 时允许”；大致位置也可用 | 解释 Android 权限实现细节 |
| 开场旅行按钮显示 `Back Nearby` | 点一次，等标题回到 `Nearby` 后重新开场 | 从 `Los Angeles` 倒着讲主线 |
| `N people` 暂时为 0 或进度条仍可见 | 至少等待 1800ms；Mapbox ready 和 23 个角色全部完成前保持可见属于正常状态。冷启动 6 秒后仍未完成才只重启应用一次 | 连续点击、缩放或清除应用数据 |
| `Chestnut Long` 已经选中 | 先选 `Silver Crop`，状态稳定后再选 `Chestnut Long` | 用几乎看不出的重复点击假装变化 |
| 提示发型加载失败 | 旧搭配会被保留；重试一次，仍失败就切到预录主路径 | 连续猛点款式或声称已经保存 |
| `Saving...` 尚未结束 | 等待，系统返回和页面操作此时会被拦截 | 重复点 `Done` 或强退应用 |
| 出现 `Couldn't save. Try again.` | 等 2 秒后再点一次 `Done`；再次失败则切预录 | 点 `Back`，这会丢弃本次草稿 |
| 完成后地图一时未显示新发型 | 等进度条隐藏，确认 switch 为 `3D` 并拉近；仍不对则用预录闭环 | 当场重装包或修改存档 |
| 底图黑屏、投屏中断或应用崩溃 | 重启一次；第二次仍失败立即切预录和静态性能截图 | 在合伙人面前进入日志排障 |
| 性能页无法打开 | 展示预先准备的截图，并说明机型、角色数和装配策略 | 报一个没有现场或历史记录支撑的数字 |

误触返回的恢复语义：换装页在点 `Done` 前返回，会丢弃草稿并回地图；保存期间返回会被忽略；
性能页返回会回地图；地图根页在 Android 上返回会把应用移到后台。

## 5. 无障碍能力边界

当前 Demo 完成的是**移动触控可用性基线**，不是完整的无障碍合规版本。

已经具备：

- 主要按钮、款式选项和地图 `↻` 采用至少 48dp 的触摸目标，并适配刘海、挖孔和底部手势安全区。
- Godot 页面文案和 Mapbox 地图标签统一使用英文；`Locating...`、`Trying on`、`Selected`
  和保存失败都有文字反馈，关键状态不只依赖颜色表达。
- 保存和异步换装期间会禁用冲突操作，加载失败时保留上一套搭配，降低误操作成本。

尚未完成或未验证：

- TalkBack、VoiceOver 的朗读顺序、控件语义和 3D/地图内容描述。
- 系统动态字号、屏幕放大、键盘/开关控制、减少动态效果和高对比度模式。
- 面向 WCAG 或平台规范的完整对比度审计与真机辅助技术验收。

被问及时统一回答：**“触摸尺寸、安全区和状态反馈已经进入设计系统；读屏、动态字号和替代输入
仍是产品化阶段的明确工作项，在完成真机辅助技术验收前不把本 Demo 表述为无障碍合规。”**

## 6. 演示者禁区

- 不主动进入性能监视，不展示 debug 命令或工程参数。
- 不承诺所有设备稳定 60 FPS，不把一次现场读数外推成量产指标。
- 不声称定位、iOS 真机或辅助技术已经全量验收。
- 不在失败后现场排日志；一次重试无效就切换到准备好的录屏或截图。
