# C-118 地图建筑数据只加载一次

起因见 `docs/plans/C-111.md`：全量建筑数据 `buildings.geojson`（r6，约 60 MB、14 万多个要素）的 Mapbox 源编号带 generation，
地图每次暂停（进 3D、切后台、锁屏）都删掉，恢复时重新加一份，于是每次回地图都要重新解析整份文件，上一份没解析完时还可能和新的一份并发。

## 改法

- `tools/android/overlay/ParcelMapController.kt`：建筑源改用固定编号 `gensen-buildings-datasf`，地块图层清掉时不删它。
  重新装图层时，同一个地址、源还在（不管是加载中还是已加载）就直接复用；只有换地址、上次加载失败、样式重载（新样式里没有这个源）
  或关闭地图时才重新加。复用已加载的源时立刻报 `buildings_source_ready`，不再等。
- `ParcelLayerState.kt` 里的 `ParcelBuildingsSource` 管这个判断（不依赖 Mapbox，JVM 单测直接测）。
- 地块源、高亮源、图层和点选逻辑都没改，仍按 generation 重建；地图显示和点选行为不变。数据集本身不动（归 C-113）。
- 日志：原生打 `DYNAMIC_BUILDINGS_SOURCE ADD/REUSE/REPLACE`（每次装图层一条）和 `LOADED ms=…`（一份源第一次加载完）；
  Godot 侧 `DYNAMIC_LOAD {"resource":"buildings","stage":"ready","elapsed_ms":…}` 记从设好源到建筑层可点的等待。
  `tools/dev/dynamic_farm/crash_repro.sh` 汇总这几项，并加了 `PAN_PASSES`（设 0 时不平移缩放，每轮都能进 3D）。

代价：在 3D 里时，解析好的建筑数据仍留在 Mapbox 里。模拟器上在 3D 时的 PSS 改前约 1069–1142 MiB、改后约 1103–1173 MiB，差约 30 MiB。

## 模拟器对照（mac-mini，AVD Sensen_P0，arm64，headless，SwiftShader 软件渲染）

两个隔离预览包（`build_worker_apk.sh --dynamic-farm`，不登录、不连测试服），每个都是全新安装，同一脚本：
冷启动，然后进出 3D 预览 5 次、Home 后重开 5 次、锁屏亮屏 5 次，每次回到地图都等建筑层可点（最多 120 秒），内存每 2–3 秒采一次。
改前包是基线 bf668d38 只加了上面那条 Godot 等待日志，没有复用。

| 项 | 改前 | 改后 |
| --- | --- | --- |
| 装地图源次数 | 15 | 15 |
| 建筑源新加 / 复用 | 每次都新加（15 次） | 新加 1 次（ADD），复用 14 次（REUSE），解析完成 1 次（LOADED） |
| 冷启动等建筑层 | 10.7 s | 10.4 s |
| 每次回地图等建筑层 | 4.7–5.5 s，中位 5.0 s | 31–64 ms，中位 49 ms |
| 回地图后 8 秒内 PSS 峰值 | 中位 1461 MiB，最高 1774 MiB | 中位 1155 MiB，最高 1183 MiB |
| 回地图时 PSS 比回去前涨 | 中位 336 MiB，最高 658 MiB | 中位 10 MiB，最高 21 MiB |
| 应用收到的流量（整轮） | 64.3 MB | 64.3 MB |
| 闪退 / ANR | 无 | 无 |

- 流量两边一样：这台模拟器上改前也只下载了一次，后面的重复请求由 Mapbox 自己的缓存接住了，浪费主要在重复解析。
  真机上的缓存会不会命中没有核。
- 改后回到地图后点 110 PIERCE ST 照常选中、黄色高亮只在楼内；进 3D 预览正常。
- 软件渲染下的数值不能直接和真机比，只看两边的差。真机没有测。
