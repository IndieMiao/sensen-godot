# C-164 · cardigan-check.yml 的合并合批派发参数

`workflow_dispatch` 新增四个可选输入：`merge_tier`（缺省 `single`）、`scope`（缺省 `full`）、`affected_paths`、`skip_checks`（缺省空）。原六个必填输入、run-name、步骤名称、顺序和数量都不变：Initialize containers、actions/checkout、Verify candidate、actions/setup-node、pnpm/action-setup、install、build、test、lint、dynamic_farm、deps、e2e。

## 校验

范围判定放在已有的 `Verify candidate` 步骤里（加 `id: verify`），不新增步骤。原因：工作流从可信基线派发，但 checkout 出来的是候选，如果把判定放进仓库脚本，候选改一下就能给自己跳过测试。

- 四个输入只经 `env` 进入，用固定的 `case` 和正则比较，不 eval、不拼进命令；`LC_ALL=C` 让 `[a-z]` 按字节比较。只把规范化后的值写进步骤输出。
- 四个输入都声明为 `string`，没有用 `choice`：值不在 choice 列表里时 GitHub 会直接拒绝派发，而本卡要求未知值按全量跑。
- 合法组合（照 Cardigan 协议）：
  - `merge_tier` ∈ `single|card|batch`；缺省、空值或未知值按全量跑。`batch` 一律全量。
  - `scope=affected`：`skip_checks` 为空，`affected_paths` 是 1–64 个用单个空格分隔的 `^(packages|apps)/[a-z0-9-]+$`，总长不超过 4096 字节。
  - `scope=docs_only`：`affected_paths` 为空，`skip_checks` 只能是 `test`、`e2e`、`test,e2e`。
  - 其它组合一律 `scope=full`，所有步骤照跑。
- 步骤条件：`test` 在 `skip_test=true` 时跳过（仍隐含 success()）；`e2e` 在 `skip_e2e=true` 时跳过。其它步骤条件不变。实际生效的范围写进 job summary 的 `check scope:` 一行。

## 和 Cardigan 参考的差别

- `scope=affected` 校验通过并记录，但 `test` 步骤仍然全量运行：这一步跑的是 Godot `res://tests/p0`，不按 workspace 包拆分。e2e（`pnpm -r test`）照协议也不缩小。结果是覆盖多于范围声明，不会更少。
- `merge_tier=card` 不跳过 e2e。Cardigan 的「卡级不跑 e2e」是它自己项目的拍板；sensen 的 e2e 是服务端测试，耗时短，跳过收益小，而且跳过一个主机没预期的步骤可能被记为未运行。以后要改，只需改 `skip_e2e` 这一行。
- 不新增候选 tree 核对，也不改其它步骤。

## 本地校验

`tools/ci/test-check-inputs.sh`：静态核对输入定义、步骤契约和 env-only 传参；从工作流里抽出真实的 `Verify candidate` 脚本，在临时 git 仓库里跑缺省、合法、非法和注入样式的输入（`;`、`$()`、反引号、换行写输出等），核对输出、标记文件不出现、`GITHUB_OUTPUT` 只有五个键。这个脚本不在 CI 里跑（不能加步骤），需要 Python 3 和 PyYAML。远端行为以合并检查为准。

合入后由张良在主机打开 `scoped_checks` 和合并队列，本卡不改主机配置。farm-dev 同步见 C-165。
