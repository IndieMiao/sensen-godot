# C-31 动态农场服务端：地块认领与地块农场存档（0.4.2）

## 选哪套服务端

选 **Journey 的 PostgreSQL 服务（`server/src/index.ts`，`/v1/auth`、`/v1/farms` 那一套）**，在同一个库里新增一张表，
不用 P0 服务端（`tools/p0_server.ts`，JSON 存档）。

| 需要 | Journey / PostgreSQL | P0 服务端 |
| --- | --- | --- |
| 身份 | Bearer token（`/v1/auth/anonymous`、邮箱、Apple、Google），客户端 `Net` 已有 | `x-p0-player` 请求头里的本地 ID，不做认证，谁都能冒充 |
| 别人地块显示昵称 | `users.display_name` 已有 | 存档里没有昵称 |
| 两人同时抢同一块只有一人成功 | 主键 + 唯一索引，多进程、多副本也成立 | 只靠单进程单线程；存档是整份 JSON 重写 |
| 重启后读回 | 数据库持久化，备份、恢复演练已有 | JSON 文件 |
| 测试包现状 | 动态农场测试包是 Journey 的 Android 预设变体（`com.sensen.dynamicfarm.cardigan`），网络层就是 Journey 的 `ApiClient` | P0 是另一个游戏（Gensen），改它的存档版本会影响线上 P0 玩家 |

复用的是 `players` / `tokens` / `users` 三张表和全部登录接口，以及 `writer` 规则（游客只读，开发服 `GUEST_WRITES=1` 时游客也可写）。
**没有复用 `farms` 表**：它每行绑定 Journey 的地区、蓝图、领域版本和整套 Journey 存档，`owner_id` 唯一，
已有 Journey 农场的玩家没法再放一块动态地块；硬塞进去还会让 Journey 的迁移工具、访客快照和实时房间把它当 Journey 农场处理。
所以新增独立的 `parcel_claims` 表，删号时随 `players` 级联删除。

物品编号沿用 P0 内容表（`hoe_starter`、`seed_carrot`、`crop_carrot`），方便客户端（C-34）复用主农场的作物定义和图标；首栋住宅蓝图为 `blueprint_cottage`。

## 数据表 `parcel_claims`（`server/src/db/schema.sql`，启动时 `CREATE TABLE IF NOT EXISTS`）

| 列 | 说明 |
| --- | --- |
| `community_id` text | 社区编号，服务端按数据集推出（`dynamic_farm.json` 的 `communities`），客户端不能自报。本版只有 `sf` |
| `layer` int | 社区内的层，本版恒为 0；以后分层不改结构 |
| `parcel_id` text | 地块编号 `p-<parcel_id>`，与客户端 `geo_contract.valid_id` 同一字符集 |
| `player_id` uuid | 认领者，`players(id)`，删号级联 |
| `kind` text | `free`（免费认领）；为以后购买、扩张预留 |
| `dataset_version` text | 认领时客户端用的地块数据集 |
| `center_lat` / `center_lng` | 地块中心点，只用于按区域查询归属 |
| `claimed_at` bigint | 认领时间（毫秒） |
| `farm_version` int | 地块农场的乐观版本，每次成功写入加一 |
| `farm_state` jsonb | 地块农场状态，见下 |
| `updated_at` bigint | 最近写入时间 |

约束：

- 主键 `(community_id, layer, parcel_id)`：同一块地只有一行。并发认领时只有一条 `INSERT` 成功，其余 `ON CONFLICT DO NOTHING`。
- 部分唯一索引 `parcel_claims_one_free (player_id) WHERE kind = 'free'`：每人只有一块免费地，同一人并发抢多块也只成功一块。
- 索引 `parcel_claims_center (community_id, layer, center_lat, center_lng)`：区域查询。

这是纯新增（新表和索引），不改、不重写旧表和旧存档；回退旧版本服务时这张表会被忽略。

## 地块农场状态 `farm_state`（版本 1）

```json
{
  "v": 1,
  "house": { "model": "cottage", "x": 10, "y": 4, "width": 3, "depth": 3, "rotation": 0, "built_at": 1795392000000 },
  "cleared": ["2,2"],
  "tilled": ["1,1", "2,2"],
  "crops": { "2,2": { "crop": "crop_carrot", "planted_at": 1795392000000, "ripe_at": 1795392060000 } },
  "bag": { "hoe_starter": 1, "seed_carrot": 2 },
  "welcomed_at": 1795392000000
}
```

格坐标用地块数据的本地网格 `"x,y"`（0–1023 的规范整数写法）。`house` 是左上角格和朝向（0–3，转 90°/270° 时宽深互换）。
`welcomed_at` 是首次进入发赠品的时间，`null` 表示还没进过；认领时背包为空。

## 规则由谁保证（本版）

服务端没有地块几何（地块形状、核心区、外围、保护通道、障碍物位置都在地块数据集里，只有客户端加载），所以分工如下：

| 规则（出处） | 服务端（本卡，已实现并有测试） | 客户端（C-33 / C-34 负责） |
| --- | --- | --- |
| 首次进入自家地块送 1 把锄头、3 粒萝卜种子（Q-39）和 1 张首栋住宅蓝图（Q-40），重开、重试不重发 | `POST /v1/parcels/mine/enter` 在行锁内只发一次，记 `welcomed_at`；并发重试也只发一次 | 每次打开自己的地块调用一次，按 `granted` 决定是否提示收到赠品 |
| 萝卜播种后按服务端时间 60 秒成熟，未满不能收（Q-39） | `ripe_at` 由服务端时间算，提前收获返回 `NOT_RIPE` | 用 `server_time` 和 `ripe_at` 显示进度 |
| 清障、开垦各点一次即完成，不耗体力或金币（Q-39） | 一条命令即完成；清障不需要任何物品，开垦只要求背包里有锄头；都不扣东西 | 点击即发命令 |
| 首栋住宅合规放下即建成（Q-40） | 放置扣 1 张蓝图，`built_at` 即放置时间，没有施工计时；只能放一次 | 预览、确认后发命令 |
| 住宅不覆盖已开垦格（Q-40） | 占地内有开垦格或作物就拒绝（`CELL_OCCUPIED`） | 预览显示不可放 |
| 住宅占地内不能开垦（Q-39） | 拒绝（`CELL_OCCUPIED`） | 预览显示不可开垦 |
| 住宅全部占地在自家核心区内，不压障碍物和保护通道（Q-40） | **未校验**：服务端不知道核心区、障碍和通道的位置，只校验坐标在 0–1023 内 | 按地块数据判断并拒绝 |
| 只在自家核心区合法空格开垦，保护通道和外围拒绝（Q-39） | **未校验**（同上） | 按地块数据判断并拒绝 |
| 只能动自己的地块 | 所有写接口只按 token 找本人的地块；别人看到的只有归属和昵称，没有农场内容 | — |

服务端未校验的几条，本版靠客户端保证；改过客户端的请求能绕过它们，只会影响自己的地块。
要在服务端校验，需要服务端能读到同一份地块数据，属于“地块几何数据来源”，不在本卡。

## 接口

全部需要 `Authorization: Bearer <token>`。响应都带 `server_time`。

`GET /v1/parcels/mine` → `{ parcel: Parcel | null }`

`POST /v1/parcels/claim`，需要账号：

```json
{ "dataset_version": "sf-dynamic-farm-20261118-r4", "parcel_id": "p-3512001", "center": [-122.4194, 37.7749] }
```

| 结果 | 状态码 |
| --- | --- |
| 认领成功，`{ parcel }`，农场为空（背包为空，赠品等首次进入再发） | 201 |
| 重复认领自己那块（网络重试），`{ parcel }` | 200 |
| 已有一块，`{ code: "ALREADY_CLAIMED", parcel: 自己那块 }` | 409 |
| 别人已认领，`{ code: "PARCEL_TAKEN" }` | 409 |
| 数据集不在 `dynamic_farm.json` 里，`UNKNOWN_DATASET` | 422 |
| 参数不对 `SCHEMA` / 游客 `LOGIN_REQUIRED` / 没登录 `UNAUTHENTICATED` | 400 / 401 |

`Parcel` = `{ community_id, layer, parcel_id, dataset_version, center: [lng, lat], claimed_at, farm_version, farm }`。

`GET /v1/parcels?dataset_version=…&ids=p-1,p-2`（最多 200 个）→ 每个都回答
`{ parcel_id, owner: "mine" | "other" | "none", nickname }`。

`GET /v1/parcels?dataset_version=…&bbox=西,南,东,北`（GeoJSON 顺序，每边最多 0.25°）→ 只列出范围内已被认领的地块，
最多 500 条，超出时 `truncated: true`。`ids` 和 `bbox` 二选一。`nickname` 是认领者账号昵称，游客或未设昵称为 `null`。

`POST /v1/parcels/mine/enter`，需要账号：进入自家地块。第一次发 `welcome_gift`，返回 `{ granted: true, parcel }`；
之后重开、重试都返回 `{ granted: false, parcel }`，不重发。没有地块 404 `NO_PARCEL`。

`POST /v1/parcels/mine/commands`，需要账号：`{ base_version, commands: [...] }`，1–50 条，整批成功才写入。

| 命令 | 规则 | 失败码 |
| --- | --- | --- |
| `{type:"place_house", x, y, rotation?}` | 扣 1 张蓝图，放下即建成；只能放一次；占地不能压开垦格或作物 | `HOUSE_PLACED`、`NO_BLUEPRINT`、`CELL_OCCUPIED`、`OUT_OF_BOUNDS` |
| `{type:"clear_obstacle", cell}` | 记一次已清理，立即完成、不耗东西 | `ALREADY_CLEARED` |
| `{type:"till", cell}` | 背包里要有 `till_tool`；不在房子占地内 | `NO_TOOL`、`CELL_OCCUPIED`、`ALREADY_TILLED` |
| `{type:"sow", cell, crop}` | 开垦格、空格、扣一颗种子；`ripe_at = 现在 + grow_seconds` | `UNKNOWN_CROP`、`NOT_TILLED`、`CELL_OCCUPIED`、`NO_SEED` |
| `{type:"harvest", cell}` | 服务端时间到 `ripe_at` 才行；产物进背包，格子保持开垦 | `NO_CROP`、`NOT_RIPE`（带 `detail.ripe_at`） |

成功 200 `{ parcel }`；命令失败 422 `{ code, index, detail?, parcel }`（状态不变）；
`base_version` 不是当前版本 409 `{ code: "VERSION_CONFLICT", parcel }`；没地块 404 `NO_PARCEL`。

`POST /v1/parcels/mine/abandon`（放弃并重选）：只有服务进程设置 `DYNAMIC_FARM_RESELECT=1` 时可用，
放弃后地块变回无主、地块农场一并删除，可以重新认领（新地块从空农场开始，首次进入再发一次赠品；只在测试服可用）。
正式配置不设这个变量（没设或设成别的值都算关闭），调用一律 403 `RESELECT_DISABLED`，地块不动。启动日志会打印 `parcel_reselect=true/false`。

## 可调数值 `assets/farm/data/dynamic_farm.json`

| 项 | 默认 | 来源 |
| --- | --- | --- |
| 社区与数据集 | `sf` ← `sf-dynamic-farm-20261118-r4` | 当前测试包数据集 |
| 首次进入赠品 `welcome_gift` | 锄头 `hoe_starter` ×1、萝卜种子 `seed_carrot` ×3 | 所有者拍板 Q-39（C-34#14） |
| 首次进入赠品 `welcome_gift` | 首栋住宅蓝图 `blueprint_cottage` ×1 | 所有者拍板 Q-40（C-33#14） |
| 房屋 | `cottage`，3×3，放下即建成 | C-30#12（模型与占地）、Q-40（即建成） |
| 萝卜 `crop_carrot` | 播种后 60 秒成熟，收获 1 个 | Q-39；收获数量沿用 P0 `crop_carrot` 的 `yield: 1` |

服务启动时校验这个文件，不合法直接退出。它不在 Journey `content_version` 指纹里，改它不影响旧农场存档。
开垦工具 `till_tool` 为 `hoe_starter`。

## 不在本卡

地块购买、扩张、好友、分层方案；地块几何数据来源（临时隧道迁移另卡）；新账号或凭据；
服务端核对 `parcel_id` 是否真的存在于数据集（服务端不持有地块数据）；账号数据导出里带上地块（`/v1/users/me/export`）。
