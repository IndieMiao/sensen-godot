# C-132 账号登录加固（仅服务端）

## 1. Google nonce 一次性
- 校验通过的 Google id_token，其 `nonce` 声明（原始 nonce 的 SHA-256）写入 `id_token_nonces`（主键 provider + nonce_hash），
  单条 `INSERT … ON CONFLICT DO NOTHING`：同一 nonce 第二次登录、或并发的几次里除第一次外，一律 401 `GOOGLE_TOKEN_REPLAYED`。
- 记录在 token 的 `exp` + 时钟偏差之后清理（那时 token 本身已过期）。客户端本来每次登录都生成新 nonce，无需改动。

## 2. 登录限流不让旁人锁号
- 每个邮箱 × 每个网络（IPv4 地址 / IPv6 /64）15 分钟 10 次，所有人都受约束。
- 每个邮箱 15 分钟 10 次，只计来自该账号 90 天内没成功登录过的网络的尝试。
- 成功签发会话（注册、登录、找回密码、Google / Apple）时把当前网络记为该账号登录过的网络（`login_networks`，只存 HMAC）。
- 效果：旁人试错只挡住陌生网络；本人从登录过的网络照常登录；陌生网络合计额度与改前按邮箱的一样，爆破不放宽。
  本人在一个从没登录过的新网络上、恰逢正被攻击时仍会被挡（与改前相同）。
- 站外删号（邮箱 + 密码 / 删号码）同一套规则。

## 3. 验证信上限
- 每封验证信按收件邮箱（每小时 5、每天 10）和全服（每小时 200、每天 1000）计。
- 发码与站外删号发码在查邮箱是否注册之前扣额度，未注册邮箱同样计数；超限 429 `RATE_LIMITED`、`reason: MAIL_LIMIT`、`retry-after`，
  回包不因注册与否而不同，客户端沿用现有“Too many attempts”提示。
- 注册超限时账号照常建出，不发信，回包 `verification_sent: false`、`verification_error: MAIL_LIMIT`。
- QA 域名不发信，不计。

## 可配置默认值
`LOGIN_ATTEMPTS_PER_NETWORK_15MIN`=10、`LOGIN_ATTEMPTS_PER_ACCOUNT_15MIN`=10、`LOGIN_TRUSTED_NETWORK_DAYS`=90、
`MAIL_PER_RECIPIENT_HOUR`=5、`MAIL_PER_RECIPIENT_DAY`=10、`MAIL_PER_HOUR`=200、`MAIL_PER_DAY`=1000（1–1000000 的整数，其它值拒绝启动）。
计数与其它限流一样在进程内存里；登录过的网络和用过的 nonce 落库。
