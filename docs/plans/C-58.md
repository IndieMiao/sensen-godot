## 存档字段（追加在 v1 上，不改版本号）

| 字段 | 说明 |
| --- | --- |
| `coins` | 金币余额，只由出售增加 |
| `sales` | 成功出售的次数（蓝图条件） |
| `gathered` | 外围物件编号 → 最近一次采集的服务端时间；已过刷新时间的记录在下次采集时清掉 |
| `blueprints_claimed` | 已领的一次性蓝图 → 领取时间 |

旧存档兼容：C-31/C-34 时期写下的存档没有这四个字段，服务端读出和执行命令前按开局值补上（金币 0、没卖过、没采过、没领过），
不动已有字段；只有该玩家下一次成功写入时才把新字段写回库里，进入地块（不发赠品时）不改写。
接口回复里的 `farm` 总带这四个字段。0.4.2 客户端（`parcel_farm.gd` 的 `normalize`）只认 `v=1` 和原有字段，多出的字段忽略，照常可用。

## 新命令（`POST /v1/parcels/mine/commands`，与原命令同批、同版本门控、整批成功才写入）

| 命令 | 规则 | 失败码（422） |
| --- | --- | --- |
| `{type:"sell", item, count}` | 单价只取服务端配置，请求里的价格字段被忽略；背包要有 `count` 个；成功后背包减、金币加 `单价×count`、`sales+1` | `NOT_SELLABLE`、`NOT_ENOUGH`（`detail.have/need`）、`COINS_CAP` |
| `{type:"gather", object}` | 编号格式见下；编号里的地块必须是 token 查到的本人地块；配方版本须等于配置；模型须是可采类；格子不能是服务端已知的核心区格；刷新前不能再采；成功得配置的物品 | `UNKNOWN_OBJECT`、`NOT_YOUR_PARCEL`、`STALE_RECIPE`、`NOT_OUTER`、`NOT_RESPAWNED`（`detail.ready_at`）、`TOO_MANY_OBJECTS`（`detail.max`，该类刷新期内已采满） |
| `{type:"claim_blueprint", blueprint}` | 本版只有 `coop`；满足条件发一次，记 `blueprints_claimed` | `UNKNOWN_BLUEPRINT`、`CONDITION_NOT_MET`（`detail.sales/min_sales`）、`BLUEPRINT_CLAIMED` |

形状不对（`count` 不是 1–999 的整数、缺字段、超长）整个请求 400 `SCHEMA`。

### 重复和并发

每个请求带 `base_version`，服务端在行锁（PostgreSQL `SELECT … FOR UPDATE`）里核对。
同一请求重发或同时发多份，只有第一份的版本对得上，其余 409 `VERSION_CONFLICT`（带当前存档），不会重复加钱、重复采集或重复发蓝图。
客户端收到 409 时以回复里的存档为准，不要原样重发。即使用新版本重发，采集会因刷新时间、领蓝图会因已领被拒。

## 外围物件编号（与 C-60 客户端共用）

```
<地块编号>:<外围配方版本>:<模型名>:<x>,<y>:<序号>
例：p-3512001:outer-groves-v2:wild_pz_tree_20:41,7:0
```

- 地块编号：本人地块的 `p-<parcel_id>`。
- 外围配方版本：`499-art-recipe.json` 的 `outer_groves.version`，当前 `outer-groves-v2`。配方改版（摆放会变）时须同步改服务端配置，旧编号会被 `STALE_RECIPE` 拒绝。
- 模型名：外围布局条目的 `asset`（如 `wild_pz_tree_20`）。可采的是配置里列出的树、花、石头模型；灌木、地被不可采。
- `x,y`：物件原点（`transform.origin`）所在的地块本地网格格子，客户端用 `farm_walk.gd` 的 `cell_at(origin)` 求得，与开垦格同一网格、同样的规范写法。
- 序号：同一格、同一模型的物件按 `FarmOuterGroves.plan()` 返回的 `layout` 顺序从 0 编号（通常为 0）。

同一块地、同一配方版本下，布局由地块数据和固定种子决定，所以每次打开编号相同。

## 服务端能核实什么（本版）

服务端仍不持有地块几何（C-31 的分工，C-37 跟进）。所以：

- 能核实：编号格式、编号里的地块就是本人那块（来自 token 查到的那一行，不看请求体）、配方版本、模型属于可采类、
  格子不在住宅占地 / 开垦格 / 作物格 / 已清障格（这些都在核心区）、刷新时间、背包数量、单价。
- 不能核实：编号对应的物件在该地块外围是否真的存在、格子是否真在外围。改过的客户端可以编造本人地块里的编号，
  但每类在 24 小时内最多采配方上限个（树 40、花 80、石 30），与一块摆满的地正常能采的上限相同，只影响自己的地块。
  服务端持有地块数据后由 C-37 一并校验。
