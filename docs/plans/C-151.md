# C-151 · 0.4.5 井和水桶浇水，没浇水的作物不长

哪吒·森，2026-11-26。卡片目标与验收以 SEN-C-151 为准；本文只记做法、来源和兼容口径。

## 来源

- 规则：所有者 SEN-C-137#6 原话“我需要有浇水来约束玩家尽量把作物的地块种植在一起……a.一开始用水桶,从井里提水,每次提水只能浇3块地……短期可以只做井和水桶”；
  SEN-C-137#15 第 1 题“按推荐”（C-137#10 第 1 题推荐：不长，必须浇过水才开始计时，干土和湿土一眼能分清）。
- 打一桶水 2 体力：C-137#10 第 3 题推荐里列的“打一桶水 2”，所有者 C-137#15 第 3 题答“照搬p0”。
- 一桶 3 次：C-137#6 原话“每次提水只能浇3块地”。浇水本身不花体力（P0 的 Water 也是 0 体力）。
- 井：卡片目标“用多栋建筑底座，模型 well.glb”“1 级只能有 1 口井”。占地 1×1，照 P0 院子里井的占地
  （`modules/p0/p0_garden.gd` 的 `"well": Rect2i(15, 13, 1, 1)`）。
- 补发：卡片目标“新老玩家都给 1 张井的蓝图和 1 只水桶（老玩家下次进农场补发，只发一次）”。

本卡没有自定的数值；数值都写在 `assets/farm/data/dynamic_farm.json`，可调。

## 规则（服务端 `server/src/parcels/farm.ts`、客户端 `modules/dynamic_farm/parcel_farm.gd` 各一份）

`dynamic_farm.json` 新增：

```json
"buildings": { "well": { "model": "well", "blueprint": "blueprint_well", "width": 1, "depth": 1, "max": 1 } },
"energy": { "costs": { "draw_water": 2 } },
"watering": { "well": "well", "pail": "pail", "pail_uses": 3 },
"grants": { "watering": { "blueprint_well": 1, "pail": 1 } }
```

- 播种：作物是干土，不计时，存成 `{crop, planted_at, ripe_at: NEVER, watered_at: null}`。
  `NEVER` 是 JS 时间能表示的最晚时刻 8640000000000000（是整数，不是 null），0.4.4 及更早的客户端照常读出存档，只当它一直在长；
  收获被服务端拒绝（`NOT_WATERED`）。
- `draw_water {building}`：这栋是 `watering.well` 类建筑（否则 `NO_WELL`），背包有水桶（`NO_PAIL`），桶没满（`PAIL_FULL`），
  体力够 2（`NO_ENERGY`）；打满到 3 次（`pail_water`）。桶里还剩 1、2 次时也可以再打满，照样花 2 体力。
- `water {cell}`：有水桶（`NO_PAIL`），格子上有作物（`NO_CROP`，开垦了没播种的也是），还没浇过（`ALREADY_WATERED`），
  桶里有水（`PAIL_EMPTY`）；用 1 次，`watered_at = now`，`ripe_at = now + 生长时间`。不花体力。
- 服务端不知道人站在哪：“在井边”只由客户端限定（主行动键只在井那一格上给 Fill，按下先走到井旁）。服务端核实的是
  井已盖好、水桶、桶里次数、格子播下了还没浇、体力，和卡片目标一致。
- 一批命令仍是全成或全不变。

## 存档

`farm_state` 版本号仍是 1，只追加字段（和 C-58、C-148、C-150 同一做法）：

- `crops.<格>.watered_at`：null 是还没浇；数字是浇水时间；**没有这个字段的是本卡以前种下的，按已浇过算**，照原来的 `ripe_at` 成熟，
  不会卡住，也不能再浇。
- `pail_water`：桶里还能浇几格，旧存档按 0。
- `grants`：已发过的一次性补发编号 → 发放时间，旧存档按 `{}`。

## 补发

进入自家地块（`POST /v1/parcels/mine/enter`）时，在同一次加锁写入里把 `grants` 里还没发过的发掉并记下：
新玩家首次进入时和赠品一起拿到，老玩家下次进入时拿到；重试、并发进入、换数据集都不会再发。
返回体加 `gift`（这次进入发的全部物品，首次进入的赠品加补发，没发为 `{}`）；`granted` 仍只表示首次进入的赠品，
0.4.4 客户端照旧读。换数据集（C-136）时井退一张井的蓝图，水桶和桶里的水不在格子上，不动。

## 客户端

- 井：`farm_building.gd` 的 `KINDS` 加 `well`（`well.glb`，墙按模型石圈量的盒子），有蓝图时显示 `Build Well`，摆放和小屋同一流程（可转向）。
- 主行动键：井那一格是 `Fill`，第二行 `2 Energy`，桶满写 `Pail full`；干的作物是 `Water`，不写价（LOCK-02），
  桶空写 `Pail empty`，没水桶写 `Need a pail`。`Water` 是 P0 浇水键的词；`Fill`（打水）、`Pail`（水桶）、
  `Well Blueprint`、`Build Well` 和三个拒绝词是本卡新增的英文，照 `Need a hoe`、`Cottage Blueprint`、`Build Cottage` 的写法，请 PM 定稿。
- 土：浇过水的作物那一格画湿土，开垦未播和没浇的作物画干土（C-138 的干湿土）；胡萝卜从浇水那一刻按 7 段长，没浇停在播种段。
- 引导卡：播下但没浇时，没井且有井的蓝图 →“Tap Build Well to place your well.”，有井 →
  “Fill your pail at the well, then press Water on your seeds.”（新增文案，请 PM 定稿）。
- 动作：接入 SEN-C-153 的水桶（`bucket_gesture.tscn`，挂在人物右手腕）和动作库（`bucket_actions.tres`，作为 `pail` 库加到人物的 AnimationPlayer）：
  Fill 播 `draw`（2.22 秒），Water 播 `pour`（2.28 秒），播完把桶收起；结果在动作播完时落地。SEN-C-153 审核写明“实际接入农场操作由 SEN-C-151 负责”。
  设计总监建议的“落点往格子中心挪一点”（C-153#33 第 4 条，不挡合并）没有做：本机没有窗口会话，看不到游戏镜头下的落点，留给模拟器录屏核对。
- 补发的物品像赠品一样飘字、飞进背包；飘字最多叠 `UiMotion.FLOAT_STACK_MAX` 行（新玩家 5 样东西，第 5 行不飘，照样飞进背包）。
