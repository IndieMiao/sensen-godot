# C-146 去掉游客入口，必须注册或登录才能玩（0.4.5）

作者：刘邦·森。依据：所有者 11-25 原话（PM Office 记在 C-137#12）：“在下一个版本移除游客模式, 必须要注册/有账号才能玩”，版本选 0.4.5、和邮箱注册（C-101）一起上；已有游客号按所有者在 Q-265 的选择 delete 删除。

## 客户端（动态农场安卓包）

- 读回已保存账号的包（`sensen/dynamic_farm/account_restore`：内部包和正式包）进地图前必须有账号。没有保存的账号时，地图什么都不建（原生地图、地块、认领都不开始），只显示登录面板（C-85 ④ 的 v3 外观，英文），面板没有 ✕，登录或注册成功前关不掉；面板里照常有注册和找回密码。返回键在面板上直接退到后台，不打开地图。
- 在地图上登出后，地块和自己的家清掉、原生地图隐藏，登录面板回来；有人登录后地图按这个账号重新加载。切到后台再回来仍停在面板上。
- C-100 的装上即建号开关 `sensen/dynamic_farm/guest_play` 删除：`Net.dynamic_farm_sign_in()` 只读回已保存的账号，不再匿名登录；登出也不再登录成游客。导出读回检查在任何动态农场包里见到 `guest_play` 都拒绝。
- 隔离预览包（`dynamic-farm`，Journey 地址是 `127.0.0.1:9`，连不上任何服务）没有账号和地块数据可读，不受影响。
- 文案：面板沿用 C-85 ④ 已定的登录面板文案，本卡不加新文案（C-45）。

## 服务端

- 新开关 `GUEST_ACCOUNTS`（`open` 默认 / `closed`，其它值拒绝启动）。`closed` 时：
  - `POST /v1/auth/anonymous` 对新安装和已有游客一律回 403 `GUEST_CLOSED`，在限流和查库之前就拒绝，不建玩家、不发 token；
  - 之前发出的游客 token 不再算登录：HTTP 接口当没登录（401 `UNAUTHENTICATED`），联机（WebSocket）认证也拒绝。
- 动态农场正式服 `compose.yml` 写死 `GUEST_ACCOUNTS: closed`，`ops.sh check` 拒绝 `.env` 里出现它。Journey 和开发服不设，照旧。
- 冒烟改为核对“游客入口已关”和“不登录不能认领、不能存档”，不再每次留下一个游客玩家行。

## 删除已有游客号（Q-265）

工具：`server/src/ops/guest_purge.ts`（入口 `server/tools/guest_purge.ts`，正式服用 `ops.sh guests`）。

- 游客号：`players.user_id IS NULL` 且 `install_key_hmac` 是 64 位十六进制（安装密钥的 HMAC）。邮箱账号和邀请账号的玩家 `user_id` 非空；预置农场的系统玩家 `install_key_hmac` 是 `preset:…`，都不会选中。
- 一起备份和删除：会随这些玩家级联删除的全部行——`tokens`、`farms`、`farm_creations`、`commands`、`farm_snapshots`、`online_players`、`parcel_claims`（地块和地块存档）、`parcel_reclaims`。工具先查外键，库里有别的表引用 `players` 或这些表时拒绝运行，免得新表的数据没备份就被级联删掉。
- `plan`：只读事务，列出每张表会删的条数、各表总数、保留的账号玩家和系统玩家数。
- `backup`：只读快照，备份文件第一行是头（格式、库名、规则、各表条数、正文 SHA-256），之后每张表一行，是 PostgreSQL `jsonb_agg(to_jsonb(行))` 的原样输出。`verify` 核对格式、哈希、表顺序和每张表的条数。
- `purge`：必须给 `--confirm-database <库名>`，且和备份头、实际连接的库都一致。锁住这些表（别人能读不能写），重新取一遍游客数据，必须和备份正文逐字节相同才删；删完核对每张表删掉的条数等于备份条数、各表总数正好少这么多、账号玩家和系统玩家一条没少、游客号为 0，任何一项不对整体回滚。
- `restore`：同样要 `--confirm-database`；把备份原样插回，再取一遍和备份逐字节相同、各表总数正好多这么多才提交；那块地已被别人认领等冲突时整体回滚。
- `ops.sh guests purge --confirm-delete`：先整库备份（`pre-guest-purge`），游客备份在主机落盘、`verify`、用 `AGE_RECIPIENT` 加密，再把同一份备份交给工具删；明文临时文件退出时删掉，只留 `.age`。任何一步失败都不删。
- 本卡只交付代码和测试，不在正式服或隔离测试服上执行删除。正式服删除随正式服部署（H-71）另行确认、由主机操作员执行，执行前先备份（`ops.sh guests purge` 自己会先整库备份）。
