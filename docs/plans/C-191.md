## 存档（`farm_state` v1 上追加，版本号不变）

- `board`: `{slots: [{req, refill_at}], seq, day, done_today, bonus_today}`。`req` 为 null 是空格，`refill_at` 之后补；
  `req` = `{id, template, item, qty, bonus, drawn_at, status: open | accepted}`；`seq` 是上一张单号（不复用）；
  `day` 是 `done_today` / `bonus_today` 记的玩家日，换日后按 0 算。
- `requests_done`：累计交了几单（羊圈“完成 5 个委托”解锁读它，SEN-C-182）。
- 旧存档没有这两项：按空板、0 单读；首次进入过的农场下次读档时两格从 `welcomed_at` 起补上（太早的那张按 72 小时一期换到最近一期）。
- 换数据集（C-136）不动委托板。

## 抽单

不用随机数。第 i 格在时刻 at 抽单：可抽的模板（按配置先后，`building` 有就要求地上有这类建筑）里去掉别的格正挂着的
（换单时连同这一格刚过期的那张），都去掉了就不去；用 `hash32("<welcomed_at>:<i>:<at>:<seq+1>:t")` 取模板、
`hash32("…:q")` 取件数。`hash32` 是 32 位 FNV-1a 加 murmur3 收尾，服务端 `requests.ts` 和客户端 `parcel_farm.gd` 各一份，
参考值写在两边的测试里。抽单时刻是格子自己的补位或换单时刻，不是读档时刻，所以读档（服务端 `farmView` 在副本上补）
看到的单子、编号和下一条命令补位抽到的一样。每批命令前后各补一次（交完的格子在回包里已是新单）。

## 命令

- `accept_request {request}`：`NO_REQUEST`、`ALREADY_ACCEPTED`；接了不过期。
- `deliver_request {request}`：不要求先接。`NO_REQUEST`、`DAILY_LIMIT {max, resets_at}`、`NOT_ENOUGH {item, have, need}`、
  `COINS_CAP`；成功扣物品、加 地板价 × 件数 + min(完成奖, 当天剩下的额度)，今天的单数和额度、累计单数 +1，这一格按交完补位。
- `drop_request {request}`：这一格空出来，8 小时后补；物品留在背包里。
- 都不花体力。“人在驿站”由客户端限定，服务端不知道人站在哪。整批成功才写入（`base_version`）。

`tests/dynamic_farm/fixtures/request_cases.json` 的用例（`server/tools/gen_request_cases.ts` 按服务端规则生成）服务端
（`server/test/parcels/requests.test.ts`）和客户端（`tests/dynamic_farm/test_parcel_board.gd`）各跑一遍，结果都要等于文件里记的。

## 客户端

- 入口：驿站房间左墙那块板（farm-dev 驿站布景的 Fare Board，`use_fee_board`）改作 `Request Board`，点击触发设施
  （LOCK-07 v2：图标按钮和名字条），点了走过去打开委托板抽屉，不出问候卡。
- 抽屉（`scenes/dynamic_farm/parcel_board.gd`，经 `parcel_town.gd`）：标题 `Request Board` 和关闭；页面事实
  `Requests today 2/6`、补位倒计时 `Next request 7h 59m`、发过完成奖后 `Bonus today 20/100`；每张单子一行 P0 的
  `UiBoardCard`：开着且不够数是 Track，够数是 Deliver（接没接都行），接了不够数是 Deliver 带缺口 `Need 2 more Eggs`
  （LOCK-10），到当天上限是 `Requests today 6/6`。奖励行照 P0：额度不够时 `20 coins · Bonus resets in 9h 12m`。
- 点标题 › 进单子详情（照 BOARD-1）：标题、状态、`Bring the required eggs to the Request Board.`、NEED-TILE、Delivery、
  另一格的等待；已接的有 `Drop request ›` → 确认页（BOARD-3）→ `Dropped`（BOARD-DROPPED）。Back 一页一页退。
- 交单成功：这一格回包里已是新单，列表随之换；金币从按钮处飘起 `+37 coins`（照 BOARD-DONE，不弹结果卡）。
- 抽屉开着时有格子到补位时刻，重新读一次存档（服务端抽单）。

## 兼容
