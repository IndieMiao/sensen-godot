# C-193 小院子能不能放下鸡场、牛棚、羊圈

需求出处：SEN-C-175#74（p-5402049 全清空也放不下 7×5 的鸡场）。统计结果见 C-193#4，逐块数据是卡上附件
`c193-building-fit.json.gz`。Q-289 选 A：放置和认领规则不改，只加护栏测试和可重跑的统计工具。

## 结论（2026-11-26 的统计）

按现行放置规则、院子全清空，能认领的地块里放不下鸡场 7×5、牛棚草稿 8×6、羊圈 5×3–9×7 的都是 0 块：
r8 起步区可认领 3,654 块、r6 老存档用的起步区 2,557 块、r8 起步区外抽样 2,000 块。10×8 有 1 块放不下
（p-0147008，核心区 8 格宽）。p-5402049 只在 r4 里有（r6、r8 都没有这块地），核心区是 267×3 的一长条。
所以羊圈只要不超过 9×7（正门外留 1 格），现行地块都放得下。

## 护栏测试

`tests/dynamic_farm/test_building_fit.gd`（CI 的 dynamic_farm 步骤跑，汇总行 `BUILDING_FIT_TESTS`）：

- 读 `tests/dynamic_farm/fixtures/r8/` 里 r8 起步区最窄的两块地 p-0147008、p-0078042，文件和数据集原样一致，
  `SHA256SUMS` 钉住字节；
- 断言院子全清空时，鸡场（真实美术的 7×5 和保留格）、牛棚 8×6（门外 1 格）、羊圈 9×7（正门外 1 格）
  四个朝向里至少有一个合法位置；鸡场的位置再用游戏的 `Building.reason` 核一遍；
- 对照：p-0147008 放不下 10×8；r4 的 p-5402049 三种都放不下。保证判定不是“什么都放得下”。

p-5402049 的旧测试（`test_coop.gd` 打印 `spots=0`）不改成“放得下”，它是 r4 的旧样例，r8 已不存在。

## 判定方法

`tools/dev/dynamic_farm/building_fit.gd`，统计和测试共用。院子按玩家清完障碍后算：没有建筑、耕地和作物，
用游戏自己的放置规则（`farm_building.gd`）：占地和保留格都在核心区、不压保护通道（入口到出生点）、
不压场景预留的行走格、所有可走的格子仍能走到出生点。每个形状逐格试四个朝向，有一个合法位置就算放得下。
不合格时分三档：`none`（核心区没有这个形状的空间）、`path`（只能压在通道上）、`reach`（会把别的格子隔断）。
另有“小屋 3×3 → 鸡场 → 牛棚 → 羊圈 8×6”依次放，每个放在第一个合法位置，算放下几个（保守下限）。

## 换数据集或改建筑尺寸后怎么重跑

1. 准备一个导入过的隔离副本（不要在 worktree 里直接导入），私有 HOME：
   `rsync -a --exclude .git --exclude .godot <worktree>/ "$QA"/ && HOME=<私有目录> godot --headless --path "$QA" --import`
2. 取地块（只读 HTTPS，每个文件按数据集清单核 SHA-256）。r8 的地址和完整清单 SHA 见
   `tests/dynamic_farm/README.md`；新数据集用它自己的：

   ```sh
   F=tools/dev/dynamic_farm/fetch_parcels.py
   R8=https://oss2.sensenjoy.cn/sensen/dynamicfarm/data/r8-ce232c99c9c8/
   SHA8=ce232c99c9c894a7c33ed047b22f8b10f4fe48cbc650fbe59343c68f336228e9
   # 起步区能认领的地块（parcels 减 too_small）
   python3 -I $F --base $R8 --manifest-sha $SHA8 --out "$W/r8" --starter-zone assets/farm/data/dynamic_farm_starter_zone.json
   # 起步区外抽样（核心格 ≥ 400，种子 193，要下载 114 MB 的 index.geojson）
   python3 -I $F --base $R8 --manifest-sha $SHA8 --out "$W/city" --starter-zone assets/farm/data/dynamic_farm_starter_zone.json --sample 2000
   # 老存档：同一批编号在 r6 的版本（ids.json 是起步区编号的 JSON 列表；r6 没有的编号会跳过）
   R6=https://oss2.sensenjoy.cn/sensen/dynamicfarm/data/r6-6c3733e3b025/
   python3 -I $F --base $R6 --manifest-sha 6c3733e3b0255a868cfdc34a964de0df8653c57dbbf82f04b94f6864a1e79376 --out "$W/r6" --ids "$W/ids.json"
   ```
3. 统计：
   `HOME=<私有目录> godot --headless --path "$QA" --script res://tools/dev/dynamic_farm/building_fit_stats.gd -- "$W/r8.json" "$W/r8/list.txt"`
   输出每块地的 `fit`（每个形状 ok / none / path / reach）和 `together`（四个依次放下了几个）。
   在本机（cardigan-ci）上约 0.43 秒一块，3,654 块约 26 分钟。
4. 有放不下的地块时，把最窄的几块按原样换进 `fixtures/r8/`（更新 `SHA256SUMS`、测试里的编号和
   `fixtures/r8/README.md`），并在卡上报统计结果；要不要改认领规则（Q-289 的 B：生成起步区时记进
   太小名单）是玩家可见口径，另行拍板。

羊圈尺寸定了以后，把测试里的 9×7 换成实际尺寸和保留格；超过 9×7 时先重跑统计。
