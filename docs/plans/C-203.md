# C-203 正式服接入 Mixpanel：后端上报 6 个核心事件（默认关闭）

所有者 11-27 选定 Mixpanel 做产品分析（原话“开卡 Mixpanel”）。这张卡只在服务端（`server/`）加上报模块，游戏客户端不改。

## 做法

- 模块：`server/src/analytics/mixpanel.ts`（队列与发送）、`server/src/analytics/events.ts`（事件名、地块命令推出的事件）。
- 事件在接口处理完成后进内存队列（`track` 只入队，不等网络、不抛错），攒够一批或到点后用 Mixpanel 批量导入接口 `POST <地区接口>/import?strict=1` 发出，认证用项目令牌（Basic 认证用户名，密码留空）。
- 发送失败（超时、网络错、429、5xx）隔 2 秒重试一次，仍失败就丢掉这批、记一行 `[analytics]` 日志；其它 4xx（数据校验不过）不重试。玩家请求从不等待上报。
- 进程关停（`app.close()`）时把队列里剩下的发完。
- 用户标识只用 `users.id`（`distinct_id`）；没有账号的游客不上报（正式服已无游客入口）。不传邮箱、昵称、IP、经纬度、地块编号；地块位置只报社区（`community_id`）。每条事件带 `ip: 0`，让 Mixpanel 不按本服务器的地址做地理定位（不带时它会用发送方地址）。
- 每条事件带 `time`（服务端时间，毫秒）和 `$insert_id`（去重键）。`account_created` 的去重键固定为 `account_created:<users.id>`、时间取账号建立时间，补发脚本重跑或与实时上报重叠都只算一次。

## 环境变量

| 名字 | 说明 |
|---|---|
| `MIXPANEL_PROJECT_TOKEN` | Mixpanel 项目设置里的项目令牌（Project Token）。 |
| `MIXPANEL_API_HOST` | 项目数据存放地区的接口：美国 `https://api.mixpanel.com`、欧盟 `https://api-eu.mixpanel.com`、印度 `https://api-in.mixpanel.com`，只接受这三个。 |

两项都不设（默认）：模块不启用，不建队列、不起定时器、不发任何外部请求。只设一项或地址不对：服务端拒绝启动。启动日志末尾 `analytics=off` 或接口主机名。

固定参数（代码常量，`mixpanel.ts`）：一批 50 条（攒够即发）；最长 10 秒发一次；单次请求超时 10 秒；重试间隔 2 秒；队列最多积压 10000 条，满了丢新事件并记一次日志。

## 事件清单

所有事件都带 `distinct_id`（users.id）、`time`、`$insert_id`、`ip: 0`。

| 事件 | 什么时候 | 属性 |
|---|---|---|
| `account_created` | 新账号建立：邮箱注册成功；Google / Apple 首登建号 | `method`：`email` / `google` / `apple`（补发脚本另有 `invite`，并带 `backfill: true`） |
| `login` | 已有账号登录成功：邮箱密码登录；Google / Apple 登录到已有账号（含按已验证邮箱挂到老账号） | `method`：`email` / `google` / `apple` |
| `parcel_claimed` | 认领到一块新地块（201）；重复认领自己那块不报 | `community_id`、`dataset_version`、`starter_zone`（起步区编号，没开起步区为 null） |
| `parcel_enter` | 每次进入自家地块成功 | `community_id`、`welcome_gift`（这次是否发了首次进入礼包）、`rebased`（这次是否换到新数据集） |
| `farm_command` | 每次地块命令请求：整批成功时每种命令一条；被拒时只报拒绝的那条；版本不符时每种命令一条 | `community_id`、`command`（命令类型，如 `till`、`sow`、`sell`）、`count`（这批里这种命令的条数，被拒时为 1）、`outcome`（`applied` / `rejected` / `version_conflict`）、`reject_code`（仅被拒时，如 `NO_ENERGY`、`NOT_SELLABLE`） |
| `market_sell` | 整批成功里的每条卖出 | `community_id`、`item`、`count`、`coins`（这条卖得的金币） |
| `blueprint_claimed` | 整批成功里的每条领蓝图 | `community_id`、`blueprint`（如 `coop`）、`item`（发到背包的物品，如 `blueprint_coop`） |

## 补发已有注册（可选）

`server/tools/mixpanel_backfill_signups.ts`：按 `users.created_at` 给每个账号报一条 `account_created`（方式取账号最早的身份：邀请账号 `invite`、Apple / Google 首登 `apple` / `google`、其余 `email`）。不加 `--send` 只数不发；可加 `--since YYYY-MM-DD`。不会自动运行。

## 启用步骤

前置（不在本卡，PM Ops 另行安排）：所有者注册 Mixpanel、选数据存放地区（建项目后不能改）、提供项目令牌；隐私政策加分析服务商；Google Play 数据安全表单补“应用活动”。完成前保持关闭。

1. 主机部署目录 `.env` 填 `MIXPANEL_PROJECT_TOKEN`、`MIXPANEL_API_HOST`（与项目地区一致），`ops.sh deploy` 或重启 app。
2. 启动日志 `analytics=` 显示接口主机名；Mixpanel 的 Events 页面能看到 `login` 等事件。`[analytics]` 开头的日志行表示某批没发出去。
3. 可选补发：部署目录里 `docker compose -f compose.yml --env-file .env exec -T app ./node_modules/.bin/tsx tools/mixpanel_backfill_signups.ts` 先数，确认后加 `--send`。

关闭：两项清空后重启 app。

详细运维说明见 `server/deploy/dynamicfarm/README.md` 的“产品分析（Mixpanel）”。
