# C-150 · 0.4.5 地块存档多栋建筑，放置按类型参数化，四个朝向

后裔·森，2026-11-25。卡片目标与验收以 SEN-C-150 为准；本文只记做法、来源和兼容口径。

## 来源

- 多栋建筑、按类型配置：需求卡 SEN-C-137 拆解方案第 2 版第 3 张（SEN-C-137#20）。
- 四个朝向：所有者在 SEN-C-134#22 第 3 题的原话“按推荐 ,添加摆放时候的旋转(0,90,180,270)”，
  该题推荐写的是“玩家像放小屋一样在院子核心区选位置，可以转向”；PM 据此把四个朝向加到本卡（SEN-C-137#30）。
- 摆放栏的 `Rotate` 键：不是新组件、新文案，是共享摆放栏 `UiPlaceBar` 已有的中间键
  （P0 Decorate 的 `Cancel · Rotate · Place`，不知火舞 on 284 ee15926a），本卡沿用同一个词。
  三键时摆放栏把“为什么不能放”的原因移到栏上方的小条里显示，这是 `UiPlaceBar` 原有行为。
- `Build Cottage` 键、`Outside your yard` / `Space taken` / `Keep the path clear` / `House here` 文案都是现有的，
  本卡没有新增玩家可见文字。

## 规则（服务端、客户端各一份，内容一致）

`assets/farm/data/dynamic_farm.json` 的 `house` 换成 `buildings`，键是建筑类型：

```json
"buildings": { "cottage": { "model": "cottage", "blueprint": "blueprint_cottage", "width": 3, "depth": 3, "max": 1 } }
```

- `width` 沿格 x、`depth` 沿格 y，是未转向的占地；`max` 是一块地上最多几栋（1–64）；一边 1–16 格。
- 必须有 `cottage`：旧存档的 `house` 和旧客户端（0.4.4 及更早）的 `place_house` 都按它算。
- 本卡不加新建筑，发布的规则只有小屋（数值和以前完全一样，Q-40 一栋 3×3）。测试在规则副本里加
  1×1 的 well、4×2 的 coop 两种测试用类型，验证多栋和非正方形转向，不进发布规则。

客户端 `modules/dynamic_farm/farm_building.gd` 的 `KINDS` 按同一类型编号给模型、碰撞轮廓和 Build 键上的名字；
以后加井、鸡场，只在规则和 `KINDS` 各加一项（加模型和碰撞），放置流程不用改。

## 存档

`farm_state` 版本号仍是 1，只追加字段（和 C-58 的经济字段同一做法）：

- `buildings`: `[{id, type, model, x, y, width, depth, rotation, built_at}]`，按放下先后。
  `x,y` 是占地 x、y 最小的格；`rotation` 是转了几个 90°（0–3），1、3 时宽深互换；
  `width/depth` 是放下时的配置，以后改配置不影响已建的；`id` 取现有最大 id + 1，以后按栋操作用。
- `house`：保留，是 `buildings` 里那栋 cottage 的镜像（没有为 null），给 0.4.4 及更早的客户端读；以 `buildings` 为准。
- 旧存档没有 `buildings`：读写时把 `house` 转成 id 1 的 cottage，位置、朝向、占地、模型、建成时间原样。
  只读不写（进入、查看）不改库里的数据；下一次写入时带上 `buildings`。
- 换数据集（C-136 rebase）：每栋建筑退一张它那类的蓝图，清空 `buildings` 和 `house`。

## 命令

- 新增 `place_building {building, x, y, rotation}`；`place_house {x, y, rotation}` 保留，等于放 cottage。
- 服务端检查（客户端本地存档同样）：类型已登记（`UNKNOWN_BUILDING`）、该类未到上限（`BUILDING_LIMIT`，
  `place_house` 仍报 `HOUSE_PLACED`）、总数不超过 64、有蓝图（`NO_BLUEPRINT`）、转后占地不出网格（`OUT_OF_BOUNDS`）、
  不和其它建筑重叠（`BUILDING_OVERLAP`，带重叠格）、不压开垦格或作物（`CELL_OCCUPIED`，带被压的格）。
  整批命令要么全成要么全不变。开垦、采集照旧不能在任何建筑占地上。
- 服务端没有地块几何：只在核心区、不压未清障碍、不挡入口到出生点的通道，仍由客户端判断（和以前一样），
  现有建筑也算进“挡路”的检查。

## 客户端摆放

- 有某类蓝图且没到上限时显示 `Build <名字>`（现在只有 `Build Cottage`，和以前一样）。
- 摆放栏 `Cancel · Rotate · Build`：Rotate 每按一次转 90°，绕占地中间格原地转（奇数边精确不动，偶数边最多偏半格），
  0 → 90 → 180 → 270 → 0。拖动手感不变：手指仍按住占地中间格。开始时不转向，落在离人最近的合法位置。
- 建成后模型和碰撞一起按朝向转，人照旧不能穿过墙；重开后按存档的朝向摆。
- 被服务端以 `CELL_OCCUPIED` 或 `BUILDING_OVERLAP` 拒绝时保留预览，按回来的存档重新判断。

## 兼容

- 0.4.4 客户端连新服务端：读 `house` 照常显示小屋；它的 `place_house` 照常可用。新放的其它类型建筑它看不到
  （它的开垦检查以服务端为准，会被拒）。
- 新客户端需要新服务端（`place_building`），按惯例服务端先部署。
