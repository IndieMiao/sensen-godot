# C-136 旧数据集认领进农场时换到当前数据集

所有者拍板 Q-168 选 rebase（2026-11-25）。

## 原因

0.4.1 用 r4 数据集（`sf-dynamic-farm-20261118-r4`）认领，C-43 起客户端只用 r6（`sf-dynamic-farm-20261124-r6`）。
同一块地在两个数据集里是两套格子（p-3139019：r4 核心 804 格，r6 523 格）。`POST /v1/parcels/mine/enter`
回的认领仍是 r4，客户端 `parcel_farm_remote_store.gd` 按“别的地块”拒收（`OTHER_PARCEL`），显示
“Could not open your farm.”，Retry 走同一条路。基线包必然复现；引入提交是 C-43 合并 321e9211（D-172）。

## 做法

- 客户端：`enter()` 的请求体带 `{ "dataset_version": <这次打开农场用的数据集> }`，即搭建这块地所用农场文件的
  `dataset_version`（`dynamic_farm.gd` 传给 `parcel_farm_remote_store.gd` 的 `_data.dataset_version`），不是写死的包默认值
  （C-136#20）。现在客户端只有 r6，带的就是 r6。以后客户端若按认领的版本打开旧版本文件（C-113、Q-172 的 r6），
  带的也是那个版本，服务端看到版本相同，不换。拒收别的地块、别的数据集的校验不变。
- 服务端 `POST /v1/parcels/mine/enter`：
  - 不带 `dataset_version`（0.4.1–0.4.3 客户端）时与以前一样；带了但不是 1–128 字符的字符串回 400 `SCHEMA`。
  - 只有同时满足才换：两个数据集都在 `dynamic_farm.json` 里登记、都属于这块地的社区、请求的比认领的新。
    新旧按社区 `datasets` 里的先后，后面的新（发新数据集时追加在末尾）。只能往新换，换过之后认领就是新版本，
    重试和并发请求不会再换。未登记、更旧、相同或别的社区的数据集一律不换，原样返回。
  - 换数据集、改存档、首次进入赠品在同一个行锁事务里写回（内存实现同步完成），版本加一。
    换之前的版本发出的地块命令按版本冲突 409 拒绝，不会落到新格子上。
  - 地块编号、社区、中心点、认领时间都不变，地块仍是这个玩家的。
- 存档内容（`rebaseFarm`，格式不变）：
  - 清空：房子、已清障碍、已开垦、作物、采集记录（采集冷却）。
  - 退还：地里每棵作物（熟没熟都算）退一颗它的种子；有房子退一张 `blueprint_cottage`，可以重新盖。
    规则里已没有的作物不知道种子，不退。
  - 保留：背包其余物品、金币、卖出次数、已领蓝图、赠品记录（`welcomed_at`）。没进过的认领换完再发首次赠品。
- 服务端日志记一行 `parcel rebased to a newer dataset`：地块编号、新旧数据集、清掉的房子 / 障碍 / 开垦 / 作物数量，不记玩家信息。

## 防刷

- 换一次需要认领在更旧的已登记数据集上；换完就是新版本，不能换回旧的再换一次，伪造版本号最多触发一次。
  目前同一社区只有 r4、r6 两个版本，每块地最多换一次。
- 退还的种子和蓝图正好是当初种下、盖房消耗掉的，不多给。
- 地块由 token 查到的那一行决定，请求里只有数据集，换不到别人的地块。

## 兼容与部署

- 服务端可以先上：旧客户端不带字段，行为不变。新客户端随 0.4.4 发出。
- 认领换到 r6 后，还在用 0.4.1（r4）的设备会按“别的地块”打不开农场，升级后正常。
- 回到地图时地图重新读一次认领（`resume` → `_start_claims`），集市和木匠用的数据集随之变成 r6。

## 测试

- `server/test/parcels/farm.test.ts`：新旧判定、清空与退还的数量、不改入参、旧存档。
- `server/test/parcels/parcels.test.ts`（内存与 PostgreSQL 两套）：r4 认领换到 r6、重试与并发不重复退还、不能换回、
  不带字段 / 未登记 / 更旧 / 相同数据集不换、非法类型 400、没进过的认领换完发一次赠品、别人的地块不动；
  PostgreSQL 两个进程同时进入只换一次。
- `tests/dynamic_farm/test_parcel_farming_scene.gd`：旧数据集认领在场景里打开（首次请求丢失后的自动重试、
  两次都丢后按键 Retry），每次 enter 都带这次打开所用农场文件的数据集。
