# C-34 自家动态地块：清障、开垦、种萝卜、收获（0.4.2，安卓）

规则出处：所有者拍板 Q-39（C-34#14）。接口按 C-31 的 `docs/plans/C-31.md`。
按 Q-44 与 C-34#37：自家地块的进入、存档接线和保护通道判定只有这一套，C-33 的住宅放置在它上面加，不另做。

## 打开自家地块

```gdscript
host.setup({"farm": farm, "dataset": dataset, "block_id": block_id, "own_parcel": true, "farm_store": store_or_null})
```

- `own_parcel: true` 时不要求 `preview_only`；宿主（`dynamic_farm_host.gd`）原样转交 `own_parcel` 和 `farm_store`。
- 场景（`dynamic_farm.gd`）建好地面与障碍后挂 `ParcelFarming` 节点（名字 `ParcelFarming`，脚本 `scenes/dynamic_farm/parcel_farming.gd`），
  随即调用 `enter()`。
- 地图入口（Q-72）：只有内部测试包（`--dynamic-farm-internal`，打包时写入 `sensen/dynamic_farm/own_farm=true`）里，
  自家地块卡片上原有的 “Enter my farm” 按钮以 `own_parcel=true` 打开自家地块；“Preview in 3D”、别人的地和正式包
  仍是只读预览。按钮和文案不新增、不改；正式入口归 C-35，C-35 复用或替换这一入口。
  本分支已合入 C-32 D-68（`d77eeb0d264c19740e9d47b33374ffd8fe8de707`）的登录和仅内部包账号恢复。
- `farm_store` 省略时用服务端存档 `RemoteStore(Net.client, block_id, dataset)`；
  只有项目设置 `sensen/dynamic_farm/local_farm_save=true` 时改用本机替身 `LocalStore`（开发用，不作证据）。

## 存档层（两种实现，返回结构相同，都可 `await`）

| 文件 | 说明 |
| --- | --- |
| `modules/dynamic_farm/parcel_farm_remote_store.gd` | C-31 `POST /parcels/mine/enter`、`POST /parcels/mine/commands`；回复里的地块编号或数据集与当前地块不符时拒收（`OTHER_PARCEL`） |
| `modules/dynamic_farm/parcel_farm_local_store.gd` | `user://dynamic_farm_local/<block_id>.json`，用同一套规则在本机结算，`now_ms` 可注入，测试和本地联调用 |

- `enter() -> {ok, granted, farm, farm_version, server_time}`：第一次进入 `granted=true` 并发赠品（锄头、萝卜种子、首栋住宅蓝图），之后不重发。
- `send(base_version, commands) -> {ok, farm, farm_version, server_time}`；
  失败为 `{ok:false, code, index, detail?, farm?, farm_version?, server_time?}`。
  命令被拒（422）和版本冲突（409）都带当前 `farm`，`ParcelFarming` 照收。
- `farm` 是 C-31 的地块农场状态 v1：`house`、`cleared`、`tilled`、`crops`、`bag`、`welcomed_at`，格坐标为 `"x,y"`（地块本地网格）。

## 规则（客户端）

`modules/dynamic_farm/parcel_farm.gd` 逐条照抄 C-31 `server/src/parcels/farm.ts`，
含 `place_house`、`clear_obstacle`、`till`、`sow`、`harvest`，失败码、检查顺序相同。数值读 `assets/farm/data/dynamic_farm.json`（与服务端同一文件，独立于主农场）。

- `ParcelFarm.house_cells(farm) -> {Vector2i: true}`：住宅占地，转 90°/270° 宽深互换。
- `ParcelFarm.apply(rules, farm, commands, now)`：本机结算（本地存档和测试用），整批成功才生效。

服务端没有地块几何，空间规则在 `modules/dynamic_farm/parcel_space.gd`：

- `Space.protected_path(data) -> {Vector2i: true}`：核心区内的保护通道。schema 4 的核心区每格都在“不放实心装饰”保留区里，
  不能直接当通道，所以取入口到出生点的最短步行路线，两侧各加 `PATH_HALF_WIDTH`（1）格，再加出生点周围 `SPAWN_CLEARANCE`（1）圈，只保留核心区格。
  这两个宽度是作者默认值；若要改变实际可放、可开垦的范围，需附代表地块对照图并取得批复。
- `Space.till_refusal(data, path, farm, cell)`：`outside`（核心区外）、`house`（住宅占地）、`path`（保护通道）或 `""`（可开垦）。
- `Space.action(...)`：主按键对某格做什么（清障、开垦、播种、收获）以及为什么不行。

## 给住宅放置（C-33）用的接口

`ParcelFarming`（`get_node("ParcelFarming")`）：

| 成员 | 说明 |
| --- | --- |
| `farm`、`farm_version` | 当前状态（服务端为准） |
| `signal state_changed(farm)` | 每次收到存档回复后发出 |
| `await send({"type": "place_house", "x": x, "y": y, "rotation": r})` | 走同一存档层；成功即建成（Q-40），失败码见 C-31 |
| `protected_path()` | 与开垦同一份保护通道 |
| `obstacle_cells()` | 还没清理的核心区障碍格；已清理的已从行走和画面去掉 |
| `server_now()` | 按服务端时间推算的当前毫秒 |

住宅能否放下由 C-33 判断（全部占地在核心区、不压 `obstacle_cells()`、不压 `protected_path()`、不压开垦格）；
住宅画面和碰撞也由 C-33 加。本卡只保证住宅占地内不能开垦（`House here`）。
