# C-175 0.4.5 串联与正式包：注册→认领→种浇收→升级→养鸡

接着 0.4.3（C-61）把 0.4.5 的内容串起来：邮箱注册（没有游客入口）→ 认领 → 盖小屋 → 种、放井打水浇水、收 → 卖胡萝卜、
买种子 → Scott 领鸡舍蓝图 → 放鸡场、喂胡萝卜、捡蛋、卖蛋 → 采木材石头、在 Scott 处升级农场。
只补衔接和引导，不新增玩法，不改已批规则和数值。

## 引导的步骤（只看存档，中途退出再进接着当前那一步）

`ParcelGuide.stage` 是里程碑（手机任务表的行），`ParcelGuide.step` 是它下一步该做的事（提示卡、地图底部那句）。
任何时候：有熟胡萝卜先 `harvest`；有干的胡萝卜，有井时桶里有水 `water_pail`、没水 `water`，没井但有井图纸 `well`。

| 里程碑（任务行） | 什么时候 | 提示（step） |
| --- | --- | --- |
| `build` … `harvest` | 同 0.4.2 / C-35 | 同前 |
| `sell` | 背包有胡萝卜，还没卖过东西 | `sell` |
| `blueprint` | 卖过东西，鸡舍蓝图没领 | `blueprint` |
| `coop` | 蓝图领了，地上没有鸡场 | 背包有鸡舍图纸 `coop`，否则不提示 |
| `feed` | 有鸡场，一次没喂过（`drop_seq` 为 0） | 背包有胡萝卜 `feed`；没有：地里有作物等它，有种子 `sow`/`till`，没种子 `buy_seeds` |
| `sell_egg` | 喂过、农场 Lv1，地上有蛋或背包有蛋 | 有蛋可捡或在下 `egg`，背包有蛋 `sell_egg` |
| `upgrade` | 农场 Lv1，有下一级 | 木材石头不够 `gather_upgrade`；金币不够，背包有胡萝卜或蛋 `sell_for_coins`，没有 `earn_coins`；都够了 `upgrade` |
| 无 | 农场已过 Lv1（且鸡场喂过） | — |

规则里没有鸡舍蓝图、鸡场或农场等级时跳过对应里程碑。卖过第一颗蛋后再喂会让存档又回到“有蛋”，分不出是不是第一颗，
任务表沿用 C-61 的做法：本机见过的进度不往回退（`Sell an egg` 那行）。

## 本机临时服务端（给 W-598 录屏）

同一完整 SHA 的服务端，内存库，只听 127.0.0.1，进程退出数据就没了；邮箱验证码打印在输出里，不发信：

```
cd server && pnpm install --frozen-lockfile   # 首次
PORT=3975 GIT_SHA=$(git rev-parse HEAD) pnpm exec tsx tools/dynamicfarm_qa_server.ts
# 输出 QA_SERVER_READY 即可；验证码看 `QA_MAIL verify <邮箱> <6 位码>`；收尾按启动时记下的 PID kill
```

`GET http://127.0.0.1:3975/v1/healthz` 的 `git_sha` 应是交付 SHA。游客关闭、邮箱注册开放，同 0.4.5 客户端。

**QA 包怎么连到它**：`tools/android/build_worker_apk.sh --dynamic-farm-internal <目标>` 只接受
`tools/android/dynamic_farm_export.py` 里 `APPROVED_TARGETS` 列的测试服，仓库里没有本机地址。C-175#15 的取证包做法：
复制一份脚本到私有目录，在暂存副本（`$p/tools/android/dynamic_farm_export.py`）里把 `http://127.0.0.1:3975/v1`
加进 `APPROVED_TARGETS` 再出 `--dynamic-farm-internal http://127.0.0.1:3975/v1`；这个包只供取证，不交付、不送签、
不提交改动。装到模拟器后 `adb -P <本机端口> -s <模拟器> reverse tcp:3975 tcp:3975`，包里的 127.0.0.1:3975 就连到本机服务端。
cardigan-ci 上的模拟器要用 `-gpu swangle_indirect`（swiftshader 下地图点地块一直 loading，模拟器问题）。

**Google 登录**：服务端只要 `GOOGLE_CLIENT_IDS`（Android 向它要 ID token 的 OAuth Web 客户端 ID，逗号分隔；
不设用与正式服务端 `src/index.ts` 相同的默认，设成空串则关闭 Google 登录），并且本机能访问 Google 公钥地址。
客户端一侧由 C-172 的 Google 登录插件在出包时带上，用 mac-mini 的调试证书签名的 QA 包才过得了 Google 安卓客户端的
证书指纹校验（cardigan-ci 上没有这份证书，所以 Google 那段在 mac-mini 录）。本卡没有在本机服务端实测 Google 登录：
服务端接口已确认可达（假 token 返回 `GOOGLE_TOKEN_BAD_NONCE`），真 token 能否过校验以 W-598 实测为准。
