# C-111 动态农场安卓包闪退排查（进行中记录）

所有者手测 0.4.2 内部包（`release/0.4.2/signed-apk.json`，源提交 1dd8aa62）闪退过一次，没有日志。
本文件记录已排查的路径、数据和还没做的部分；结论随取证更新。

## 已排查

### 1. Godot 侧：地图 ↔ 3D 地块反复切换（桌面 headless，无内存增长）

`tools/dev/dynamic_farm/switch_memory_probe.gd` 按地图的方式打开 `dynamic_farm_host.tscn`，等农场报 ready，
再按 `AppRouter.pop_instance` 的方式拆掉（remove_child + queue_free），每轮采样。

| 项 | 第 2 轮回到地图 | 第 20 轮回到地图 | 3D 中 |
| --- | --- | --- | --- |
| Godot 静态内存 | 127.70 MB | 127.74 MB | 135.7 MB |
| 对象 / 资源 / 节点 / 孤儿节点 | 2306 / 599 / 9 / 0 | 2306 / 599 / 9 / 0 | 2896 / 618 / 173 / 0 |

20 轮后对象、节点、孤儿节点数完全不变，静态内存 18 轮只多 0.04 MB。GDScript 侧没有随切换累积的泄漏。
headless 用的是空渲染器，GPU 内存、Vulkan 表面和原生 Mapbox 地图都没有覆盖到。

### 2. 原生侧：全量建筑数据每次回到地图都整份重新加载（最可疑，未在设备上证实）

- 地图的建筑块来自 `buildings.geojson`（r6 数据集）：60,434,854 字节，服务器不压缩、没有 Cache-Control，
  143,752 个要素、146,190 个环、1,905,469 个顶点（本机下载后统计）。
- 这份文件不经 Godot，而是整份交给 Mapbox 原生解析成一个 GeoJSON 源（`ParcelMapController.kt` `install()`）。
- 源编号带 generation（`gensen-parcels-<generation>-<turn>-buildings`），不复用：
  - 地图暂停（进 3D、切后台、锁屏、打开登录页或外链）时 `selection_controller.pause()` 删掉所有源；
  - 恢复时 `activate()` 重新取 manifest、换新 generation，再整份加一次 60 MB 的源；
  - 加载出错或 45 秒超时后也会自动重载一次。
- 所以“加载全量建筑数据时反复缩放拖动、地图和 3D 反复切换、前后台切换”这三条路径，每一次都会让 Mapbox
  重新下载（是否命中 Mapbox 自己的 HTTP 缓存未核）并重新解析 190 万个顶点。上一份还在解析时被删、新的一份又开始，
  可能出现两份同时占内存。原生内存不够时，系统会直接杀进程，表现就是没有 Java 堆栈的闪退。

### 3. 原生侧：每次进出 3D 都重建 Godot 的渲染表面（次可疑，未在设备上证实）

`GodotMapPlugin.setGodotSurfaceOpaque` 在运行时对 Godot 的 Vulkan SurfaceView 调 `holder.setFormat`，
系统会销毁并重建表面，Godot 要重建交换链；进 3D、回地图、回到前台各发生一次。暂停时插件还会提前调
`onActivityStopped`，恢复时再调 `onActivityStarted`。这几条组合在真机上没有记录过反复切换的测试。

## 还没做（需要模拟器）

- 模拟器复现、内存峰值（PSS）、logcat 和系统退出原因：本 Run 在 mac-mini 上，没有 android.emulator 资源；
  且这台机器的 AVD 卷被系统隐私权限拦截（见 SEN-C-114#20），无法起模拟器。
- 复现脚本已备好：`tools/dev/dynamic_farm/crash_repro.sh`，按轮执行平移和双击放大、选地块进 3D 再返回、
  Home 后重开、锁屏再亮屏，每 2 秒记录 PSS，收集 logcat 和 `dumpsys activity exit-info`，并统计建筑源重装次数。
  0.4.2 包只有 arm64，要用 arm64 模拟器；带 Vulkan 时 Godot 可能卡住，关掉 Vulkan 会改走 GLES3，
  第 3 条的表面路径也随之改变，结论里要写明用的是哪一种。
- 所有者真机的退出原因（Q-123）：如能导出，可直接判断是内存被杀、原生崩溃还是 Java 崩溃。

## 下一步建议（等取证结果再定）

- 如果证实是第 2 条：建筑块改成和地块一样的矢量瓦片（数据卡 SEN-C-113 正在重新生成数据），
  或者至少让建筑源在暂停和恢复之间保留、不随 generation 重建。
- 如果证实是第 3 条：进出 3D 时不改表面格式，改用遮挡色或隐藏 MapView 的办法。
