# C-111 动态农场安卓包闪退排查

所有者手测 0.4.2 内部包（`release/0.4.2/signed-apk.json`，源提交 1dd8aa62）闪退过一次，当时没有日志。
本文件记录真机证据、定位过程、修复，以及排查过、但不是这次闪退原因的路径。

## 结论

背包打开时点暗色遮罩关闭背包，就会闪退。`scenes/dynamic_farm/parcel_farming.gd` 里遮罩的点击回调先调
`close_bag()`，它把 `_scrim` 置空；回调接着调 `_scrim.accept_event()`，等于对空对象调方法。

- 编辑器和测试用的是调试版引擎，这一步只报 `SCRIPT ERROR: Cannot call method 'accept_event' on a null value.`，不会崩。
- 发布包用的是正式版引擎。Godot 4.7.2 的 GDScript 虚拟机在正式版里不做空对象检查
  （`modules/gdscript/gdscript_vm.cpp`，`OPCODE_CALL_METHOD_BIND_VALIDATED_NO_RETURN` 的 `#else` 分支直接取对象指针），
  于是 `Control::accept_event()` 拿着空指针读 `is_inside_tree()`，触发 SIGSEGV。

## 真机证据

1. 所有者导出的 `dumpsys activity exit-info`（C-111#20）：2026-11-24 21:55:39，APP CRASH(NATIVE)，status=11（SIGSEGV），
   前台，RSS 2.5 GB。
2. 所有者的 bugreport（C-111#28，只在本机临时目录读取，读完已删）里有同一时刻的墓碑 `tombstone_03`：
   - 崩溃线程是 Godot 的 VkThread，`SEGV_MAPERR`，fault addr `0x1b8`，Cause: null pointer dereference。
   - 崩溃库 `libgodot_android.so` 的 BuildId `270121fef88100c19643517c328b5868e01d345c`，和本机 Godot 4.7.2 官方正式版模板一致。
   - 用 Godot 官方发布的 4.7.2 正式版安卓调试符号（arm64）和 `llvm-dwarfdump --lookup` 还原的调用栈（从下往上）：

     | 帧 | 函数 |
     | --- | --- |
     | #15 | `Java_org_godotengine_godot_GodotLib_step`（每帧主循环） |
     | #13–#11 | `Input::flush_buffered_events` → 分发触摸转来的鼠标事件 |
     | #08–#05 | `Window::_window_input` → `Viewport::push_input` → `Viewport::_gui_call_input` |
     | #04 | `Control::_call_gui_input` 发出 `gui_input` 信号 |
     | #03 | `Object::emit_signalp` |
     | #02 | `GDScriptLambdaSelfCallable::call`（脚本里的 lambda） |
     | #01 | `GDScriptFunction::call` |
     | #00 | `Control::accept_event()` 内联的 `Node::is_inside_tree()`，`this` 为空 |

   - 全仓库在 `gui_input` 的 lambda 里对成员调 `accept_event()` 的只有 `parcel_farming.gd` 这一处。
3. 崩溃前 2 分钟应用刚从后台回到前台，崩溃时刻没有窗口或表面变化，和“进出 3D 重建表面”无关。
   bugreport 的系统日志里没留下应用自己的输出（已滚掉）。

## 修复

- `parcel_farming.gd`：回调里用打开时记下的局部 `scrim`，并且先 `scrim.accept_event()` 再 `close_bag()`。
  背包的样子和交互都不变：点遮罩照旧关闭背包。
- `tests/dynamic_farm/test_parcel_farming_scene.gd`：打开背包后在遮罩上发一次左键抬起，检查背包关上、遮罩被释放。
  去掉修复时这个文件报上面的 SCRIPT ERROR，测试脚本判失败；恢复修复后通过。

## 排查过、不是这次原因的路径

### Godot 侧：地图 ↔ 3D 地块反复切换（桌面 headless，无内存增长）

`tools/dev/dynamic_farm/switch_memory_probe.gd` 按地图的方式打开 `dynamic_farm_host.tscn`，等农场报 ready，
再按 `AppRouter.pop_instance` 的方式拆掉（remove_child + queue_free），每轮采样。

| 项 | 第 2 轮回到地图 | 第 20 轮回到地图 | 3D 中 |
| --- | --- | --- | --- |
| Godot 静态内存 | 127.70 MB | 127.74 MB | 135.7 MB |
| 对象 / 资源 / 节点 / 孤儿节点 | 2306 / 599 / 9 / 0 | 2306 / 599 / 9 / 0 | 2896 / 618 / 173 / 0 |

20 轮后对象、节点、孤儿节点数完全不变，静态内存 18 轮只多 0.04 MB。headless 用的是空渲染器，
GPU 内存、Vulkan 表面和原生 Mapbox 地图没有覆盖到。

### 全量建筑数据每次回到地图都整份重新加载（真实的浪费，但不是这次崩溃）

- `buildings.geojson`（r6）60,434,854 字节，服务器不压缩、没有 Cache-Control；143,752 个要素、1,905,469 个顶点，
  整份交给 Mapbox 原生解析（`ParcelMapController.kt` `install()`）。
- 源编号带 generation，地图暂停（进 3D、切后台、锁屏、登录页）时删掉，恢复时重新加，所以每次回到地图都重新下载、重新解析。
- 墓碑显示崩溃在 Godot 线程、不在 Mapbox，所以这条不是这次闪退的原因。它仍然费流量、费内存（RSS 2.5 GB 里可能有它的份），
  建议另开卡处理：让建筑源在暂停和恢复之间保留，或者改成按视野加载的矢量瓦片（和 SEN-C-113 的数据重做一起）。
  本卡曾写过一版“同 URL 复用建筑源”的原生改动（提交 a3c09d59，含 JVM 测试），因为不是崩溃原因、又没在设备上验证，
  已从本卡交付里撤回，后续卡可以直接拿这个提交做起点。

### 进出 3D 时重建 Godot 渲染表面

`GodotMapPlugin.setGodotSurfaceOpaque` 运行时改 SurfaceView 格式，会销毁重建表面。墓碑里崩溃时刻没有表面变化，
栈也在输入分发里，不是这条。真机上反复切换仍没有专门测过。

## 还没做

- 模拟器或真机录屏：发布包里“打开背包 → 点遮罩关闭”修复前闪退、修复后不闪退。需要按本提交打内部包。
  mac-mini 的模拟器要等 H-59 授权和重启生效；也可以在 cardigan-ci 上做。
- `tools/dev/dynamic_farm/crash_repro.sh` 是排查时写的通用复现脚本（平移缩放、进出 3D、前后台、锁屏，每 2 秒记 PSS，
  收 logcat 和 exit-info）。它没有覆盖“点遮罩关背包”，验证这次修复按上一条手动操作即可。

## 后续建议

- 正式版引擎里，脚本对空对象调方法会直接闪退，调试版只报 SCRIPT ERROR。测试里出现的
  `Cannot call method ... on a null value` 都应当按闪退对待；`tools/ci/dynamic_farm_tests.sh` 已经把 SCRIPT ERROR 判为失败。
- 以后真机闪退，导出 bugreport 拿墓碑，用 Godot 官方同版本的安卓调试符号还原调用栈，比在模拟器上猜路径快。
