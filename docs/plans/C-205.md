# C-205 Mixpanel 上报补齐：删号同步删除、关停限时、重设密码记登录

补 SEN-C-203 代码审核提出的三处缺口（C-203#15）。只改服务端 `server/`，游戏客户端不改。没配 Mixpanel（`MIXPANEL_PROJECT_TOKEN`、`MIXPANEL_API_HOST` 都空）时三项都不启用、不发外部请求。

## 1. 删号时删除 Mixpanel 数据

- 两个删号入口（应用内 `DELETE /v1/users/me`、站外 `POST /v1/account/delete`）共用的删号流程在数据库删除成功后调用 `analytics.deleteUser(users.id)`，不等网络、不抛错。
- `deleteUser` 先从队列里丢掉这个用户还没发出的事件，再等正在发的那批落地，然后提交删除任务。删除请求排队一个个发（接口限每秒 1 次），超时、网络错、429、5xx 重试一次，仍失败或其它 4xx（如令牌无效 401）只记日志。
- 接口（Mixpanel 官方 GDPR API v3，https://docs.mixpanel.com/reference/gdpr-api ）：`POST <地区主机>/api/app/data-deletions/v3.0/?token=<项目令牌>`，请求体 `{"distinct_ids":["<users.id>"],"compliance_type":"GDPR"}`，认证 `Authorization: Bearer <GDPR OAuth 令牌>`。地区主机与上报地址对应：`api.mixpanel.com` → `mixpanel.com`，`api-eu.mixpanel.com` → `eu.mixpanel.com`，`api-in.mixpanel.com` → `in.mixpanel.com`。删除任务最长 30 天完成。

### 额外凭据

只有项目令牌不够，删除接口要另一个凭据：

| 项 | 内容 |
|---|---|
| 凭据名 | Mixpanel GDPR OAuth 令牌（OAuth token for GDPR APIs） |
| 环境变量 | `MIXPANEL_GDPR_TOKEN`（选填，只能和 `MIXPANEL_PROJECT_TOKEN`、`MIXPANEL_API_HOST` 一起设；单独设拒绝启动） |
| 获取方式 | 项目所有者或管理员登录 Mixpanel，右上角头像 → Profile & Preferences → Data & Privacy 生成 |
| 有效期 | 一年；到期前生成新令牌换进 `.env` 并重启 app |

没配时删号照常成功，日志记一行 `[analytics] MIXPANEL_GDPR_TOKEN not set, Mixpanel data of deleted user <users.id> was not deleted; delete it in Mixpanel by hand`，由人按编号在 Mixpanel 后台补删。启动日志 `analytics_delete=on/off`。

## 2. 关停限时

`close()` 最多等 `SHUTDOWN_MS`（5 秒，代码常量，`mixpanel.ts`；构造参数 `shutdownMs` 可改）。到点还没发完：丢掉队列里剩下的事件和排队的删除请求、取消还在路上的请求和重试等待，记一行 `[analytics] shutdown limit 5000ms reached, dropped N queued events and M pending deletions`。`docker stop` 的 10 秒宽限期内能退出。补发脚本先不限时 `flush()` 再 `close()`，不受这个时限影响。

## 3. 重设密码记一次登录

`POST /v1/auth/email/reset` 成功、签发新会话后报 `login`，`method` 为 `password_reset`。码错或过期不报。

## 启用步骤补充

在 C-203 的启用步骤第 1 步同时填 `MIXPANEL_GDPR_TOKEN`；第 2 步确认启动日志 `analytics_delete=on`。详见 `server/deploy/dynamicfarm/README.md` 的“产品分析（Mixpanel）”。
