# C-209 · 旧 8×6 牛棚存档兼容：退还蓝图让玩家重新摆放

张衡·森，2026-11-27。卡片目标与验收以 SEN-C-209 为准；本文只记做法和口径。

## 哪些算旧牛棚

规则里这一类写了缺口（`buildings.<类型>.cutouts`，C-202），存档里这栋自己没有缺口的建筑。C-202 起放下时会把缺口抄进存档，
所以只有 C-202 之前盖下的会这样；按现在的配置只有 SEN-C-192 时期 8×6 的牛棚。鸡场、小屋、井的规则没有缺口，不受影响；
11×6 带缺口的新牛棚不受影响。

## 怎么处理

读档时把它拆掉，东西退给玩家，玩家按新的 11×6 占地重新摆：

| 东西 | 去向 |
|---|---|
| 牛棚本身 | 拆掉，退一张蓝图（`blueprint_barn`） |
| 盖它花的材料 | 按现在的规则退（20 木材、10 石头），重新盖正好够，等于没花 |
| 两头牛 | 跟着牛棚拆掉；重新盖时照规则带上两头牛（存档里牛只是规则的副本，没有别的状态） |
| 已经下了、还没捡的奶 | 进背包 |
| 喂过、还没下的奶 | 也按奶进背包：胡萝卜和体力已经花了，退胡萝卜会白丢体力，给奶才不丢东西 |
| 已买蓝图的记录、等级、金币、其它建筑和它们的掉落物 | 不动；掉落物编号不回退 |

和换数据集（C-136 `rebaseFarm`）的口径不同：那边退蓝图不退材料、没下的奶退胡萝卜。这里是我们改了牛棚的占地，玩家不该为此吃亏，
所以材料全退、没下的奶也给奶。旧牛棚已经不可能再盖出来（放下时一定抄缺口），不会被反复利用。

## 什么时候处理

结果只看存档和规则，不随时间变，所以读出来的就是写回去的：

- 服务端 `server/src/parcels/farm.ts retireDraftBuildings`：
  - 读档（`GET /v1/parcels/mine` 等所有带地块的回复，`routes.ts farmView`）显示已拆、已退，不写回；
  - 进入自家地块（`POST /v1/parcels/mine/enter`）在同一次加锁写入里写回，只写一次，重试、并发进入不会再退；退的东西不算进 `gift`；
  - 每批命令（`applyFarmCommands`）先过一遍，没进入就下命令也一样。
- 客户端 `modules/dynamic_farm/parcel_farm.gd retire_draft_buildings` 照抄：`view`（本机存档的读）、`apply`（命令）、
  本机存档 `parcel_farm_local_store.gd enter`（写回一次）。

存档字段和版本号都不变；不清任何服务器存档，不改新牛棚的占地和数值。
