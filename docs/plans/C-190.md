## 衔接：引导接到 0.4.6 的内容

0.4.5 的引导（`ParcelGuide`）升到 Lv2 后就结束，0.4.6 新加的委托板、牛棚、羊圈没有任何提示：玩家不知道驿站里有委托板，
也不知道 Scott 那里能买牛棚蓝图。本卡把引导接下去（只看存档，中途退出再进接着当前那一步）：

| 里程碑（手机任务行） | 什么时候 | 提示（step） |
| --- | --- | --- |
| `request`（Deliver a request） | 农场过了 Lv1，一单委托都没交过 | `request` |
| `barn`（Build the Barn） | 地上没有牛棚 | 金币不够 600 `barn_coins`；够了 `barn_blueprint`；蓝图在包里：木材石头不够 `gather_barn`，够了 `barn` |
| `sheep_pen`（Build the Sheep Pen） | 有牛棚，地上没有羊圈 | 羊圈蓝图在包里：木材石头不够 `gather_pen`，够了 `sheep_pen`；否则牛棚里没有奶在产、包里有 2 根胡萝卜时先 `feed_cows`；然后按 Scott 键和服务端的顺序：委托不够 15 单 `pen_requests`，不到 Lv3 走升级的几步（`gather_upgrade` / `sell_for_coins` / `earn_coins` / `upgrade`），金币不够 1,200 `pen_coins`，都够了 `pen_blueprint` |
| `feed_sheep`（Feed the sheep） | 有羊圈，羊圈里没有羊毛、包里也没有 | 野草药够 3 份 `feed_sheep`，不够 `gather_herbs` |
| 无 | 有羊毛了 | — |

规则里没有委托板、牛棚或羊圈时跳过对应里程碑。卖掉羊毛后存档看不出喂过，和 C-175 的「卖蛋」一样：手机任务表沿用本机见过的进度
（`ParcelTasks.done_count` 的 `reached`），地块上的提示在本机已经看到全部完成时也不再出现（`ParcelGuide.step` 的 `finished`）；
熟了的胡萝卜、干的胡萝卜仍然照常提示。

模拟器第一遍（afdf5933）发现：买到羊圈蓝图、材料也够时，牛闲着又有胡萝卜，提示仍是喂牛，左下键却已是 Build Sheep Pen。
改为蓝图在包里时先提示盖羊圈（缺料先提示采木材石头），再轮到喂牛。

## 本机临时服务端和测试存档（录屏用）

同 C-175：同一完整 SHA 的服务端，内存库，只听 127.0.0.1，邮箱验证码打印在输出里。C-190 加了测试存档入口，用来跳过攒单和升级金币的等待：

```
cd server && PORT=3975 QA_CONTROL_PORT=3976 GIT_SHA=$(git rev-parse HEAD) pnpm exec tsx tools/dynamicfarm_qa_server.ts
curl -s localhost:3976/qa/farm                                    # 最近认领的那块地的存档
curl -s -X POST localhost:3976/qa/test-save -d '{"set": {"coins": 700, "bag.wood": 20}}'
```

`set` 的键是存档里的字段路径（`coins`、`level`、`requests_done`、`bag.<物品>`、`board.done_today` 等），值为 null 删除该字段。
写入会让存档版本 +1，所以先关掉应用（`am force-stop`）再写，重开后读到新存档。每次写入在服务端输出里打印 `QA_TEST_SAVE <路径>=<值>`，
录屏报告照抄这些行，注明哪一段用了测试存档。

QA 包：照 C-175，复制 `tools/android/build_worker_apk.sh` 到私有目录，暂存副本的 `APPROVED_TARGETS` 加上 `http://10.0.2.2:3975/v1`，
出 `--dynamic-farm-internal http://10.0.2.2:3975/v1`，用临时调试证书签名后装到模拟器（模拟器里 10.0.2.2 就是本机的 127.0.0.1）。
这个包只取证，不交付、不送签、不提交改动。
