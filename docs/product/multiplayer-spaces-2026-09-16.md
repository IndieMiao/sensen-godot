# 街区、农场与合作矿井

2026-09-16：用户要求三类空间多人在线、单副本最多 300 人、同步位移/动作/血量，并明确要求共享怪物、合作清层和独立掉落。本文记录本轮合同；验证与部署结果另见 QA 记录。

## 空间与归属

- 街区按地区、蓝图版本及线路区分；不同几何布局不混入同一副本。农场按实际 farm_id 和线路区分，遵循原访问权限。
- 矿井采用副本模板 `starter_mine` + 独立实例 UUID。未组队的玩家进入各自实例；组队后只有重新进矿才重新决定绑定，绝不在组队时传送或修改现有场景。
- 重新进入时，若队长正在该模板的矿井内，队员绑定队长当前实例、继承该实例全部进度，覆盖自己旧实例入口（旧实例中其他成员不受影响）。若队长在矿外或离线，不读取队长历史绑定；队员继续自己已绑定的实例，或首次创建个人实例。
- 队长自己重新进矿继续其绑定实例。组队以邀请码加入，最多 300 人；退出或解散不立即改变正在探索的实例。矿井实例最多 300 位成员，五层各自同步可见对象；玩家可独立上下楼，共享通路与怪物进度。
- 网络短暂断开使用服务器签名的恢复凭据，回到原实例原楼层的安全入口，不把网络抖动当作主动重新进矿。主动出矿撤销恢复资格；凭据过期后由玩家选择重新进入。
- 每个空间实例最多 300 人，满员明确拒绝。街区/农场可选线路；矿井使用队伍绑定，不手动选择他人的实例 ID，也不静默把同伴分到别处。
- 个人矿井原存档完整保留。合作矿井使用独立持久化状态；首次建立为新探险，不从任何玩家的旧存档复活怪物或补发奖励。
- 清矿规则沿用 R5：1/2 层清矿；3/4 层清矿或清怪任一即可；5 层只有 300 HP、2.8 移速的抗打断精英。可通行楼层的剩余资源保留。
- 每只怪物的有效伤害参与者各获独立、稳定随机掉落；岩石完成时的有效开采参与者各获独立掉落。相同事件每人最多一份，满包进入现有暂存。精英参与者永久获得个人电梯解锁。
- 单人倒下立即送回农场、保留 1 HP；其他成员继续。背包/暂停只停止自己的输入，不暂停共享世界；断线角色退出战斗，重连安全出生，已提交伤害和掉落不回滚。
- 普通地下城式手动重置：单人本人/组队队长在所有成员都已出矿后确认放弃进度与未采资源，旧实例作废，下一次进入创建新实例。不会自动重置，已入袋物品与永久电梯保留。其他成员再次入场仍遵循“队长当前在矿内才继承”，不能借旧绑定进入已重置实例。

## 架构

- HTTPS API 保留账户、装备、物品与原存档；同源 WSS 承载空间连接。登录令牌仅在首包发送，不放 URL。
- 每个实例只有一个权威写入者。20 Hz 固定步长模拟移动、碰撞、AI、攻击范围/朝向/冷却与血量；客户端发送目标位置及动作意图，不能上报命中、伤害或奖励。
- 本地移动预测，序号确认与误差校正；远端位置插值。紧邻成员 10 Hz，其余 2 Hz；二进制位置帧、稀疏成员资料及可靠状态事件。慢连接有有界发送缓冲和断开策略。
- 导出的导航网格与 Godot 同源。合作矿井布局由服务器下发，所有客户端使用同一份岩石位置、导航和怪物状态。
- 副本状态、事件序号与玩家物品/生命在同一 PostgreSQL 事务提交；房间版本比较与提交 ID 防止重放和不确定提交重复发奖。位置不逐帧写数据库。
- 生产实时进程通过 PostgreSQL 会话锁保证唯一写入者。HTTP 可独立扩容；反向代理将实时路径送至该进程。扩展至多实时节点需要明确分片路由，不能直接轮询多个独立内存房间。
- 300 人目标必须用真实 WebSocket 压测证明，另记录客户端渲染规模和模拟器证据；测试客户端数不等于 300 台手机实测。
