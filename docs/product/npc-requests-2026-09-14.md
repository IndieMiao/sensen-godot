# NPC 与邻里委托

- 日期：2026-09-14；对应 [SGODOT-114](https://plane.sensenjoy.cn/zili/browse/SGODOT-114)。
- 状态：首版已实现并完成 Godot 与模拟器流程验证；未发布，未完成自然玩家观察。见[验证记录](../qa/npc-requests-2026-09-14.md)。
- 基础：复用三名既有居民、请求、街边成果、人物回应、统一背包和人物效果；不另建平行任务系统。

## 本轮玩家选择

玩家比较苗圃看护人、小馆主理人和修缮师当前的需求，决定先帮助谁。铜矿既能做装备、木箱，也能直接交付；料理既能出售、自用获得效果，也能用于邻里委托。完成后显示实际奖励和对应人物回应。

保留已有故事、赠礼和关系成长。重复委托奖励继续使用金币与已有街边成果，不增加新的无限友情刷取规则，也不将委托序号当作历史完成次数。

## 接取与追踪

每名居民保持一份冻结的当前委托，最多可同时接取三名居民的委托；地图仍只追踪一个目标。

| 行动 | 状态变化 |
| --- | --- |
| 接取并追踪 | 当前委托标记已接取，同时成为地图目标；比较页保持打开 |
| 切换追踪 | 地图改追另一份已接委托；前一份仍已接取 |
| 停止追踪 | 清除地图目标，保留已接取状态 |
| 放弃 | 清除该份已接取状态，保留同一需求供重新接取；序号递增使旧操作失效 |
| 换一份 | 切到下一份当前可用需求，清除该份接受和追踪状态；序号递增 |
| 交付 | 必须已接取且物品足够；原子扣物、结算金币与街边成果，保存完成记录并准备下一份 |

接取和放弃不收费，不硬冻结材料。批量出售继续保护当前追踪委托所需的直接物品及合成食材，其他资源分配由玩家选择。换单与放弃不领取任何奖励，不自动接取下一份。

为兼容既有入口，旧“追踪委托”命令可以同时完成首次接取；取消追踪仍不表示放弃。
“请求纯木料工作”明确切换到保留的纯木料请求，不依赖普通换单的轮换顺序；已有委托时先确认取消该份接取。

## 内容范围

保留原六份委托的顺序与奖励，再追加三份：

| 居民 | 新需求 | 金币 | 已有街边成果 |
| --- | --- | --- | --- |
| 小馆主理人 | 岩盐蔬菜汤 1 | 24 | 小桌餐食 |
| 修缮师 | 铜矿石 3 | 18 | 街边长凳 |
| 修缮师 | 铜箍木箱 1 | 26 | 街边物资篮 |

纯木料委托保留为缺钱时的恢复路径。新需求依赖已有工作台或厨房能力；小馆所有委托入口、接受、追踪、换单和交付统一要求完成首次共餐，解决旧接口条件不一致。

每份定义有稳定 ID、居民归属、用途说明与交付回应。需求统一按物品 ID 计算，兼容旧木料、作物、料理字段，并扩展普通材料和可制作手作品；永久装备不作为交付物。

## 界面与反馈

背包中的委托页显示三名居民的当前需求、持有量、实际金币和街边成果，允许比较与接取。“前往目标”由玩家主动点击，交付在现有 NPC 或餐桌场景完成。

人物交互保留对话、故事、赠礼，补充简短身份与性格说明和统一委托入口。缺料追踪能展开木箱实际制作成本，以及汤所需的岩盐；已有料理或手作品优先作为成品交付，不再次计算其配方。

完成后显示人物回应、实际扣除与奖励，并保存每名居民最近一次完成记录。重新打开或重启后可查看该记录，不再次发奖或重播完成动画。蔬菜汤委托展示真实的汤模型。

## 保存与验证

领域版本升至 18，结构版本保持 1。旧有效追踪转换为已接取，原库存、人物效果、矿坑和已有街边成果保留；没有记录的历史完成次数与回应不回填。

每次操作校验槽位与准确序号，并继续使用农场版本和请求幂等保护。重点验证接取后切换目标、停止追踪与放弃的差异、矿物和手作品跨堆交付、暂存消费、缺料拒绝、重复领奖、丢失响应和旧 17 存档恢复。

开发者的 Godot 与模拟器操作只证明工程和指定流程；玩家能否理解两份不同需求并自主决定下一项行动，需要另行观察。
