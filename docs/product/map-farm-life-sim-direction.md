## 0. 本版结论

### 0.1 已冻结的产品决策

1. **只有两层可见空间**：第一层是生活地图；第二层是独立实例，包含我的农场、他人农场和关键地点小场景。
2. **私人农场不占据现实土地**：城市只传递天气、时间、地区内容和邻居池；进入农场后切换到独立 `farm_instance_id`。
3. **农场继承街区骨架**：主路拓扑、区块邻接、轮廓和方位可识别一致；真实尺度、道路宽度、可耕面积和步行距离统一归一化。
4. **同一区域可以有很多独立农场**：`region_id` 只负责相遇，多个玩家可以选择同一蓝图，但不会争抢、买卖或占领同一块地。
5. **Avatar 只表达形象**：参与移动、劳作动画、拜访、合照和换装，不提供产量、体力、速度、掉率或关系倍率。
6. **玩法以《星露谷物语》式劳作和生活为主**，保留少量《沙石镇时光》式居民委托与地区修复；不保留《异星工厂》式排产、吞吐、物流和生产线优化。
7. **MVP 包含异步只读拜访**：地图上选择 Avatar，先看静态农场预览，再进入独立访客实例；不做实时多人、聊天、交易、偷菜或共同经营。
8. **MVP 不做任意地点实时生成**：一个城市只提供三个经过离线生成与人工 QA 的候选街区蓝图。
9. **MVP 使用受控天气脚本**：地图环境、农场田况与剧情保持一致；实况天气只做 shadow log，不作为首轮可玩内容。

### 0.2 与 v0.2 的冲突清理

| v0.2 表述或范围 | 本版处理 |
|---|---|
| “私人农场、生活地图、居民关系、四季庭院”被称为四层世界 | 改为两层空间；居民关系和四季庭院是系统，不是地图层 |
| 农田在现实道路之间浮现，播种位置回写地图 | 删除；只在创建流程高亮街区蓝图，正常地图不显示私人土地边界 |
| 只选择粗粒度经营区域，农场为通用矩形 | 改为城市内三个 `layout_patch_id`，每个农场继承所选街区拓扑 |
| 地区锚点可在季节结算时迁移 | 删除；创建后冻结蓝图版本，现实道路更新不自动改动老农场 |
| MVP 完全排除多人 | 改为保留异步只读拜访，继续排除实时同场及所有资源交互 |
| 五种作物、三道料理、三名完整居民、四个完整地点 | 收敛为四种作物、两道料理、两名完整居民、一名次要居民、一个复用地点实例模板 |
| 园艺等级和活跃日同时重复解锁同一内容 | 分工：章节解锁七日核心作物、料理和成长选择；园艺等级只解锁非阻塞便利与手账表达 |
| 十二周逐周内容矩阵属于当前制作承诺 | 移除；只保留 84 个活跃日的长期北极星和 MVP 后假设 |
| 地图降级为无关插画或任务列表 | 改为使用同一蓝图生成的缓存地图快照/示意图，继续保留方向和区块关系 |

### 0.3 产品宪法

- **地图是生活入口，不是现实地产系统**。
- **拓扑影响个性，不影响经济能力**：不同街区的地块数、最大产能、工具效率和核心移动成本一致。
- **劳作有过程但不惩罚离线**：漏浇或漏登只会让作物安全暂停，不会枯死、倒退或腐坏。
- **天气改变今天怎么做，不改变谁更富**：不同天气的基础产量、金币和核心进度期望相同。
- **定位是建议，不是门票**：默认手选城市与街区，拒绝定位仍可获得完整玩法。
- **时间制造氛围，不制造错过恐惧**：关键剧情、成熟作物和已接受请求不自然过期。
- **居民和地点均为虚构内容**：不得暗示 NPC 对应真实住户、商家或现实建筑。
- **访客默认没有主人权限**：不能收获、播种、移动物件、出售或消耗主人资源。
- **等级不阻塞首周主线**：轻度玩家不会因少收几株作物而打不开厨房、工程或成长选择。
- **不出售体力、天气、关系和产能**：MVP 不接商业化，长期也只考虑外观和额外表达。

## 1. 产品定位与目标

### 1.1 核心幻想

玩家是一名刚在某座城市开始新生活的耕作者。他从三个公开街区母版中选择一个喜欢的道路与区块结构，系统据此生成独立农场。玩家在农场中亲手劳作，在地图上逐渐认识人和地方，并让最初荒废的“四季庭院”留下自己的生活记录。

核心情感路径为：

```text
认出街区
-> 选择一种空间
-> 亲手把它种起来
-> 认识地图上的人
-> 访问别人的生活
-> 共同留下地区记忆
```

### 1.2 第一印象与宣传点

前 30 秒必须同时成立：

1. **地图是真的**：玩家能认出城市、道路方向和街区轮廓。
2. **农场是我的**：农场来自我选的街区骨架，但明确位于独立实例中。
3. **我真的在劳作**：不是一键生产，而是 Avatar 移动、翻土、播种、照料和收获。
4. **这里有人生活**：地图上有居民、天气事件和可以拜访的其他耕作者。

宣传序列固定为：

```text
生活地图识别街区
-> 比较三个街区蓝图
-> 卡片扩展进入独立农场
-> 天气改变劳作动作
-> 地图发现居民与其他耕作者
-> 四季庭院留下第一处变化
```

不得用以下画面作为宣传主表达：

- 私人农场贴合现实地块或门口对齐现实道路。
- 仓库数字、订单列表、运输倒计时或生产线。
- Avatar 属性、战力、效率或稀有度。
- 玩家之间争地、偷菜或现实位置追踪。

### 1.3 玩家看到的长期终极目标

长期北极星仍是完成一个农场年的“四季庭院”。玩家从 D0 就能看到四区蓝图：苗圃、水景与凉亭、公共厨房与小集市、温室与公共客厅。

- 一个经营章为 21 个活跃日。
- 四章共 84 个活跃日，预计覆盖约 14-28 个自然周。
- 玩家通过种植、料理、居民关系和共同事件完成四处设施。
- 主结局要求完成四处设施，并让六名长期居民中的任意四名成为“合伙人”。
- 不要求全作物、全料理或全居民满进度。

这只是玩家可见的远期承诺。MVP Demo **只制作苗圃入口的三状态变化**，其他区域只显示不可交互的未来剪影，不进入产能和内容承诺。

### 1.4 MVP 的七日目标

> 玩家从选择街区蓝图开始，在七个活跃日内建立一块可辨认的私人农场，体验晴、雨、风三种劳作，认识两名居民，完成一次无奖励的他人农场拜访，并用首周收获修好四季庭院的苗圃入口。

D6 结束时必须留下三个下一周动机：

- 把 9 格田地扩到 12 格，或补上尚未购买的第一档工具。
- 继续了解一名已经达到“熟悉”的居民。
- 查看苗圃主体的下一阶段蓝图。

## 2. MVP Demo 定义

### 2.1 必须验证的五个命题

| 编号 | 命题 | 失败意味着什么 |
|---|---|---|
| H1 | 玩家能看出农场继承了所选街区的道路和区块结构 | 地图生成农场只是昂贵的随机皮肤 |
| H2 | 玩家理解农场是独立实例，不是现实土地所有权 | 两层空间表达和隐私设计失败 |
| H3 | 9 格基础劳作在第三天后仍有手感和主动性 | 种田退化为重复家务 |
| H4 | 天气至少两次改变玩家的劳作或种植选择 | 天气只是视觉特效 |
| H5 | 地图上的人物、地点和农场访问比普通列表更能形成记忆与回看 | 生活地图没有不可替代价值 |

MVP 不验证完整社交留存、完整四季内容或长期经济。七日结果只能决定是否继续投入下一纵切，不能证明全年成立。

### 2.2 玩家可玩范围

| 模块 | MVP 内容 |
|---|---|
| 城市与地图 | 1 个城市、街区级固定浏览范围、当前 Mapbox Streets 基准 |
| 农场蓝图 | 3 个离线预生成并人工 QA 的街区蓝图，全部可创建和游玩 |
| 农场规模 | 初始 9 格；工具路线或扩地路线二选一；扩地后 12 格 |
| 作物 | 小萝卜、生菜、胡萝卜、洋甘菊，共 4 种 |
| 料理 | 蔬菜沙拉、洋甘菊茶，共 2 种 |
| 天气 | 晴、雨、风 3 个完整表现与照料包 |
| 居民 | 2 名完整居民；1 名修缮师作为 D5-D6 次要角色 |
| 地点 | 苗圃、小馆、四季庭院 3 个地图入口；共用 1 套轻量地点实例骨架 |
| 地区工程 | 苗圃入口：荒废、清理、竣工 3 个状态 |
| 访问 | 1 套完整聚合/预览/只读访问/返回流程；至少 2 个预置访客农场 |
| 进度 | 7 个活跃日章节、7 级园艺手账、关系前三阶段 |
| 经济 | 金币 1 种可消费货币；出售、请求和一次性启动补贴 |

### 2.3 明确不做

- 任意城市、任意框选或在手机端实时解析全球街区。
- 真实地籍、建筑复刻、现实土地认领、入口对齐住宅或道路。
- 精确到场、步数、路线轨迹、后台定位和位置奖励。
- 实时多人同场、好友系统、聊天、自由留言、点赞排行、交易、偷菜和协作经营。
- 畜牧、钓鱼、矿洞、战斗、恋爱、婚姻和家庭。
- 自动排产、加工队列、物流路线、仓库压力、动态价格和自由市场。
- 作物死亡、腐坏、维护费、居民降好感和签到连胜。
- 体力条、能量药水和用等待恢复行动次数；MVP 用真实动作时间而不是体力门槛控制负担。
- 炎热、寒冷、雪与极端天气的完整资产。
- 完整四季庭院、六名居民和十二周内容。

## 3. 两层空间结构

### 3.1 第一层：生活地图

生活地图负责“看见、选择和返回”，不负责耕作：

- 展示玩家所选城市与街区范围；每个城市配置一个固定 `street_zoom`，Demo 为 `zoom 16.0 / pitch 45° / north-up`，正常浏览禁用双指缩放和旋转。
- 展示当地环境天气、三个虚构地点入口和四季庭院状态。
- 展示街区级近似存在的 Avatar 或人数簇，不展示陌生人的实时 GPS 点。
- 点击 NPC 入口进入关键地点实例；点击玩家 Avatar 先进入农场预览。
- 正常地图不绘制任何人的可耕边界、农场围墙或土地所有权。
- 玩家只能在已配置的街区边界内平移；不能缩到城市级或放大到建筑级，也不通过现实步行控制地图上的 Avatar。

### 3.2 第二层：独立实例

第二层共享同一类场景切换规则，但实例内容不同：

| 实例 | 谁拥有状态 | 玩家可做什么 |
|---|---|---|
| 我的农场 | 当前玩家 | 自由移动、耕作、料理、布置、出售和查看状态 |
| 他人农场 | 农场主人 | 访客自由移动、观察、挥手或查看预设信息；不能改变资产 |
| 关键地点 | 系统剧情 | 对话、短交互、提交物品和观看环境变化 |

进入第二层后 Mapbox 完全隐藏或暂停。场景内不保留道路名称、POI、地图按钮或实时位置语义。

关系、园艺手账、金币和庭院项目是跨空间系统，不构成第三、第四层地图。

### 3.3 固定访问流程

```text
地图人数簇
-> Nearby Farmers 横向列表
-> 选中一个 Avatar
-> 底部静态农场快照 + Visit Farm
-> 独立访客农场
-> 返回原地图相机状态、角色选择和列表位置
```

交互规则：

- 同时只能选中一个角色并打开一张农场预览。
- 预览绑定 `player_id + farm_instance_id`，不绑定该 Avatar 下方的经纬度。
- 预览位于地图 UI 中，不贴合、不替换、不连线到任何现实地块。
- 访客页明确显示主人名称和 `Visiting` 状态，不能复用主人的完整耕作工具栏。
- MVP 只允许挥手和预设印章，不开放自由文字；两者只是访客本机即时动画，不发送给主人、不持久化，也不产生金币、经验或物品。
- 主人天气和作物状态来自冻结快照，访客进入不会推进或修改主人时间。

### 3.4 农场内移动

- 镜头保持约 45° 俯视，不提供自由旋转，降低移动和场景识别成本。
- 左侧虚拟摇杆控制 Avatar 自由移动；点按可达地面作为无障碍替代。
- 靠近可交互对象时只显示一个上下文动作，不同时铺开完整工具栏。
- 劳作以田畦为操作单元，Avatar 必须移动到合理距离，但不要求逐格精确站位。
- 出生点、房屋、储物箱、九格田地和出口必须全部可达。

## 4. 街区蓝图与农场生成

### 4.1 三个对象必须分离

```text
region_id
城市级天气、时间、内容目录和邻居池

layout_patch_id
250-450 米候选街区的共享、只读、版本化空间母版

farm_instance_id
某名玩家独立拥有的作物、摆件、解锁和经营状态
```

同一个 `layout_patch_id` 可以被很多玩家选择；实例之间没有共享土地和资源状态。

### 4.2 继承与归一规则

| 数据 | 农场处理 |
|---|---|
| 主路方向与连接关系 | 保留，变成主步道 |
| 3-7 个主要街块 | 保留数量、顺序和邻接，映射为农场区块 |
| 河流、绿地的大轮廓 | 可变成水渠、池塘、树林或花圃边缘 |
| 主要路口 | 可成为入口、水井或小广场 |
| 真实距离和道路宽度 | 等比缩放后按游戏可读性统一 |
| 过窄巷道、细碎弯折和微小区块 | 简化、合并或作为装饰，不进入玩法 |
| 建筑、门牌、商户、住宅和地籍 | 不继承、不持久化、不对外展示 |

每份蓝图必须区分：

```text
visual_ground_mask  形成街区轮廓和环境
walkable_mask       控制 Avatar 与 NPC 移动
buildable_mask      控制家具、建筑和装饰
cultivable_mask     经过公平配额后的可耕田格
```

真实街块面积不能直接等于可耕面积。

### 4.3 创建流程

1. 玩家先手选城市；只有主动点击“使用当前城市”才请求一次前台大致位置。
2. 地图展示三个公开候选区域，以同源 GeoJSON 高亮主路和区块。
3. 玩家逐个查看农场缩略预览；预览与最终农场引用相同 `layout_patch_id`。
4. 三个候选都明确显示相同的 9 格初始容量和 12 格首周扩建上限。
5. 玩家确认后创建唯一 `farm_instance_id`，冻结 `blueprint_revision`。
6. 高亮卡扩展为全屏，地图消失，进入独立农场完成首次劳作。
7. 创建完成后，普通生活地图不再常驻显示该候选的土地边界。

### 4.4 公平与可玩性门槛

- 三个蓝图初始均为 3 个田畦、每畦 3 格，共 9 格。
- 第四田畦均增加 3 格；首季和首年远期容量统一为 16/24 格。
- 出生点到最远开放田畦的移动时间差不超过 10%。
- 相同工具完成九格基础农活的 P75 时间差不超过 10%。
- 建筑槽、水域玩法槽、装饰预算和未来扩建阶段一致。
- 地区形状不参与产量、售价、成长时间、稀有率或关系计算。
- 无法满足 3-7 个主要区块、可达性和容量条件的候选直接淘汰，不强行拉伸。

### 4.5 MVP 技术路线

```text
冻结的合规道路数据
-> 本地双精度米制投影
-> 道路拓扑修复与区块 polygonize
-> 简化、等比缩放、玩法配额和可达性验证
-> map_overlay.geojson + farm_blueprint + 静态地表 Mesh
-> 人工 QA 后随 Demo 发布
```

硬规则：

- Mapbox 只负责显示底图，不作为永久农场数据的运行时来源。
- 不从截图做图像分割，也不在端上使用 `queryRenderedFeatures` 生成存档。
- 地图高亮和农场必须由同一份蓝图编译，不允许分别临摹。
- 手机只加载已三角化地表、稳定逻辑格、锚点和预计算寻路数据。
- 蓝图修订不可变；现实道路或生成算法更新只产生新 revision。
- 老玩家不自动迁移；无法映射的未来迁移应把摆件无损回收到仓库。
- Demo 准备一份通用安全蓝图作为资源损坏降级，但不进入三个主候选。

### 4.6 蓝图验收

- 去掉标签后，至少 80% 测试者能把农场与三个候选地图轮廓正确匹配。
- 保留的主路图拓扑和区块邻接关系必须一致。
- Android、iOS 对同一 checksum 生成完全相同的 `block_id/cell_id`。
- 任意模板不得出现不可达田格、窄路卡死、镜头外关键物件或碰撞穿越。
- 访客接口只下发本地坐标和蓝图内容，不下发经纬度、街道名或逆变换。

## 5. 核心玩法循环

### 5.1 主循环

```text
生活地图查看天气、来信和人物位置
-> 进入私人农场并完成一轮亲手劳作
-> 将收获分给出售、居民、料理或庭院
-> 返回地图选择一个人物、地点或农场访问
-> 获得关系、手账、金币、地区变化或空间灵感
-> 为下一轮天气和收获做准备
```

人物与地点事件若不改变农场用途、居民关系或永久记忆，就只是入口动画，应从 MVP 删除。D4 访问是唯一验证性例外：它不写入奖励或主人状态，只用后续自发回看率验证“观察别人的空间”本身是否有价值。

### 5.2 循环层级

| 循环 | 周期 | 决策 | 即时反馈 | 回注 |
|---|---:|---|---|---|
| 原子劳作 | 5-20 秒 | 清理、翻土、播种、天气照料或收获 | 手势、Avatar 动作、土地和作物变化 | 作物进入下一状态 |
| 农场循环 | 3-5 分钟 | 九格种什么、收获用于什么 | 库存、金币、料理或关系物品 | 改变下一轮种植和用途 |
| 生活循环 | 每活跃日 8-13 分钟 | 今天见谁、去哪个地点 | 对话、请求、地点记忆 | 改变居民后续事件和庭院材料 |
| 访问支线 | 2-4 分钟 | D4 首次引导必做；此后想看哪名耕作者的农场 | 空间与主人表达 | 只形成回看动机，不进入经济 |
| 首周循环 | 7 个活跃日 | 工具还是扩地、收获如何分配 | 苗圃入口竣工、合照和周报 | 打开下一周目标 |

### 5.3 每日会话

目标玩家每天一次主会话即可完成核心进度：

1. 查看今日田况和成熟状态，约 20 秒。
2. 移动并完成收获、播种和本轮天气照料，约 90-150 秒。
3. 决定收获用途，约 45-90 秒。
4. 从地图进入一项人物或地点内容，约 2-5 分钟；D4 用首次访问替代普通地点内容。
5. 查看下一次成熟与下一目标，约 20 秒。

第二次打开只提供额外收获、布置、对话和自愿访问。除 D4 首次引导外，访问不成为主线、金币安全线或周结算的必要条件。

### 5.4 轻经营的唯一核心题

每批收获只有四个方向：

| 用途 | 主要回报 | 放弃什么 |
|---|---|---|
| 自助摊出售 | 稳定金币 | 人物和项目用途 |
| 居民请求或赠礼 | 关系和故事 | 即时金币 |
| 料理 | 组合用途、人物反馈和手账 | 两种原料的灵活性 |
| 四季庭院贡献 | 永久地区变化 | 个人工具与扩地速度 |

访客不能参与主人的任何资源循环，也不能通过拜访获得额外货币。

## 6. 种田、劳作与天气

### 6.1 田地规模

- 初始 9 格，分成三个稳定田畦。
- 首周可选择扩建至 12 格。
- 第一经营章远期上限 16 格；第一农场年建议上限 24 格。
- 每次扩地必须同步提供覆盖更多格的工具路线，不能只扩大重复点击。
- 所有蓝图的田格和解锁数量完全一致，差异只在空间排布和环境表达。

### 6.2 作物状态

```text
荒地 -> 清理 -> 翻土 -> 播种 -> 待本轮天气照料
-> 连续生长 -> 成熟 -> 收获
             \-> 可选追加照料 -> 精心标记
```

- 每轮作物只有一次必需照料和至多一次可选品质动作。必需照料在播种后立即出现，并绑定播种时的今日田况。
- 未完成基础照料时停在起点且不开始成长；完成后从该时刻连续计时到成熟，中途不再设置离线门槛。
- 目标夹具要求相邻主会话间隔至少 18 小时，因此四种作物在下一次主会话前均已成熟。提前返回只会看到剩余时间，不会伪造收获。
- 成熟作物永久停留，不腐坏、不在换日时清除。
- 杂草只占空格，不覆盖已种作物。
- 普通与精心作物售价和基础产量相同；精心只影响手账、料理表现和居民反馈。

### 6.3 MVP 劳作动作

| 行为 | 手势 | 点按替代 |
|---|---|---|
| 清理 | 短滑拔草或扫开小石 | 逐个点按目标 |
| 翻土 | 沿一个田畦横向滑动 | 点按单格 |
| 播种 | 选择种子后扫过空格 | 点按单格确认 |
| 天气照料 | 按住并拖动水流、疏水线或覆盖物 | 选择田畦后一键播放逐格动作 |
| 收获 | 连续滑过成熟作物 | 点按成熟作物 |

基础工具允许连续拖动，但每格仍逐个判定并播放动作。点按替代可以选中整畦，却仍按三格顺序播放并占用同等劳作时间。240 金币行级工具让翻土、天气照料和收获一次覆盖同一田畦的 3 格；播种仍由玩家选择种子并拖动，避免工具替玩家做经营决定。它不提高产量或缩短成长时间。

D5-D6 分支农活时长使用同一批任务和同一蓝图测量，菜单、对话与转场不计入：

| 路线 | 可用田格 | 预期 P50 | 验收 P75 | 玩家得到什么 |
|---|---:|---:|---:|---|
| 基础工具 | 9 | 95-105 秒 | 不超过 120 秒 | 基准劳作过程 |
| 行级工具 | 9 | 65-75 秒 | 不超过 90 秒 | 少约 30 秒和逐格重复动作 |
| 基础工具扩地 | 12 | 115-125 秒 | 不超过 145 秒 | 多 33% 种植容量，但主动操作更长 |

因此首周选择是“固定产量、较省时间”与“更高容量、保留更多劳作”之间的取舍。若真机测试无法让至少 70% 玩家感知工具省时，先调整动作覆盖和价格，不给工具增加隐藏产量倍率。

### 6.4 四种作物

| 作物 | 成长时间 | 种子价 | 每株产量 | 单价 | MVP 作用 |
|---|---:|---:|---:|---:|---|
| 小萝卜 R | 4 小时 | 4 | 1 | 8 | 教学、快速出售、第一份赠礼 |
| 生菜 L | 8 小时 | 6 | 1 | 12 | 雨天照料、蔬菜沙拉 |
| 胡萝卜 C | 12 小时 | 8 | 1 | 16 | 沙拉、居民请求、庭院 |
| 洋甘菊 H | 18 小时 | 10 | 1 | 19 | 风天照料、花草茶、庭院 |

只有 D0 首次播种的 6 株教学小萝卜使用 3 分钟成长特例；完成首次收获后，所有小萝卜恢复 4 小时正式参数。

小萝卜的较高单位时间收益必须用更高操作频率换取。自助摊每个 `player_day_id` 最多按固定价收购 100 金币，达到预算后产物留在库存且不降价；居民请求不占该预算。目标表七日使用 381/700 的摊位预算；即使先把六份生活选择物全部多卖 71 金币，剩余 248 毛收入也至少需要 124 种子成本，高频路线相对目标最多多约 195 净金币。以“钱包 + 已购成长资产原价”计算七日期末账户价值，两条目标路线均为 545，高频理论上限约 740，即 1.36 倍；实测 P90 不得超过 1.8 倍，否则调整收购预算、售价或成长时间。

### 6.5 两道料理

- 蔬菜沙拉：`1C + 1L`。
- 洋甘菊茶：`1H`。

料理是一次 10-20 秒的生活交互，不设置设备队列、燃料、失败率或加工吞吐。首次制作进入手账，此后可以快速重做。

### 6.6 天气双层模型

- **环境天气**：改变地图与场景的天空、降水、环境声和问候。
- **今日田况**：按玩家所选地区的当地 04:00 冻结到下一日，决定当天基础照料动作。

| 田况 | 农场基础动作 | 地图与居民表现 | 数值原则 |
|---|---|---|---|
| 晴 | 浇水 | 苗圃、晒种和户外对话 | 基础产量不变 |
| 雨 | 疏水、扶正叶片 | 雨棚、积水和室内事件 | 不因免浇水减少操作或增加收益 |
| 风 | 固定覆盖、扶苗 | 风来种子和修缮事件 | 不扣产量，不制造作物损失 |

MVP 主体验的受控序列为：

```text
晴 -> 雨 -> 晴 -> 晴 -> 雨 -> 风 -> 晴
```

Demo 中环境天气、田况和剧情共用这条受控序列，不同时显示可能相反的实况天气。真实天气服务只做不出现在玩家界面的 shadow log；首轮通过后再验证由实况生成次日田况。

D0 晴、D1 雨和 D5 风是固定教学/剧情槽。天气公平 QA 只轮换 D2、D3、D4、D6 的田况，并为普通对白使用等价文本；任何 QA 种子都不得改写 D0 浇水、D1 疏水与 D5 修缮的完成条件。

## 7. 成长、货币与数值

### 7.1 Avatar、玩家与居民分别如何成长

- **Avatar 没有经验和等级**：换装与动作纯粹表达身份。
- **玩家拥有园艺手账等级**：MVP 只解锁预报、提示、快捷操作和纪念表达；不增加产量、售价、体力或关系倍率，也不阻塞七日核心内容。
- **居民拥有关系阶段**：通过对话、赠礼、请求和共同事件推进；不能靠重复送礼跳过剧情条件。
- **农场拥有区块成长**：9 格到 12 格，以及苗圃入口的三状态变化。

顶栏只长期显示金币。园艺经验和关系只在手账或人物页出现，不与金币组成多货币 HUD。

### 7.2 园艺经验

| 行为 | XP | 限制 |
|---|---:|---|
| 首次清理一个可耕格 | 1 | 每格一次 |
| 收获一株作物 | 2 | 按株，不按产物数量；每个活跃日最多计 9 株 |
| 首次收获一种作物 | 8 | 每种一次 |
| 完成当天基础照料 | 15 | 当前所有已播种田格均完成本轮天气动作后，每活跃日一次 |
| 首次完成一种天气应对 | 5 | 每种田况一次 |
| 首次完成一道配方 | 10 | 每道一次 |

等级累计阈值为：

```text
Lv1 0 / Lv2 40 / Lv3 80 / Lv4 120 / Lv5 160 / Lv6 220 / Lv7 290
```

目标路径：

| 日 | 当日 XP | 累计 | 等级 | 非阻塞回报 |
|---:|---:|---:|---:|---|
| D0 | 49 | 49 | 2 | 三日预报、精心标记 |
| D1 | 46 | 95 | 3 | 已知赠礼线索高亮 |
| D2 | 33 | 128 | 4 | 种子栏预设 |
| D3 | 51 | 179 | 5 | 已做料理快速重做 |
| D4 | 51 | 230 | 6 | 行级工具与第四田畦效果预览 |
| D5 | 38 | 268 | 6 | 无等级回报；体验风天与成长选择 |
| D6 | 33 | 301 | 7 | 首周手账相框 |

上表是“每天收完目标九格”的 QA 路径，不是章节门槛。轻度完成路径可能在 D6 仅达到 Lv6，也必须能完成苗圃入口；高频玩家受每日 9 株收获 XP 上限约束，不能靠 4 小时小萝卜在同一活跃日刷穿等级。

MVP 的核心内容只按章节开放：D1 开个人请求与赠礼，D2 开胡萝卜，D3 开厨房与洋甘菊，D5 开工具/扩地选择，D6 开苗圃结算。等级可早到或晚到，但只能改变信息效率和表达，不能提前或延后这些内容。

### 7.3 金币如何产生

金币不是每日任务凭空发放，主要来自玩家已经完成的生产行为：

- 自助摊按固定价出售作物或料理；每个 `player_day_id` 最多结算 100 金币，超额物品留在库存。
- 完成有明确人物理由的居民请求。
- 首周天气故事和苗圃竣工各有一次启动补贴。

拜访、对话、登录、定位、步行、点赞和观看他人农场均不产金币。

### 7.4 金币主要消耗

- 反复消耗：种子。
- 首周永久选择：240 金币行级工具，或储蓄 400 金币扩建第四田畦。
- 可选表达：80-300 金币的农场装饰；不带属性。
- MVP 不包含路线费、加工费、维护费、仓库罚款和天气修复费。

### 7.5 首周经济守恒夹具

初始金币为 180。D0 的 6 枚教学小萝卜种子和表内其他绑定种子均为一次性剧情 Grant：种子本身不能转售、赠送或跨章囤积，种下后的收获物是正常可交易产物。

|---:|---|---|---:|---:|---:|---:|
| D0 | 6R：3R 教学回购 30，3R 出售 24 | 6R 付费；3L 绑定 | 54 | 24 | 0 | 210 |
| D1 | 6R/3L：3L 请求 45，1R 赠礼，5R 出售 40；天气故事 20 | 4R+2L 付费；3L 绑定 | 105 | 28 | 0 | 287 |
| D2 | 4R/5L：1L 赠礼，4R+4L 出售 80 | 2R+3L+2C 付费；2C 绑定 | 80 | 42 | 0 | 325 |
| D3 | 4C/3L/2R：沙拉耗 1C1L；2C1L 请求 55；1R 赠礼；1C1L1R 出售 36 | 4C+2L+1H 付费；2H 绑定 | 91 | 54 | 0 | 362 |

总账为：

```text
wallet_end = 180 + 685 - 320 - 240 = 305
```

| 来源 | 七日金额 | 占比 |
|---|---:|---:|
| 自助摊出售 | 381 | 55.6% |
| 具体居民请求 | 224 | 32.7% |
| 首周一次性补贴 | 80 | 11.7% |

金币统计中的“居民请求”包含教学回购、生活回购和施工委托；每名居民只有首个标记为 `personal_story` 的请求获得 15 点熟悉度，普通回购不会被重复刷成关系进度。

工具路线 D6 剩余 305。两条路线不依赖余额制造互斥，而是使用两个明确状态：

```text
growth_choice_intent    none | tool | field
growth_choice_purchase  none | tool | field
```

D5 选卡写入 `intent`，在付款前可改选且足以完成章节教学；原子扣款成功后才写入 `purchase`、激活资产并锁住另一项，MVP 不退款。入口只在 D5 章节开放；扩地交易会同时预留并支付本轮 12 格种子，不能买出空田后无钱播种。装饰商店在首次购买前只可预览，即使高频种萝卜攒够钱也不能绕过首周互斥锁。

目标夹具到 D5 足以支付任一路线。若玩家主动少出售、余额不足，仍可记录意向并继续章节，但资产要等攒够金币后才生效；分析中继续计入全入组分母并标记 `intent_without_purchase`，不能用贷款、剔除样本或隐藏补贴伪造购买率。

扩地分支使用同一份 D0-D4 账本，并在 D5 购买后立即实际使用新增田畦：

| 日 | 扩地分支变化 | 收获 XP | 金币计算 | 期末金币 |
|---:|---|---:|---:|---:|
| D5 | 支付 400；在原 9 格配方外多买并播种 3R，种子共 84 | 18 | `413 + 117 - 84 - 400` | 46 |
| D6 | 收获原 9 格和新增 3R；3R 额外出售 24；下一轮再买 3R，种子共 60 | 24（实际入账封顶 18） | `46 + 135 + 24 - 60` | 145 |

扩地路径 D5 累计 XP 仍为 268；D6 虽物理收获 12 株，只按每日上限计 18 收获 XP，因此最终仍为 301，不因扩地多得等级优势。

两条目标路线的 D6 期末账户价值相同：工具为 `305 + 240 = 545`，扩地为 `145 + 400 = 545`。差异只应来自省时或容量，不能来自系统暗中多发价值。

苗圃入口的首周工程配额固定为 `2C + 4H`，MVP 不设置替代兑换。D3 展示缺口后，工程篮允许玩家明确预留物品；预留物不进入一键出售、赠礼或料理候选，可主动取回但会显示竣工延后。目标夹具在 D4 提交 `1C+1H`、D5 提交 `1H`、D6 提交 `1C+2H`，提交必须原子完成。若玩家主动挪用材料，D6 章节保留且请求不过期，系统不伪造补交物。

生活优先目标路径在 D6 结算后保留 `1L`，其他当周收获均已在表内分配；出售优先路径将这份保留物一并出售。

目标表是一条“生活优先”分配路径，不是唯一答案。另一条“出售优先”分支把 D1-D6 原本用于赠礼或保留的 `1R+1L+1R+1L+1H+1L` 全部出售，七日多得 71 金币：工具路线期末 376，扩地路线期末 216；苗圃配额不变，两名完整居民仍分别以 52/50 点和共同事件达到“熟悉”，修缮师以 19 点停在“相识”。

两条分支共用场景骨架但冻结不同反馈：六次用途选择中，赠礼或保留累计至少 4 次即记为生活优先，D6 解锁两页手写手账、个性化合照站位和一条居民下周线索；0-3 次得到对应出售收入、标准合照与通用苗圃线索。每次赠礼仍即时获得针对作物的个性回应。两边都不增加产量倍率，玩家是在“更多故事表达”和“更快个人建设”之间选择，而不是为错误答案受罚。

该表是约 18-26 小时主会话间隔下的确定性 QA 夹具，不是对每名玩家的强制脚本。章节不得要求尚未成熟的单一作物；提前进入时可继续浏览和布置，项目只接受明确配额并等待成熟，不发放伪造收获。

### 7.6 经济安全线

- 任意合理选择都不能形成无种子可买的永久死锁。
- 钱包低于种满当前田畦的最低种子成本且库存不足时，每日一次提供不可交易的基础种苗包。
- 请求不罚款、不降关系、不自然过期；放弃请求不返还已消耗物品，因为提交必须原子完成。
- 收获、出售、请求领取、购买和项目提交都必须使用幂等键，重试不能复制货币或物品。
- D7 起关闭一次性金币，继续测试仅靠出售和请求能否覆盖种子。

## 8. 居民、地点与访问

### 8.1 两名完整居民和一名次要居民

| 角色 | 绑定虚构地点 | 生活主题 | MVP 内容 |
|---|---|---|---|
| 苗圃管理员 | 街角苗圃 | 种子、天气与耐心 | 2 段关键场景、1 个请求、苗圃共同活动 |
| 小馆主理人 | 社区小馆 | 食物、分享与记忆 | 2 段关键场景、1 个请求、共同备餐 |
| 修缮师 | 四季庭院 | 修复与旧物 | D5 登场、D6 合照，不制作完整个人线 |

地点是地图上的安全虚构入口，不对应现实店铺、住宅或人物实时位置。MVP 共用一套关键地点场景骨架，通过苗圃、小馆和庭院的轻量布景替换控制资产量。

### 8.2 关系阶段

长期结构保留五阶段：`初见 -> 相识 -> 熟悉 -> 信任 -> 合伙人`。MVP 只开放前三阶段：

- 初见：0-14。
- 相识：15-44，完成首次见面。
- 熟悉：45-89，且必须完成一次共同事件。

| 行为 | 熟悉度 | 限制 |
|---|---:|---|
| 当日第一次有效对话 | 2 | 每名居民每日一次 |
| 符合已知线索的赠礼 | 6 | 每名居民首周两次 |
| 完成个人请求 | 15 | MVP 每名有请求的居民一次；普通回购不计 |
| 参与共同活动 | 25 | 首周每名完整居民一次 |

赠礼不能独立解锁“熟悉”；关系奖励不能提供产量、售价、体力或掉率。

目标关系夹具：

| 日 | 苗圃管理员 | 小馆主理人 | 修缮师 | 结果 |
|---:|---:|---:|---:|---|
| D0 | 2 | - | - | 知道首周苗圃目标 |
| D1 | 10 | 17 | - | 两人完成初见，小馆主进入相识 |
| D2 | 12 | 25 | - | 玩家完成第一次有线索的赠礼 |
| D3 | 29 | 58 | - | 苗圃请求完成；小馆共同备餐后达到熟悉 |
| D4 | 29 | 58 | - | D4 不安排居民对话或赠礼，生活回购不加关系 |
| D5 | 31 | 60 | 23 | 修缮师以对话、施工午餐请求和第一份赠礼进入相识 |
| D6 | 58 | 62 | 31 | 苗圃共同活动完成，两名完整居民均熟悉 |

关系逐笔来源固定为：D1 的 `1R` 给苗圃管理员，D2 的 `1L` 和 D3 的 `1R` 给小馆主理人，D5 的 `1H` 和 D6 的 `1L` 给修缮师；D4 的 `1L` 只保留，不计关系。除 D4 外，每次表内增长均包含对应居民的当日首次对话；D1 小馆、D3 苗圃、D5 修缮师分别完成各自唯一的 `personal_story` 请求。D3 共同备餐只给小馆主理人 25 点，D6 苗圃共同活动只给苗圃管理员 25 点。

### 8.3 地图事件

MVP 不制作每日随机事件生成器，只制作五个可复现的主事件：

1. D1 雨天苗圃疏水。
2. D2 小馆主理人根据玩家“赠礼、保留或出售”的选择给出不同反馈。
3. D3 苗圃管理员在小馆提出种植请求，玩家与小馆主理人共同完成第一份沙拉。
4. D4 他人农场访问教学与苗圃入口首次清理。
5. D5 风天修缮与 D6 苗圃入口竣工。

环境对白可以按晴、雨、风做轻量修饰，但关键剧情保持手写，避免天气乘居民乘地点的内容组合爆炸。

### 8.4 异步农场访问

- Demo 的人数簇来自 `region_id` 下的预置测试账号，不声称是真实附近用户。
- 至少提供两个风格明显不同的系统农场，并复用已发布街区蓝图。
- 访问前必须经过静态预览，不允许直接从地图坐标“钻入地块”。
- 访客只可移动、观察、挥手和使用预设印章；不显示锄头、种子、收获、出售和布置工具。印章仅在访客本机播放后消失，不进入主人存档或任何收件箱。
- 访问不产生金币、XP、关系、其他任务进度或每日奖励；D4 只写入一次无奖励的 `visit_tutorial_completed` 教学事实。
- D4 的首次引导访问是 Demo 章节必做验证项；完成后，D5-D6 不再提示，所有再次访问均可选，以自发再次访问率判断价值。
- 未来真人访问只对明确选择开放的农场生效；默认权限仍为 `Only me`。

## 9. 七个活跃日内容

### 9.1 活跃日定义

- D0-D6 是七个章节活跃日，不等于连续签到，也不等于分析口径中的安装后日历 D1/D7。
- `player_day_id` 按所选城市时区与当地 04:00 边界生成；漏一天后继续未完成章节。
- 每个 `player_day_id` 最多激活一个新章节，不把多天教学堆到一次回归中。
- 作物成长由权威时间推进，章节不因改设备时区而提前。
- QA 构建提供明确标识的时间倍率和指定天气种子，不能混入正式测试数据。

### 9.2 七日逐日设计

除特别说明外，每日农场内容都以“收获上一轮 -> 分配用途 -> 播种下一轮 -> 完成本轮天气照料”收口；下表只强调当天新增内容，精确播种组成以 §7.5 为 QA 基线。

| 日 | 唯一重点 | 农场内容 | 地图、居民与访问 | 永久结果 | 核心时长 |
|---:|---|---|---|---|---:|
| D0 | 两层空间与基础劳作 | 从三个蓝图选一个；自由移动；完成 6R 教学轮；首次收获后再播并照料次日 9 格 | 认识苗圃管理员；看到完整四季庭院蓝图 | 创建独立农场；苗圃入口保持荒废 | 15-18 分钟 |
| D1 | 天气改变劳动 | 雨天以疏水和扶叶替代浇水；完成一轮收种 | 从地图进入苗圃地点；决定赠送、保留或出售 1R 并说明用途；认识小馆主理人并完成第一请求 | 获得苗圃所需作物线索 | 8-11 分钟 |
| D2 | 收获的四种用途 | 章节开放胡萝卜；在出售、赠礼、料理预留和庭院预留间取舍 | 根据地图找到小馆；第二名居民记住玩家的用途选择 | 苗圃入口显示明确缺口 | 9-12 分钟 |
| D3 | 料理 | 章节开放厨房与洋甘菊；第一份蔬菜沙拉在共同备餐中完成 | 苗圃管理员在小馆提出个人请求，两名居民进入同一场景 | 料理与人物需求首次闭环 | 10-13 分钟 |
| D4 | 他人农场访问 | 完成当天对应的常规照料，制作洋甘菊茶并提交第一批工程材料 | 人数簇 -> 角色列表 -> 静态预览 -> 只读访问 -> 恢复地图；不再叠加居民对话或共同事件 | 苗圃入口从荒废变为已清理 | 9-12 分钟 |
| D5 | 成长路线选择 | 风天固定覆盖；目标夹具当日购买 240 工具或 400 第四田畦 | 修缮师登场；选择苗圃入口两种等价值外观 | 记录 `intent`；目标夹具付款后写入 `purchase` 并立即生效 | 10-13 分钟 |
| D6 | 周结算 | 收获代表作物、完成下一轮播种，不强制清空库存 | 庭院共同场景、两名居民反馈、合照、地图前后对比 | 苗圃入口竣工；显示第二周目标 | 14-17 分钟 |

核心主动内容合计 **75-96 分钟**。可选对话、布置、手账和额外访问为 **25-40 分钟**，完整七日体验预算为 **100-136 分钟**。后台成长等待、成熟后停留和重复短作物不计为内容时长。

可选预算只来自已制作内容：居民分支回应 6-9 分钟、6 件初始摆件的布置与合照调整 8-12 分钟、手账/预报/地图前后对比 5-7 分钟、两个预置农场的额外访问 6-12 分钟。重复收萝卜和纯等待不用于凑时长。

### 9.3 每日完成条件

| 日 | 最小完成事实 | 不得作为完成条件 |
|---:|---|---|
| D0 | 农场创建、首次收获、次日批次播种并照料 | 定位授权、命名、换装 |
| D1 | 完成一次雨天基础照料和居民请求 | 第二次登录、精心品质 |
| D2 | 完成一次资源用途选择并让第二名居民记住它 | 清空当日全部作物 |
| D3 | 在共同备餐中首次制作沙拉并完成苗圃请求 | 达到指定钱包余额 |
| D4 | 完成一次完整访问返回并提交第一批工程材料 | 在访客农场互动或获得奖励 |
| D5 | 确认工具/扩地互斥方向并完成风天照料 | 同时购买两项、为选项补发隐藏金币 |
| D6 | 交齐工程篮中 `2C+4H` 配额、完成共同场景 | 番茄等未进入 MVP 的指定作物 |

### 9.4 D6 玩家状态

目标玩家应拥有：

- 一个可从街区轮廓辨认的独立私人农场。
- 目标经济路径拥有“9 格 + 行级工具”或“12 格 + 基础工具”；余额不足的最小完成路径至少记录一个未付款 `intent`，并把购买留作明确下一目标。
- 四种作物的种植记录和两道料理记录。
- 两名达到“熟悉”的完整居民及其地点记忆。
- 至少一次因天气改变劳作动作的记录，以及一次影响种植/用途的选择。
- 一次完整、无经济奖励的他人农场拜访。
- 荒废到竣工的苗圃入口变化、合照和下一周明确目标。

### 9.5 内容量清单

玩家实际可接触的首周内容只有：

- 7 个章节主目标。
- 4 种作物、2 道料理、5 个基础劳作动作。
- 2 名完整居民各 2 段关键场景；1 名次要居民 1 段登场。
- 5 个固定地图事件，不建设随机事件生成器。
- 3 种天气照料与环境包。
- 1 个地区项目、3 个视觉状态、2 个等价值外观结局。
- 1 次引导访问、2 个预置访客农场。
- 1 张合照的标准/个性站位、1 份首周手账和 1 个下一周预告。

## 10. 信息架构与首次体验

### 10.1 一级导航

| 入口 | 核心任务 | 空间属性 |
|---|---|---|
| 地图 | 看天气、找居民、看庭院、选择其他耕作者 | 第一层空间 |
| 农场 | 进入自己的独立实例，劳作、料理和布置 | 第二层快捷入口 |
| 手账 | 作物、关系、地点记忆、园艺等级和周目标 | 非空间 UI |

三个 Tab 不代表三层地图。他人农场与关键地点均从生活地图进入第二层实例。

### 10.2 首次八分钟

1. 进入选择页，地图展示当前 Demo 城市和三个候选街区。
2. 点选候选时，同源高亮与农场缩略图同时变化；三个候选容量完全相同。
3. 确认后缩略卡扩展为全屏，地图元素淡出，进入独立农场。
4. Avatar 自由移动，完成清理、翻土、播种和晴天浇水。
5. 教学萝卜 3 分钟成熟，等待期间查看四季庭院蓝图或调整 Avatar 形象。
6. 玩家亲手收获并看到第一份居民来信。

八分钟节点只完成第一次“看见地图到亲手收获”的承诺；D0 剩余时间继续完成用途分配，并播下、照料 D1 所需的 9 格作物。

不得出现“田地从现实道路上长出来”、现实地块围栏、房屋入口对齐或播种坐标回写地图。

### 10.3 返回状态

从农场或地点返回地图时必须恢复：

- 原地图中心和内部相机状态；对玩家可见的 `street_zoom/pitch/bearing` 始终保持城市固定值。
- 原选中角色与横向列表滚动位置。
- 原底部预览开合状态；返回按钮可以直接关闭预览。
- 玩家进入实例前看到的地图天气和节点状态。

因内存压力无法保留视图时，也必须从持久化 UI state 重建等价状态，不能回到默认城市中心。

### 10.4 视觉基线

- 生活地图沿用当前浅色 Mapbox Streets，并使用城市配置中固定的 45° 俯视和正北朝上。
- Avatar 沿用 3.5-4 头身 DonutAvatar、黑色椭圆眼、玩具感 PBR 和圆形投影。
- HUD 使用白色、薄荷绿、珊瑚色，保持紧凑移动端信息层级。
- 真机重点验收比例为 1080x2344，同时覆盖其他安全区和窄屏。
- 农场是低模、平涂、均匀日光的可玩场景，不使用写实欧洲街区、电影雨夜、景深或复杂材质。
- 缩略图与最终农场必须复用同一布局和标志物，不能独立重画后发生漂移。

## 11. 系统与数据边界

### 11.1 最小实体

| 实体 | 核心字段 | 所有权 |
|---|---|---|
| `region` | `region_id/city/timezone/weather_key` | 地区目录 |
| `geo_candidate` | `region_id/layout_patch_id/source_revision/map_bounds/preview/active_blueprint_revision` | 受保护地理目录 |
| `farm_blueprint` | `layout_patch_id/revision/checksum/blocks/paths/masks/anchors` | 只读玩法模板，主键为 `layout_patch_id + revision` |
| `farm_instance` | `farm_instance_id/owner_id/layout_patch_id/blueprint_revision/seed/state_version` | 玩家私有状态 |
| `crop_cell` | `cell_id/crop/state/care_state/care_weather/ready_at` | 玩家私有状态 |
| `resident_state` | `resident_id/relation_stage/points/story_flags` | 玩家私有状态 |
| `growth_choice_state` | `intent/purchase/locked_at/transaction_id` | 玩家私有状态 |
| `farm_snapshot` | `farm_instance_id/revision/visible_props/weather_snapshot` | 只读访问数据 |
| `chapter_state` | `player_day_id/chapter/status/step_flags` | 章节进度 |

`geo_candidate.layout_patch_id` 与同 revision 的 `farm_blueprint.layout_patch_id` 为 1:1 编译关系；实例通过 `layout_patch_id + blueprint_revision` 唯一定位冻结蓝图。地图业务、蓝图与玩家状态不能混在同一结构中。作物和摆件记录稳定 `cell_id/anchor_id + 本地量化偏移`，不记录真实经纬度。

### 11.2 权威状态

- 作物计时、钱包、库存、购买、项目提交和关系进度由同一权威状态层处理。
- `ready_at` 在本轮必需照料成功时才按作物时长写入；播种但未照料的田格保持 `ready_at = null`，避免离线跨日后错误补算成熟。
- Demo 可以使用轻量服务或确定性本地存档，但接口必须保留幂等键、版本号和服务端时间语义。
- 客户端动画不是章节完成事实；重启后根据资产和状态恢复到下一可行动作。
- 农场访问读取版本化快照，不直接读取或锁住主人的在线场景。
- 地图不可用时农场仍可进入；D4 所需的两个系统农场快照随包提供，远端访问不可用时自动使用本地快照，不能阻塞七日主线。

### 11.3 位置与隐私

- 默认手选城市，不在启动时弹定位权限。
- 主动选择“使用当前城市”时只请求一次前台大致位置，确认后停止订阅。
- 不保存设备原始 fix、住宅关联、轨迹和最近真实到访时间。
- `owner_id -> layout_patch_id` 仍按位置数据保护，不能写入普通分析、崩溃日志或公开资料。
- 精确道路拓扑可能被反向匹配；MVP 只提供公共候选模板，让多名玩家共享，并在访客数据中删除城市、街名和坐标。
- 分享截图默认隐藏地图街名、精确地点和位置元数据。

### 11.4 数据与许可

- Mapbox 展示许可不自动等于可以抽取 Streets 特征并永久制作为游戏资产。
- Demo 蓝图使用冻结、来源可追踪并经许可确认的数据；保存 `source/license/revision`。
- 公共 Overpass 只可用于一次性开发抓取，不作为生产运行时依赖。
- 中国大陆发行需要重新评估持证地图供应商、坐标系、审图与互联网地图资质，不能只增加 WGS84/GCJ-02 转换。

### 11.5 移动端表现实现

- 地面、道路和不可变边界使用预生成静态 Mesh。
- 作物和重复装饰按材质与成长阶段使用 MultiMesh 或实例池。
- 种植、摆放和交互以逻辑 mask 为权威，渲染 Mesh 不承载玩法状态。
- 移动优先使用预计算网格/AStar；不在手机上为每个蓝图重新烘焙复杂 NavMesh。
- 边界使用少量合并碰撞体，不为每格创建独立 `StaticBody3D`。
- iOS 当前 PoC 桥只传小指令；地图候选数据应按蓝图 ID 从本地资源加载，不通过 UDP 发送大段 GeoJSON。

## 12. 制作范围与顺序

### 12.1 MVP 资产预算

| 类型 | 数量 |
|---|---:|
| 城市地图配置 | 1 |
| 街区蓝图与农场地表 | 3 + 1 安全降级 |
| 自家农场可玩实例 | 3 个蓝图共用 1 套系统 |
| 预置访客农场 | 2 |
| 作物 | 4 种 x 4 个可见阶段 |
| 天气表现 | 晴、雨、风 3 套 |
| 完整居民 | 2 |
| 次要居民 | 1 |
| 地点实例骨架 | 1 套，3 种轻布景 |
| 料理 | 2 |
| 初始可布置摆件 | 6 件，共用现有交互与材质 |
| 苗圃入口 | 3 个状态 x 2 个竣工外观 |
| 七日关键场景 | 5 个地图/地点事件 + 1 个结算场景 |

### 12.2 制作 Gate 顺序

1. **G0 蓝图证明**：三个候选地图高亮与三个可漫游农场灰盒，先验证识别、公平和可达。
2. **G1 劳作证明**：一个蓝图、九格田、三种作物、晴雨照料和完整作物状态机。
3. **G2 访问骨架**：本地预置人数簇、预览、只读实例、权限和返回恢复；先提供 D4 可用步骤。
4. **G3 七日纵切**：四作物、两料理、两居民、经济夹具、苗圃三状态，并接入完整访问表现。
5. **G4 真机整合**：三个蓝图、三天气、完整 D0-D6、弱网/恢复和 Android/iOS 一致性。

不得先批量制作居民、季节或装饰，再补蓝图与劳作核心。

## 13. 验证 Gate

Gate 0 使用 12-15 名首次接触项目的目标玩家做形成性测试。Gate 1-4 使用至少 30 名新的纵向测试者；除明确写“D6 完成者”外，行为比例均以所有到达该功能且技术可用的入组玩家为分母，并同时报告全入组 ITT。D6 有效完成者少于 18 人时不得给出 Go 结论，也不得用“只看幸存者”掩盖流失。

### Gate 0：空间概念是否成立

使用 12-15 名目标玩家测试地图选择、三个农场灰盒和一次访问流程。

- 至少 80% 能把农场正确匹配到所选街区轮廓。
- 至少 80% 能说出“地图负责选择，农场是独立场景”。
- 将其理解为现实土地所有权者不超过 2 人。
- 将 Avatar 理解为属性工人者不超过 2 人。
- 三蓝图所有关键点可达，移动与九格劳作 P75 差异低于 10%。

不通过时先修改蓝图抽象和转场，不增加教学文字。

### Gate 1：劳作是否值得重复

- 至少 80% 无额外提示完成移动、翻土、播种、照料和收获。
- 9 格基础农活 P75 不超过 120 秒。
- 至少 70% 在第一次收获后主动再种一轮。
- 至少 80% 理解未照料只会安全暂停，并能让作物恢复成长。
- 点按替代可以完成全部核心行为。
- 描述为“清任务、逐格点完、打卡”的测试者低于 20%。

### Gate 2：七日循环是否自洽

- 至少 60% 全入组玩家在安装后 10 个自然日内完成 D6；未付款 `intent` 仍算章节完成，但单独报告购买转化。
- 目标路径钱包、库存、绑定种子和工程物品守恒错误为 0。
- 工具路线必须得到 D6 钱包 305；扩地路线必须在 D5 播满 12 格、D6 实际收满 12 格并得到钱包 145。
- 生活优先和出售优先两条分配路径都必须交齐 `2C+4H`，且两名完整居民均达到“熟悉”。
- 行级工具 9 格农活 P75 不超过 90 秒，基础工具 12 格 P75 不超过 145 秒；至少 70% 能说出“省时”与“容量”的路线差异。
- 明示金币差和故事差后，生活优先/出售优先两路各至少有 20% 选择，且至少 60% 能复述自己放弃了什么。
- 轻度每日一次打开路径不会破产、卡请求或卡苗圃竣工。
- 至少 30% 的有效活跃日出现因天气改变照料或种植选择。
- 至少两个活跃日出现“看地图 -> 选择人物/地点 -> 改变农场用途”的完整链。
- D6 完成者中至少 60% 能无提示说出两名居民及其地点差异。
- D6 完成者中至少 50% 能复述一次“出售还是保留”的真实取舍。
- 在固定 D0 晴、D1 雨、D5 风，只轮换 D2、D3、D4、D6 田况的 QA 矩阵中，七日金币、关系和项目完成率差异低于 5%。
- 轻度路径未达到目标等级时仍能完成核心章节；高频萝卜路径不能提前打开后续章节内容。
- 每日 1/2/3 次会话模拟均通过种子与摊位预算守恒；高频“钱包 + 成长资产原价”P90 不超过目标值 545 的 1.8 倍。

### Gate 3：访问是否增加价值而不制造误解

- 至少 80% 能理解预览属于选中玩家，而不是 Avatar 脚下的现实地块。
- 至少 90% 能判断自己处于访客态，并知道不能收获或布置。
- 引导访问后，至少 30% 在 D5-D6 自发再次打开其他农场。
- 访问退出后地图中心、固定 `street_zoom`、选中角色和列表位置恢复成功率为 100%。
- 未授权资源修改、主人状态推进、重复奖励和自由文本输入均为 0。

若访问记忆明显高于蓝图和种田记忆，先把访问推迟到第二周，不用奖励强行提高使用率。

### Gate 4：是否值得制作第二周

D6 结算不额外发强制通知，观察下一次自然打开，并进行结算访谈：

- 至少 50% 能明确选择“扩地、工具、居民、苗圃”中的一个下一目标。
- 至少 40% 主动查看苗圃下一阶段或某名居民的下一段线索。
- 日历 D7 回访与章节 D6 完成分别记录，禁止混为同一留存指标。
- 若玩家只记得领取金币、访问别人或地图画面，而不记得劳作、关系和蓝图映射，不批准第二周内容。

## 14. 对抗性风险与处理

| 风险 | 失败信号 | 优先处理 |
|---|---|---|
| 地图只是农场皮肤 | 玩家认不出所选蓝图，或地图选择不影响记忆 | 停止扩城，重做蓝图映射和转场 |
| 现实拓扑破坏可玩性 | 窄路、远田、异形区块使劳作变慢 | 淘汰候选、简化拓扑、统一玩法 mask |
| 劳作第三天变家务 | 重复点击、P75 超时、主动再种率低 | 先重做手势与工具覆盖，不增加作物 |
| 天气只是特效 | 玩家说不出天气改变什么 | 让天气替换必要动作和地图事件，不加产量倍率 |
| 天气制造地区阶级 | 某天气序列收益或时长明显更优 | 调整等价动作与机会，保持核心差异低于 5% |
| NPC 退化为订单牌 | 玩家只用“要什么东西”区分角色 | 增加共同场景和选择记忆，减少请求数量 |
| 访问抢走核心循环 | 玩家只看别人，不关心自己的农场 | 延后访问，不加访问奖励和社交数值 |
| 访问产生骚扰或盗取误解 | 玩家寻找聊天、偷菜、点赞奖励 | 收紧只读表现，默认关闭真人访问 |
| 精确拓扑泄露位置 | 访客能反查玩家选择地点 | 使用公共共享模板，删除访客地理元数据 |
| 地图更新破坏老存档 | 道路更新后摆件、田格漂移 | 冻结 revision，绝不自动重生成 |
| 数据许可不允许衍生 | 无法确认蓝图持久化权利 | 暂停发布该数据源，不用客户端缓存规避 |
| MVP 被全年内容拖垮 | 团队开始制作六居民、四季和随机事件 | 只按 §12 资产预算排期，Gate 通过后再追加 |

## 15. MVP 后北极星

只有全部 MVP Gate 通过，才进入以下假设：

| 经营章 | 四季庭院区域 | 主要生活主题 |
|---|---|---|
| 新芽 | 苗圃 | 学会天气、认识第一批居民 |
| 盛长 | 水景与凉亭 | 花草、共同活动与第一次分歧 |
| 丰收 | 公共厨房与小集市 | 料理、分享与跨居民事件 |
| 归藏 | 温室与公共客厅 | 回顾承诺、年册和年终庆典 |

长期可增加六名居民、16/24 格农场、更多城市蓝图、真实天气田况和经批准的好友访问，但以下原则不变：

- 两层可见空间不增加。
- 私人农场仍是独立实例。
- 街区只提供拓扑与生活语境，不提供经济优势或现实产权。
- Avatar 仍然没有生产属性。
- 访问仍不能破坏主人资产。
- 物流、生产线和吞吐优化不重新成为核心。

最终 Go/No-Go 判断只有一句：

> 玩家是否因为农场确实继承了自己选择的街区、天气真的改变了劳作、地图上的人和地方留下了记忆，而比普通移动端种田游戏更愿意回来继续生活。
