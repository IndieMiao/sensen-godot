# P1 出口 · 模拟器全套复跑（sim_p1.py）

方案 v2 §17.3.2 的 P1 出口（q(155)：功能完成 + 模拟器全套复跑）里「节奏」「账本」「公平」三行的模拟器判定。结果在同目录 `out_p1.md`：第 1–6 节与第 8 节「结论」由 `sim_p1.py` 写，第 7 节「旋钮对照」由 `knobs_p1.py` 插在结论之前。

## 怎么跑

```
python3 -B docs/product/research/gameplay-plan-v2-2026-10-02/p1-exit-2026-10-13/sim_p1.py
python3 -B docs/product/research/gameplay-plan-v2-2026-10-02/p1-exit-2026-10-13/knobs_p1.py
```

两条按顺序跑（第一条覆盖写 `out_p1.md`，第二条把第 7 节插回去），默认 120 天 × 12 seed，合计约 4 分钟。其他参数：`--seeds 6`（快一点）、`--only main`（sim_p1 只跑主表）、`--md 路径`。只用 Python 标准库；两个脚本都设了 `sys.dont_write_bytecode`，不会在旧模拟器目录里留 `__pycache__`。

**出口主表的口径（10-13 李白定）**
- 基线田数 = Homestead **Lv7 起 48 格**（`BASE_LADDER`；q(172) 已提出，待批），现数据 40 格并列一列作对照；第 4–6 节也按这个基线跑。
- 判定照 sim_v3 的约定：两轨与 Cooking 21 ± 5 看 **P30**（34 竿），P30C 参考；Homestead 看 **HEAVY 与 P30C**；中界看 **P5 / P30 / HEAVY**，P30C 参考。
- **金币去向的记账按方案 §9.15.1 分类表**：蚯蚓归 A（必需），亮片（6 × ≤ 10 / 日）归 C（日常可选）；分类表里「蚯蚓 + 亮片 | A / C」指蚯蚓 A、亮片 C。sim_v3 把整笔鱼饵算进 A，这里拆成 `bait`（蚯蚓）与 `lure`（亮片）两笔；第 7 节与结论里另列旧口径（亮片算 A）的数作对照。

## 建模了什么

做法是 `import sim_v3`（round3 第 15 章的全量模型），用子类 `P1Player` 覆盖，换成 P1 的真实数据与口径；`sim_v3.py`、`p0_v1.py`、`p1_step1.py` 一行没改。

**全部从数据读**：`assets/p0/p0_content.json` + `assets/p0/content/*.json`，按文件名合并，规则同服务端 `mergeContentDir`（对象按键合并、带 id 的数组按 id 追加、冲突即报错）。

## 简化（读数时记住）

1. **S1 玩家行为是 sim_v3 的画像**：会话时刻、每日播种体力 / 竿数 / 锅数 / 矿洞局、"均衡 / 轻量"购买、选种（等级差优先、每体力净金币排序）与选菜（追 XP）都照旧。P1 新东西的买法是我定的：洒水器按"盖满露天一年生"建（40 格时 6–7 台）、温室有钱有料就建、果园默认 4 株（苹果 2 + 柑橘 + 葡萄，够做茶）、配方卡有钱就买未发现页、重度买齐摆件。**偏向**：均衡画像什么都买，金币去向的上界偏高；真玩家可能不建那么多洒水器（见田数表里的"按两座温室规划"）。
2. **S2 钓鱼不模拟小游戏**：成功率仍是 sim_v3 的手感常数（90 / 80 / 72 / 62%），渔场按等级固定（Lv4 River、Lv5 起 Coast）。**偏向**：实际成功率高低直接平移两轨与金币。
3. **S3 田块只按三类计数**：洒水器覆盖与温室块按真实 8 × 5 格网算（温室固定在左右两个 4 × 4 锚点、树种在最下最右），但作物不跟踪具体格子；扩田变体用 q(172) 的 8 格：用户定在现有田靠镜头 / 出生点一侧加一整行（网格第 −1 行，世界格 y1），超过 48 格的敏感性才在网格下方加整行。
4. **S4 委托是估算**：每天接 P5 0.5 / P30 2 / 重度 4 单，从门槛已满足、不交材料（材料留给升级）、不需外城（不旅行的画像）的模板里随机抽；收入 = 完成奖（日上限 100）− 交付物按地板价少拿的 20%（作物 / 鱼按单价估）+ 料理单按料理地板价约 3 / 件；不扣真实库存。得到 30 分钟约 50、重度约 80 金币 / 日，比 sim_v3 的常数（15 / 32）高。**偏向**：Homestead 偏快、中界偏高；敏感性表给了"sim_v3 常数"与"接满板"两端。
5. **S5 料理便利与赠餐**：居民赠餐第 10 天起每日 1 份（Familiar 的估计到达日，sim_v3 是第 5 天）；Big Pot、三口灶、Cook All、Lucky Double、熟练金区不建模（只省时间或小幅改品质）；品质用固定命中率。
6. **S6 时段 / 天气**：天气每天随机（晴 50 / 雨 30 / 风 20），时段按会话开始时刻（20:00 是夜窗、08:00 是白天）；鱼笼按 Pond 模板、不计时段天气。
7. **S7 不建模**：背包与鱼篓容量、摆件上限、仓库；矿洞战斗必胜不掉 HP；外城地区鱼沿用 sim_v3 的簇派生；Row Hoe 只省时间。
8. **S8 特产换料**：数据里 `homestead.barter.items` 现在是空的（服务端 `barterItems` 返回空 = 当前构建里换不了），主跑按 §8.4.5 补上（本带地区作物 + 本城 2 种地区鱼），"data" 模式按空表跑作对照。换料只在升级缺料时做，每级上限用服务端的算法（⌊需要量 × 0.5⌋，升级后清零）。
9. **S9 岩盐的假设（5.1 节 s1–s5，10-13 李白要求）**：`p1_config(barter=…, stall_salt=…)`。s1 岩盐也能换、和矿物一样受每级 50%；s2 岩盐能换且不受上限、矿物仍受；s3 岩盐能换、全部不设上限；s4 岩盐不能换，改成农场驿站每天卖 1 份、20 金币；s5（补充）驿站卖盐 + 矿物不设上限。买盐只为下一级缺的那几份、钱包够地板就买，记在 A 类去向（sink `salt`）。"从不下矿"画像去掉矿洞、每天种 10 格本带地区作物、换料库存各留 24 件；5 分钟画像这一节跑 240 天（照常下矿的 5 分钟玩家 120 天也到不了 Lv10）。

## 复核与数据里查到的两件事

- 默认 12 seed；6 seed 与 12 seed 的结果相差 ≤ 1 天、占比 ±2 个百分点。贴着判定线的项（P30 Cooking Lv10 约 26 天等）在两者之间可能翻 PASS / FAIL，以 12 seed 为准。
- `homestead.barter.items` 为空：服务端 `barterItems()` 返回空，当前构建里特产换料一次也换不了。
- 岩盐只有矿洞岩石与怪物掉落，没有别的来源，§8.4.5 又把它排除在换料之外；Homestead Lv2–5 每级要 3–4 件，所以从不下矿的玩家停在 Lv1。另外换料每级每种矿物 ≤ 50%，铜 / 石英的另一半也只能下矿。`out_p1.md` 5.1 节跑了 s1–s5 五种补法（见 S9），结论节写了哪一种能让 §8.4.5 那句话成立、以及照常下矿的玩家会不会因此绕过矿洞。
