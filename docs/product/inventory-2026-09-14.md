# 物品与背包

- 日期：2026-09-14。
- 对应任务：[SGODOT-112](https://plane.sensenjoy.cn/zili/browse/SGODOT-112)。
- 状态：首版已实现并完成 Godot 与模拟器功能验证；未发布，未完成自然玩家观察。证据见[验证记录](../qa/inventory-2026-09-14.md)。
- 本轮设备：Godot 桌面与 Android 模拟器。用户已取走真机。

## 目标

将矿坑、农场和街区所得统一放进可查看、整理和使用的背包。玩家能看到一份材料的数量、属性和用途，并接续已有的种植、制作、料理、布置与交付流程。

本轮沿用既有内容和物品标识。装备对应当前基础农具与整畦工具，不新增战斗、饥饿或耐久规则；角色外观继续使用已有外观系统。

## 容量与堆叠

| 项目 | 本轮规则 |
| --- | --- |
| 背包容量 | 24 格；已装备工具使用独立装备位 |
| 种子、作物、材料、矿石 | 每堆最多 99 |
| 料理、手工作品 | 每堆最多 20 |
| 工具 | 独立实例，每格 1 件，不可丢弃 |
| 合并条件 | 物品、品质、种子来源与实例属性一致；独立实例不可合并 |
| 种子来源 | 购入和绑定种子保留原有来源语义，分堆显示 |

背包提供物品详情、分类筛选、搜索、整理、拆分、指定目标合并、装备与卸下。丢弃需要确认且不能消耗工程已保留的作物。详情展示既有经济、配方或农具作用中的实际属性，不为尚未实现的系统展示虚构效果。

## 获得与消耗

普通获取超过容量时整次失败：矿石、收获物、材料点、金币成本与任务进度均保留。制作和料理先计算完整消耗，再判断产物是否能放下；输入消耗腾出的格子可以放产物。

旧存档超额物品以及自动进度奖励进入可见的“暂存”。暂存不丢物，仍可作为制作、料理、交付的材料，消耗优先使用暂存；整理或领取可将物品移回有空位的背包。暂存不作为普通采集的无限扩容通道。

满包时玩家可以合并、消耗、出售或确认丢弃物品腾出空间。永久工具不能丢弃，装备交换可以使用原工具所在的格子。

旅程模式的首次花箱制作也发放真实库存；庭院新增摆件扣除一件，收回返还，移动和旋转不改变数量。旧旅程存档此前拥有的免费庭院道具按既有解锁转换一次，已摆放的不重复发放，独立工作台存量另外保留。未进入旅程的旧章节模式保留原布置规则，进入旅程时再转换对应权益。

## 存档与命令

`bag` 是新的权威库存；已有 `inventory`、`journey.wood/materials/workshop.stock` 和 `tools.row_tool` 是兼容汇总。仅缺少 `bag` 的存档从旧计数转换，已存在的背包不能从过期汇总重复补发物品。

背包保存堆栈 ID、数量、品质、种子来源、实例 ID 与属性，包含独立序号。管理命令使用 `sequence`，继续由既有请求幂等与存档版本保护处理重试。领域版本升至 16，部署前需显式迁移；数据库结构版本保持 1。

## 验收边界

工程验证包括堆叠边界、跨堆消耗、拆分合并、满包回退、装备实例、幂等重试、保存恢复和旧库存迁移；客户端验证包括中文、图像、窄屏布局与四个场景的背包入口。

Godot 和模拟器操作属于开发验证。自然玩家能否独立查清材料属性与用途并完成一次使用或交付，仍需单独观察，不用自动化或开发者操作代替。
