## 玩家流程

洛杉矶、上海各提供 6 个固定的系统鱼塘。地图使用现有 POI 风格显示图标，增加“钓鱼”筛选；选中后点击“进入鱼塘”。筛选后的地点列表也能找到这些入口。入口使用独立游戏名称，不对应真实湖河。

每城都有月牙池、葫芦池、曲湾池，每种两个。生成时使用固定种子打乱三种模板的分配，结果保存为共享目录；同一地点的名字、位置、轮廓和装饰种子保持固定。地图图标由对应水面轮廓生成。不同玩家、重进、重启、拖动地图和自动切城都不重抽。

场景活动外接范围为 12 × 16 m，导航格 0.25 m，外围保留不可通行缓冲。默认正交镜头横向 7.5 m，以原有角色尺寸呈现紧凑场所；拖动约一屏可查看主要岸线，总览按钮可一次看全。自由镜头直接复用农场 ScenePan，支持惯性、双指焦点缩放、后台取消和离屏头像回位。

| 模板 | 轮廓与表现 |
| --- | --- |
| 月牙池 | 弯曲凹湾、开敞石岸和较多睡莲 |
| 葫芦池 | 大小两湾经窄水颈相连，沿岸芦苇与碎石 |
| 曲湾池 | 两端收口的 S 形水面，弯曲草岸和较少浮叶 |

水面沿用现有水底、折射光斑、涟漪和岸边反射。树木、灌木、花草复用农场资产并批量绘制；新增轮廓有对应的岸距纹理。水面、岸石、导航和服务端抛竿校验使用同一套多边形。

点击水面可以选择落点，“前往钓鱼”会选择最近的可达岸边。使用现有鱼竿装备、抛竿/提竿/收线交互、鱼种和背包。三种系统鱼塘统一使用现有街区湖泊配置，普通/优良/稀有/传说权重为 35/40/20/5；价格和难度来自原配置。原农场池塘的几何与掉落不变。

鱼塘有独立在线房间，每线 16 人；现有其他空间容量不变。鱼获进入各自背包，满包沿用溢出机制。队伍跟随可以进入队友所在鱼塘，保留原房间票据和到达前再次验证的规则。退出恢复地图位置、缩放、朝向、筛选和选中卡片。

## 固定内容与服务端契约

- [共享目录](../../assets/ponds/catalog.json)保存 12 个地点及三套导航、水域轮廓；[生成工具](../../tools/art/build_system_ponds.py)只在构建内容时使用，保留已经保存的地点。修改已存在的模板需要显式新版本。
- `GET /v1/ponds?region_id=...` 返回该城入口和目录 SHA-256。客户端只接受与本地目录一致的已登记地点。
- `join kind=pond` 验证地点 ID、目录版本和线路；服务端从自己的目录选择导航与水域，不信任客户端提供的坐标、轮廓或奖励权重。
- 钓鱼命令继续作用于玩家自己的农场账户背包；实时房间提供权威位置、鱼塘身份与连接代次。另一个鱼塘 ID、旧连接或离场后的站位不能结算。
- 目录使用独立版本，不改变既有农场领域 **27** 与经济内容哈希 **50c2dbdde04c9678**，不需要重写农场状态或历史命令。
- 本期采用预配置区域内的固定生成；不在每次浏览时动态扩展全球地点，不读取真实水域作为入口，不依赖 Search Box。

## 构建与本地复现

本地隔离服务：`pnpm --dir server exec tsx tools/system_pond_qa_server.ts`，端口 3201，使用新建测试账号和内存农场。正式包不包含该账号、服务配置或观察器。

使用 `tools/dev/prepare_system_pond_qa.gd` 准备 QA 项目；Android 安装后通过 `tools/android/run_test.sh --serial emulator-5560 com.sensen.journeypondqa -- node tools/dev/system_pond_android_qa.mjs` 完成整段验证。该过程保留模拟器原 Journey 与手机数据。

`tools/dev/prepare_system_pond_release.gd` 准备原包名、原签名、无观察器的 Journey 构建。生产需先提供新目录接口与 `pond` 房间，再发布配套客户端。新客户端连接尚未更新的服务时，不把本地目录当作已经开放的线上鱼塘。

上线时继续保留现有 `NODE_OPTIONS=--network-family-autoselection-attempt-timeout=1500`、数据库与地理服务配置。本次没有执行线上部署、公开 APK 发布或外部消息发送。
