# 地图农场：完整玩法策划与 7 日数值方案

- 日期：2026-09-03
- 版本：v1.7，七日玩法框架、可执行数值夹具与对抗性终审
- 工作名：街区农场
- 平台：移动端竖屏，Android 封闭测试优先
- 品类：真实地图驱动的轻量经营游戏

> 一句话：把熟悉的街区变成一张城市供给网络；玩家在私人农场生产，通过真实路网形状完成虚拟订单，让自己的地区地图逐步变化。Avatar 只表达“我是谁”，不决定“我能赚多少”。

关联概念图：

- 地图即土地：`output/imagegen/map-farm-land.png`
- 地图即物流：`output/imagegen/map-farm-logistics.png`
- 地图即公共世界：`output/imagegen/map-farm-community.png`

三张图是早期视觉方向，不是当前机制或 UI 规格。可以继承俯视街区、道路上的虚拟物流、经营前后环境变化和 Avatar 作为个人签名；不得照搬图中的多货币/属性倍率、Avatar 等级、现实土地占有、附近真人头像或公共贡献。前两张只作构图与可读性参考，第三张属于 Gate 3 之后的共享方向；Alpha 必须替换为仅本人可见的地区花园，实际控件与数值以本文为准。

## 0. 执行摘要

### 0.1 推荐方向

采用“空间经营”作为唯一主假设，而不是把三张概念图做成三个互不相干的模式：

1. **地图层负责发现和选择**：显示经营区域、需求市场、加工站、配送站和个人地区花园。
2. **私人农场负责生产**：种植、收获、加工、库存和扩建都发生在私人实例中。
3. **物流层负责取舍**：订单连接地图节点；Alpha 使用归一化距离档、当前物流队列和玩家下次回访时间形成路线题，真实路网的走廊与拓扑规则只记录、不在验证前夸大；合单和走廊效率只在第二周验证。
4. **地图变化负责周与赛季目标**：Alpha 只展示玩家自己的地区修复进度；共享公共工程必须等核心循环和隐私 Gate 通过后再立项。
5. **Avatar 只负责身份表达**：头像、农场迎宾、个人结算动作和换装；不带等级、产能、速度、掉率或工人功能，公共地图不展示可识别账号。

核心循环为：

`地图发现需求 -> 农场安排生产 -> 必要时加工 -> 选择物流路线 -> 订单结算 -> 扩建与个人地图变化 -> 地图产生新需求`

### 0.2 这个项目成立的唯一理由

传统农场游戏在内容深度、装饰数量和成熟经济上天然更强；传统地图产品在检索和导航上天然更高效。本项目只有在以下命题成立时才值得继续：

> 用户因为认识街道形状、地区名称和地点记忆，更愿意安排第二条供给路线、回看自己的经营区域，并对个人地图变化产生归属感。

如果拿掉真实地图后，用户的订单选择、路线选择、地区记忆和七日留存没有显著损失，就应该把地图降为表现层，甚至停止这一方向。不能用更精美的 3D 美术掩盖这个结论。

### 0.3 产品宪法

以下规则优先级高于任何单个玩法和商业需求：

- **GPS 是快捷方式，不是门票**：拒绝定位仍可获得 100% 核心货币、产能和长期进度。
- **地图是空间经营题，不是现实土地买卖**：私人农场不代表拥有某块现实土地，公共节点不可抢占、买卖或收税。
- **Avatar 纯形象**：服装、表情、载具外观和地图标记都不提供数值加成。
- **不惩罚离线**：作物不枯萎，订单失败不罚款，长时间未登录没有负收益。
- **位置不产生经济优势**：城区、郊区、无 POI、行动不便和拒绝定位玩家的期望收益一致。
- **不显示实时附近的人**：不公开他人精确位置、最近到访时间、住宅关联或实时 Avatar。
- **不用付费购买产能**：地块、仓库、加工槽、订单次数、运输速度和赛季点不可用真钱购买。

### 0.4 首周目标

首周不是“把所有按钮开放”，而是让目标玩家在 7 个活跃日内完成一次完整的城市供给故事：

`建立农场 -> 学会按回访时间生产 -> 比较地图节点 -> 选择路线 -> 学会一条加工链 -> 推进个人地图变化 -> 完成首周节庆单`

候选目标为：

- 第一轮可证伪 Alpha 的**核心主动设计预算为 73 分钟**，目标玩家完成可选地图、整理和周报后的假设区间为 **104-120 分钟**；二者尚无玩家样本，Gate 2 后才报告实际 P25/P50/P75，不是已承诺时长，也不把后台等待、必要回访间隔或被章节挡住的时间计算为内容。
- 核心收益的 80% 可在每天 15 分钟、最多 3 次打开内获得。
- Alpha 包含 25 个日常订单、1 个周订单、4 种作物、1 个配方、8 个订单模板、2 种路线和个人地图三阶段变化；完整目录中的另 2 种作物、3 个配方和联运在第二周后逐步验证。
- D6 结束时接近但尚未自动获得下一次大扩建，形成自然的下一日目标。

## 1. 用户、需求与定位

### 1.1 核心用户

- 20-35 岁、城市通勤或固定生活半径用户。
- 玩过治愈养成、放置、轻种田或收集游戏。
- 每天愿意打开 2-3 次，每次 3-8 分钟；偶尔愿意进行一次 10-15 分钟规划。
- 喜欢“我的地方在慢慢变化”，但不希望被步数、连续签到、作物死亡或陌生人社交绑架。

首发建议按 **16+** 设计。不是因为玩法本身复杂，而是位置数据、公共地图和潜在社交会显著提高未成年人合规与安全成本。

### 1.2 不优先服务

- 追求多工厂、多层供应链和自由市场的硬核模拟经营玩家。
- 把长距离步行、跑步或户外打卡作为主要目标的位置游戏玩家。
- 需要实时附近社交、开放聊天或线下组队的用户。
- 期待一周内持续数小时无等待内容的重度玩家。

### 1.3 用户任务

| 层级 | 用户任务 | 产品回答 |
|---|---|---|
| 30 秒 | 我现在能做一点什么 | 收获、重种、领取运输、选择下一批 |
| 3 分钟 | 我想让今天有明确进度 | 完成一个订单，调整库存和加工队列 |
| 10 分钟 | 我想做一次有取舍的规划 | 比较节点需求、生产时长和物流方案 |
| 一天 | 我想在不被打扰的情况下持续成长 | 2-3 次短会话完成主要经济价值 |
| 一周 | 我想看到经营造成的变化 | 完成节庆单和个人地区花园阶段，获得周报与外观 |
| 长期 | 我想积累地点记忆与个人表达 | 经营区域图鉴、地图变化、农场主题和 Avatar 换装 |

### 1.4 对替代品的差异化

| 替代品 | 它天然更强的地方 | 本产品必须证明的独占价值 |
|---|---|---|
| 传统农场游戏 | 内容量、成熟经济、装饰深度 | 熟悉街区形成可记忆的供给网络 |
| 位置游戏 | 移动、发现、现场活动 | 不要求专门走路，位置不造成收益差距 |
| 地图应用 | 搜索、导航、真实信息 | 地点能被长期经营并产生个人历史 |
| 放置游戏 | 低负担、清晰成长 | 地图带来真实的空间取舍而不增加惩罚 |

## 2. 总体玩法框架

### 2.1 四层世界模型

| 层 | 玩家看到什么 | 核心决策 | 产出 | 失败时的替代路径 |
|---|---|---|---|---|
| 城市地图 | 真实道路形状、经营区域、公共节点 | 今天服务哪些节点 | 订单、地区故事、路线题 | 地图失败时切节点网络列表 |
| 私人农场 | 6-10 个地块、作物、仓库、加工位 | 种什么、何时回来、留多少库存 | 原料和加工品 | G0-G2a 离线只读；G2b 才验证有限私有命令队列 |
| 虚拟物流 | 节点间路线、时间、费用、批量 | 首周快或免费；后续是否合单 | 订单回款和声望 | 不使用真实出行，不依赖 Directions |
| 地图变化 | Alpha 为个人地区修复；验证后才可能共享 | 如何分配周订单产能 | 周进度、故事、外观 | 关闭后不影响生产和订单 |

四层的依赖关系是单向可降级的：农场在地图不可用时仍能玩；订单在地图变化关闭时仍能结算；个人或共享地图目标都不能反过来卡住私人经营。Alpha 的第四层不是多人系统，不出现附近人数、共同贡献或分片进度。

### 2.2 玩法层级与回注

| 循环 | 周期 | 输入 | 决策 | 即时反馈 | 回注下一轮 |
|---|---:|---|---|---|---|
| 原子循环 | 20-40 秒 | 成熟作物、批次报告或空地 | 手动收种，或确认自动批次结果并调整下一计划 | 数量跳字、时间轴完成态、轻触感、Avatar 结算表情 | 新库存、空地与计划偏差改变本次订单选择 |
| 短循环 | 3-6 分钟 | 库存、订单、空加工位 | 交哪张单、生产什么、走哪条路线 | 金币、声望、节点进度 | 余额、库存和队列成为下一会话初始状态 |
| 日循环 | 2-3 次打开 | D0 固定 2 张教学单；D1 起 6 张候选；章节激活时发 D1=3、D2 起=4 配送额度 | 选择订单组合和短/中/隔夜排产 | 扩建储蓄、节点记录、个人花园值 | 日末安全库存与回访计划决定次日候选可行性 |
| 周循环 | 固定 7 个活跃日 | 周订单和个人地区项目 | 在日单与周单之间分配产能 | 地图阶段变化、周报、外观奖励 | 周结算选择“快收/均衡/夜作”，锁定下周等收益的需求权重与预报方式 |
| 赛季循环（G4 候选） | 8 周 | 主题订单、地区图鉴、收藏 | 选择经营主题和侧向合同 | 赛季结局、地图主题、Avatar/农场外观 | 选择下季的合同池与视觉主题，不增加产量倍率 |

五级循环不是五条平行任务线，而是三条相互咬合的主循环：

```text
生产循环：回访预期 -> 提交手动/批次排产 -> 收获或自动批次报告 -> 库存 -> 对照偏差后再排产
空间经营循环：地图比较 -> 接单 -> 改变排产 -> 路线 -> 回款/队列 -> 新的地图比较
长期回注循环：日单与周单 -> 个人地图变化 -> 选择下周经营方案 -> 改变下一周需求结构
```

如果某一层只发徽章或播放动画，却不改变下一轮的输入、选择或反馈，它只能称为“进度层”，不能称为循环。周与赛季回注只改变等价值的需求结构、信息预报和视觉主题，不提供产量、速度或掉率优势。

### 2.3 玩家目标栈

同一时刻只给玩家三个不同时间尺度的可见目标：

1. **现在**：一个可立即推进的订单或成熟作物。
2. **今天**：一次扩建储蓄或个人地区进度目标。
3. **本周**：一个明确的大订单和地图视觉阶段。

不得同时展示超过三个货币进度、四个任务倒计时和多套签到。复杂度来自生产与订单组合，不来自 HUD 堆叠。

### 2.4 关键策略来源

第一周只允许以下四类真正影响结果的选择：

- **时间选择**：20 分钟、60 分钟、3 小时、8 小时作物如何配合作息。
- **库存选择**：立即交单、保留原料、还是先加工以换取更高单价。
- **订单选择**：D1 起每日 6 张候选订单，先完成 3 张、D2 起完成 4 张，不能全部拿完；D0 只做固定教学闭环。
- **物流选择**：免费慢线和付费快线适用于不同回访时间；合单是第二周候选，不计入首周复杂度。

第一周不加入天气增减产、肥力、品质随机、工人属性、土地五行、社交偷菜或实时价格。它们会让问题来源不可诊断。

### 2.5 资源闭环与控制阀

这套经济只有一个可消费软货币。复杂度来自资源排程，不来自堆货币：

| 资源 | 主要来源 | 主要去向 | 控制阀 | 玩家失败保护 |
|---|---|---|---|---|
| 金币 | 日订单、周订单、受限清仓、一次性章节补贴 | 播种、加工、快线、固定价扩建、纯外观收藏 | 日配送额度、候选订单预算和清仓上限 | 基础种苗包；没有维护费和负债 |
| 原料/加工品 | 地块收获、加工完成 | 订单、周单、后续配方 | 地块、成长时间、仓库和加工位 | 不腐坏；满仓时留在产出位置 |
| 声望 | 订单和一次性章节目标 | 不消耗，只作为内容解锁条件 | 活跃日章节与订单额度 | 落后时靠常规订单追赶，不售卖加速 |
| 花园值 | 核心订单、活跃日章节、周单 | 不消耗，只触发个人地图阶段 | 每周最高 105 | 低档也能结算，不倒退 |
| 配送额度 | 每章首次激活原子发放：D0=2、D1=3、D2-D6 各 4；D7 起每个活跃日补 4，最多持有 8 | 每派发一张日订单消耗 1 | 单自然日最多使用 8；周单独立；同章重进不重发 | 漏登不会错过章节额度，不可付费购买 |

核心守恒关系为：

```text
wallet_end = wallet_start + daily_order_coin + weekly_order_coin + clearance_coin
             + chapter_coin + first_clear_coin + compensation_coin
             - planting_cost - processing_fee - route_fee
             - chosen_expansion - chosen_collectible

inventory_end = inventory_start + harvested_goods + processed_output
                - recipe_inputs - dispatched_goods - cleared_goods
```

订单是主要金币阀门：多上线可以更早准备库存，但不能绕过配送额度把短作物无限变现。仓库是计划约束，不是惩罚；满仓不得销毁、覆盖或自动折价任何产物。

### 2.6 决策因果链

每一层都必须改变下一层的选择，否则应从 Alpha 删除：

1. 地图节点改变候选需求组合，但不改变地区总收益预算。
2. 被接受的订单改变下一轮种植与安全库存。
3. 回访时间决定短作、日内作或隔夜作的地块组合。
4. 现金缺口和预计下次打开时间决定慢线或快线。
5. 订单结算推动扩地与个人地图阶段，产生下一次回看理由。

验证时不以“打开过地图”代替因果。合格事件链必须是 `比较两个节点 -> 选择需求 -> 改变后续计划`；若这条链不发生，真实地图仍只是表现层。

## 3. 地图与位置玩法

### 3.1 地图为何不可替代

地图必须同时承担三件事，否则只是昂贵背景：

1. **需求空间化**：不同公共市场展示不同订单组合，玩家需要在地图上选择经营对象。
2. **空间进入决策**：Alpha 把每个区域归约为相同数量的近、中、远节点；D2-D6 每章至少一组等收益候选必须由“节点距离档 × 当前物流队列 × 玩家下次回访时间”产生优劣反转。D0 是固定闭环、D1 只有第一市场，都不用于证明跨节点价值。`corridor_group` 与 `topology_motif` 在 Alpha 只用于记录和画面解释，是否进入合单与排程规则留到第二周验证。
3. **结果留痕**：Alpha 的个人地区目标完成后，地图叠加层发生阶段变化，形成可回看的经营历史；共享历史是 Gate 后能力。

不同地区获得相同的距离题分布和总价值预算，所以空间关系会改变“今天选哪两个节点、走快线还是慢线”，但不会让某个城市更富；合单只在第二周候选中验证。地图不承担产量倍率、稀有掉落、步行收益或他人实时位置。

三个市场在一周内保持稳定、可记忆的需求身份，例如“即时补给 / 混合采购 / 长线备货”；每日只轮换数量和组合，不把节点彻底洗牌。三种身份的周总价值和声望预算相同。玩家应逐渐记住“这个方向通常适合什么计划”，而不是每天重新阅读三张没有空间记忆的订单卡。

节点列表必须提供与地图等价的可访问性和故障降级，但“系统强制玩家从地图点进去”不计作地图价值。Alpha 要验证的是熟悉道路与地区语境是否让用户更快理解、记住并回看供给网络；若 Geo/虚构地图对照无增益，就应诚实地把真实地图降级为可选表现层。

Alpha 的路线不冒充导航：从真实路网提取的只是归一化邻接与距离档，画面可以沿道路显示示意折线；未接 Directions 前不声称是实时或可通行路线。

### 3.2 五种位置状态必须拆开

当前 PoC 中的定位、镜头、Avatar 和 Marker 共享锚点，正式产品必须拆成：

| 状态 | 含义 | 是否持久化 | 是否上传 |
|---|---|---|---|
| `device_fix` | 设备本次前台定位 | 否，只在内存短暂存在 | 默认否 |
| `view_center` | 用户正在浏览的地图中心 | 可仅存本地 | 否 |
| `operating_region_id` | 用户明确确认的经营区域，首发建议 2-5 km 级 | 是，受保护位置数据 | 是，限业务域 |
| `private_instance_anchor` | 私人农场的视觉入口 | 是，服务端生成 | 是，不可反推 GPS |
| `public_nodes` | 区域目录中的需求节点；Alpha 不承载玩家身份 | 是 | 是，自有节点数据 |

`operating_region_id` 仍然属于位置数据，不能因为没有原始经纬度就进入普通分析或公开资料。若大致位置的精度圆大于候选区域，系统只推荐城市或大区，并要求用户手动确认，不能静默落入更细网格。

私人入口可使用服务端持钥的 `HMAC(user_id, region_id)` 生成稳定的伪名化位置，但只能本人看见，只用于进入实例，不能参与路线距离、订单、分片和经济。入口跨赛季不搬家，不钉在住宅，不描画地籍边界，也不声明现实产权。

### 3.3 区域与节点结构

每个经营区域首周固定 7 个功能槽：

| 节点 | 数量 | 功能 | 首周开放 |
|---|---:|---|---|
| 私人农场入口 | 1 | 进入生产实例 | D0 |
| 市场 | 3 | 不同订单组合 | D0 开 1 个，D2 再开 2 个 |
| 加工站 | 1 | 配方故事与加工入口提示 | D4 |
| 配送站 | 1 | 路线报价与运输状态 | D3 |
| 地区花园 | 1 | Alpha 的个人周目标和阶段变化 | D4 随周单只读预览，D5 首次变化 |

G0-G3 只使用自有、名称中性的合成节点，并全部标记为仅远程。底图上的真实 POI 只作为地图视觉，不抽取、不持久化、不用作商家名称，也不暗示合作。真实 POI 节点是 Gate 3 之后的独立立项，需要重新确认许可、品牌、删除更新和安全审核。

节点不复制业务功能：市场节点是新需求的主发现与接受入口；加工站、配送站和地区花园只展示状态、故事与单一深链。播种、批次排产和加工队列的写操作统一落在农场页，路线确认统一落在订单派发底栏，领取统一落在订单页；从地图或通知进入都读取同一份服务端实体和幂等键，不生成第二张订单、第二个队列或额外奖励。地图故障时节点网络列表提供完全相同的深链。

城区、郊区和无 POI 区域采用相同功能槽、近中远距离档、网络题分布与总需求预算。首个 Alpha 的经济配置完全相同，只改变节点空间布局、视觉和订单叙事。二期即使调整订单配比，任意两地区在每种目标作息策略下的期望净收益差也必须小于 5%。

### 3.4 定位权限流程

首次进入提供平权选项：

- `选择经营区域`
- `使用当前区域`

只有点击第二项才请求前台定位，并明确大致位置已经足够；产品不为经营玩法主动升级到精确权限。大致位置只用于推荐它能可靠覆盖的区域层级；拒绝、超时、精度不足或无 GPS 时回到手选或上次区域，不显示伪造的“当前位置”。用户确认区域后立即停止定位订阅，恢复前台时不自动重定位或搬迁经营区。

精确蓝点不是核心功能。只有用户另行点击“本次显示我的位置”，系统才可解释用途并接受操作系统返回的精确 fix；该点只在本次前台内存中显示，不上传、不改变经营区和奖励。数据超过 5 分钟、离开地图或应用 pause 后立即清除。浏览其他城市不改变经营区。经营区二期允许主动切换，但至少 7 天冷却、没有重领奖励、没有第二份日额度，且未结订单先保留在原区域。

首发不做后台定位、轨迹记录、沿路收货、步数任务、随机地点任务或真实通勤加速。

### 3.5 远程和到场边界

| 行为 | 远程 | 到场 | 数值差异 |
|---|---|---|---|
| 种植、收获、加工、升级 | 完整 | 相同 | 0 |
| 查看和完成公共节点订单 | 完整 | 相同 | 0 |
| 派发和领取物流 | 完整 | 相同 | 0 |
| 推进个人地区项目；未来共享项目 | 完整 | 相同 | 0 |
| 自动推荐当前区域 | 手选替代 | 可用 | 只减少一次选择 |
| 到访纪念章 | 无 | 二期可选 | 不可交易、无属性、无排名 |

任何现场功能都必须默认为 `REMOTE_ONLY`。只有人工审核过的公共入口才能进入 `VISIT_ELIGIBLE`，且只给纪念性反馈。

### 3.6 公共节点安全状态

Alpha 所有节点固定为 `REMOTE_ONLY`。二期状态不是单向升级链：

```text
CANDIDATE --审核--> REMOTE_ONLY 或 VISIT_ELIGIBLE
REMOTE_ONLY / VISIT_ELIGIBLE --举报、过期或 kill switch--> SUSPENDED
SUSPENDED --复核--> REMOTE_ONLY / VISIT_ELIGIBLE / RETIRED
```

默认排除住宅、学校与托幼、医院与诊所、庇护所、宗教场所、军警与政府敏感设施、监狱、墓园、施工区、危险工业区、高速与铁路沿线、水中与危险岸线、悬崖和私人园区。

一次可信的危险地点举报应先关闭现场入口，再审核；远程经营不受影响。首发没有现场数值奖励，因此伪造定位的直接收益接近零。

## 4. 私人农场系统

### 4.1 基础结构

- 初始 6 个生产地块，长期上限 10 个。
- 初始仓库 80 单位，长期上限 160。
- 初始 1 个加工工作位和 2 个排队位。
- D1 开放 12 小时批次排产板；每块地最多 5 个连续步骤，服务端按计划自动换茬，玩家也可继续手动种收。
- 作物成熟后永久等待，不枯萎、不降品质。
- 播种直接消耗金币，不把“种子、水、阳光、叶子”同时做成货币。
- 收获是确定性产出，首周不使用暴击、品质和天气随机。
- 农场无法被他人偷取、破坏或占领。

### 4.2 农场的三个决策

1. **地块时间配置**：选择下次回访档，并在 12 小时排产板上确认各地块的连续批次，而不是反复回来追短倒计时。
2. **仓库配比**：在日单、加工/周单和下一次预测订单之间分货；D0-D6 以不死锁和可完成周单为准，D7-D9 先验证无章节奖励下的现金循环，只有稳态探针通过后才使用 §19.2 的成熟物资分配带。
3. **加工队列**：加工提升订单价值，但占用时间和金币；直接交原料更快但利润低。

### 4.3 地区差异的处理

不采用“真实位置哈希出向阳、湿润、热闹，并提供 +25% 产量”的方案。它会把随机住址转换为永久经济差异，也会刺激多账号找最优格。

地区可以影响以下内容，但所有选项期望价值应在 ±5% 内：

- 哪一类订单出现得更多。
- 地图与农场的视觉主题。
- 地区故事、图鉴文本和路线形状。
- 玩家可以主动选择的经营方案，例如短作、均衡、夜作。

地区不能影响总地块数、单位产量上限、金币倍率、稀有外观概率或赛季进度上限。

### 4.4 Avatar 的使用边界

Avatar 可以出现于：

- 个人资料和换装入口。
- 私人农场边缘的迎宾位。
- 完成收获、扩建和周结算时的 1-2 秒情绪动作。
- 仅本人可见的个人贡献回顾，或去除地图、地区名和节点信息后的受邀好友实例。

Avatar 不可以：

- 站在作物格上承担工人、移动单位或自动生产语义。
- 显示等级徽章、战力、效率、职业或装备属性。
- 因服装影响产量、运输、订单、体力或掉率。
- 在公共地图上表示本人或他人的实时位置。
- 在公共节点、公共贡献卡或地区榜单中把可识别头像与地点绑定。

自己的位置使用标准蓝点；Avatar 入口使用头像；两种语义不能合并。

### 4.5 生产、加工与仓库状态机

**地块**

```text
EMPTY --支付播种成本--> GROWING --服务器时间到--> MATURE
MATURE --仓库容量足够且收获成功--> EMPTY + 库存入账
MATURE --仓库容量不足--> MATURE_CAPACITY_BLOCKED --腾出容量--> MATURE
```

- 播种扣款和进入 `GROWING` 必须是同一笔原子事务；失败时不扣金币。
- `MATURE_CAPACITY_BLOCKED` 不损失产量、不降品质、不重置成熟时间，也不阻塞其他地块。
- 收获采用整批入库；Alpha 不做容易产生误解的部分收获。

**批次排产**

```text
DRAFT --校验钱包/地块/预计容量；支付全部播种费--> COMMITTED
COMMITTED --步骤到时且容量足够--> 自动收获上一批 + 启动下一批
COMMITTED --步骤到时但容量不足--> PAUSED_CAPACITY
PAUSED_CAPACITY --玩家腾出容量并确认--> COMMITTED（后续时点整体顺延）
COMMITTED --最后一步成熟且容量足够--> COMPLETED + 自动入仓
COMMITTED --最后一步成熟但容量不足--> FINAL_CAPACITY_BLOCKED
FINAL_CAPACITY_BLOCKED --玩家腾出容量并确认--> COMPLETED + 自动入仓
COMMITTED --删除尚未开始的步骤--> 退回对应已付金币
```

- D1 起玩家先选 `1-2h / 3-5h / 8-12h` 下次回访档，系统给出两张由订单、库存和周单缺口生成的排产卡；一键确认后可逐格修改，但首周不要求操作时间轴。
- G2 的 D0-D9 每块地计划包含当前批次在内最多 5 步、总跨度不超过 12 小时；稳态通过后的内容版本若解锁 18 小时南瓜，才把跨度扩为 24 小时，步数仍为 5。提交时一次性从 `wallet_coin` 扣除全部播种费，并立即按 `planting_cost` 计入重复消耗 R；后续步骤开始不再扣款。已开始步骤不可取消，未开始步骤可改或删，并在同一事务结算差额。
- 删除未开始步骤时把对应金额退回钱包并记录 `planting_cost_reversal`，该金额冲减原 R，不计入 faucet；扩建、路线和加工都只读扣款后的 `wallet_coin`，因此不存在预付后的二次占用或双扣。提交、改单、步骤开始和冲销均使用 `plan_id + plan_version + step_id` 幂等。
- `COMMITTED` 计划从当前步骤开始到最后一步结束持有对应地块的 `plot_lease`。玩家要在该地块手动播种，必须先在同一事务删除所有未开始步骤、写入负 R 冲销并递增 `plan_version`；当前步骤已经开始时只允许查看或等待成熟，不能用手动命令覆盖。这样“逐格修改”不会留下后台旧计划再次扣款或把新作物顶掉。
- 计划步骤由服务端时间推进。上一批产物容量足够时自动进入仓库并启动下一步；容量不足则产物安全留在地块，后续步骤暂停，不丢货、不补算暂停时间。订单只能扣已经入仓的货物，不能提前消费预测产出。
- 作物成熟、加工完成和容量恢复恰好落在同一服务端 tick 时，统一按 `due_at -> created_at -> stable_job_id` 排序，逐项做容量预检；先成功入仓的任务占用容量，后续任务进入各自的容量阻塞态。客户端、离散事件模拟器与服务端必须复用同一排序，禁止同一存档因重试顺序不同得到不同库存。
- `production_plan_committed` 因而是可执行命令而非愿望清单。D3 基准中的 `T+3h/T+6h/T+7h/T+8h` 换茬由同一 `plan_id` 执行，不要求玩家为每次成熟打开应用；玩家回访时领取订单、检查批次报告并作下一次取舍。
- 手动模式仍沿用上方地块状态机；Avatar 不参与自动换茬，也不出现工人、体力或效率属性。若 Gate 1 中超过 20% 用户把自动入仓理解为“无需再经营”，先缩短计划步数或改为批次确认，不增加点击假装深度。

**加工位**

```text
IDLE --原料与费用预占成功--> QUEUED -> PROCESSING
PROCESSING --服务器时间到且容量足够--> IDLE + 成品自动入账 -> 下一项 QUEUED
PROCESSING --服务器时间到但容量不足--> OUTPUT_READY
OUTPUT_READY --腾出容量并领取--> IDLE + 成品入账 -> 下一项 QUEUED
```

- 进入队列时原子扣除原料和加工费；仅 `QUEUED` 且尚未开始的任务可取消并全额退回。
- 容量足够时服务器自动入库并启动下一项，不要求玩家每 30 分钟上线；下一次打开只展示可跳过的加工报告，不再要求一次“领取”事务。只有仓库满时成品才安全停在 `OUTPUT_READY`，该工作位暂停取下一单，但成品不会丢失或被自动出售。
- 客户端倒计时只是显示，服务器决定开始、完成和退款结果。

**仓库与待领取物**

- 仓库不允许负数、覆盖和超容量写入。
- 未手动收获或因批次计划容量不足的成熟作物留在地块；加工成品仅在仓库满时留在加工位。章节赠送的实物进入无期限领取箱。金币、声望和花园值不占仓库。
- 每次可能增加库存的操作都先做容量预检，并返回“需要腾出 N 格”的可操作提示。
- 只有用户主动清仓才按受限清仓价处理；系统不能因满仓自动折价。

| 作物 | 播种成本/个 | 单格参考总值 | 单格参考毛差 | 毛差/格小时 | 6 格整批播种成本 | 数值含义 |

这里的“参考毛差”是 `单格产量 × 参考价值 - 播种成本`，不是可直接出售的利润。它刻意让短作物在理想高频操作下更高效、长作物在少回访时更省操作；订单额度、需求品类和仓库共同阻止无限刷短作。若模拟中每日 2 次打开者仍总是选择生菜或小麦，说明长作物的需求与回访价值不足，应先调订单结构，而不是继续提高番茄单价。

### 5.3 加工配方

| 配方 | 预计解锁 | 输入 | 加工费 | 时长 | 输出 | 参考价值 | 作用 |

| 面粉 | D4 | 小麦 3 | 4 | 30 分钟 | 面粉 1 | 18 | Alpha 唯一加工链 |

加工品不能无限出售，必须进入订单、周目标或受限清仓。加工的价值来自稀缺队列和订单组合，不来自无风险循环套利。

一份面粉的输入参考值为 12，现金成本为一格小麦播种 6 加加工费 4，共 10；输出参考值为 18，因此扣除输入参考值和加工费后的价值提升只有 2。加工单的额外收益主要补偿 30 分钟队列和占用周单原料，而不是凭空制造高倍率货币。若玩家永远加工或永远交原料，优先调加工订单出现率与 handling bonus，不增加第二种配方来掩盖。

### 5.5 订单奖励公式

订单使用统一公式，避免每张订单靠手工拍数：

```text
goods_value = sum(item_reference_value * quantity)
coin_reward = floor(goods_value * order_multiplier + handling_bonus + 0.5)
base_reputation = ceil(goods_value / 4)
reputation_reward = base_reputation + configured_progression_bonus

fast_route_fee = max(4, ceil(coin_reward * 0.08))
bundle_route_fee = max(6, ceil(sum(coin_reward) * 0.04))
clearance_coin = floor(sum(item_reference_value * quantity) * 0.25)
```

所有金币以整数结算：正数奖励采用上述 `floor(x + 0.5)` 的半入取整，费用向上取整，清仓向下取整。只允许服务端按配置版本计算；客户端展示同一笔服务端报价，不得各自调用语言默认的 `round()`。

| 订单类型 | `order_multiplier` | `handling_bonus` | 设计用途 |
|---|---:|---:|---|
| 单一原料单 | 1.70 | 10 | 快速清理指定库存 |
| 混合原料单 | 1.70 | 18 | 奖励跨时长库存组合 |
| 单次加工单 | 1.85 | 18 | 覆盖加工费和队列机会成本 |
| 加工混合单 | 2.05 | 30 | 奖励原料与加工排程 |
| 周节庆单 | 2.05 | 50 | 另有一次性章节奖励，不重复刷取 |

金币奖励在派发路线前显示毛额和净额。路线费用只改变净额与到账时间，不改变声望，避免玩家为了成长被迫购买快线。

`configured_progression_bonus` 是订单实例所属章节的版本化进度补足，不伪装成货物价值或难度，也不读取玩家余额、位置或历史付费。金币表达经济价值，声望负责内容节奏；为了让首周阈值可复算，目标订单包使用以下声望组合：

| 活跃日订单包 | 声望组合 | 合计 |
|---|---|---:|
| D0 | `10 + 10` | 20 |
| D1 | `15 × 3` | 45 |
| D2 | `17 + 17 + 18 + 18` | 70 |
| D3 | `22 + 22 + 23 + 23` | 90 |
| D4 | `27 + 27 + 28 + 28` | 110 |
| D5 | `30 × 4` | 120 |
| D6 | `35 × 4 + 周单 60` | 200 |

生成器可以在同一合计内交换订单，但不得为单个玩家临时补声望；落后者通过多一个活跃日完成当前订单追赶。

### 5.7 订单生成护栏

- 只使用已解锁的作物和配方。
- 新作物解锁当天只要求“种下”，普通订单至少 1 个活跃日后才强制需要其产物。
- D0 的两张单是固定教学闭环，不用于证明生成器或 Pareto 选择。D1 起每次展示 6 张，至少 3 张可由现有库存或 60 分钟内生产完成。D1 的 6 张来自第一市场的两组需求题；D2 开放其余市场后，才要求三市场共同生成。
- D1 至少存在两组不同的 3 单可行组合，D2 起至少存在两组不同的 4 单可行组合；每组总输入都不能超过当前可用库存加上玩家所选回访窗口前会确定完成的产出，派发和补种后钱包仍须保留两轮播种储备。不能把 6 张互斥候选的需求简单相加，也不能用尚未播种的假想产量证明可行。
- D1 起每次至少 3 张当前可行，并对应至少两种不同生产计划。`current_window_net` 定义为“本候选窗口所选订单金币 - 从候选快照后新提交的播种、加工和路线现金成本”，不计章节奖励、扩建、历史库存沉没成本和窗口结束后的下周退出计划；扩建等永久投入必须另列为 `progression_outlay`，不能藏在净额之外。
- 每个 `candidate_set_id` 先从同一冻结快照枚举**不带评分的可执行计划骨架**，只求订单、生产、加工、物流状态与下一次必需决策/章节收口检查点；再按固定规则取这些骨架中最晚的共同检查点并冻结一个双方共用的 `projection_at`。冻结后才计算 `weekly_gap`、期末预测库存、次章覆盖和 Pareto，任何筛选、推荐或玩家选择都不得回头移动它。上述库存指标只读取该时点会话事务完成后的已入仓现货；仍在地块、加工或物流中的确定供给另记为 `projected_in_flight_supply / ready_at`，不能提前算作现货。`chosen_return_bucket` 单独影响现金可用性和推荐权重，不能让 A/B 各用一个投影窗。
- 现金维同时记录 `claimable_coin_at_return`（玩家所选回访时点实际可领金额）和 `cash_ready_at`（全部订单奖励最早可领取）。方案只有在回访时多出至少 `max(8, 较低值的 5%)` 可领金币，或在共同生产/章节门之前让全部现金早至少 30 分钟可领，才算赢得“现金可用性”；被更长生产门完全覆盖的提前到达不算。另记录 `reserve_safe_action_at`（路线回款首次让声明动作包执行后仍满足运营储备的时点）和 `full_plan_at`（窗口内承诺的关键生产全部自动完成）。安全动作包、提交后现金、在途供给与产能终态必须另列，玩家脱离推荐卡手动接受低储备状态不会把 `reserve_safe_action_at` 提前。
- D1-D2 尚未向玩家披露周单，`weekly_gap=N/A` 且该维退出支配判断；D3 必须在候选选择前展示完整只读周单，才可从 D3 起把周单缺口纳入比较。D9 是稳态夹具的观测末日，没有冻结 D10 预测集，`forecast_coverage=N/A` 并退出当日支配判断；正式长期生成器不得使用这一豁免。两套计划在当时可见的“净金币、现金可用性、周单缺口、结算后预测订单覆盖”维度上必须互不支配，不能只给一个正确答案和其余障眼单。
- `结算后预测订单覆盖` 定义为：用计划结算后的同一库存快照，对次活跃日冻结的 6 张预测单枚举子集，求能够**同时原子扣货**的最大订单数；不能逐单独立检查后重复使用同一份货物。同数时再比较跨至少两类物资的参考价值覆盖率。它不能退化为总件数，否则 6 份生菜会被错误判为比 5 份面粉或番茄更安全。
- 统一“越高越好”的方向后，计划 A 支配 B 定义为 `A` 在全部当时可见维度不差且至少一个严格更好；候选集中不得出现这种单一支配解。“互不支配”还必须可感知：每套计划都至少在一个维度领先另一套并越过该维阈值。阈值为净金币差 `max(8, 较低方案净金币的 5%)`、现金可用性满足上一条金额或 30 分钟阈值、周单缺口少 1 份配方或 1 个完整地块批次、预测订单覆盖多 1 张；若可完成张数相同，则覆盖率需相差至少 10 个百分点且涉及至少两类物资。A 在两个维度大胜、B 只多 1 件低价值库存的数学解仍视为 A 实质支配。
- D2 起每天至少有一组跨节点候选，单看奖励或现有库存不能直接得出答案；结合距离档、当前配送队列和玩家选择的下次回访档后，推荐结果才允许反转。强制打开地图或把同一答案拆成两个节点不算比较题。
- 每一组可完成计划都必须严格命中当天的声望包，防止玩家因选择适合作息的方案而卡章节。标准可行计划的金币合计控制在当天预算 ±5%，高负载高收益组合最高不超过 +8%；需求量、完成时间和期末库存必须同步变化，不能只换奖励数字，也不能为轻度玩家生成低价专属订单。
- D0 单作物教学豁免；D1 任一单品不超过选中计划需求参考价值的 55%；D2 起任一单品不超过 40%。这些上限同时约束生成器产出的每套合格计划和冻结基准种子。
- 不得同时生成两张争抢同一个加工瓶颈的强制订单。
- 固定会话章节有更严格的即时派发门：D4 每套允许玩家确认的 4 单组合都必须在会话 B 的首份真实面粉入仓快照中全部可派发；D6 每套可确认组合都必须在会话 A 全部可派发，而且不得占用周单标记保留的 `F4/C8/T8`。这里的“可派发”只读取已入仓现货，禁止用未来批次或加工队列证明。未满足 `dispatchable_at_session=ALL_K` 的组合不进入可确认集合；若因此不足两套，整个候选包拒绝并进入版本化保底，不能用第四次必需会话补救。
- 同一模板连续出现不超过 2 次；前三模板的长期完成占比目标低于 60%。
- D1 起每日 2 次免费换单；D0 固定教学单不可换，不售卖额外换单。
- 已接受订单不会因 48 小时经过而减价、失效或受罚。满 48 小时后只增加“继续准备 / 无损替换”入口；选择替换等同主动放弃并生成当前可行单，不返还已经用过的免费换单次数，也不产生任何金币差额。
- 第二经营节点不可用时，不生成强制跨节点任务。

生成器按固定顺序执行，避免“先随机六张，再祈祷其中可玩”：

1. 冻结库存、地块/加工/物流队列、钱包、回访档、周单缺口、章节时钟和 `forecast_version` 快照。
2. D1 从第一市场生成 6 张；D2 起按三个稳定市场身份共同生成 6 张。随后过滤解锁、单品占比、模板重复和地区公平。
3. 按当日完成上限 `k` 枚举六张候选的全部 `C(6,k)` 组合：D1 的 `k=3` 最多 20 组，D2 起 `k=4` 为 15 组；再枚举满足步数、租约、容量、提交时现金非负和章节 `dispatchable_at_session` 硬约束的生产/加工/物流 `plan_skeleton`。这一遍只重放状态和计算每个骨架的 `required_checkpoint_at`，不计算投影库存、周单缺口、预测覆盖或支配关系。D0 不运行这一步。
4. 令 `projection_at=max(configured_chapter_checkpoint, max(required_checkpoint_at))`；纯后台完成且不要求玩家决策或章节收口的任务不进入 `required_checkpoint_at`。将结果连同候选快照版本一起冻结，随后才让同一离散事件模拟器推进到该时点，计算扣货、成熟、加工、派发、到账、补种后余额、现货/在途、周单缺口和次章覆盖。
5. 删除在共同投影下不可执行、会跌破两轮播种储备或产生实质支配解的组合；至少保留两套跨过可感知阈值的计划。D2 起两套计划的 `session_node_slot` 多重集合必须不同，并至少有一张替换单来自不同槽位，不能只在同一节点换数量。筛选后即使最晚骨架被删除，也不得缩短 `projection_at`。
6. 若不足两套，不放宽安全或公平规则；改用该章节的版本化保底候选包，生成新的 `candidate_set_id` 并从第 1 步完整重跑，同时记录 `order_generator_fallback`。同一快照和配置版本必须得到同一结果，便于复现；禁止在同一个候选集上事后挪动投影时点救数据。

免费换单、候选自然刷新和 48 小时后的无损替换都必须重跑同一验证器。若已有 `n` 张本章订单处于 `ACCEPTED / SCHEDULED / IN_TRANSIT / ARRIVED / CLAIMED`，把它们的需求、金币、声望、瓶颈占用和已用额度冻结为固定集合，只枚举剩余 `k-n` 个位置，并对拼回后的完整 k 单包重新检查金币带、声望包、单品占比、周单安全库存和非支配性。验证不通过就拒绝该替换并给版本化保底，不能把多个局部合格候选拼成从未验证的超额计划。

### 5.8 防破产与防套利

- 不设置无限系统收购。单次清仓收入为 `floor(该批物品参考总值 × 25%)`，每日最多 20 件；先汇总再取整，不能逐件取整制造套利或端服差异。
- 如果金币低于“填满当前地块所需的最低播种成本”且库存不足，提供每日一次不可交易的基础种苗包，避免永久死锁。
- 客户端不能提交奖励数、完成时间或库存结果，只能提交带版本号的命令。
- 服务器必须为播种、收获、加工、派发和领取使用幂等键，重复请求不能复制收益。
- 首周任何单一作物策略的最优净收益不能比第二名高 15% 以上；D14 后单一作物种植占比目标低于 45%。

### 5.9 订单状态机与结算原子性

```text
OFFERED --接受--> ACCEPTED
ACCEPTED --用户放弃、尚未排程--> ABANDONED
ACCEPTED --货物可交且报价确认；原子扣货/费用/额度--> SCHEDULED
SCHEDULED --获得运行位--> IN_TRANSIT --服务器时间到--> ARRIVED
ARRIVED --领取--> CLAIMED

OFFERED --刷新或自然过期--> REPLACED
SCHEDULED / IN_TRANSIT --仅服务端故障撤单--> CANCELLED_REFUNDED
```

周单使用参数化的独立子状态，不能把首周的 D5/D6 章节名写死进通用状态机：

```text
OFFERED --玩家确认--> WAITING_SUPPLY
WAITING_SUPPLY --ready_gate满足且货物齐备--> READY_LOCKED
READY_LOCKED --货物被其他订单消耗--> WAITING_SUPPLY
READY_LOCKED --settle_gate满足且玩家确认；原子扣货--> IN_TRANSIT
IN_TRANSIT --30分钟--> ARRIVED --领取--> CLAIMED
```

- “货物齐备”是根据实时库存计算的派生条件，不保存为独立状态。其他配方或订单消耗库存后，按钮自然回到缺货态，不存在失效的 `READY` 状态。
- `OFFERED -> ACCEPTED` 只发生在玩家确认一套完整的当章组合时：D1 为 3 单、D2 起为 4 单。节点卡上的“加入今日计划”只是本地/服务端短期 `TENTATIVE` 预选，可随时撤销，不锁报价、不占接受上限；确认时才原子写入全部 `accepted_order_ids` 和关联的排产草稿，避免玩家在看不到组合后果时逐张锁单。
- 接受订单不扣货；排程时才原子检查并扣除货物、配送额度和路线费。任一检查失败则全部不变。
- 玩家在 `ACCEPTED` 阶段可无罚放弃；已排程后不能主动取消。最多同时保留 4 张 `ACCEPTED` 订单，避免无限囤积旧报价；订单年龄只用于回流提示与分析，不进入奖励公式。
- D0 两张教学单使用独立的 `TUTORIAL_OFFERED` 标记，不能放弃、刷新或自然替换；关闭应用后从原状态恢复。它们仍在排程时原子扣货，并从 `SCHEDULED` 起复用正常物流与结算状态。
- `ABANDONED` 会占用该候选槽直到下一次正常刷新，不自动补出新单，也不返还免费换单次数；只有对 `OFFERED` 显式使用免费换单才会立即替换候选，防止反复接受、放弃来无限刷池。
- 派发后不可取消，货物进入服务端托管；到达时自动释放在途位，金币留在待领取账本，不要求玩家准点上线。
- 同一个 `idempotency_key` 重试只能得到第一次结果，不能重复扣货、重复派发或重复领取。
- 首周额度只在对应 `chapter_state` 第一次进入 `ACTIVE` 时发放一次，幂等键为 `player_id + chapter_day + delivery_grant_version`。D0 发 2、D1 发 3、D2-D6 各发 4，共 25；未用额度跨日保留但钱包上限为 8，单自然日最多消耗 8。D7 起改为每个新活跃日补 4，同一活跃日重进不补发。
- 日订单和周订单分开计额。周订单每周只能结算一次，使用固定 30 分钟的节庆收货，不消耗日配送额度、普通运行位或计划位，也不提供额外路线选择。
- `weekly_order_def` 配置 `offer_gate / ready_gate / settle_gate / requirements / reward / first_clear / reputation / garden_value`。首周分别绑定 D4 可接受、D5 完成可就绪、`d6_core_complete` 可发运；第二个个人经营周绑定第 1 活跃日可接受、货齐即就绪、第 7 活跃日当日日单闭环后可发运。`READY_LOCKED` 不扣货；若物资被其他订单使用，立即回退 `WAITING_SUPPLY` 并显示最新缺口。只有 `settle_gate=true` 且货物再次齐备时，玩家确认才原子扣货并进入 `IN_TRANSIT`。30 分钟后到 `ARRIVED`，领取奖励；`first_clear` 只在配置为真时发放。客户端隐藏按钮不能替代服务端门控，扣货与重复领取都沿用幂等键。

## 6. 物流系统

### 6.1 物流的角色

物流不是第二套战斗系统，也不模拟真实交通。它只回答一个经营问题：

> 我愿意付出多少金币，换取多快到账和多少批量效率？

路线连接的是游戏节点，不是用户移动轨迹。车辆按服务器时间虚拟运行；真实步行、驾车和通勤不会加速，也不会增加载量或稀有奖励。

### 6.2 首周路线

订单实际从每区统一的虚拟配送站发出，不从每个玩家的私人农场 Marker 计算。每个市场节点具有：

- `distance_band`: `near / medium / far`，每区分布完全相同。
- `corridor_group`: 表示两个节点是否共享运输走廊，决定能否合单。
- `topology_motif`: `single / fork / hub`，来自路网邻接的归一化结果。

Alpha 的可玩计算只读取 `distance_band`、当前物流队列和下次回访档。`corridor_group` 与 `topology_motif` 仅随配置记录并用于验证数据完整性，不参与首周价格、时长或推荐；只有 W2 联运通过独立 Gate 后才读取它们。基础时长按距离档乘以 `0.8 / 1.0 / 1.25`，订单金币和声望公式完全不读取距离档，也不另发中远距离补贴。地区公平由各区相同的近中远分布、订单价值预算和画像模拟保证；若同活跃度地区收益仍差超过 5%，修节点配额或候选生成，不增加账外金币源。

| 路线 | 解锁 | 时间 | 费用 | 容量 | 适用情境 |
|---|---:|---:|---:|---:|---|
| 街区慢线 | D0 自动，D3 可选 | 基础 90 分钟 | 0 | 1 单 | 下次回访较晚，不急于释放配送位 |
| 直达快线 | D3 | 基础 15 分钟 | `max(4, ceil(奖励 × 8%))` | 1 单 | 希望下次短回访前到账或尽快推进计划队列 |
| 联运合单 | W2 候选 | 基础 45 分钟 | `max(6, ceil(两单总奖励 × 4%))` | 同走廊 2 单 | 两个节点共享走廊时节省一个在途位 |

第一笔教学运输使用一次性 15-30 秒路线，确保“建场、播种、收获、派发、领取到账”在 5 分钟内真正闭环；之后恢复正式时长。

首周不设置随机丢货、随机损耗和不可预测延误。地图事件若改变路线，必须在派发前给出确定报价。玩家可以比较净收益，不需要猜概率。

### 6.3 物流状态机

```text
DRAFT -> QUOTED -> SCHEDULED -> IN_TRANSIT -> ARRIVED -> CLAIMED
          |              |           |
          +--报价过期--> REQUOTE_REQUIRED --新报价--> QUOTED
                         SCHEDULED / IN_TRANSIT --服务端撤单--> CANCELLED_REFUNDED
```

每名玩家有 1 个运行位和 3 个计划位。玩家确认报价后，第一单立即进入 `IN_TRANSIT`，其余按确认顺序进入 `SCHEDULED`；前一单 `ARRIVED` 时自动释放运行位并发出下一单，不要求玩家在线。每张单在入队时锁定路线、费用和预计发出/到达时间，队列中途不能暗改报价。

报价只在玩家确认前有短 TTL；过期进入 `REQUOTE_REQUIRED`，不扣任何资源。服务端若因配置下线或故障撤销已排程订单，必须在同一原子事务中退回全部货物、路线费和配送额度，释放计划/运行位并启动下一单；退款重试同样幂等。额度上限 8 只限制新 Grant，故障退款恢复原额度时允许余额暂时超过 8，且该恢复不算新发放、不增加当日 8 单消耗上限；余额回到 8 以下前不再接受新 Grant。正常派发不存在随机 `EXPIRED`，客户端不能修改结束时间。

分析中的 `order_scheduled` 表示成功扣资源并进入计划队列，`order_dispatched` 只在真正进入 `IN_TRANSIT` 时触发，“订单完成”统一指 `CLAIMED`；三个事件和额度消耗不能混用。

### 6.4 路线可读性

路线状态不能只靠红、黄、绿：

- 运行：实线 + 方向箭头。
- 等待：虚线 + 时钟。
- 阻塞：断线 + 警告符号。
- 已选：高对比外描边，并降低其他路线到 30%-40% 视觉强度。

地图底部情境栏一次只显示当前订单、起终点、净收益、到达时间和一个主 CTA。全局导航不混入浇水、改道或开箱等上下文操作。

### 6.5 二期物流扩展

只有当首周路线选择确实分散时，才增加以下内容：

- 冷链、易损品和已知天气窗口。
- 多仓库调拨和中转节点。
- 预定运输、批量排程和路线升级。
- 合作订单中的分工运输。

不能只看总选择率。至少要在“预计下次打开时间 × 当前金币缺口 × 待发订单数”中的两个情境看到同一用户群发生合理反转；否则即使各路线占比都低于 75%，选择也可能只是不同作息用户的固定偏好。未出现情境反转时，先删掉或重做成本曲线，不继续加路线。

## 7. 成长系统

### 7.1 首周声望等级

声望是不可消费的进度值，不显示在 Avatar 头像旁。

| 等级 | 累计声望 | 预计时间 | 主要解锁 |
|---:|---:|---:|---|
| 1 | 0 | D0 开始 | 生菜、小麦、6 地块、第一市场 |
| 2 | 60 | D0 结束 / D1 开始 | 胡萝卜、番茄、批次排产；当章订单仍不强制番茄 |
| 3 | 150 | D1 结束 / D2 开始 | 第二与第三市场、节点比较 |
| 4 | 280 | D2 结束 / D3 开始 | 仓库章节扩容、慢线/快线、第 7 地块购买资格 |
| 5 | 450 | D3 结束 / D4 开始 | 加工位、面粉、首周供给单 |
| 6 | 650 | D4 结束 / D5 开始 | 个人地区花园、周单排产 |
| 7 | 900 | D5 结束 / D6 开始 | 首周结算章节 |
| 8 | 1,200 | D6 结束 | 第二周经营方案和长周期作物预告；G2 稳态探针期间不解锁 |

每日章节奖励帮助目标玩家在**当日结束**命中下一档阈值，但不是唯一来源。章节“完成”和下一章“激活”是两个状态：完成时原子结算奖励和等级；完整的下一章只能在满足 `player_day_id > completed_player_day_id` 且 `critical_supply_ready=true` 的后续 `session_start` 激活，同一 `player_day_id` 最多写入一次 `system_intro`。`critical_supply_ready` 要求结算页下次准备作物均已成熟、本章关键 `production_plan=COMPLETED`，以及明确列入下章开场库存的加工任务已经自动入仓；任一任务因容量暂停时保持 false，并动态更新预计就绪时间。它保证下一章开场有真实供给，不要求玩家提前多开应用。结算页可以开放一个明确标记的“下次准备”动作，例如 D0 结束后确认包含胡萝卜与番茄的 D1 批次、D1 结束后查看 D2 冻结预测，但不能继续展开新节点或新经济规则。下一章同时检查“前一章节已完成”和“已达到上一日结算阈值”，不会要求玩家先使用尚未解锁的系统来赚取其自身门槛。章节奖励只在完成明确玩法目标后发放一次，不因自然日登录自动领取。

进度落后的玩家继续完成当前已解锁范围内的订单即可追赶；订单生成器优先给可完成的追赶单，但不提高单价、不赠送额外声望。这样轻度玩家会延长章节，而不会在同一个自然日叠加多套教学，也不出售声望或经验加速。

### 7.2 中长期成长

前 12 级预计 21-28 个活跃日完成，累计阈值候选为：

`0, 60, 150, 280, 450, 650, 900, 1,200, 1,550, 1,950, 2,400, 3,000`

D7 起移除首周尖峰，把订单、章节和周目标合计控制在每活跃日 90-120 声望。由 1,200 到 3,000 还需 1,800，约 15-20 个活跃日，因此总进度约 22-27 个活跃日，与 21-28 日目标一致；超出区间时优先调订单包，不出售经验加速。

前 12 级开放核心系统、最多 10 个地块、第二加工设施和基础配方。之后主要提供：

- 新配方和等价经营方案。
- 地区故事和城市图鉴。
- 农场主题、车辆皮肤、地图 Pin 和 Avatar 外观。
- 新个人地区主题；共享工程通过 Gate 后另行配置。

后期不持续按百分比提高产量。永久效率提升必须有上限，避免老玩家经济指数增长并永久碾压新玩家。

### 7.3 第一周个人地图进度

首周使用不可消费的“花园值”表现个人综合投入；Alpha 不将其包装成真实邻里共同结果：

- 每个核心订单：2 点，预计 25 单，共 50 点。
- 每个活跃日章节：5 点，共 35 点。
- 首周节庆单：20 点。
- 首周最高：105 点。

| 阈值 | 地图反馈 | 奖励 |
|---:|---|---|
| 65 | 嫩芽阶段，个人地区花园第一次复绿 | 地图纪念章 |
| 85 | 盛放阶段，第二次视觉变化 | Avatar 纯外观配件 |
| 100 | 繁茂阶段，完整地图变化 | 下周花园主题选择 |

未达到最高档也能结算，不回收地块、不损失作物、不重置连续天数。首周没有连续登录奖励。

花园值只决定全局复绿程度，不能让所有玩家在同一阈值看到完全相同的地图。Alpha 同时记录一层**空间经营历史**，只改变同阶段内“绿在哪里、通过什么路线形成”，不改变金币、声望、花园值、订单概率、路线效率或解锁速度：

- 接受订单时记录当次 `session_node_slot` 与 `distance_band`，排程时锁定 `route_option`；只有订单进入 `CLAIMED` 后才生成一枚等面积 `service_imprint`。
- `service_imprint` 不等到 65 点阶段门才出现：从 D2 第一张地图订单 `CLAIMED` 起就在对应槽位显示一条低强度经营痕迹，并随后续订单增密。65/85/100 仍只控制地区花园的三次全局阶段变化；这样轻度玩家即使首个自然周只推进到 D3，也能看到“我服务过这里”的地图回报。
- `session_node_slot` 只用于会话内事件关联。服务端把业务节点映射为本个 `player_week_index` 内稳定的 `weekly_visual_slot=A/B/C`；分析侧只接收槽位、距离档和路线类型，不接收稳定节点 ID 或坐标。
- 近、中、远只决定印记落在内、中、外圈，不改变面积、亮度或数量；慢线和快线使用两种等显著度纹理，只表达路线选择，不暗示优劣。
- 重复服务同一槽位时，印记在该区域内增密或分枝；服务多个槽位时形成分散图案。系统不提供多样性奖励，也不惩罚专注同一市场。

## 8. 七个活跃日内容设计

### 8.1 口径

本节的 D0-D6 是**七个章节活跃日**，不是安装后的七个自然日，也不要求连续签到。`player_day_id` 由服务端按经营区域固定时区、当地 04:00 边界生成；当日首次有效会话才算活跃，改设备时区不能推进。一个章节在某个 `player_day_id` 完成后，下一章最早只能在更大的 `player_day_id` 激活。漏一天后从未完成章节继续，不叠加两套新系统，也不清空订单；分析中的日历 D1/D7 仍按安装后 24 小时窗口单列。

主动时长包含核心经营、地图选择、剧情和可选整理，不包含作物与运输在后台运行的时间。目标不是让玩家盯着倒计时，而是让每次回来都有决策。

### 8.5 每日内容脚本

#### D0：第一条供给线

目标：在不先弹系统权限的情况下理解地图、农场和订单的关系。

流程：

1. 选择经营区域或主动使用当前位置。
2. 进入地图，第一市场和私人农场入口同时可见。
3. 创建个人虚拟农场；系统先给默认名，命名是可跳过的个性化步骤。入口使用“虚拟农场”标识，不贴合现实地块边界。
4. 使用 `d0_lettuce_tutorial_v1` 的 3 个播种份额种植 30 秒教学生菜；等待期间查看第一张市场订单。
5. 收获并交单，使用一次性 15-30 秒教学运输，并实际领取金币。
6. 首单到账后，Avatar 预览作为可选庆祝入口，不插入核心教学。
7. 使用同一 Grant 剩余 6 个播种份额完成第二轮 2 分钟教学生菜；用 12 份生菜完成第二张数量变体单，在首会话结束前排入正式慢线，并把 6 格空地全部改种 60 分钟小麦，实际支付 36 金币。
8. 至少 2 小时后的第二次打开领取第二单、收获 18 份小麦，完成 D0 章节。结算页只开放“下次准备”动作：安排 3 格胡萝卜、3 格生菜；这 36 金币在 D0 真实发生并计入 D0 的 72 常规消耗，完整 D1 教学要到更大的 `player_day_id` 的 `session_start` 才激活。

验证：用户能说出“地图找需求，农场做东西，路线送过去”；Avatar 不被理解为工人。

#### D1：为下一次回来种植

目标：理解“选择下次回访档 -> 提交可执行批次计划”，而不是守着倒计时。

- D0 结算后同时解锁 3 小时胡萝卜和 8 小时番茄，用两种时长承载 D1 的唯一新规则；番茄在 D1 只进入排产卡，不进入强制订单，避免“刚解锁就欠货”。
- 扩建页从 D1 起只读显示“第 7 地块 700 金币，D3 后可购”，让价格成为既有目标；D3 真正购买时不再临时教授第二套成长货币或随机定价。
- 三张核心订单使用生菜、小麦和当日可完成的胡萝卜；番茄只用于离开前的 8 小时计划，遵守“新作物次活跃日才强制需求”。
- D1 第一次打开应在胡萝卜成熟后，收下 9 份胡萝卜和 6 份生菜，以库存中的 18 份小麦比较两套完整的“订单组合 + 排产”卡。短档 B 选择 04/05/06，并提交 `1W + 5C`，3 小时产 W3/C15、成本 46；长档 A 选择 01/02/03，并提交 `2T；3C；W -> L`，8 小时产 L2/W3/C9/T8、成本 58。B 的当前窗口净金币高 9 且完整计划早 264 分钟，A 对 D2 冻结候选多覆盖 1 张；二者真实互不支配，不能只换标题。种子 A 选择长档，三张同节点慢线在 T+216m 已到达，玩家第二次在 T+8h 查看批次报告、领取回款并完成章节。若更早打开，章节顺延，不罚款也不清空；“两次打开”是目标作息路径，不是对任意时间窗口的硬保证。
- 教玩家保留约 20% 库存，而不是见货即交。
- 当天最后一步明确显示“回来后仍会等待，不会枯萎”。

验证：至少 70% 可用性测试用户能选择符合自己回访时间的计划，并无提示说出“提交时付全款、后台会自动换茬、满仓会暂停”；任一关键点错误都不算理解。

- 种子 A 分三次：会话 A 排入番茄快线与其余三张慢线；会话 B 在 T+18.75m 领取番茄款、购买第 7 地块并提交 9 小时计划，此时安全动作包比全慢提前 93.75 分钟；会话 C 在 T+558.75m 领取其余三单并确认计划报告。路线提前到达时回款安全等待领取，批次仍在后台继续；两者都完成后才把 §8.3 的库存快照作为 D3 期末状态。

Alpha 使用 `player_week_index` 管理个人经营周期，不与未来赛季的 `season_week_id` 混用。Gate 2 的 W2 前三个活跃日就是 §8.8 的稳态探针：选中的快收/均衡/夜作方案只改变四种既有作物的等收益需求权重和预报方式，莓果、南瓜、沙拉盒、莓果酱与联运全部保持关闭。它们只有在稳态探针通过后，才作为后续内容版本按“先新作物、次活跃日进订单，再新配方或联运”的顺序验证；不能与 D7-D9 同时开放后再声称自己测的是无新系统稳态。

这里的章节节流是实验控制，不等同于内容量。必须记录 `chapter_gate_seen`、`post_cap_session` 和被挡住后的次日回访；若高频玩家大量撞门，不继续增加日历锁，而是改善可重复的订单与库存决策。

分析中的 D1/D7 始终指安装后的日历留存；`chapter_day` 和 `chapter_6_complete` 单独记录，不能把“活跃日 D6 完成”与日历 D7 留存混为一个漏斗。

### 8.8 D7-D9 无章节尖峰运营稳定性探针

D0-D6 覆盖七个活跃日和 73 分钟核心设计预算，但其中五天有教学、D6 有强结算，不能据此宣称长期经营已经成立。Gate 2 因此给所有 D6 完成者自动开放三个**实验性系统日**；下文 D7-D9 指 `system_day_index=7..9`，不是安装后的日历留存 D7。测试配置关闭莓果、南瓜、新配方、联运、章节金币、首清与新系统教学，只复用四种作物、面粉、三个节点、两条路线和已学周单。它们不计入“首周 73 分钟”，也不靠额外奖励制造回访；它们只验证无教学补贴时的运营稳定性，不能单独证明目标耗尽后的长期自驱。

#### 8.8.6 结论边界与延长验证

D7-D9 恰好围绕第 8 地块的 2,500 金币目标，因此通过时最多可以写“无章节补贴的运营循环可执行”，不能写“长期留存或自驱成立”。G2b 才追加 D10-D13 耐久窗：D9 扩地完成后不开放新作物、新配方、新扩建价签、章节奖金或限时任务，只让同一生成器继续产生四个系统日，并在 D13 以常规 W2 周单收口。该窗只允许既有收藏目录作为可选目标，不能临时再造一个强奖励来救回访。

延长窗对所有完成 D9 的玩家自动开放，固定为 `endurance_window=[d10_eligible_at, d10_eligible_at+96h)`；样本少于 12 人只报“证据不足”。至少 50% 的 D9 完成者需在 D10-D13 再完成两个有效供给链，且其中一次不是由通知或章节入口直接唤起；否则第 8 地块就是一次性终点。D10-D13 的订单理由重复、钱包、R/source、保底率和必需会话单独报告，不与 D7-D9 合并抬高结果。直到该窗或至少第二个完整个人经营周通过前，文档中的“赛季自驱”都只是待验证扩展，不是 Alpha 结论。

## 9. 日、周与赛季内容框架

### 9.1 每日结构

每天刷新的是选择，不是惩罚：

- D0 固定 2 张教学订单；D1 起刷新 6 张候选，D1 计划 3 张、D2 起计划 4 张。首周可派发总量由章节激活 Grant 控制，不在自然日午夜重复发放。
- D1-D6 各 1 个由节点、库存和回访档自动组成的“今日比较题”，不是人工剧情消耗品；D0 固定教学比较单列。
- 2 次免费换单。
- 成熟、运输和加工通知由玩家分别订阅，默认每天最多 2 条，遵守本地静默时段。

Alpha 全周只制作 3-5 条固定地区文案，分别用于建立区域、地图首次变化和周结算。日常变化来自订单组合、节点关系和库存状态；不承诺首周 21 条情报或 7 段一次性故事。

不设置签到连胜、午夜清空的强制任务、精准收获窗口或“现在去附近”的位置推送。

每日可重复内容由同一套“系统日生成器”提供，不靠继续加教程：

```text
输入：可用库存 + 各地块成熟时间 + 加工/配送队列 + 下次回访档 + 周单缺口
生成：D1 由第一市场、D2 起由 3 个稳定身份市场生成共 6 张候选单与至少 2 条当前可行的生产/路线计划
选择：玩家接受至多 4 张，并提交种植、加工与路线组合
输出：净金币 + 结算时点 + 周单缺口变化 + 结算后预测订单覆盖
回注：输出状态成为下次打开的生成器输入
```

两套计划必须是 Pareto 意义上的互不支配：不存在一套计划在当时已披露的净金币、回访时现金可用性、周单推进和次日预测订单覆盖维度上同时胜出，并且差异要越过 §5.7 的可感知阈值。D1-D2 计划时的周单维度为 N/A；D2 收口被动预告后，D3 才把该维加入比较。`projection_at` 必须在无评分骨架枚举后、A/B 指标计算与筛选前冻结；`full_plan_at` 与 `reserve_safe_action_at` 作为安全证据另列，不能把生产更少造成的“更早”伪装成路线优势。D5 只是玩家首次“机械稳态日”，没有新经济控件，但仍有视觉反馈和章节奖励，不能单独证明长期自驱。

上线前还要冻结同一库存、订单与奖励，离线做三组配对种子：只改变下次回访档、只改变物流队列、只交换近远距离档；每组都必须让最优计划发生可解释反转。真人不会被实验员在 D8 强制切换作息或回滚库存，只使用自己选择的回访档；因果反事实来自模拟或事先随机化的独立任务。随后按 §8.8 给全部 D6 完成者自动开放 D7-D9。若同时改变所有输入后碰巧得到不同答案，不算因果证据；若控制变量后不反转，或离开教学奖金后不再回访，7 日内容仍是一次性任务脚本，不得以增加作物数量掩盖。

这里的“最优”必须在测试前绑定画像效用函数，四维先归一到 0-1，再使用固定权重，禁止看到结果后换指标：

| 决策画像 | 净金币 | 回访时现金可用性 | 周单缺口缩减 | 次日预测订单覆盖 | 典型情境 |
|---|---:|---:|---:|---:|---|
| 短回访 / 现金周转 | 0.25 | 0.50 | 0.05 | 0.20 | 1-2 小时后再开，希望关键单到账 |
| 周单收口 | 0.20 | 0.10 | 0.50 | 0.20 | D4-D6 优先补齐跨日合同 |
| 隔夜稳健 | 0.40 | 0.05 | 0.15 | 0.40 | 8 小时后再开，不为无效提前付费 |

权重只用于验证生成器是否制造了符合画像的反转，不替玩家自动接单，也不读取付费、位置或个人余额来暗调候选。

首周内容容量按三类时间分别验收：核心决策设计预算 73 分钟、31-47 分钟可选地图/整理/周报，以及不计为新内容的重复经营。目标玩家七个章节活跃日的完整参与假设区间为 104-120 分钟；每日一次打开的轻度轨迹预算为 50-64 分钟；高频玩家可以继续排产，但新增点击和等待不能被包装成独立内容量。Gate 2 后再用实际 P25/P50/P75 替换这些设计数。

### 9.2 个人经营周结构

一个 `player_week_index` 固定包含 7 个活跃日，不按自然周一或赛季周重置。每个个人经营周包含：

- 1 张需要 2-3 天准备的周订单。
- 1 个个人地区修复阶段；共享工程在 Gate 3 后才进入路线图。
- Alpha 只使用 NPC 叙事角色；最多 3 人的异步协作是共享项目通过后的独立功能。
- 1 次地图前后对比和经营周报。
- 1 个外观或地区图鉴奖励。

周订单独立于日单配送额度钱包。首周额度按章节一次发放，D7 起日单额度改为按活跃日补充；周单始终不消耗该额度。个人周订单、个人地区花园和周报全部绑定同一 `player_week_index`，完成第 7 个活跃日才结算，不自然过期；缺席只推迟结算，不丢进度或奖励。首周和后续个人经营周都不再叠加另一张“任选四天”任务；§9.3 的 100 点弹性任务只属于未来赛季时钟。

两个“周”必须由不同主键和界面标签区分：

| 时钟 | 主键 | 包含内容 | 重置与补领 |
|---|---|---|---|
| 个人经营周 | `player_week_index` | 7 个活跃日方案、周订单、个人花园、周报 | 第 7 个活跃日结算后递增；无自然过期 |
| 赛季内容周（G4） | `season_week_id` | 主题内容发布、赛季任务槽 | 按服务端自然周切换；个人经营周不跟随切换 |

客户端不得用 `season_week_id` 关闭个人周订单，也不得用 `player_week_index` 重置赛季主题。

### 9.3 八周赛季

候选赛季长度为 8 个 `season_week_id`。22 个核心等级每级 100 点，共 2,200 点；2,300 和 2,400 点各有一个不影响能力的加码外观。每个赛季周首次 4 个合格活跃日各 50 点，另有 1 张 100 点弹性任务，常规节奏为 `4 × 50 + 100 = 300`，八周上限 2,400，因此核心完成有 200 点、约 9.1% 的容错。

下表先按单人赛季成立。Gate 3 后若共享工程获批，可以替换同一周的叙事与视觉，但不能增加第二套并行进度或提高毕业点数。

| 来源 | 点数 | 上限 |
|---|---:|---:|
| 前两张日订单 | 每张 15 | 30/日 |
| 完成今日节点比较题 | 10 | 10/日 |
| 推进个人地区订单；共享版通过后再替换 | 10 | 10/日 |
| 周弹性任务 | 100 | 100/周；三个不同活跃日各完成一条有效供给链 |

赛季周结束时，未领取的 50 点活跃日槽进入账号追赶池，最多保留 8 槽；后续某周完成当周 4 个槽后，第 5-6 个合格活跃日可各消耗 1 个追赶槽。100 点弹性任务在发布周后仍保留到赛季结束；每条任务要求三个不同活跃日各完成一条有效供给链，一条供给链只记入最旧的一张未完成任务，同一自然日最多推进一张。所有来源共享 2,400 总上限。漏一整周会留下 4 个 50 点槽和 1 张 100 点任务；最少需要分布在两个后续周的 4 个额外合格活跃日，再完成那张保留任务，才能补回 300 点，不是“上线一天全领”。第 8 周只强化追赶入口，不出售赛季点；加码外观不是核心故事结局的条件。

| 周 | 主题 | 新内容 |
|---:|---|---|
| 1 | 建立供给线 | 基础种植、订单、路线、首个个人地区花园 |
| 2 | 加工周 | 新配方和加工排程，不增加货币 |
| 3 | 地区故事 | 第二经营区域的候选与地图图鉴 |
| 4 | 地区里程碑 | 第一幕个人地图大变化；共享版可替换叙事 |
| 5 | 供应选择 | 三种经营方案的差异化订单 |
| 6 | 批量配送 | 异步合单与运输外观；好友协作不在默认范围 |
| 7 | 城市节庆 | 赛季大型订单和剧情结局准备 |
| 8 | 结局与追赶 | 个人地区收官；共享版通过后才使用公共工程结局 |

功能性配方在首次剧情中直接获得，不能锁在付费通行证。季末配方进入常驻研究，外观可以返场，避免 FOMO 成为留存主力。

### 9.4 Gate 3 之后的共享工程分片

本节不是 Alpha 范围。只有个人地图变化与 Geo 对照均通过后，共享工程才进入独立验证。共享版不按现实城市总人口直接累计，建议把活跃玩家动态分入 50-200 人的异步分片：

- 目标阈值按近 7 日活跃人数缩放。
- 每个账号的公共影响有软上限，超出后仍可完成个人订单，但不继续放大公共权重。
- 最后阶段允许系统保底推进主剧情，玩家贡献决定视觉丰富度和纪念品，不决定是否能看结局。
- UI 使用“本区小队”或其他真实定义，不伪装成全体现实邻居。
- 不显示贡献排行榜，防止少数重度玩家控制地区叙事。

如果小分片依赖 NPC 保底，必须在文案和数据口径中诚实表达为系统进度，不能伪造具体玩家贡献。

## 10. 社交与表达

### 10.1 开放顺序

社交必须建立在单人循环已经验证之后：

1. **Alpha 单人**：私人农场、NPC 城市订单和个人地区修复，不创建共享分片，也不暗示附近玩家正在贡献。
2. **好友互访**：邀请码进入去除真实底图、地区名、公共节点和私人 anchor 的实例，只能留下一个预设照料印章。
3. **异步协作**：最多 3 名已建立关系的好友共同完成一张订单，最后 6 小时可由 NPC 补位。
4. **聚合公共记录**：正式开放前重新做隐私评估；候选门槛为 `k >= 10-20`，只显示人数区间，并以固定时间桶加随机延迟展示阶段，不显示账号、精确人数或时间轨迹。

### 10.2 明确不做

- 附近陌生人列表和实时 Avatar。
- 私信、开放聊天、线下见面 CTA。
- 偷菜、破坏、土地抢占、节点税收和公会圈地。
- 玩家间金币、资源或付费物转移。
- 位置排行榜、到访榜和步数榜。

### 10.3 Avatar 奖励原则

Avatar 是最自然的商业与表达载体，但不能反过来侵入经营数值：

- 奖励服装、发型、表情和手持外观。
- 只在个人结算或去地图化的受邀好友实例中展示；公共节点不展示可识别头像。
- 不显示等级角标，不把稀有度写成战力。
- 同一套装在任何经营系统中的收益完全相同。
- 外观来源可显示“首周花园”“春季工程”等纪念信息，不显示获得地点的精确坐标。

应用内分享导出默认隐藏街名、当前位置和精确节点，并清除图片定位元数据，同时提供一键隐私视图。系统级截图无法被应用自动脱敏，界面不得承诺所有截图都安全。

## 11. 商业化原则

### 11.1 验证阶段

首个 7 日 Alpha 和留存 Beta 不设置硬货币，不接广告，不销售加速。先证明地图和经营循环成立，再验证装扮需求。

### 11.2 候选商业化

验证 D30 留存后，可直接销售：

- Avatar 服装、发型、表情和动作。
- 农场地表、围栏、温室和季节主题。
- 车辆皮肤和地图 Pin 外观。
- 只含外观与故事的赛季通行证。

禁止销售：

- 地块、仓库、加工位和订单次数。
- 生产或物流加速。
- 声望、赛季点和公共贡献倍率。
- 位置范围、稀有节点、换单和现场奖励。
- 随机属性外观或可交易抽奖物。

若商业系统必须使用代币，只能是独立“造型点”，不得出现在经营 HUD，不得兑换金币、资源、时间或进度。

### 11.3 商业化否决线

- 同活跃量下，付费和非付费玩家的经营成长差距目标小于 1%。
- “必须付费才能跟上”反馈超过 8% 时，停止扩展商业化。
- 任何外观销售需要用产能加成才能提高转化，说明 Avatar 纯形象商业模式尚未成立。

## 12. 信息架构与关键页面

### 12.1 一级导航

首周只保留三个有文字标签的一级入口：

| 页面 | 核心任务 | 默认信息 |
|---|---|---|
| 地图 | 选节点、看路线和个人地区变化 | 当前位置蓝点、经营节点、情境底栏 |
| 农场 | 种植、收获、加工和仓库 | 地块状态、加工队列、下一成熟时间 |
| 订单 | 管理已接受、运输中和可领取订单 | 状态、缺货、净收益和领取；新需求从地图节点发现 |

Avatar 头像位于顶栏次级入口；换装不是底部主导航。个人地区修复通过地图节点进入，首周不单独占一个 Tab。无障碍和地图失败时可以用等价节点列表发现新需求，但列表必须保留市场角色、距离档、物流队列和节点关系，不能退化成脱离空间上下文的一张总订单表；W2 通过联运 Gate 后才增加走廊信息。

### 12.2 地图主屏

- 顶部最多显示金币、当前周目标和头像。
- 标准蓝点表示本人当前位置，仅本人可见；Avatar 不承担定位。
- 右侧提供回中和图层按钮，触摸目标至少 48 dp。
- 选中节点后从底部出现一个情境栏，只保留名称、状态、一个关键指标和唯一 CTA“加入今日计划”；这一步只做 `TENTATIVE` 预选，不接受订单。
- 地图底部常驻稳定高度的“今日计划 0/k”抽屉。展开后汇总本候选集的 6 张单，并至少并列两套完整组合；每套比较净金币、现金可领时间、周单缺口变化和次日预测覆盖，另以次级信息显示完整计划完成时间。D1-D2 的周单项显示 N/A，不把六张单拆成无法比较的卡片墙。玩家可切换系统方案或编辑为另一套已验证组合。
- 点击抽屉唯一主操作“确认 k 单并去排产”时，服务端一次写入 `accepted_order_ids + candidate_set_id + plan_window_id`，生成 `draft_plan_id` 后深链到农场排产板；部分失败则全部不接受。返回地图仍可查看选择依据，不能靠跨屏记忆四张单。
- 地图标签、Mapbox attribution 和 telemetry 入口不得被 Godot UI 遮挡。
- 地图加载失败时显示节点网络示意图或列表，不能只剩黑屏。

### 12.3 农场屏

- 地块具有稳定尺寸和明确状态：空闲、成长、成熟、待收获。
- 首周不显示水、阳光、叶、人口、宝石等多资源顶栏。
- 选择空地后显示作物、时长、成本和下一回访建议。
- 选择成熟作物后唯一主操作为收获；批量收获在解锁后提供。
- D1 起提供 12 小时批次排产板：默认展示所选组合对应的两张排产卡、总成本、预计产出、仓库峰值和下次回访档；确认后以稳定时间轴显示每格最多 5 步及暂停原因。W2 扩到 24 小时时不改变操作结构。
- 批次报告合并展示自动入仓数量、与原计划的偏差和被容量暂停的地块；没有偏差时一键收起，不要求逐格点击领奖。
- Avatar 位于不遮挡农田的迎宾区，动作不能改变交互布局。

### 12.4 订单与物流

- 订单卡优先显示缺少的物品，而不是只显示最终奖励。
- 接受前显示预计最快完成时间。
- 派发时两种路线使用分段控制或清晰列表，不使用无文字彩色大按钮。
- 时间、费用和净收益同时可见。
- 运输完成后可从通知直达领取，不强迫先加载地图。

### 12.5 可访问性底线

- 路线和状态使用颜色 + 线型 + 图标 + 文字，不依赖红绿区分。
- 所有图标按钮有可见标签或无障碍名称，移动端不依赖 hover tooltip。
- 触摸目标至少 48 dp；地图小节点使用放大的透明命中区。
- 支持动态字号后，金额、时间和按钮文本不能溢出。
- 白色图标放在黄色、亮绿背景前必须实测对比度，不以概念图为准。
- 地图、3D 场景和复杂动效提供减少动态效果模式。
- TalkBack/VoiceOver 的地图替代结构应是一份可导航的节点列表。

## 13. 通知、离线与回流

### 13.1 通知

通知必须由用户主动订阅，分为作物、加工、运输三类：

- 默认每天最多 2 条。
- 同一时间窗口合并多项成熟或到达。
- 遵守本地安静时段。
- 锁屏默认只显示“作物已成熟”或“运输已到达”等通用文案，不包含真实地区、街名和节点；详细预览需用户主动开启。
- 不发送“你的作物要死了”“附近限时奖励”等惩罚或位置诱导文案。

### 13.2 离线状态机

```text
ONLINE_SYNCED -> DEGRADED_CACHED -> OFFLINE_READ_ONLY
                                  -> OFFLINE_PRIVATE_PENDING   (仅 G2b 实验)
OFFLINE_PRIVATE_PENDING / OFFLINE_READ_ONLY -> RECONCILING
RECONCILING -> ONLINE_SYNCED
RECONCILING -> CONFLICT_REVIEW --释放或重提命令--> ONLINE_SYNCED
```

- 无 GPS 但有网络：手选或使用上次经营区域，核心玩法完整。
- 有 GPS 但地图瓦片失败：使用缓存，或切换节点网络列表。
- G0-G1 弱网或离线进入 `OFFLINE_READ_ONLY`：只允许查看最近同步的农场与订单；联网恢复后再操作，避免虚假承诺离线进度。
- G2b 若验证写队列，进入 `OFFLINE_PRIVATE_PENDING`，只允许 `plant` 和尚未开始的本地 `queue_reorder`。命令携带 `last_server_version`、幂等键和过期窗口，本地先预占资源但不把待同步产出计入可消费余额。
- 待同步的离线播种只显示“等待同步”，不进入 `GROWING`、不显示成熟倒计时；服务端确认后才生成 `started_at`。冲突时保留作物与地块草稿供一键重提，但不补算尚未被服务器接受的生长时间。若这一语义在 G2b 仍造成明显欺骗感，就删除离线播种，只保留离线排程草稿。
- 多设备策略采用先到服务端者生效；旧版本命令冲突后释放本地预占并明确说明，不能静默吞单、复制收益或补算不存在的等待时间。
- 个人地区结算、市场刷新、物流派发与领取保持联网操作，直到完整租约与冲突模型经过验证；未来共享结算始终联网。
- `chapter_step` 不依赖客户端播放过哪段动画，而由“农场已创建、订单已领取、真实配方已完成”等服务端事实派生。重启、地图失败或重复回调后直接恢复到下一可行动作；教程样品与章节奖励分别使用唯一 `grant_id` 幂等发放，任何一次性表现丢失都不能永久卡章。

客户端可以估算倒计时，最终成熟和奖励以服务器时间为准。地图 SDK 缓存必须遵守供应商条款，游戏节点和网络示意图作为自有数据单独缓存。

### 13.3 回流

- 作物、加工品和已完成运输继续等待领取。
- 离开超过 48 小时后，只替换尚未接受的 `OFFERED` 候选。`ACCEPTED` 日单和周单必须继续显示“继续准备 / 主动放弃”，不能被回流逻辑静默覆盖；已经排程或到达的货物与回款照常保留。
- 配送额度最多积存到 8，不补发无限资源。
- 回流首个有意义操作应在 3 分钟内完成。
- 不展示连续签到断裂、腐坏损失和逾期罚款。

## 14. 安全、隐私与反作弊

### 14.1 数据最小化

以下是目标状态，不是当前 Demo 已满足的事实。当前 Android 插件会在进入地图时自动启动持续定位，并在日志中输出 last-known 的完整经纬度；两项都必须在 Alpha 前移除，否则本节不能作为隐私验收依据。

- 精确经纬度默认只在端内内存短暂存在。
- 服务端持久化 `operating_region_id`、节点 ID 和经营状态，不保存移动轨迹。
- `operating_region_id` 和稳定 `node_id` 仍是受保护的业务位置数据，限权、加密、限期保留且可删除，不进入普通分析域。
- 普通分析不上传原始 GPS、区域格 ID或稳定节点 ID，只记录区域类型、定位授权档位、合成/精选来源和归一化距离分桶。
- 截图、日志和崩溃报告不得包含 token、原始坐标或可识别住宅的视区信息。
- 提供清除最近区域、撤回权限和删除账号入口。

可验收的保留与删除基线：`device_fix` 在确认区域、离开地图、Activity pause 或 5 分钟超时中最早发生者立即从内存清除；本地 `view_center` 30 天未使用自动删除；当前 `operating_region_id` 只在该经营档案存续期间保留。用户清除区域或删除账号后，在线业务副本 7 天内删除，备份 30 天内滚出；法定留存例外必须单独登记且不可用于产品分析。普通分析事件保留 90 天，且从产生时就不含稳定区域、节点、分片或原始坐标。

地图供应商可能接收 IP、视区和遥测信息，需要进入隐私政策、App Store Privacy Label、Google Data Safety 和供应商 DPA 审查。

### 14.2 反作弊优先级

第一层防御不是检测假 GPS，而是让位置没有经济价值。其余经济使用：

- 服务端权威库存、时间、订单和个人地区进度；未来共享进度同样只认服务端。
- 命令带 `state_version` 与 `idempotency_key`。
- 账号和 API 速率限制。
- 设备时钟不参与奖励计算。
- 无自由交易、无现金化、无位置榜单、无稀缺公共槽。
- Play Integrity、App Attest、mock/provider、速度和不可达跳跃只作为风险信号，不单项永久封禁。

### 14.3 车速与现场安全

真实移动不加速任何玩法，也不在移动中推送附近任务。二期若加入无数值到访纪念，明显高速度状态下隐藏 CTA，只提示停车后使用，不提供“乘客模式”绕过。

### 14.4 未成年人

首发建议 16+。若未来面向更低年龄，未知年龄也按未成年人默认：定位关闭、只可手选区域、公共身份隐藏、无聊天、无附近玩家、无地点广告。年龄门槛不能替代隐私最小化。

### 14.5 地区发行边界

当前技术调研前提为海外发行和 Mapbox。若进入中国大陆，必须重新冻结地图供应商、GCJ-02、地图合规、审图/备案和个人信息处理方案，不能把现有 Mapbox 路线直接上线。

### 15.5 必做对照试验

使用完全相同的经营、订单和经济，建立两个版本：

- **Geo 组**：经营区域使用真实粗粒度地图，可命名和回看。
- **Control 组**：相同时序、特性和经济，但使用虚构地图。

随机化必须发生在 `region_choice_viewed` 之前，分组在实验期固定。Control 使用交互次数相当的虚构区域选择，但不请求与其功能无关的位置权限；因此主分析估计的是“真实地图带来的地点价值减去加载、授权和隐私摩擦”这一完整产品包效果，而不是只估计已经确认区域者中的渲染差异。手选区域用户的预注册分层分析可以辅助解释画面效应，但不能替代全量 ITT。不要让 Geo 组额外走路，否则又会混入移动惩罚。

前 100 名只校验分流、事件和严重摩擦；G3a 至少 300 名随机用户才有资格筛选大效应，并同时使用两个不可互相补偿的共主指标。完整分母、窗口与决策规则见 §20 Gate 3：

| 角色 | 指标 | 固定定义 | G3a 门槛 |
|---|---|---|---|
| 共主 A：机制 | 跨两日计划因果 | 两个不同活跃日主动比较两个节点、从地图接受需求并改变后续生产计划；未激活或未跨日计 0 | Geo 比 Control 高 >=15pp，且双侧 90% 区间下界 >0 |
| 共主 B：地点记忆 | 次日无提示地点回忆 | 首次 12-36 小时自然回访、重新显示市场标签前，无奖励询问昨日主要服务方向与对应地区线索；跳过和未回访在 ITT 中计错 | Geo 正确率 >=60%、比 Control 高 >=15pp，且双侧 90% 区间下界 >0 |
| 体验护栏 | 计划形成时长 | `candidate_set_exposed` 到 `production_plan_committed`；10 分钟未提交按 600 秒计入 | Geo 中位数不得比 Control 慢超过 `max(30 秒, 10%)`，且 P75 不得慢 10% 以上；变快只作正向解释，不是第三个主指标 |
| 诊断 | 非任务主动回看 | 首枚印记后 7 日内，从非任务、非通知、非章节入口打开历史图层，停留至少 5 秒且查看印记或发生平移/缩放 | Geo >=25%，且比 Control 高 >=8pp |
| 诊断 | 市场固定答案率 | 至少 4 个合格比较窗、冻结画像应有至少 2 次最优市场反转；仍有至少 80% 窗口选择同一市场者计为固定答案 | 合格用户覆盖 >=50%；固定答案率 <35%，且 Geo 不得比 Control 高 5pp 以上 |

两个共主指标必须同时过线，不能合成一个可调权重总分，也不能用 D7、第二节点使用或主动回看事后替换。形成计划更快但地点回忆不提升，只能说明地图降低当次操作成本；回忆提升但固定答案率过高，说明三个市场被学成固定按钮；机制提升但用户认不出服务地区，则真实地图仍未证明不可替代。地图打开后超过 70% 订单从快捷列表完成只是一条行为伤害护栏，自选入口不能当作 map-vs-list 的因果证据。

G3a 的 15pp 是小样本筛选线，不是最终成功标准。进入 G3b 前锁定确认方案：两个共主指标各自的最小有意义组间差均为 10pp；地点记忆仍要求 Geo 绝对正确率 >=60%；两项都要双侧 95% 置信区间下界 >0，任一失败即确认失败。功效和样本按更难的一项及“二者共同通过”计算，禁止沿用 G3a 数据改阈值。

若要用约 2-3 个百分点的 D7 绝对差异做正式决策，需要另行计算更大样本，不能塞进当前小规模封测承诺。

## 16. MVP 与研发路线

### 16.1 现有工程可复用能力

当前 Godot 工程已经具备：

- Mapbox 原生底图与 Godot 透明叠加的 Android PoC。
- 单一权威相机、平移、缩放、惯性和浮动原点。
- Android 已有 Demo 级权限请求和 location sample 桥；精确/大致/拒绝的产品状态、精度与新鲜度处理、显式触发和停止订阅尚未完成。
- 地图 Marker、相对锚定和地图到换装房的场景闭环。
- Avatar 换装、持久化、地图回写与移动端安全区。
- 统一设计 token 和 48 dp 触摸基线。

这些能力证明“地图 + Avatar”能连通，不等于已经有可运营游戏。当前没有生产经济、后端权威时间、订单生成、物流状态、公共分片和正式隐私模型。

### 16.2 产品化前必须改造

- 将 `home_lat/home_lng` 拆成设备定位、视图中心、经营区域、私人实例锚点和公共节点五种状态。
- 自己的 Avatar 从 GPS 点移走；现有附近假 Avatar 不能升级成真实用户位置。
- `START_LAT/LNG` 只可作为明确标注的演示区，正式产品失败时回到上次区域或手选，不伪装为“附近”。
- 地图默认手选路径不得调用定位；只有用户主动选择当前区域才请求系统权限。
- 为 `MapBridge` 和双端插件增加 `stop_location()`；首个合格 fix、拒绝或超时、离开场景和 Activity pause 都必须停止，重复进入地图不能自动重启。
- 当前定位 signal 只用于前台回中，不能作为服务端到场证明；回调必须带精度与新鲜度，不能无条件接受第一个 last-known。
- 删除或 release 编译期禁用 `GodotMapPlugin.kt` 中完整经纬度日志；日志只允许新鲜/过期、精度分桶、耗时和错误码，崩溃上报过滤坐标字段。
- 发布前自动扫描源码和真机日志中的经纬度、token 与 camera center；手选路径无弹窗、定位成功后无后续采样、切场景后无更新，三条均为阻断验收。
- 地图 Marker 数据改为稳定 `node_id` 和区域坐标，不再相对每个用户生成“附近的人”。
- G0-G3 的游戏节点全部使用随包或自有配置的合成节点；底图 POI 不进入产品数据。
- 地图标签按首发 locale 配置，不能沿用 Demo 的 English-only 过滤，否则会破坏“熟悉地区”的价值命题。
- 新增游戏状态、内容目录、服务器时间、批次排产执行器、订单、物流、outbox 和分析层。
- 地图不可用时提供 Godot 原生节点网络列表。
- iOS 透明叠加和定位尚未形成量产证据，Android 先行；所有现场功能保持 feature flag 关闭。

### 16.3 7 日 Alpha 的两段范围

玩家最终看到的 Alpha 仍是同一套玩法，但交付必须拆开，先证明冻结内容和权威状态能跑七日，再承担动态生成、定位与弱网写入风险：

| 能力 | G2a：固定夹具在线版 | G2b：动态与硬化版 |
|---|---|---|
| 地图入口 | 手选一个真实粗粒度经营区域；无地图时节点列表 | 加一次前台大致定位；手选仍平权，地图/list 降级完整 |
| 经营与时间 | 服务端权威地块、库存、扣款、批次、加工、物流和幂等；只接受在线写命令 | 加有限离线 outbox、冲突恢复、退款重试和弱网测试 |
| 内容 | `FW-AUDIT-01` 的 38+1 与 `FW-STEADY-01` 的 18+1 冻结候选，D0-D9 | 运行时订单生成器、换单/保底、10,000 次分布；通过后才开 D10-D13 耐久窗 |
| 目标 | 证明七日内容、两套计划、钱包/库存和 72h 运营尾窗在真机闭合 | 证明换状态、换作息和网络故障后仍闭合，并开始验证无扩建目标的重复循环 |
| 不在本段 | GPS、动态随机包、离线写入、共享项目 | 共享项目、iOS、实时 POI、商业化与赛季运营仍关闭 |

两段共享的不可删基线为：一个经营区域、7 个规范节点、一个私人农场；4 种作物、1 个配方、6-8 个地块、80-100 仓库；慢/快两条确定路线；D0-D6 七个活跃日章节、节庆单、周报与个人花园三阶段；Avatar 头像、迎宾和周奖励。D1 起的服务端批次排产必须支持 12 小时、每地最多 5 步、整单扣款、自动换茬、容量暂停、改单冲销和批次报告，没有它就不得宣称每日 2-3 次打开。

G2a 仍展示 D1 的 6 选 3、D2 起的 6 选 4和两套互不支配计划，只是候选来自冻结版本而非运行时随机。G2b 才启用 8 个模板的动态组合、每天 2 次免费换单和版本化保底。关键状态、金币流水、决策链、崩溃与地图加载埋点从 G2a 就必须存在；G2b 再补齐生成器与弱网诊断。最小区域目录、节点快照和图标始终随包，不能把可能命中的瓦片缓存当保证。

### 16.4 Alpha 明确不做

- 实时多人、附近的人、DM、UGC 和玩家交易。
- 真实到场奖励、步数、轨迹和后台定位。
- 真实 POI 搜索、道路级 Directions、实时天气和真实交通。
- 随机物流事故、作物品质、肥力、天气产量和 Avatar 属性。
- iOS 对外承诺、商店、广告、硬货币和付费通行证。
- 多地区自由套利、跨区交易、公会和排行榜。
- 共享公共分片、附近玩家贡献、公共排行榜和真实共同进度。

### 16.5 建议里程碑

以下估时假设 2 名 Godot/客户端工程师、1 名后端工程师、1 名产品/策划、1 名 UI/TA；从 G2a 开始 QA 与数据必须是明确负责人并全程投入，不能继续按“有空兼职”估。单工程师串行实现不应承诺完整 Alpha。

## 18. 对抗性审查

### 18.1 高风险命题与否决条件

| 攻击问题 | 最坏结果 | 当前护栏 | 可证伪指标 / 否决条件 |
|---|---|---|---|
| 地图只是背景 | 普通空间 UI 也能完成计划，真实位置成本纯浪费 | G1.5 随机 map/list 脚本；G3 机制与地点记忆两个共主指标 | 任一共主指标复测后仍不过线，或 D2 后 >70% 订单自选快捷列表，则降级地图；列表占比本身不作因果证据 |
| 地图变化与选择无关 | 同花园值玩家看到同一复绿动画，无法形成“这是我的经营史” | 等面积 `service_imprint` 按周槽位、距离档和路线纹理分布，数值进度保持相同 | D6 去标签三选一辨认 <60%，或半数玩家说不出一个真实痕迹来源，则删除个性化宣称 |
| 三个市场变成三个固定按钮 | 稳定角色被学成永远相同的答案，地图比较消失 | 冻结画像、单变量反转种子与随机状态覆盖率 | 合格用户固定答案率 >=35%，或生成器应反转的窗口覆盖 <50%，重做需求权重 |

### 18.2 最强反方论证

**反方一：这就是把普通农场贴在 Mapbox 上。**

这个批评目前成立一半。只有当玩家确实比较多个市场、通过地图理解路线、记住经营区域，并因地图变化而回访时，真实地图才进入因果链。必须用 Geo/虚构地图对照证明，不能靠访谈中的“看起来很新鲜”。

**反方二：既然拒绝定位也能完整玩，为什么还要位置？**

位置提供自动进入熟悉区域、地区记忆和地图叙事，不提供数值。如果这些非数值价值不足以提升使用和留存，就说明位置不是核心，不应该用奖励强迫它变核心。

**反方三：七日内容只有四种作物，太薄。**

对轻量经营，内容容量主要来自作息、节点订单、库存、一条加工链和路线组合。首周故意只用四种作物，以便识别选择是否真实。如果必须靠 20 种换皮作物才能撑到 D7，底层循环没有成立。七日测试后再根据重复率决定增加配方还是增加系统。

**反方四：物流只是在种植倒计时后再加一个倒计时。**

如果路线选择不改变净收益或领取时间，它确实是多余的。首周只验证“免费慢线、付费快线”能否随作息和现金缺口发生选择反转；合单留到第二周，且只有两路线已经成立才加入。选择长期单边时直接删掉物流交互，保留视觉动画。

**反方五：公共工程是伪社交。**

首发不应靠假 Avatar 和假附近人数制造热闹。没有真实共享后端时，应明确称为个人地区修复；有后端后再开放聚合分片，并如实说明系统保底。

**反方六：位置隐私和地图成本远大于玩法收益。**

这是项目级风险，不是文案问题。前台单次定位、粗区域 ID、无实时他人和地图降级能降低风险，但不能消除地图 SDK、法规和双渲染器成本。因此 Geo 对照 Gate 是继续投资的前置条件。

### 18.3 必须先于美术扩量的问题

1. 灰盒里地图是否真的改变订单选择。
2. 4 种作物和 8 个模板是否能形成至少两种可行策略。
3. 订单生成是否永远提供可行动项。
4. 两条路线是否在至少两个预注册情境出现合理反转。
5. D0-D2 是否能在不解释的情况下学会。
6. 拒绝定位、无地图和弱网是否仍可完成首单。
7. 7 日经济是否在轻度、目标和高频三类行为下都不破产、不膨胀。

在这些问题回答前，不继续制作更多城市模型、季节植物、车辆或 Avatar 动作。

## 19. 经济模拟与调参计划

### 19.1 必跑策略

上线前使用 §8.3 的 `FW-AUDIT-01` 作为首周可人工审计夹具：共 38 个日单 offer（D0 固定 2，D1-D6 各 6）和 1 张周单；再使用 §8.8 的 `FW-STEADY-01` 验证 18 个 D7-D9 offer 和 1 张 W2 周单。每单都可解析出 `candidate_set_id / selected / bundle_id / goods / reward / reputation / node_slot / distance_band / queue_position / route / accepted_at / scheduled_at / dispatched_at / arrived_at / claimed_at / plan_id`。首周 25 张 selected 复现总账；每章和每个稳态日的两套完整组合同时列出净金币、现金可领时间、完整计划时间、周单缺口和预测覆盖，并通过 §5.7 的可感知反转。实现测试还必须从这些表机械生成每批播种、自动换茬、收获、加工输入、容量峰值和期末库存夹具，不能另建一套手抄真值。随后对同一配置运行至少 10,000 次随机首周和三个稳态系统日，再模拟至少 90 天：

- 每日打开 1、2、4、8 次。
- 永远选最短作物。
- 永远选单位时长最高收益作物。
- 永远只做加工单。
- 每天清满 20 件，或永远不清仓。
- 永远不买装饰。
- 优先买地块或优先买仓库。
- 连续离开 2、7、14 天后回流。
- 城区、郊区、无 POI、拒绝定位四种区域身份。

模拟输入必须包含订单权重、可行性过滤、玩家回访窗口、批次计划步数与跨度、提交扣款/改单冲销、容量暂停、路线选择规则、快线使用率、满仓处理和升级策略；不能只用“每日平均收入减每日平均支出”。每次逐日输出期初/期末余额、分物品库存、手动/计划内地块状态、计划完成偏差、加工/物流队列、已领取订单、章节进度、主动动作预算和地图决策链，并对余额、库存价值、订单放弃、批次暂停、满仓阻塞与无可行计划次数报告 P10/P50/P90。

### 19.2 健康区间

经济报表必须拆开四类量：

```text
F = faucet：日/周订单、受限清仓、一次性章节、首清和补偿产生的金币
R = recurring burn：播种、加工和路线产生的重复消耗
P = progression sink：地块、仓库等有限次永久扩建
C = collectible sink：玩家实际购买的无属性固定价收藏
actual total sink = R + P + C
```

同时报告 `F / R` 与 `F / (R + P + C)`，不能把可跳过、终会买完的扩建算成稳定回收。确定性种子 A 的首周基准是 `F/R = 3,211/600 = 5.35`，`F/actual total sink = 3,211/1,300 = 2.47`；这是高补贴教学期的透明结果，不是成熟经济目标。若随机模拟只能靠制造额外播种、满仓或快线费用把比率压低，应判为模型失真，而不是健康回收。

在没有 D14 行为数据前，不承诺一个虚假的 D30 单点比率。先按每 100 金币来源设置内容预算，再用实际购买率校准：

| 阶段 | 重复消耗 R | 永久扩建 P | 实际收藏 C | 实际总回收 | 解释 |
|---|---:|---:|---:|---:|---|
| D8-D30，每 100 来源 | 35-45 | 20-30 | 0-20 | 55-95 | 玩家仍在扩建；收藏购买率未知，不能按满额假设 |
| 主要扩建完成后，每 100 来源 | 35-50 | 0-10 | 15-30 目标 | 50-90 | 允许非收藏玩家积累；无交易经济不强迫收支相等 |

首批金币收藏采用永久可见、无随机、无属性、全员同价：

| 收藏 | 固定候选价 | 价值定位 |
|---|---:|---|
| 小径/田埂样式 | 600 | 约 2-3 个目标活跃日的净储蓄 |
| 围栏或路牌套组 | 900 | 一次周内可达的小目标 |
| 车辆外观 | 1,200 | 物流表达，不改变速度和容量 |
| 地图 Pin 套组 | 1,800 | 地图表达，不改变节点收益 |
| 农场季节主题 | 3,000 | 约三周储蓄的长期目标 |

候选绝对基线按每周 4 个活跃日估算：约 `350 × 4 + 378 = 1,778` 金币来源；重复消耗占 35%-45% 时，扩建与收藏前周净储蓄约 978-1,156。由此 600 是数日目标、900 约一周、1,200-1,800 约 1-2 周、3,000 是约 3 周目标；实测来源变化后整体调一次配置，不能按个人余额动态定价。

商店永久保留已发布收藏，不用倒计时逼迫回收货币。每周应保持 1,500-2,500 金币的可选目录深度，不等于每周都制作同价值的新资产；这是“可购买需求”，只有真实购买才计入 C。若主要扩建完成玩家的 P50 钱包连续两周增长超过 15%，且超过 30% 的访谈用户找不到想买的固定价目标，判为内容型通胀；优先补横向收藏或减少后期来源，禁止维护费、腐坏、随机灾害和个人动态涨价。

以下物资分配带只用于 **D7-D9 稳态探针通过后的成熟观察窗**。分母固定为 `A_raw = 窗口开始时已入仓原料 + 窗口内实际入仓原料`；加工成品、仍在地块上的成熟物、尚未成熟的预计产出、免费领取箱和仅存在于 UI 的计划都不进入分母。对一个连续观察窗只在起点计一次期初库存；汇总 D10-D30 或 90 日时不能把逐周期初库存重复相加。

窗口内每一份 `A_raw` 必须按最终去向互斥归入且只归入一类：直接扣入日/周订单 `direct_order`、被配方消耗 `processing_input`、窗口结束时仍在仓且已硬保留给已接受订单 `committed_on_hand`、未承诺库存 `uncommitted_on_hand`、主动清仓 `clearance`。因此必须满足：

```text
A_raw = direct_order + processing_input + committed_on_hand
        + uncommitted_on_hand + clearance
```

成熟目标为 `direct_order 50%-60%`、`processing_input 25%-35%`、`committed_on_hand 10%-20%`、`uncommitted_on_hand 0%-10%`、`clearance <5%`；五项实际占比必须合计 100%，不是五个可以各自取上限的独立预算。原料进入加工时即归入 `processing_input`，其产出的 F 后续交单不得再计一次原料；窗口末已经付费且结束时间确定的地块/加工产出另记为 `future_committed_supply / ready_at`，用于覆盖风险，不混入上述百分比。D7-D9 只先验收重复消耗占来源 35%-45%、选择非支配和状态可执行；三天手工夹具不冒充已经满足成熟物资结构。

首周是教学和节庆交付周，不伪称满足成熟带。种子 A 排除 D0 Grant 后，D0-D6 实际入仓的付费原料池为 202：直接进入订单 176（87.1%）、进入加工 21（10.4%）、D6 结束时未承诺在仓 5（2.5%），三类合计 100%；已经付费但仍在地块的确定产出 22 另报 `future_committed_supply`，不写成已产出，也不进入 202 的分母。它只验收不破产、队列可执行和期末缓冲；若希望验证成熟物资结构，必须在 D7-D9 探针后另跑 D10-D30 模拟。Alpha 的个人花园值不吞货；Gate 后若做共享项目，也必须通过正常订单结算，不能再额外无偿销毁原料。

### 19.3 七日模拟验收

- 目标玩家种子 A 在 D6 以 2,211 金币和 7 格在种作物结束，为下一大扩建 2,500 的 88.4%；随机样本 P25-P75 应处于价格的 85%-95%。
- 轻度轨迹按 `[1, 1, 0, 3, 0, 4, 0]` 的跨日领取批次，在七个自然日后完成 D0-D2、严格达到 280 声望，余额约 884，另有四张 D3 日单在途；任一天都能支付 6 地块两轮最贵已解锁作物。第八日领取并完成 D3 后约为 1,284。
- 高频最优轨迹的候选区间为约 2,282-2,402 金币；部分随机种子可能在 D6 已达到 2,500，但仍只能在 D7 条件开放后扩地。验收的是来源被 25 个日单额度封顶，而不是强行让所有玩家停在同一余额。
- 在任何可选永久购买发生前，75% 内容完成者仍有足够金币填满当前全部地块至少两轮，P10 余额从不为负；购买后低于两轮运营储备的确认率和 24 小时救济触发率必须单独报告。
- 每日 1 次打开者未解锁加工时，生成器不提供强制加工单；第二节点不可用时不提供强制跨节点单。
- 高频玩家不能在 D3 前解锁 D5 系统，受限清仓收入必须显著低于正常订单，且每日封顶 20 件。
- 任意满仓路径中，成熟作物留在地块、加工品留在输出位、章节物品留在领取箱，丢失物品数必须为 0。
- 10,000 次订单包模拟中，应用保底后的玩家无可行订单包为 0；D1 的两组 3 单计划、D2 起的两组 4 单计划及当日即时可行护栏通过率均为 100%。同时单列保底前失败率、失败原因和连续触发次数，不能让保底掩盖生成器失效。
- 对可达状态空间按短回访、周单收口和隔夜稳健三种预注册画像，分别报告“只改回访档 / 只改物流队列 / 只交换距离档”时的推荐计划反转覆盖率与无反转率；三组手工样例通过不能替代分布验收。
- 对每个完成 D6 的模拟状态继续运行 D7-D9：先用 `FW-STEADY-01` 复现 A/A/A 的 `2,427 -> 2,631 -> 318` 钱包、D9 +180m 周单就绪、隔夜档 3/2/2 及短中档不超过 3/3/3 会话，再运行随机包。关闭章节金币、首清和新系统，只保留每日 4 额度、6 选 4、现有批次/加工/物流/地图痕迹。任何一天出现余额低于 0、购买后两轮储备不可恢复、`required_fourth_session=true`、preload 重复扣款、plot lease 冲突或保底后仍无可行包，均判 G2 失败。
- 不同区域和定位权限的同活跃玩家，D6 金币与声望中位数差低于 5%。

## 20. 决策 Gate

### Gate 0：概念理解，观察与分析约 1 周

- 12-15 名目标用户看灰盒。
- 以具体人数判定：12 人时至少 10 人、15 人时至少 12 人能无提示说出“地图找需求，农场生产，路线交付”。
- Avatar 被误认成工人、真人位置或属性载体的用户不超过 2 人，且不得出现无法修复的安全误解。
- 愿意提供大致前台位置、愿意手选区域、以及偏好真实/虚构地区分别报告人数和原话；小样本不把 60% 写成精确市场结论。

不通过：不进入城市美术和共享公共项目制作。

### Gate 1：可用性，测试与修复约 1-2 周

- 10-15 名用户测试 APK。
- 10 人时至少 8 人、15 人时至少 12 人在 5 分钟内独立完成首单；失败必须按地图加载、授权、教程或订单不可行逐例归因。
- 同样人数能区分当前位置、Avatar、私人入口和需求节点；所有人都必须能在拒绝定位后继续手选区域。
- 位置泄露、无法停止定位、物品丢失和无路可走订单均要求 0 例；地图加载或授权造成的阻断不超过 1 人。

不通过：先修流程，不增加作物和订单数量。

### Gate 1.5：地图/列表脚本筛查，约 3-5 天

- 另取 12-16 名目标用户，用同一库存、订单、节点名称、距离档和收益做两道等难任务；一道从熟悉地区地图进入，一道从同一批节点的结构化列表进入，不混入虚构布局。顺序随机且互换题目，避免学习效应被误算成地图价值。
- 当场记录完成、错误、计划形成时间和具体决策理由；12-36 小时后在不展示标签、不发奖励的情况下回忆服务方向与地点线索。该小样本只负责尽早发现明显伤害，不声称统计显著。
- 若真实地图中位计划时间慢 60 秒以上、错误率高 10pp 以上，或没有更多用户能复述地点如何改变计划，先迭代节点信息一次；复测仍无方向性优势，则不进入大规模 Geo 实验，地图先降为可选表现层。

这一步提供受控的 map-vs-list 证据；正式产品中的快捷列表占比仍只是自选行为，不能代替随机比较。

### Gate 2a：固定夹具七日 Alpha，观察与修复约 2-3 周

- 12-20 名目标用户使用在线写入、手选区域和冻结的 `FW-AUDIT-01 / FW-STEADY-01`；测试员可以约访，但不能代操作、发额外资源或跳过章节时钟。
- 每名用户仍按 168 小时核心窗运行；核心窗内完成 D6 者再开固定 72 小时运营尾窗。此阶段主要看状态重放、理解、有效决策和会话负担，不用被约访样本声称自然留存。
- 任何双扣、丢货、不可恢复容量阻塞、订单无解、章节重复发奖、第四次必需会话或定位/身份泄露都阻断 G2b。冻结 A/B 被多数用户理解为同一个答案换标题，也必须先重做题面。
- G2a 只证明手工内容与核心状态机可运行；它没有权力证明动态生成、公平分布、弱网写入或长期自驱。

### Gate 2b：动态七日 Alpha，招募、观察与分析约 2-3 周

- 30-50 名目标用户。
- 主分析从 `study_enrolled_at` 起对全部入组者观察满 168 小时；未回访、未激活和未完成章节者仍留在 ITT 分母并按 0 计相应成功，不把“完成七天”当入选条件。招募较晚者的 168 小时窗口顺延，不能因统一截数日被截短。
- 研究同意在入组时一次取得；所有在主窗口内完成 D6 的玩家自动获得 D7-D9 稳态配置，不再用“愿意继续”筛选。为每位完成者单独冻结 `steady_probe_window=[steady_probe_eligible_at, steady_probe_eligible_at+72h)`：D7 可在起点进入，之后跨两个 04:00 边界开放 D8/D9，最不利边界下仍给 D9 至少 24 小时回访。到窗仍未进入或未闭环的系统日计 0；窗口不因打开较晚而顺延。
- 这 72 小时只是 D6 完成者的无奖金运营诊断尾窗，最晚会把单个用户的数据采集延长到主窗口后 72 小时；它不修改全员 168 小时 ITT、D1/D7 留存或其他主指标的截止时间，也不把未在 168 小时内完成 D6 的玩家移出主分母。最后一名合格完成者的 `steady_probe_window` 结束后做第一次 `core_lock`，只判断七日经营与 D7-D9 运营稳定性；自愿访谈只作解释，不能验证自驱回访。
- 安全与状态是硬门：位置/身份泄露、不可恢复丢货、重复领取、经济死锁均为 0；拒绝定位和地图失败路径必须能完成首单。
- 首单激活 60%、日历 D1 30%、日历 D7 12% 和激活用户使用两个需求节点 40% 都是方向性参考；逐项报告人数、分母和区间，不能让其中两项的好看结果补偿经营循环失败。
- 稳态诊断至少要有 12 名在核心窗内完成 D6 的玩家；不足就延长招募并明确写“证据不足”，无权用 4-6 名幸存者进入 G3。以全部这些 D6 完成者为固定分母，至少 50% 在 72 小时尾窗完成 D7-D9 中两个完整供给链，且至少 50% 有两次从非通知、非章节入口开始的计划回访；未进入某个系统日计 0。
- 对全部 D6 完成者逐人报告完成 0/1/2/3 个运营探针闭环、按自选窗口回访次数、章节奖金移除后的净金币、生成器保底次数和安全动作提前次数；未进入 D7/D8/D9 分别计 0，不只报进入者。
- `core_lock` 后继续按 §8.8.6 自动观察所有 D9 完成者的 D10-D13：从各自 `d10_eligible_at` 起固定 96 小时，不因迟开顺延。最后一名耐久窗结束后做第二次 `endurance_lock`；至少 12 名 D9 完成者且至少 50% 再完成两个有效供给链才通过。样本不足或门槛失败时，不进入 G3、不制作赛季内容，只能延长招募或修重复循环。
- 会话负担硬门沿 §15.4：建议会话主动时长 P75 <=8 分钟、单活跃日核心主动 P75 <=18 分钟、10 分钟计划超时占比 <10%，且 `required_fourth_session=0`。这里的强制会话指按已显示计划操作仍不可避免的额外打开；主动提前看倒计时、可选地图回看和设置通知不计入。
- 强烈认为真实地图麻烦、权限不信任、章节撞门和无动作会话分别报告计数与访谈原因；任一核心摩擦在小样本中达到 5 人即必须先迭代。

Gate 2 的经营硬门不可被地图打开率或幸存者质量补偿，必须同时满足：零安全/状态硬阻断；全入组七日经营 ITT >=25%；§15.4 的 D5 机械稳态、两会话降载、有效决策日和 `required_fourth_session=0`；D7-D9 与 D10-D13 各自至少 12 人及对应 50% 门槛；运行时经济与 10,000 次模拟都不出现负余额、丢货或保底后死锁。任何一项失败都先修核心循环，不进入 G3。

经营硬门通过后，只有“两个需求节点 >=40%”或地图因果链方向性达到其预注册参考线中的至少一项，才值得进入 G3a 测真实地图增益。若经营成立但地图两项都弱，只允许做一次节点信息/入口迭代和 G1.5 脚本复测；仍弱则地图降为表现层。D1/D7 留存继续作为招募与价值背景，不参与“二选三”式过关。

### Gate 3：Geo 对照 Beta，招募与实验周期另估

- 可以先用 100 人检查埋点、分流和严重摩擦，但该阶段无权判定通过。具备方向性决策资格的 G3a 目标为至少 300 名完成随机分组的用户，约 150 人/组；实际下限要在看到 Control 基线后重新做功效分析。
- 在首次 `region_choice_viewed` 前随机分组，分组在实验期固定。Geo 与 Control 的节点数、拓扑题、距离档、订单、经济、教程核心和性能预算同构；Control 使用虚构区域且不请求无功能必要的位置权限，入口差异本身属于完整产品包成本，必须留在主效应中。
- 主分析采用 ITT：分母是全部成功随机化用户。区域选择前退出、拒绝定位、未激活、未到 D2、未跨两日或事件缺失者在两个共主指标中按预注册失败规则计入，不能随机后只挑幸存玩家；“手选区域”与“已到 D2 且跨两活跃日”只作为预注册副分析。
- 单日成功定义为：从地图 surface 第一次打开需求节点开始一个 `plan_window_id`；10 分钟内查看两个不同 `session_node_slot`，从其中一个通过地图接受订单，并在窗口开始后 30 分钟内提交比查看前快照至少改变 2 个地块的生产计划。服务器事件 ID 去重，快捷列表接受不计主指标分子。两个不同活跃日各成功一次才计为主指标成功。
- `map_node_opened -> order_accepted -> production_plan_committed` 必须共享 `plan_window_id`，订单还要共享 `candidate_set_id` 与会话节点槽；提交计划时产生 `plan_id` 和 `planned_order_ids`，后续 `order_scheduled -> order_dispatched -> delivery_claimed` 必须携带同一 `plan_id`。D7、单纯打开地图、第二节点使用和 per-protocol 结果都只作副指标，禁止事后用 `OR` 选择最好看的结果。
- 访谈从成功与未成功、Geo 与 Control 中分层随机抽 12-20 人；不能只访问成功用户。报告能否具体描述地区线索如何改变计划，以及未改变的原因。

G3a 按以下优先级顺序决策，前一条触发后不再被后面的正向结果覆盖：

1. **硬阻断**：出现位置/身份泄露 P0，立即停止；Geo 激活率点估计比 Control 低超过 5pp，计划形成时长违反 §15.5 体验护栏，或地图快捷列表完成占比超过 70%，不得进入确认实验，只允许针对加载、授权、信息层级或入口做一次摩擦修复。
2. **进入 G3b**：随机样本 >=300，机制共主指标与地点记忆共主指标都满足 §15.5 的绝对值、组间差和 90% 区间门槛，且未触发硬阻断。
3. **迭代一次**：未触发硬阻断，任一共主指标组间提升在 `[5pp, 15pp)`，或达到 15pp 但区间仍跨 0，同时分层访谈能稳定复述地图因果。只改节点信息和交互，不加新系统；另一共主指标已经过线也不能补偿失败项。
4. **地图降级或停止**：完成一次迭代后任一共主指标仍不满足第 2 条；或任一指标提升 <5pp/方向为负；或多数分层访谈无法说明具体地区因果。

激活率的 5pp 在 G3a 只是产品伤害护栏，不声称完成统计非劣检验。G3b 必须分别按机制与地点记忆的 Control 基线做功效分析，并为两个共主指标共同通过预留样本；只按较容易的一项估样本无效。若机制目标为从约 20% 提升到 30%，单看这一项通常已需要约 300 人/组、总计约 600 人，完整确认实验只会相同或更大；它不包含在实现估时或小样本观察承诺中。

G3b 的最终判定沿 §15.5：两个共主指标都达到预注册 10pp 最小效应、地点记忆绝对值门槛和 95% 区间要求才通过；任一失败都不能靠另一个指标、访谈或副指标补偿。确认失败后真实地图降级或项目停止，不再进行第二轮指标替换。

决策：

- 经营成立、地图无增益：地图降级为可选表现层。
- 地图归属成立、经营弱：转向地区收藏或生态修复，不继续堆生产链。
- 两者都成立：再评估共享项目、社交和赛季扩展。
- 两者都弱：停止项目，不靠美术补救。

## 22. 立项建议

建议先批准到 G2a，而不是一次性批准“完整地图农场”：这是一个可被否定的 7 日纵切，动态生成、定位、弱网写入和 Geo 大样本分别在后续 Gate 追加预算。

> 一个经营区域、一个私人农场、三个市场、一个加工站、一个配送站、一个个人地区花园；四种作物、一个配方、八个订单模板、两条路线和一份首周结算。

先用灰盒证明以下链条：

`真实地图带来节点选择 -> 节点选择改变生产计划 -> 生产计划改变物流选择 -> 一周后地图变化值得回看`

若链条中任一箭头无法通过行为数据和访谈同时证明，就缩短或删除该层。G2a 只批准固定夹具与核心状态，G2b 必须先通过不可补偿的经营硬门，G3 的机制和地点记忆两个共主指标再决定真实地图是否值得保留。只有这些链条成立，才继续投入真实 POI、复杂城市美术、社交、更多 Avatar 资产和商业化；D10-D13 未通过前也不得宣称长期自驱。
