# 队伍跨街区汇合方案

> **资料范围（2026-10-05 清理）**：当前玩法、数值、操作与分期统一以 [玩法方案 v2](gameplay-plan-v2-2026-10-02.md) 为准。保留跨场景票据与再验证、角色/账号归属保护；旧免费队伍汇合与访问权限应让位 v2 第11/12章旅行/关系/客票规则。

状态：2026-09-16 用户已采纳测试阶段方案；0.10.1 已实现并上线，APK 和验证详情见下方发布记录。
用户确认双方已在同一队伍，但无法找到/访问队友农场，无法在地表场景汇合。

## 线上诊断

本次只读查询确认一个非发布测试队伍有两位成员，地区均为上海，街区布局分别为 `sh_b` 和 `sh_a`，
两座农场访问权限均为 `only_me`。数据库中保存的矿井实例绑定也不同；保存的绑定不代表实时所在楼层。

修复前，街区实例包含地区、蓝图、修订和线路，因此同一线路号不能让不同街区的成员相遇。
农场发现依赖“附近农场”，访问仅支持公开农场；队伍面板只有成员管理，没有跨区拜访或跟随场景的入口。
矿井选实例已经独立于地理区域：队长当前在矿内时，队员主动出矿再进会跟随队长。

## 0.10.0 旧版临时测试路径

保留当前队伍。队长从自己的农场进入矿井，留在第一层入口；队员从自己的农场进入矿井。
队员若已经在矿内，使用出口回农场再进入，随后双方一同下楼。
无需先访问对方农场；重新登录/断网重连会恢复原实例，不能代替主动出矿再进。

## 0.10.1 已实现规则

在队伍面板增加成员当前场景、线路、矿井楼层、在线状态，以及主要操作“前往队长”。
成员行另提供“拜访农场”，并可前往该队员所在的街区/农场；矿井匹配始终以队长为准。
入口直接按队伍成员定位，不依赖附近列表。

| 目标场景 | 行为 |
| --- | --- |
| 街区 | 加载目标成员的街区布局与访客展示，进入其当前线路，从公共入口出生 |
| 农场 | 加载目标农场的访客视图及导航，进入对应农场实例和线路 |
| 矿井 | 明确作为主动出矿/重新入场操作，重新验证队长当前在矿内，再绑定队长实例；落在队长所在层的安全入口 |

矿井汇合到队长当前所在层；普通主动重新进入矿井也采用该楼层规则。
服务器仅允许前往队长已合法进入的楼层；不直接修改清层、掉落、个人永久电梯或其他玩家的层数。
队长在矿外/离线时，“加入队长矿井”不可用；普通矿井入口仍遵循原有个人绑定规则。
组队、转让队长、其他人的场景变化均不自动传送当前成员。

农场增加“允许本队访问”的独立选项，由主人开启。队友只有访客权限，离队后访问资格失效。
访问资格与全服公开设置分别管理，农场经营权保留给主人。

## 实现边界

- 服务器向本队成员提供在线位置摘要，区别断线、地表场景、矿井实例与楼层。
- 点击汇合后服务器解析目标，返回场景类型、农场、街区布局、线路、安全入口和短期入场凭据。
- 加入时重新检查队伍关系、主人允许的访问范围、目标是否变化和 300 人容量。目标变化时更新提示，避免静默进入别的实例。
- 客户端加载目标布局和访客数据后加入实时房间，保留自己的身份、背包、角色和农场归属。
  离开拜访场景后返回原场景，不更改本人的城市选择或农场位置。
- 有未确认的采矿/攻击/库存操作时先完成结算，再进行跨场景移动；短暂断线恢复仍回原实例。

## 验收范围

覆盖同城不同街区、不同城市、不同线路、两个仅自己可见的农场开启队伍访问、权限拒绝、离队失效、
队长三层而队员一层、队长在矿外、汇合过程中队长换场景、满员、传输断线和拜访返回。
双端确认相同实例及相同楼层，并验证双方各自的原农场、城市归属、人物与背包保持正确。

验证使用隔离账号与存档；线上玩家既有队伍、矿井绑定和农场数据不作为测试夹具修改。
实际覆盖与测试限制见[发布验证记录](../qa/party-travel-public-release-2026-09-16.md)。
