日期：2026-09-07。状态：工作区可运行的首版实现，已通过部分 vivo 真机流程检查，见[真机记录](journey-physical-2026-09-07.md)。独立检查 APK 已安装；尚未部署、对外发布或完成新玩家试玩。

本文保留 domain 3 首个切片的实现与验收历史。当前 domain 4 的资源路线、持续设施、地面拖动和独立运行目录见[第二轮记录](journey-expansion-2026-09-07.md)；下文版本号、存档目录与 APK 状态不能当作最新版本说明。

## 已实现

- 新建普通农场默认启用 `journey.version = 1`。萝卜、生菜、胡萝卜、洋甘菊分别为 3/6/12/18 分钟；料理与地点按行动事实解锁，现实日期只继续管理环境与离线生长。
- 开局批量推荐先处理 3 格，首批生长时推荐田外探索。厨房开放后，批量播种优先安排缺少的沙拉材料，一次 1 格，留下其他种植空间。
- 苗圃、小馆、庭院可以从地图直接进入。显示未领取木料、侧径与庭院变化；原附近农场列表改为主动打开。Mapbox 不可用时显示可操作的街区连接示意图；示意图不伪装成真实街道底图，也不显示无效的地图缩放控件。
- 点击 NPC、木料、工作台、备餐台、餐桌、侧径和庭院标识，角色自动走近后交互。也可以点人物/物件附近的实际场景位置。标识避让重叠；普通探索默认关闭面板，临时面板不超过可用高度的 39%。
- 持久化木料探索轮次：已领取节点不会因重进场景或重发命令恢复。当前可达节点领完后可开始下一轮；侧径开放后新增一个资源点。
- 4 木料修工作台、2 木料制作首个花箱、2 木料修侧径。共同用餐消耗实际制作的沙拉；种花消耗 1 株洋甘菊。工作台、菜肴、苗圃与空/有花花箱具有对应场景状态。
- 首个花箱可直接点地面摆放、移动、旋转、撤销和保存。解锁后可以继续使用已有的六种摆件。路径计算避开已摆物件和固定设施，交互点会选择邻近可站位置。
- 小馆、苗圃、修缮师各有两种循环请求。交付消耗真实材料并轮换需求；可以无奖励地更换请求，确保空仓玩家能持续通过纯木料请求取得周转收入。
- 原料售价 5/8/12/16，沙拉/茶售价 24/18，摊位无每日限额。默认批量出售保留首份沙拉所需食材、首份沙拉和首株花。工具和扩地允许先后购买，各一次。

## 存档与版本

- 服务端领域版本为 3，状态 schema 为 1。旧 G3 存档仍保留旧规则；旧账号可从生活面板主动开始旅程。
- `start_journey` 保留钱包、库存、已购买成长、已有章节和合照，不改已种作物的成熟时间。旧工程预留标签解除，原有农产品仍在库存。已有章节发放的 C/H 奖励不会重复发放。
- 数据库升级工具支持 domain 1/2 到 3，只接受当前或确切的上一版内容哈希；默认只报告。历史命令结果和旧快照保持不变。迁移本身不会把旧账号强制切成新玩法。
- 本轮只在专用测试库与新建的 `sensen_farm_journey_playtest` 中写入验证数据，没有部署线上服务或迁移现有业务库。

## 运行

```sh
node tools/dev/run_journey.mjs
```

依赖：Godot 4.7、Node、服务端 workspace 依赖、`server/.env` 的 `TEST_DATABASE_URL` 和 `TOKEN_PEPPER`。首次启动需有创建独立试玩数据库的权限。启动器使用回环地址和空闲端口，窗口关闭后服务退出，数据库与 `sensen-journey-playtest` 客户端存档保留。

生成的隔离工程在 `output/journey-playtest/project`；源资源链接到本工作区。不会覆盖原客户端的 `server.txt`、安装密钥、选址或服装。正常再次启动会载入上次旅程农场。

自动冒烟流程使用独立的 smoke 客户端目录，每次创建新的验证身份：

```sh
node tools/dev/run_journey.mjs -- --journey-smoke
```

## 验证证据

本轮结果：服务端类型检查通过，含 PostgreSQL 的服务端测试 364/364 通过；Godot 农场 173、地点 71、地图 110、网络 59、旅程 4 项通过。原生场景检查覆盖 360×640、390×844 与 960×720，18 组场景状态、36 张探索/面板截图通过像素、边界与导航检查；真实 HTTP 冒烟流程通过。

- 服务端新流程测试覆盖同日完成 6 个里程碑、15 分钟后离开再回来、重复交付、领取幂等、过期轮次与请求拒绝、空仓恢复、旧存档转换、两种购买顺序和原有 G3 回归。
- 90 分钟的理想高频经营模拟：9 格萝卜共收 30 轮，累计销售 1350，钱包由 180 变为 438，结尾已支付下一轮种子。该模拟不计真实操作和移动耗时，不能作为玩家时长结论。
- 理想同日闭环在第 33 分钟完成种花；第 15 分钟离开、第 30 分钟继续的轨迹在第 48 分钟完成。两个结果只证明成熟时间、材料与前置关系可行，不证明有 33/48 分钟主动内容。
- Godot 农场、地点、地图、网络与旅程测试分别验证已有交互回归和新开局/出售/旋转规则。日志位于 `output/journey-*-tests.log`；完整服务端含数据库结果位于 `output/journey-server-db-tests.log`。
- 原生图形探针检查三个地点的改造前后、探索与面板状态，采样场景像素并检查控件边界、标识重叠、目标可达性与人物移动。截图和报告在 `output/journey-visual-probe/`。
- 实际触摸事件经过 Godot、HTTP 和 PostgreSQL，验证地图进入苗圃、走近采集、采集物消失、重新读取后仍记住领取、点击居民完成初见。报告和地图截图在 `output/journey-playtest/`。没有使用 QA 跳日或补材料命令。

## 尚未证明与后续优先项

这是一条可玩的首版闭环，不是完整设计已完成，也没有证明新手愿意连续游玩 60–90 分钟。下一轮首先观察自然玩家何时失去目标，再决定扩充哪些内容。

当前地图仍以三个地点的连接和状态为主；真实街道障碍、可选择资源组合和有分量的路线决策尚不足。采集主要重复相同木料点，制作只有首个花箱，循环需求仍可能很快变机械。NPC 已会回应事件并转向，但没有复杂活动日程。布置已有点按操作与旋转，尚未加入拖拽手势。制作反馈还需补足过程表现。原图形探针的手机尺寸截图来自桌面原生渲染；新增 vivo 真机截图、实测范围与剩余问题见[真机记录](journey-physical-2026-09-07.md)，iOS 验收仍未完成。
