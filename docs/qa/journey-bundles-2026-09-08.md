# 场景资源取舍与制作闭环

日期：2026-09-08。继续推进“60–90 分钟主动游玩、模拟器验证玩法与交互、强化 3D 表现”的目标。本轮增加每个采集点的材料选择，让重复探索能服务于不同制作需求。完整目标仍未完成。

## 本轮实现

修好工作台后，从场景木牌开启的下一轮路线会出现相邻的两份材料堆，每个采集点只选一份。点击实际物件，角色以速度 3.75 点到点跑近，播放采集动作后向服务端请求结算；成功后显示实际获得的材料，两份候选物件一起移除。

| 地点 | 原有组合 | 另一份选择 | 开放条件 |
| --- | --- | --- | --- |
| 苗圃两侧，木料路线 | 每处 2 木料 | 每处 1 石料 | 修好工作台后的新路线，且侧径已开放 |
| 苗圃侧径，木料路线 | 3 木料 | 2 石料 | 同上 |
| 庭院两侧，石料路线 | 每处 1 木料 + 3 石料 | 每处 3 木料 | 修好工作台后的新路线 |
| 小馆两侧，芦苇路线 | 每处 1 木料 + 3 芦苇 | 每处 3 木料 | 修好工作台后的新路线 |

苗圃少量石料提供就近制作的选择，庭院仍是更多石料的来源。上述数字是对应专项路线的产出；旧的未领取资源保留原组合，直到玩家在该地点开启新路线。教学首轮没有额外选择。

资源堆分别显示木料、石料和芦苇造型，纯石料不再混入木料模型。候选材料使用跟随物件投影的紧凑文字，混合材料分两行，人物靠近时淡化；不进行跳动避让或增加连线。采集复用现有清理、翻土、播种动作，持续约 0.9 秒后发送命令；没有新增专用采矿或捆扎动画。

地图优先显示追踪目标，其次显示可选材料；工程和修复目标查找材料时也会检查另一份资源，定位到对应物件。路线木牌提示每处只能取一份。

服务端沿用原采集点 ID 作为共同领取凭据，增加可选的 `choice` 参数，旧客户端默认选择原组合。重复领取、换选同点另一份、过期轮次和未解锁选择均拒绝。刷新某个地点只清除该处的领取与选择记录，其他地点继续保留。

主要文件：`assets/farm/data/journey.json`、`server/src/domain/journey.ts`、`modules/farm/journey_progress.gd`、`scenes/place/journey_place.gd`、`scenes/place/journey_activity_panel.gd`。

## 玩法审查与后续

本轮使采集有了可影响制作安排的材料取舍，也验证了“资源选择 → 制作 → 场景修复 → 食材 → 料理招待”的用途链。但选择仍发生在固定的相邻物件之间，取完再开下一轮的操作仍然重复；材料用途虽然改变了取舍，尚未证明能持续激发探索欲。

后续优先验证玩家是否看得懂两份资源之间的互斥关系，并让已修复连接、目的地距离和居民需求更直接影响路线决策。当前真实街区道路拓扑仍未进入可玩循环；不能把材料选项数量当作地图深度。

还需要从新存档观察陌生玩家的首次迷路、等待、主动改选和重复劳动比例，再处理最早出现的无聊点。本轮操作者熟悉实现，过程包含开发停顿，不能算自然玩家 60–90 分钟主动体验，Goal 保持 active。
