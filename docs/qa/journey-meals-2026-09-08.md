# 料理交付与居民场景反馈

日期：2026-09-08。目标仍为支持 60–90 分钟主动游玩，通过模拟器验证玩法、交互并强化 3D 表现。本轮解决重复料理交付缺少场景反馈的问题，不代表整体目标完成。

## 实现

- 小馆重复请求引导玩家走到备餐台和餐桌；主理人面板中的当次操作前置，避免被故事正文挤出可见区域。
- 成功交付才显示对应的沙拉或茶，关闭面板，保留获得金币的反馈。请求轮换后仍展示实际交付的料理；移除仅凭历史用餐事实永久显示的沙拉。
- 主理人跑到餐桌旁、挥手回应，再跑回原位置。复用点到点寻路与 3.75 移速；玩家移动或交谈时暂停，继续时按玩家和其他居民的实际位置重新寻路。
- 人物标记与身体点击区域随实际位置更新。餐盘显示期间隐藏桌子标记，保留桌面点击，避免标记遮住料理。
- 餐盘显示八秒。长对话期间到期后清除，关闭对话直接返程，不再面对空桌继续回应；重新生成居民时取消旧人物的演出并更新寻路。

主要文件：`scenes/place/journey_activity_panel.gd`、`scenes/place/journey_place.gd`、`modules/farm/resident_moment.gd`。没有修改本轮的服务端规则、经济数值、领域版本或存档结构。

## 目标仍未完成的部分

1. 尚未完成无引导的新玩家自然首小时试玩。本轮包含开发停顿、熟悉实现的操作者和已有进度，不能计作 60–90 分钟主动内容或自愿继续的证据。
2. 地图目前仍以固定地点和有限路线为主；需要继续验证材料差异、修复连接和行走关系是否真正影响目的地选择，真实街区道路拓扑仍未接入玩法。
3. NPC 只新增了交付事件触发的靠近与挥手。没有通用日常活动、坐下或进食动画，场景生活感仍需继续完善。
4. 重复料理仍只有沙拉与茶，需要观察两轮之后是否有新的材料用途取舍，及设施补给是否压过种植收益；增加演出不等于解决循环单调。
5. 其他地点请求成功后也使用面板回收信号；本轮模拟器未逐一重跑这些交付路径。已有自动化通过，但不能扩大为全地点触控验收。
