# 新旅程真机检查

日期：2026-09-07。设备：vivo V2509A，Android 16，1080×2344，密度 480，Vulkan / Mali-G1-Ultra MC12。

本文保留首版 domain 3 的验收历史。最新 domain 4 安装包、持续设施、地面拖动与种花供茶验证见[第二轮真机记录](journey-physical-v4-2026-09-07.md)。

## 范围与隔离

- 从选城、地图选址开始，使用正常旅程规则和真实 ADB 触控。
- 独立包 `com.sensen.journeyqa`，显示名 `Sensen Journey QA`。没有覆盖 `com.sensen.avatarphase1`，没有读取、清空或迁移原应用存档。
- 仅连接回环试玩服务和专用 `sensen_farm_journey_playtest` 数据库，没有部署线上服务。
- 没有跳日、改时钟、赠送测试材料或直接调用玩法回调。萝卜、生菜、胡萝卜按 3/6/12 分钟自然成熟。
- Android UIAutomator 只暴露 Godot Surface；检查包的只读观察器导出当前 Godot 控件树、裁剪后屏幕边界和收到的触摸事件。ADB 按这些边界操作，未从截图猜测点击坐标。
- 观察器和检查路由仅在独立调试包、显式启用检查的回环服务中使用。它们不注入玩法命令。

## 本轮修正

1. 场景标记在进入场景主题前设置尺寸，被项目默认主题撑大为约 54×50。改为挂入控件树后设置 44×44，真机屏幕边界由约 162×150 px 恢复到 132×132 px。
2. 居民对话标记上移，苗圃居民脸部不再被自己的对话按钮遮住。其他标记仍可能遮挡走近的玩家，尚未实现动态人物避让。
3. 选地文案从 `9 plots · 12 in week one` 改为 `9 plots · expandable to 12`，移除旧规则的周进度暗示。

## 产品结论

首轮生产等待已能接上采集、居民、修复和制作，行为里程碑确实能在同一天推进。但本次只能证明玩法链路可操作，不能证明新玩家觉得好玩或愿意持续玩 60–90 分钟。

下一轮优先改善：

1. 地图地点卡较大，连线在真实街道上交叉，地点卡与锚点的对应关系不够直观。应减少遮挡、清晰表达连接，并让路线选择带来资源或事件差异。
2. 采集轮次重复相同木料点，制作过程主要是点击后切换状态。需要不同资源用途、沿路发现和看得见的制作过程，而不是仅延长采集次数。
3. 布置保存按钮位于滚动区域下方；一次简单的摆放仍需打开面板、放置、滚动、旋转、保存。应将常用操作放在选中物件附近，并固定保存/取消入口。
4. 场景有较大空白区域，交互标记会遮住走近的玩家。需要随人物和当前操作调整镜头与标记位置。
5. 沙拉材料开始生长后，农场主按钮仍可能继续推荐播种，田外目标主要留在顶部目标入口。应在材料已安排妥当时更清楚地给出田外机会。

准备检查包：

```sh
godot --headless --path . --script res://tools/dev/prepare_journey_device.gd
godot --headless --path output/journey-device/project --export-debug 'Android Journey QA' "$PWD/output/journey-device/sensen-journey-qa.apk"
```

服务端在 `server/` 目录启动：

```sh
JOURNEY_PORT=3117 JOURNEY_DEVICE_INSPECT=1 node --import tsx tools/journey_playtest_server.ts
```

手机通过 `adb -s SERIAL reverse tcp:3117 tcp:3117` 连接后，启动独立包。在项目根目录运行 `JOURNEY_SERIAL=SERIAL node tools/dev/journey_device_control.mjs status` 查看当前控件，`tap '控件文案或提示'`、`swipe '起点控件' '终点控件'` 执行实际触控并留证。使用其他 ADB server 端口时，额外设置 `ADB_SERVER_SOCKET=tcp:127.0.0.1:PORT`。
