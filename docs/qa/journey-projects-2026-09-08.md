# 工程目标、材料来源与模拟器验证

日期：2026-09-08。状态：本轮实现与测试完成，60–90 分钟主动体验目标仍未完成。

## 玩家得到的变化

三个两阶段工程现在可以从实际 3D 物件上选为目标。地图、场景顶部与农场行动入口会随库存和生长状态，指向材料采集点、已修复设施、种子、待照料田格、料理台和最终施工物件。追踪贯穿中间阶段，完成最终阶段后结束；玩家可以取消或改选，重启后保留选择。

本轮实际走通：选择茶露台 → 建遮阳棚 → 买菜种、播种照料 → 等待期间采集、改建庭院补给站 → 收获并做沙拉与茶 → 完成茶露台。补给站建成后实际使用了木料换芦苇功能。茶露台建成后出现来访管理员，可直接点人交谈。

选择某个目标不会冻结物品用途。批量“出售剩余产出”会保留所选工程本阶段需要的食材和成品，商品行标明数量；逐件出售仍可用。主动卖掉工程所需的茶后，引导正确恢复为补充洋甘菊，继续种植或通过育苗设施取得原料。

本地采集节点耗尽后，场景出现可点选的路线木牌。开启下一轮会更新本地点的资源和设施采收状态，同时保留当前场景、镜头与角色位置。选择其他地点的路线仍正常切换场景。

## 实测发现并修复

1. 点“获取洋甘菊种子”后，摊位所需商品原来在屏幕外，必须自行滚动寻找。现在定位到对应种子、购买数量设为 1，打开入口本身不交易。
2. 追踪茶露台时，批量出售原来会把做沙拉所需的胡萝卜、生菜卖掉。现在按阶段配方和已有料理计算需保留的数量，并继续尊重服务端工程预留。
3. 项目地图提示测试原来把相机放在投影原点，断言虽通过却输出投影错误。已修正测试相机，最终客户端日志无脚本及引擎错误。

## 玩法审查与下一步

本轮证明了工程目标能连接多种行为，已有设施能改变下一轮的材料取得方式，玩家主动改主意后也能恢复推进。它没有证明陌生玩家会自行看懂或愿意持续玩 60–90 分钟：操作者熟悉实现，期间有代码修改和测试停顿，不能用总经过时间冒充主动游玩时间。

接下来优先处理：

1. 居民真正使用新建场地。茶露台已经有来访人物，但此次没有增加入座、使用新茶桌或围绕场地的持续活动；设施招待也未接入专属的上菜回应。
2. 第二、第三轮探索的选择深度。当前育苗设施有明确用途，但重采相同节点依然容易机械化；应让已有侧径、不同地点的补给与居民活动影响路线选择，不能仅增加任务条数。
3. 从新存档连续观察主动时间、首次迷路/等待点、完成后自主选择与重复劳动比例。保留可随时中断续玩，按实际最早出现的无聊点继续修。
4. 真实街区道路与地点关系仍未整合为可玩的地图拓扑；目前局部捷径和地图状态不能代表该部分完成。

Goal 保持 active。
