# Journey v6 真机验证

日期：2026-09-08。对应[地点发现](journey-discoveries-2026-09-08.md)和[场景操作](journey-spatial-2026-09-08.md)版本。

后续进展：本记录发现的短间距缩放与后台渲染问题，见[定向修复及真机复测](journey-device-fixes-2026-09-08.md)。以下保留原始验证结果。

## 结论

在 vivo V2509A、Android 16、1080×2344 上完成核心功能回归。三个地点、农场和原生地图可操作，库存、修复、料理、路线刷新及重启保存核对通过。本轮没有修改游戏规则或渲染代码，新增真机数据库迁移工具与验证记录。

不能视为没有遗留问题：一次短间距双指缩小没有生效；后台切换记录到两次 Vulkan 表面丢失错误。扩大双指间距后缩小和回弹有效，恢复前台后画面、触控及存档正常。两项仍需专项定位，未宣称修复。

## 失败与限制

- 107 条动作或截图记录，其中 94 次 tap / swipe / pinch 有触控回执。回执只证明输入到达：一次农场短间距缩小（约 419 px → 146 px）镜头一直为 1.4，不计为缩放通过；后续约 798 px → 280 px 的缩小生效。尚未定位较小手势未识别的具体原因，不把重试成功当作此问题已修复。
- 手机切到其他应用时，一次地图点击没有收到回执；记录为失败，不计入通过数。切换后的截图移到本机私有目录，未用于界面证据。随后恢复应用继续测试。
- 两次 `VK_ERROR_SURFACE_LOST_KHR` 发生在前后台切换阶段。恢复后仍为相同启动 ID，场景重新绘制、输入继续响应、存档相同；目前没有复现持续黑屏或崩溃，仍应定位窗口生命周期与 Vulkan surface 的恢复路径。
- Godot 另有既有 `xr/shaders/enabled` 配置警告。按本应用 PID 取出的 logcat 还有 Mapbox 类查找及 AppCompat 主题诊断；原生地图仍正常显示与交互。未把这些日志描述为已修复或已证明无影响。
- 四次旧选择器 / 锚点预检拒绝发生在面板关闭、工作台仍打开、地点变化或缩放之后，没有发送对应输入。后台暂停时工具另拒绝过时采样。
- 9 块田的批量收获超过控制器 15 秒动作等待窗口，首张动作后状态为 version 235；继续采样确认到 version 238、9 次收获全部完成。核对使用最终状态，没有按首张截图算作完成。
- 本地附近列表为 0 个公开农场，未覆盖其他真实玩家农场的访客模式。地点手势主要覆盖庭院，未遍历每个地点、所有手势方向及每个陈列位。
- 这是成熟存档功能回归，包含构建和调试停顿，不是新玩家首小时、长期收益平衡、留存或“已经好玩”的证明。未做长时间性能、功耗、弱网或 TalkBack 测试。
