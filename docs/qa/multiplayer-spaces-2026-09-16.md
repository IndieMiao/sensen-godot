## 已实现

街区按布局/线路、农场按实际农场/线路、矿井按独立实例隔离，均硬性限制 300 人。
位置、动作、血量、装备武器同步；矿井由服务器运行移动碰撞、AI、攻击与掉落。
共享怪物、岩石、清层进度，参与者各获稳定独立掉落，满包使用暂存。
既有个人矿井、农场物品、装备和永久电梯保留；合作进度存于独立表。

队伍提供创建、邀请码加入、队长转让、移出成员、离开与解散。验证的关键语义：

| 情形 | 服务端结果 |
| --- | --- |
| A、B 未组队进矿 | 两个不同实例 |
| A 在 id3 三层，B 在 id4 三层，然后组队 | 两人位置、楼层、绑定保持原状 |
| A 为队长且仍在 id3，B 主动出矿再进 | B 绑定 id3，继承共享进度；旧 id4 不再作为其入口 |
| A 有历史进度但在矿外，新队员 B 进矿 | B 不继承 A 的历史实例 |
| B 在矿内、A 在矿外，另一队员 C 新进 | C 不擅自跟随非队长 B |
| B 组队后短暂断网 | 签名恢复凭据返回原实例/原楼层，不把网络抖动当作主动换绑 |
| 伪造恢复凭据、重用已主动离开的凭据 | 拒绝 |
| 离队后主动重新进矿 | 不进入旧队伍实例 |
| 队长确认重置 | 必须所有成员都在矿外；旧实例 retired，旧绑定不能复活它 |

## 自动验证

- 完整服务端阶段回归：**713 项通过**，含 PostgreSQL 存档、迁移、装备、战斗与 HTTP。
  后续实例恢复、并发保护和队伍修改的相关套件：**64 项通过**，含 29 项多人专项；两批重叠，不相加。
- TypeScript 类型检查通过；Godot 新脚本可实例化检查通过。
- 通过实际 HTTP 处理器验证同一 NAT 下 300 个不同安装登录并加入同一队伍，避免旧的每 IP 十次登录限制
  把第十一位同网玩家挡住；重复安装登录与伪造代理头的限制仍通过测试。
- Godot 客户端最终回归 **169 项通过**、0 错误/失败/孤立节点，覆盖新协议/人群、矿井、
  农场会话、农场场景、街区交互和中文。测试进程退出有 5 个 ObjectDB 资源警告；独立原生与 Android
  场景运行没有脚本异常，未将测试进程警告当作内存泄漏验证通过。
- 实际交易检查包括双人同时击杀、独立随机奖励、重复提交、丢失提交响应、并发开采、血量救援、
  旧 epoch/序号、非有限坐标和超出 u32 的序号、私有农场隔离、令牌撤销及慢事务期间的移动。
- 独立 PostgreSQL 测得 **300 位参与者同一批掉落约 697 ms**，所有参与者获奖且重试结果完全一致。
  为避免数据库等待冻结空间，结算等待期间继续移动和位置广播；后续战斗等本次提交结束。

无界面 Godot 4.7 的 dummy renderer 对 MultiMesh 变换回读恒返单位矩阵：独立 0.44 缩放复现得到 1.0，
同一最小复现在 Metal 原生渲染器得到 0.44。原有成熟尺寸断言在 headless 下改查生长阶段，
原生模式保留尺寸断言；没有为此修改作物玩法或渲染代码。

## 真实连接容量

Mac Apple M4、Node 22，本机回环 WebSocket，每项 20 秒，300 个独立账号/连接。
第 301 个街区/农场入口明确拒绝；矿井的实例硬上限和队伍上限另由自动测试覆盖。
机器人发送 20 Hz 目标位置及动作，服务端按 20 Hz 运行；此表使用 MemoryStore，矿井场景为第一层。

| 空间 | 实测逻辑 Hz | 输入确认 P95 | 最低客户端快照 Hz | 总下行 | 每客户端平均下行 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 街区 | 19.45 | 58.49 ms | 9.75 | 8.55 MB/s | 28.51 KB/s |
| 农场 | 19.45 | 58.42 ms | 9.75 | 8.55 MB/s | 28.51 KB/s |
| 矿井 | 19.40 | 60.16 ms | 9.70 | 8.64 MB/s | 28.80 KB/s |

三项均保持 300 人、0 慢客户端关闭、0 房间失败。首次建连名单采用增量增删，避免每次加入
向所有人重发整份名单。数据见 `output/online-2026-09-16/load.json`。

## Godot 与 Android

两台真实 Godot 客户端分别验证了街区、同一农场和同一矿井。矿井实例 ID 一致，
双方可见，实际走近岩石、共享开采、分别获得资源并下到第三层；服务器怪物追击和攻击使两人 HP
分别变化，客户端显示同一怪物剩余 HP。Godot 原生 Metal 画面已查看。

独立 Android 包 `com.sensen.journeyonlineqa`，`emulator-5560`，本机内存服务 3163。
通过 `tools/android/run_test.sh` 启动并清理，现有应用、存档和模拟器保留。
一台 Godot + 一台 Android + 298 个真实 WebSocket 机器人构成同一矿井的 **300 人**。
最终 Android：299 个远端玩家、8 套完整动画骨架、平均帧回调 **56.77 FPS**、70 draw calls，
实际移动超过 6 m、共享开采并到达第二层。第 6 秒模拟传输断开后成功恢复同一实例，
有效连接累计 16.54 / 18.00 秒。证据为 `android/report.json`、`android/mine-300.png` 和日志。

近处 8 人使用完整动画，其余 291 人使用实例化简化人物；远端基础造型目前统一。
高密度重叠位置的名字仍可能拥挤。容量验证不是 300 台手机、公网延迟/丢包或 300 人同时围攻精英的测试；
这里没有把回环输入确认时间或模拟器平均帧回调当成真实公网体验承诺。

## 交付与复现

代码与文档保留在当前工作区，已有未提交工作未回退。输出目录为 `output/online-2026-09-16/`。
本页本地验证使用 `sensen_farm_online_test_20260916`，没有修改线上存档或公开服务；后续上线另有发布记录。
QA APK 包含本地测试账号并只连本地服务，仅用于开发验证，不作为公开安装包分发。

服务端正常入口默认启用 WSS；旧服务未提供能力时，客户端继续使用原个人矿井。
发布时必须一并部署支持 WebSocket 的服务端和客户端。生产按单实时写入者启动，
已有 Caddy 转发支持 WebSocket；多 HTTP 副本需将实时路径固定送往唯一实时进程。
