# SGODOT-41: Chapter Progression

Branch: `feat/farm-ui-playability`. This stage adds authoritative D0-D6 completion and chapter goals. Public deployment is tracked separately in SGODOT-39.

## Rules

Successful commands record chapter facts; clients cannot mark a chapter complete. All minimum facts in `assets/farm/data/chapters.json` must be true. Completion writes one `chapter_done` handbook entry and adds no numeric reward.

| Chapter | Required Facts |
| --- | --- |
| D0 | Farm created, first harvest, all nine original plots newly sown after that harvest and cared for |
| D1 | Rain care and the bistro lettuce request |
| D2 | A resolved harvest choice, followed by a bistro conversation that remembers the actual choice |
| D3 | First salad and cooking together, plus the nursery request |
| D4 | Visit and return, plus the first engineering contribution |
| D5 | Growth intent and wind care; purchasing both choices is not required |
| D6 | Full engineering quota and the shared garden scene |

D0 retains seven visible steps: create, clear, till, sow, care, harvest, next batch. Selling is optional for chapter completion. Existing growing lettuce cannot prove a new post-harvest batch. The teaching flow first grows six radishes, then sows and cares for the next six radishes and three lettuce. Crop durations, prices, budgets, and SGODOT-31 cadence are unchanged.

The player's day starts at 04:00 in their farm's city. A completed chapter can open the next chapter on a later player day. Finishing an overdue chapter can open one chapter that day; it cannot open two. Opening a chapter later in the same day preserves already-spent daily budgets. D6 opening alone does not build the nursery.

Owner reads, creation responses, successful commands, and version conflicts use the same pure projection. Reads return coherent chapter state, grants and `derived.next_chapter_opens_at`, without changing the stored farm or version. The next successful command persists the projection. Grant issuance and completion entries remain idempotent. Visitor snapshots retain their explicit privacy allowlist.

The client displays the current chapter's goals and server-confirmed completion. Missing progress from an older server stays pending. Countdown uses the last server time plus monotonic elapsed time; at the boundary it requests the authoritative state, with serialized requests and a five-second retry limit. It never advances the chapter locally.

## Release Boundary

`DOMAIN_VERSION` is now `2`; state schema remains `1`. The explicit migration defaults to read-only inspection and only changes `farms.domain_version`. It does not rewrite saves or replay old commands. Stop old writers, review a database backup and dry-run report, then apply migration with the matching release. Commands on incompatible farm versions fail closed.

See [server migration instructions](../../server/README.md). Production migration and deployment have not been performed.

Resident, location, kitchen, handbook and nursery interfaces remain tracked by SGODOT-42 through SGODOT-45. Full seven-day device play and the 15-minute demonstration remain SGODOT-46; server command coverage alone does not complete that task.
