## 原因与修复

部分 `BaseButton` 默认 `MOUSE_FILTER_STOP`，触摸模拟鼠标事件无法到达祖先
`ScrollContainer`。既有衣柜、背包和 SessionPanel 各自设置 PASS，其他页面漏设；
卡片包裹层和横向列表自己的 STOP 也可能截断外层纵向滚动。

新增 `TouchScrollContainer`，替换项目现有全部 12 处滚动容器（10 处动态创建、2 处场景节点）：

| 区域 | 处理 |
| --- | --- |
| 队伍与在线 | 普通按钮、禁用按钮、成员选择、访问权限开关共同参与滚动 |
| 附近农场 | 横向卡片、外层纵向内容、地点按钮及预览内容 |
| 路边摊 | 收购、种子购买、数量按钮及图文行 |
| 背包 | 物品网格、详情、角色、装备、委托等动态内容 |
| 农场生活面板、目标列表 | 纵向内容与操作项 |
| 地点、旅程地点、街区对话 | 共用滚动组件，包含制作、烹饪、居民、布置等内容 |
| 衣柜 | 横向分类、纵向部件网格，统一既有局部处理 |

组件在节点进入树时处理已有和后续刷新的内容，让按钮及包裹容器继续传递事件。
嵌套滚动容器传递未使用方向的手势；最外层仍阻止输入穿透到地图。
滚动阈值、惯性、越界限制与按钮按压取消继续由 Godot 原生处理。
下拉按钮和开关改为松手生效，避免按下时已经弹菜单或切换权限，来不及识别拖动。
文本输入、数值编辑、滑块及滚动条保留原生编辑手势。

另检查地图、场景平移/缩放、角色转身、移动摇杆和布置拖动的输入入口：它们有独立的
手势处理与 UI 边界，不属于本次滚动祖先传播链缺失。未修改这些玩法输入或存档逻辑。
