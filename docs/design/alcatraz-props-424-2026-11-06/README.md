十件合计 **2,144 独立三角面**；按当前 442 个点位摆放为 **23,216 面**。每件一份 GLB、一个 mesh、一个 surface，全部使用哑光线性顶点色（roughness=.9、metallic=0、specular=.18），无贴图、骨架或动画，供 MultiMesh 按类型/区块合批。白模原装配器统一使用 roughness=.94 / specular=.15 的顶点色覆盖材质，实拍保留它以匹配原场景。树增至30棵时，以较重柏树作保守估计，额外27棵为14,040面；实际屏幕可见量仍须最终装配后重测。

模型在 `assets/landmarks/alcatraz_island/`，元数据单列 `props_manifest.json`，没有覆盖马可波罗的 `manifest.json`。`.import` 已经 Godot 导入，**保留34df9c0b原占位的十个UID**，`texture_map_mode=1`、`light_baking=1`，避免替换时打断消费者引用。Blender 的十个 collection 与命名部件可编辑，导出后在源文件中并排摆供检查；GLB 是各自局部原点，没有烘入岛上坐标。

## 段距与装配交接

`layout.instances` 与 `placements` 是相同重复点位的两份表示，只选一张装配。原直段/石沿使用2 m原型，实际水平段长 **0.25–2.00 m**（X缩放0.125–1）。台阶20段栏杆及20段石沿带 `basis_columns`，须直接构造Basis，不能只用TRS；本地+Y保持竖直。原始layout 179对连接端点完全重合。

有两类整岛摆位问题需要马可波罗在接入时处理，已提前报 Plane 424 `febbbb16`，没有在审阅副本里暗改：

- **10处原始平/斜过渡高度差0.125 m。** GLB保持标准2m端面，差异来自layout的端点Y值。具体段名见 `tools/art/source/alcatraz_props_424/seam-audit.json`，请由场景方统一平/斜接点高度；不要用拉长标准模块去补高差。
- **花坛占位尺寸升级。** 旧1.4×0.7 m占位变为派活要求的1.7×1.7 m；台地 `alc_flowerbed_000..003` 原位替换会碰后侧栏杆，建议往花园侧（-Z）收约0.4 m。码头 `alc_flowerbed_004` 在图中包住原 `alc_sign_003`，建议花坛往-Z收约0.6 m。最终移动须检查地面支撑、通道和遮挡。碰撞/导航障碍同步更新到实际尺寸；树保留根部碰撞，不给树冠加整盒。详细尺寸与逐件建议见 `integration_notes.json`、`placement-review.json`。

原4个转角点位全是yaw=0；本包遵守+X/+Z臂约定，实际朝向须装配方按路口核定。由于新树高度5–7m，后续增至20–30棵时也要重查相机遮挡。此处交的是正式原型，整岛最终验收不以当前占位场景的检查代替。
