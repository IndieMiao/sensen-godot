# SGODOT-423 · Grace Cathedral 室内 v1

黄忠制作，virtual_user_id `5281cd25-6a49-4df8-9802-f3e534956e80`。
采用上官婉儿 `church_concept_v1.jpg` / `c_church.png` 设定，第一版仅对应旧金山 Grace Cathedral。
美术装配资产供审阅；POI 数据、正式可进入房间和路由接入由后裔 / 哪吒处理。

## 设计与交付

10.5×10.5 m 石铺地面，约 5 m 石墙加 3 m 深色拱顶 / 木梁带；外圈实际台阶、墙基座和低草坪。
两列各四排木长椅，中间通道；入口内侧同色系圆形迷宫；三级台阶祭坛含白布桌、蜡烛、两侧花架。
四扇尖拱几何彩窗、圆形玫瑰窗、低强度地面彩光，两盏铁艺吊灯；侧面小管风琴、盆栽和四叶纹挂旗。
彩窗无人物；桌布与挂旗无十字。新增背面细节和结构尺寸依据实测可见构图合理补齐，并非对真实建筑的测绘复原。

## 尺度、挂点与预算

默认镜头为固定 43° 俯角、45° 方位、6.72 m 正交宽度；对照茶馆使用同一宽度、同一 1.745 m 人物。
默认图原生 360×800，未通过裁切、拉伸或换远近来伪造全屏覆盖。
四角来自墙体 / 拱顶带、台阶和草坪实际几何；另拍背景颜色从浅灰蓝改为洋红的控制图，验证没有背景像素露出。

- `spawn / exit / badge_exit` 位于屏幕左前入口，`badge_exit` 对应原 i-door + `Map`。
- `seat_left_1..4 / seat_right_1..4` 共 8 个，挂点 Y=0.795 m（地面 0.08 + 坐面 0.715），有 module、朝向与 approach。
- 中央通道 1.60 m、排间净距 0.85 m、入口净宽 1.40 m，均使用实际碰撞射线及角色通行检查。
- 右下操作区只保留地面；默认图检查该区与高模块投影不相交，出口按钮和名字条不被前排椅端遮挡。

摆放后 **104,938 三角面 / 37 surface**，植物包含 16,984 面；分别低于 200,000 / 60 / 100,000。
统计口径：排除 `review_only=true` 的模板原件，计入 `instances` 的每次摆放，不含角色、UI、调试标注与重复阴影绘制。
逐件顶点实测、尺寸和哈希见 `asset-table.md` 与 validation JSON。

彩光平面 alpha 为 0.28（≤0.35），使用成组宽色块，无实时彩窗投影；地面迷宫为较深一档的同色系石纹。
灯光沿用茶馆的 `local_lights` 写法，两盏暖色无阴影点光。

## 审阅与验证范围

媒体前缀 `SGODOT-423_church_v1_`：默认 360×800、全景、俯视通道及座位、与茶馆同比例对照，以及四张角落放大图。
review 的挂点展示使用 b1 现有 i-door / i-seat 图标，座位不写字；`Player` 名字条为可读性测试占位。
另附人物站在迷宫上的可读性截图，保持同一镜头、照明和人物比例。
没有提交 P0PoiRoom、POI 地理数据、保存或后端改动。

几何检查从 GLB 实际顶点 / UV / 材质读取；独立 Godot 检查人物、长胶囊通道、入口投影和右下区域；
`scene_bench` 使用未修改的共享测试核心，验证移动、阻挡、墙边滑行、入口进出、间距和比例。
详见 validation JSON 中每项结果。媒体清单包含 SHA-256，上传 Plane 后下载回读核验。

共享 bench 的 35 项检查全部通过，入口 / 中央通道 / 排间净距的实际碰撞射线分别量得 1.4000 / 1.6000 / 0.8500 m。
首轮使用桌面默认显示驱动发生渲染节奏导致的路线超时；改用现有 X11 / Mobile、关闭垂直同步并限 60 fps 后，
保持测试核心和时间门槛不变，完成同一批路线。低于 torso 高度的祭坛台阶另用低位射线核对，
共享 bench 的上身阻挡探针对应实际祭坛桌体，避免把探针高度问题误当成通道故障。

所有 Blender / Godot 生成、导入与实拍均通过 `flock ~/gs66-render.lock` 串行。
桌面 Godot 4.7.2 Mobile/Vulkan、RTX 2060；审阅图长边 ≤1600 px。未进行实体手机性能或上线验收。
