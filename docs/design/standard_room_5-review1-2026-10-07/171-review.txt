一、为什么看起来 AI 味重（两个系列共有，每张都要改）




光照平，没有冷暖和明暗层次
：现在的截图都是高调奶油色平光：没有窗光投影，墙角和家具落地处没有 AO，灯具和炉火也不照亮周围。设计图的立体感七成来自光。→ 每个场景加一套 lighting preset：一盏暖色主光（DirectionalLight，开阴影，方向与设计图窗光一致）、偏青/蓝的冷色环境光，灯具和炉火各配一个 OmniLight（小范围、不开阴影）。atlas 里的 AO 要加强（墙角、家具底部、物件接触处）；地板烘一层从窗口向室内衰减的暖色渐变。移动端不用 SDFGI/VoxelGI，靠烘焙 AO 加少量实时灯。




重复太规则
：等大方格的墙砖、一排完全相同的瓶子/罐子/杯子/书、等距的木板、同一段反复出现的藤蔓，一眼就看得出是程序生成的。→ 砖石错缝砌，用 3–4 种尺寸，边角随机倒圆；重复物件每类至少做 3–4 个变体（高度、颜色、朝向、±8° 旋转），摆放时故意打破对齐；藤蔓用 2–3 段不同长度拼接，叶片朝向随机。




密度不够，空地太多
：赵云系列的房间占地 7–9.5 m，明显大于 Basic Room 的 6.45 m，但道具没有跟着加，地面中间大片空白。设计图每面墙都有"大件 + 中件 + 小件"三层堆叠。→ 按设计图收回占地，或者补齐道具；验收时用同机位 50% 半透明叠图，对齐大件位置。




倒角和圆润度不足
：设计图是厚实、大圆角的黏土玩具风格（梁柱、台面、底座边缘都有明显圆角和高光边），现在很多边是硬边或者倒角太小。→ 主体结构倒角至少 2–4 cm，台面和底座边缘做出 bevel 高光；底座（plinth）加厚到设计图的比例。




材质是单一平色
：木头、石头、布料都只是一块颜色。→ 在 atlas 上做手绘风格的色彩变化：木地板每块板的色相和明度略有差异，端头稍深；墙面石灰轻微斑驳；布料加织纹、格纹或缝线；金属加高光边和磨损亮边。要的是手绘 stylized，不是写实贴图。




色板偏离设计图
：赵云系列多数套用了 Basic Room 的浅松木 + 奶油色，刘备系列统一成了黄奶油底，丢了各场景自己的主色（邮局的红棕木、铁匠铺的深灰、奶茶店的粉/薰衣草、便利店的薄荷、潮牌店的水泥灰）。→ 每个场景先从设计图吸 6–8 个主色写进 README 作为色板，再据此调 atlas。




植物显廉价
：叶子只有少数几片平板，体积也小。植物是这批场景可爱感的核心。→ 建一个共享植物库（龟背竹、白掌、绿萝垂吊、开白色小花的爬藤、橄榄树、果树、矮灌木花丛），提高叶片数量、做成簇状、叶片带叶脉色变。两人共用一套，分工见第三节。




评审机位与设计图不一致
：Godot 截图普遍比设计图更俯视、取景更小，不方便逐件比对。→ 以设计图为准对齐相机的 yaw/pitch/正交 size，评审图增加第三栏：50% 半透明叠图。



二、新增要求：基准角色位移测试（每张卡都要补）

原卡把 benchmark 排除在范围外，现在补回来。没有角色在场景里走一圈，就判断不了尺度、通道和碰撞；"细节不够"的观感也常常是比例错造成的。




基准
：以已验收的 Basic Room benchmark（
tools/dev/basic_room/
）为准：同一个 Avatar fixture，CharacterBody3D 胶囊 r=0.21 / h=1.25，SPEED 3.75，相机一致。




通用 harness
：新建 
tools/dev/scene_bench/
，从 
basic_room.gd
 / 
test_basic_room.gd
 / 
room_controls.gd
 抽出来，以场景 slug 为参数，加载 
scenes/<slug>/<slug>_art.tscn
 和 
assets/rooms/<slug>/layout.json
。不要改 Basic Room 已验收的文件。




每个场景的 layout.json 增加 
spawn
 和 
bench
 两个块
：
route
（入口 → 柜台/主家具前 → 各座位旁 → 四角可达点，共 6–10 个航点）；
blocked
（必须挡住的探针：柜台、货架、墙、矮墙/栏杆、开放边缘）；
gaps
（必须能穿过的通道及其宽度）。各卡已列出本场景的航点和探针建议。




必过检查
：① 出生点站在地板上；② 沿 route 依次到达每个航点，任一段超过 3 s 判为卡住；③ blocked 探针全部挡住；④ 开放边缘和矮墙走不出去，入口缺口可以进出；⑤ 斜向撞墙时能沿墙滑行；⑥ 所有可走通道净宽 ≥ 0.70 m（胶囊直径 0.42 m 加余量），不够就改摆放；⑦ 松手即停，idle/run 动画切换正确。




尺度检查
：先在 Basic Room 里量出角色头顶高 H 与门净高、台面高、椅面高、桌面高的比值，作为基线。每个场景同类物件的比值偏差不超过 ±15%；超出的要么改模型，要么在 README 写明理由。




产物
：测试结果 JSON（逐项 PASS/FAIL）；3 张带角色的截图（出生点全景、站在柜台/主家具前、站在门口）；一段 10–15 s 的桌面走位录屏（沿 route 走）；一张碰撞体可视化截图。
必须在真实渲染模式下跑，不能 headless
（Avatar 的 RigActivity 会在 headless 下暂停）。
