# 三层东侧顶面修复与中段台阶脚部复核

修复 `27417c0a` 中三层台地开口以东的草皮/路面顶面丢失。原裁切器对共享平面上的顶点只保留在一侧；后续相邻切口再次经过同一平面时，外侧大三角形退化为两点并被丢弃。现在平面顶点同时属于两侧半多边形，从原始 GLB 重新裁切，只扣 `construction.json` 中九个台阶/平台施工体积。

输入 `edd184d65` 的 terraces / summit GLB 与周瑜比对的 **farm-dev `188d82c0` 字节一致**。沿用原顶面高度、材质、UV、顶点色和向上法线，未用新纯色平面覆盖。运行时文件只更新 `alc_ground_terraces.glb` 和资产 manifest；layout、导航、台阶本体、栏杆、两端旧台阶、summit GLB、两个地标脚本与测试均不改。源 BLEND、裁切器及复核工具同步更新。

## 开口外表面复核

对原始与修正版 GLB 的**实际朝上水平三角面**逐高度比对；0.5 m 网格以 x/z = 0.25 m 偏移取样，排除真实施工体积内及边界 0.1 mm。每一层高度分别计数，不把上下重叠表面合并，因而数量不等于唯一 x/z 格数，也不等于导航格数。另做连续多边形覆盖差，防止网格漏掉窄缝。

| 地形 / 高度层 | 开口外样本 | 修前缺失 | 修后缺失 |
|---|---:|---:|---:|
| terraces 全部朝上水平层 | 8,283 | 1,877 | **0** |
| 其中草皮 3.25 / 5.50 / 7.75 m | 2,808 | 1,401 | **0** |
| 其中路面 3.27 / 5.52 / 7.77 m | 1,056 | 236 | **0** |
| summit 全部朝上水平层 | 8,256 | 0 | **0** |

逐高度连续覆盖差在 0.01 mm 容差下均为 0。其余缺失样本包含被路面覆盖的支撑面等；没有把这些藏在总数之外。完整坐标、每层统计在 [surface-preservation.json](surface-preservation.json)。工具 `tools/art/source/alcatraz_mid_stairs_424/check_surface_preservation.py` 可复跑，并会在开口外缺面时失败。

两条指定路面按“**三角面与条带相交面积大于 0**”计数，不按三角形中心筛选：

| 条带（Godot x/z） | 原版路面高 | 修前朝上面 | 修后朝上面 | 恢复覆盖 |
|---|---:|---:|---:|---:|
| 第一层 x[1.25,9.25] / z[7.75,8.75] | 3.27 m | 0 | **5** | **8.0 / 8.0 m²** |
| 第三层 x[-3.25,9.25] / z[-1.25,-0.25] | 7.77 m | 0 | **7** | **12.5 / 12.5 m²** |

原始大三角形与每个条带相交的路面面数均为 1，裁切后重三角化使面数增加；和按中心筛选或统计顶点得出的数字不可直接比较。terraces 总三角数 4,065→4,184。
