## 2. 规格（C-I1～C-I7）

- 统一光照：左上 45° 主光，暖色环境光，软阴影朝右下；同一类素材用同一段提示词前缀。
- 物品图标：手绘写实、柔光立体，无描边，自带浅投影；正方形透明画布，主体占 80%。
- 头图物件：完整的立体静物，暖色、轻卡通比例；主体占 92%，放进面板时上溢标题色带约一半。
- 系统图标：浅灰白泥塑，双色明暗，只有任务本的铅笔是橙色；主体占 90%。
- 页签/分类：彩色扁平立体，只出彩色一套；未选中由代码去色、亮度降到 50%。
- 命名：`icon_<类>_<名>.png`、`hero_<面板>.png`；物品按名称命名，和 items.json 的对照见 `assets.json` 的 `item_id`、`replaces` 字段。

## 3. 出处记录（`assets.json`）

- 每个批次记了整版附件号、prompt.txt、provenance.json、模型、参数、参考图，以及请求尺寸和实际尺寸。
- 每张素材记了所在批次、格位、在整版上的像素范围、各尺寸文件的 SHA-256；物品图标另记 item_id 和被替换的旧图标路径。
- 提示词原文在 `prompts/`，主机出处记录在 `provenance/`。prompt.txt 的 SHA-256 和 provenance 里的一致（去掉末尾换行后计算）。
- 参考图：`refs/ref-style.png`（attachment-947）是从概念稿帧和 C-84 图 10 裁的；I1～I3 另有现有图标的网格布局参考 `refs/ref-layout-I*.png`（948～950）。

## 4. 后处理（`tools/slice.py`，只用 Pillow）

生成图的透明底能直接用，但有三个问题，都在切图时统一处理了：
1. 物体周围有大片看不见的淡色雾（alpha 1～30），会连到物体上。处理：只保留物体实心部分（alpha>200）周围约 28 像素以内的半透明像素，8 像素羽化；alpha 小于等于 8 的清零。
2. 物体本身的 alpha 只有 252～253，不是完全不透明。处理：246 以上一律拉满到 255。
3. 接触阴影是中棕色半透明，压在深色玻璃底上会发亮。处理：半透明像素的颜色压向深暖色 #342A22，透明度乘 0.6。这样在浅色纸面上看着基本没变，在深色底上是正常的阴影。
切图：按网格取连通块，丢掉没有实心部分的碎块（例如手套上方的烟），裁到外接框，再按“主体占比”补成正方形，用 Lanczos 缩放到各导出尺寸。

## 6. 已知问题

1. `icon_item_row_tool`（Row tool）画成了短柄三齿耙，不是提示词要的长柄中耕器。它和 `hand_tools`（交叉的铲和叉）能分清，但两者都有耙齿。所有者如果要更明显的区别，可以单独重出这一格。
2. 主机返回的尺寸和请求的不同：H1、H2 是 1536x1024（请求 1024x1024），S1 是 1774x887，C1 是 1448x1086。切图按实际像素切，没有影响，`assets.json` 里两种尺寸都记了。
3. 本卡没有 worktree，素材没有入库；替换 items.json 的 `icon` 路径、删掉旧 SVG 和 lucide 引用，由 C-105 实现时做。
4. 没在安卓真机上看过；游戏内大小的预览是按 C-84 令牌在离线渲染里放大 2～3 倍看的。
