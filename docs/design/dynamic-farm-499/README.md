## 程序接入顺序

1. 先完成 r4。地图蓝色认领框、农场扩展区域各用各自的数据，保留查询层和昵称；美术不改全城生成规则。
2. 后裔冻结 schema-r4 后，刘邦把正式字段映射到 recipe 所列的语义输入。这里不抢定义字段名、0.8m 格尺或扩展宽度。当前 7 格/4–10 格只是后裔方案，不由美术自行冻结。
3. 先生成正确的两区地面与角色可达关系，再应用素材参数。依赖不齐时不得先假设整个扩展区都允许放阻挡物；可先呈现地面并记录缺项。
4. 高物件避核心和主要路线。`visual_radial_extent_m` 是完整网格的视觉范围，不是树干碰撞半径；使用实际变换后的 bounds 做完整区域包含测试，不能只判中心点。
5. tree/rock/shrub 能否占用扩展可走格，交后裔与刘邦联合确认。若允许装饰障碍，要保留所有 schema 承诺的连通性；若要求每格可走，高障碍只能放显式可布景区。美术不更改原有权限掩码。
6. 农场局部场景若按后裔建议不与真实地理外圈一一重合，扩展区不回投地图，不额外对道路/邻地做地理裁剪。真实水、住宅等属性与场景装饰水分开；水/崖没定义时先交干地样本，不静默创造可走水面或吃掉核心格。
7. 同 parcel/版本使用稳定 PRNG 与候选顺序。不同装饰类别用独立随机流，避免新增花种把全部大树位置重新洗牌。版本变动显式记录，不更改已认领身份。

## 素材与外观

已核 13 件均为单节点静态网格、单 surface、顶点色，无贴图/动画/骨架依赖，适合沿用 `FarmArt.mesh_for/material/batch`。GLB 与 `.import` 成对保留；顶点色沿用 linear 解释，不新增 shader。共同运行时依赖仍包括 `modules/farm/farm_art.gd`，不能把“没有外链图片”说成“没有任何依赖”。

白名单来源沿用主线 manifest 内记录的 Pandazole 包及用户 bot 579 入库记录；本轮没有重新回读用户原始聊天，记录为既有来源证据，不等于自动布景画面已被用户批准。

参考图已经本人打开。目标是暖草、清晰核心格形、外围成簇树石花、留出可走草地。不是照抄红蓝线，也不要求每块住宅地都造出河湾和高崖。圆冠主树、少量松树、低灌木过渡；高树远离前景主要视线。核心格线只表达区域，不表达已耕作/收获状态。

`recipe` 中 24 树、32 灌木、18 石、48 花、64 草是首轮整场景的上限，不是必须放满的配额，不是手机性能承诺。按最重候选计算摆放上界，并另算地面、水、阴影、角色和 HUD。分块不重置这些总上限；极长地块宁可留疏草，也不缩小格子或人物。尺寸以 JSON 的实际 GLB 顶点为依据。

现有野外 `pond_wild_ground.gd` 有固定 AREA/PATHS/SPAWN/SDF 范围；可复用已验配色与材质思路，不能原样 build 任意地块。水距、泡沫和树影要从新场景几何生成。原 455 结论不覆盖新动态地面或新 shader。
