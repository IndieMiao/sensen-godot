## 渲染约定

- `title / state / effect / quantity / keyFacts / requirements / rows / items / actions` 是新 UI 的唯一产品内容入口。禁止再次直接渲染 `original.heading / meta / rows`，否则会把本轮移除的混排全部带回来。
- 原图的 Bag 抽屉、五列物品格、第一行快捷栏、Gear 六槽规格继续由共享组件处理。这里的数据归一化不授权重画另一套背包。
- `commit` 是资源消耗、领取、保存、发送、装备或移动等实际动作；`navigate` 只打开信息、列表、详情或预览；`dismiss` 关闭/返回；`destructive` 表示需明示后果的提交；`blocked` 保留动词并提供 `feedback`。
- 一个页面至多突出一个主要操作。多个提交并列时，次级操作也必须保持“会执行”的形态，不能伪装成普通详情链接。每个提交的资源成本在操作区上方展示，不只出现在 Toast。
- 通用信息行：名称、状态、数量、作用、事实/时间、行操作各自独立。行标题不因“已领取/可领取/满包”变化；只有状态和行操作改变。
- 7 项 `reviewActions`、所有 `sourceNote / reviewNotes / unresolvedRules / original / sourceRef` 放在画板外说明区。`reviewOnly` 卡必须明确为状态参考或待定规则方案。
- `target: null` 不是已完成的可执行跳转。带 `context` 的条目需要参数化的地图/覆盖/居民面板；长途票制作结果尚无来源稿。不得回退到一个不相干的现有画面来消除断链数量。
- 这些流程依然是状态分镜。页面上示例库存和等级不能被连续点击当作真实状态推进；生产逻辑由服务端及玩法规则决定。
