## 必须先改的问题

### A1 · 身份、数量、效果、来源、状态分离（最高）

`GIFT-CLAIM` 标题同时含菜名、×1、Gifted；`PROFILE-1-P0` 把 Farming/Fishing/Cooking 和各等级拼成一个跨行标题；旧 `COOK-2a-2` 的 Stove 1/3 · Empty · Cooking Lv3 也把三种事实置于一个标题。数据源中的 FAC-6「Compost ready · ×5」、HOME-LV4「Second Stove / 230 Energy · 320 plots」同样缺少稳定语义。

重构为一个共享 **Entity Row** 契约，不为每个功能画一种临时行：`Identity`（名称）、`Category`（类型/来源）、`Quantity`（整数/分母/单位）、`Status`（单一状态）、`Outcome`（本次行为效果）、`Action`（执行或导航）。标题只回答「这是什么」，不能塞 `×N`、`N/N`、价格、倒计时、已装备、按钮动词。标题可两行，不缩字号；数量始终独立且右对齐、等宽数字。Effect 和状态可开关，但不改变其它字段含义。

- 物品：Herb Grilled Fish｜右侧 ×1｜Gifted 标签｜Eat restores +40（仅实际可得）｜查看详情 chevron。
- 材料：Timber｜独立 `8 / 8` +「Owned / Needed」或同义短标签｜满足/短缺符号。
- 装备：Copper Pickaxe｜Equipped 状态｜2 rocks per swing｜4 Energy per action｜Equip 行内执行。
- 目的地：Tokyo｜Japan｜当地可做的事摘要｜导航 chevron；Travel 才是执行。

### A2 · 把决策信息放在提交前，移走规则噪声（最高）

`FAC-1` 材料环和 Craft 占主要位置，唯一需要在此了解的「自动浇 8 格、占用 1 格」却在按钮下方微小脚注。`SOC-2` 的付费对象、`MAP-4-PAID` 的三种扣除资产、`GIFT-CLAIM` 的到期时间，都不应藏在附属小字或仅在失败时告知。

每个决策面板固定顺序：**名称 → 结果/核心效果 → 本次成本/去向 → 相关可选项 → 提交**。对现有已满足的一般前置条件不逐条常驻；进详情看规则，点击不满足时给可处理反馈。但价格、会被扣除的材料/门票、实际收到什么、返还明细、覆盖旧效果、7 天锁定、临近过期、容量不足导致的留存去向须在操作前可见。不能以「少文字」隐藏这些信息。

通过改变字重、字号、组间距、专门的结果/费用区形成层级。不要把所有文字都做 Bold。说明中重复「0 Energy」「你的种子和产量不变」「一场旅行限制」等规则，若当前不影响决定，从主面板移到详情/帮助。

### A3 · 执行、导航、取消、危险操作必须有不同组件（最高）

`MAP-5-PAID` 两个相同描边按钮分别打开指南和取消旅程；`MAP-2-FREE`、`PROFILE-1-P0` 的纯信息导航却使用和 Craft/Claim 一样的绿色提交按钮。仅按数组顺序把第一个按钮染绿无法表达动作。

| 语义 | 外观与结构 | 文案 | 行为 |
|---|---|---|---|
| Commit | 深绿填充，单一主提交区 | Craft / Claim / Buy / Equip | 才会改变状态或花资源 |
| Navigate | 奶油信息行/文字入口 + chevron；无主 CTA 填充 | Travel guide / Recipe details / Edit look | 打开页面/信息，不结算 |
| Dismiss | 安静的文字或关闭图标；至少 44×44 触区 | Not now / Keep current / Close | 返回/关闭，绝不暗中提交 |
| Destructive | 危险文字/描边；必要时进入明确确认 | Cancel trip / Remove helper | 展示后果后确认 |
| Selection | 分段/选项卡/单选状态，不采用提交外观 | Bag / Gear、类别、目的地 | 只更改当前选择 |
| World action | 沿原 176 圆键 + 工具徽标 | Sow / Cast / Mine / Attack | 保留四行动规则 |

取消旅程确认可以把 Keep travelling 作为安全默认，但 Cancel and refund 必须明确是会结束旅程的确认控件，不再长得像 Travel guide。普通确认页同时只保留一个主要执行按钮。

### A4 · 从用户界面移除分镜推进操作（最高）

现场确认 `Tap Stove 2`、`View progress after interaction`。204 张源数据扫描还找到 `Return after making room`、`After collecting: continue`、`Tap next heat ring`、`Tap the pot`、`Tap to cook`。这些按钮替代了真正的触点、等待、条件变化或用户行为，虽然附注写「仅审阅」仍会误导原型使用者。

- 灶台/锅/火候点按：给对应场景对象、原有火候控件建立热点和状态链接。
- 关系累计、容量变化、计时完成：作为不同状态夹具，外置「审阅下一状态」导航，不出现在设备画面里。
- 普通打开详情可真实连线；不能「点进度」就把交互数从 2 变成 3。
- 替换 Buff、制作、领取与出发：确认前后示例库存/余额需要有可核对的变化。

### A5 · 字号、触区与对比度未达到手机阅读要求（高）

`componentize.js` 明写 Body `26/3 = 8.67`、Caption `22/3 = 7.33`，Need S `19/3 = 6.33`（360 画板单位）。原稿 1080×2400 只是源画布，机械除 3 不能等同于可读规范。现场 P1/P2 卡在 360 宽下文字细小，长标题与重要费用尤其难看清。

按当前原 `kit.css` 不透明 token 做 WCAG 相对亮度计算：白字 / 主绿亮端 #7FC66A = **2.06:1**、白字 / 深端 #5FA85A = **2.90:1**；次字 #6E7B74 / 奶油 #FBF8F1 = **4.17:1**。因此绿色渐变白字不能直接认定合格，奶油半透明又会受底图影响。这是 token 计算，不是所有屏幕像素的完整对比检测。

保留 Nunito、奶油、柔和圆角、物品原 SVG 和绿色品牌，修正语义色深度：正文通常 14–16，辅助至少 12，面板标题 20–24；普通正文/按钮至少 4.5:1，关键非文字控件边界 3:1。按钮/关闭/导航触区至少 44×44（画面小图标可嵌入更大透明触区）。原抽屉五列可保持，但小图标名不能承担唯一识别信息，选中后的详情提供可读全名。最终触区和缩放仍需运行验证。

## Toast 与禁用状态的边界

Toast 适合短暂反馈：买入成功、装备切换、暂无可领取、普通材料不足、冷却未到、请求失败。格式为「发生什么 + 解决动作」，例如「Not enough Timber · Need 3 more」「Bag full · Open bag」。同类 toast 合并，不遮主行动键，不依颜色传达，较长信息进入可持续详情。

不是所有不满足条件都做死灰按钮：常规请求入口可允许检查并反馈；可修复表单把原因显示于字段；技能锁定行仍可点看四件事；进行中的重复提交才真实禁用并显示 Busy/Loading；已完成显示状态，勿把它做成“不能点击的按钮”。体力不足有已定的琥珀行动键+Energy Card，应保留。

关键费用、实际所得、不可逆损失、接收对象、长期授权与到期不能仅靠 toast。满包保留于锅/鱼笼、包裹到期退回等数据去向必须能再次查看。

## 规则冲突与不得擅改的约束

1. **Energy Card**：10/04 已采纳修订（§3.7.2/3.7.3、变更表 o(9)）规定仅显示已知事实、只引导，不代吃/代休息。旧附录行 8185/8264/8418 仍有 Eat +40 / Rest +60，不能据此恢复直接执行。正文需补足 Eat / Cook / Tea / Rest 四条事实入口；不随便预测统一回复值。
