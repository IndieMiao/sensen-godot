# B2 IM 界面 —— 实施记录（2026-09-07，第一刀 + 第二刀）

对应 Plane SGODOT-91。服务端与网络层（D3：REST + WS 网关 + `Net.im` / `im_event`）已就绪，本篇是最小闭环：
会话列表 + 单聊页 + 用 @handle 发起单聊。群聊管理、图片消息、长按举报 / 拉黑、已读回执展示留后续。

## 1. 页面

- **消息 Tab**（`scenes/app/pages/im_page.gd`）：顶部「@handle → Chat」发起单聊（先查资料拿 user_id，再
  `POST /im/dm`），列表每行 = 对方昵称 / 群名 + 未读数 + 最后一条预览；点行压栈聊天页；任何 `im_event`
  到达且页面可见时刷新列表；底部保留实时连接状态行。Dev 会话与服务端不可达只给一句提示。
- **聊天页**（`scenes/app/pages/chat_page.gd`，压栈，`AppRoutes.CHAT`，`setup({"conversation": …})`）：
  标题取对方昵称或群名；进页拉最近 30 条（服务端倒序，本地升序渲染）并把已读推进到最后一条；
  底部输入框 + 发送；自己的气泡靠右薄荷底，对方靠左纸色；`Net.im_event` 里本会话的 `message` 追加
  （按 message_id 去重、按 seq 插位）、`message_deleted` 改成「消息已撤回」。

## 2. 决策

| 问题 | 决定 | 理由 |
|---|---|---|
| 发送幂等 | `client_id` 在失败重试间保持不变，成功后才清 | 断网点两次不会存两条；服务端同 client_id 重放返回原消息 |
| 失败时输入框 | 保留文字 | 用户改一个字再发也是同一个 client_id，服务端会返回原消息——这是可接受的取舍：重试语义优先 |
| 实时 vs 补拉 | 都从 `Net.im_event` 来，页面不区分 | Net 层已按用户级 seq 去重并推进游标 |
| 会话列表刷新 | 有事件就整表重拉 | Demo 量级；列表分页与增量更新等会话数上来再做 |
| 已读 | 进页与收到新消息（页面可见）时 `POST …/read` | 单聊对方会收到 `read` 事件（展示留后续） |

## 5. 第二刀（2026-09-07 晚）：群聊、已读回执、长按举报 / 拉黑 / 撤回

真机 1v1 收发与键盘避让收口后（qa-flow-device.md §6），补上 B2 里不被 C3 / R2 卡住的三项。

### 5.1 服务端补的口子（D3 / D6）

- `GET /v1/im/conversations` 与建会话响应多一个 `peer_read_seq`：单聊对方已读到的 seq（群聊 null）。
  回执的初始值从这来，之后靠已有的 `read` 事件推进，不用再拉。
- 新增 `GET /v1/im/conversations/:id/members`：`{user_id, display_name, handle, avatar, joined_at, last_read_seq}`。
  群聊气泡上的昵称和「N 人已读」都从这张表算；非成员 404。
- 举报目标加 `message`（`POST /v1/reports`）：只有会话成员能举报，已撤回的 404；3 个不同人举报同一条
  自动撤回并推 `message_deleted`（和发送者撤回走同一条路 `retractMessage`），管理员 `remove_content` /
  `ban_user` 处置同样撤回。测试：im.test.ts 新增两条。

### 5.2 客户端

- **消息 Tab**：「Group」按钮展开建群面板（群名 + 一串 @handle）。handle 解析与批量查 id 放在
  `ProfileApi.parse_handles` / `user_ids_for`（逗号 / 空格 / 全角逗号分隔、去 @、小写、去重；哪一个
  查不到就指出哪一个）。
- **聊天页**
  - 群聊：别人的气泡上方带昵称（成员表没到之前显示「Someone」，到了再刷）；页头「•••」→ 成员 /
    拉人（展开一行 @handle 输入）/ 退群（确认框）。`members_added` / `member_left` 事件到了重拉成员。
  - 已读回执：只标在**最后一条被读到的自己的消息**上，其余隐藏（常见 IM 的做法，不刷屏）。单聊看
    `peer_read_seq`（`read` 事件推进，自己在别的设备上的 read 不算）；群聊数成员表里 `last_read_seq ≥ seq`
    的人数，「N 人已读」，只在进页 / 成员变化时更新（服务端群聊不推 read 事件，够用）。
  - 长按（0.5 s，移动超过 12 px 视为在滚列表则取消）或右键气泡：别人的 → 举报这条消息（原因菜单同
    feed）/ 拉黑发送者（确认框；单聊拉黑后直接离开本页，群聊留着）；自己的 → 撤回。已撤回的没有菜单。
    单聊页头「•••」→ 举报对方 / 拉黑对方。气泡 `mouse_filter = PASS`，事件继续传给 ScrollContainer 滚列表。
  - 新增可注入：`profile` / `safety` / `leave_handler`（退群与拉黑后离开，默认 `AppRouter.pop_instance`）。
