# B2 IM 界面 —— 实施记录（2026-09-07，第一刀）

对应 Plane SGODOT-91。服务端与网络层（D3：REST + WS 网关 + `Net.im` / `im_event`）已就绪，本篇是最小闭环：
会话列表 + 单聊页 + 用 @handle 发起单聊。群聊管理、图片消息、长按举报 / 拉黑、已读回执展示留后续。

## 1. 页面

- **消息 Tab**（`scenes/app/pages/im_page.gd`）：顶部「@handle → Chat」发起单聊（先查资料拿 user_id，再
  `POST /im/dm`），列表每行 = 对方昵称 / 群名 + 未读数 + 最后一条预览；点行压栈聊天页；任何 `im_event`
  到达且页面可见时刷新列表；底部保留实时连接状态行。Dev 会话与服务端不可达只给一句提示。
- **聊天页**（`scenes/app/pages/chat_page.gd`，压栈，`AppRoutes.CHAT`，`setup({"conversation": …})`）：
  标题取对方昵称或群名；进页拉最近 30 条（服务端倒序，本地升序渲染）并把已读推进到最后一条；
  底部输入框 + 发送；自己的气泡靠右薄荷底，对方靠左纸色；`Net.im_event` 里本会话的 `message` 追加
  （按 message_id 去重、按 seq 插位）、`message_deleted` 改成「消息已撤回」。

## 2. 决策

| 问题 | 决定 | 理由 |
|---|---|---|
| 发送幂等 | `client_id` 在失败重试间保持不变，成功后才清 | 断网点两次不会存两条；服务端同 client_id 重放返回原消息 |
| 失败时输入框 | 保留文字 | 用户改一个字再发也是同一个 client_id，服务端会返回原消息——这是可接受的取舍：重试语义优先 |
| 实时 vs 补拉 | 都从 `Net.im_event` 来，页面不区分 | Net 层已按用户级 seq 去重并推进游标 |
| 会话列表刷新 | 有事件就整表重拉 | Demo 量级；列表分页与增量更新等会话数上来再做 |
| 已读 | 进页与收到新消息（页面可见）时 `POST …/read` | 单聊对方会收到 `read` 事件（展示留后续） |
