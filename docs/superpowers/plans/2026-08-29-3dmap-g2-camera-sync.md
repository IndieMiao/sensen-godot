# G2 PoC 运行手册：相机同步（角色地理锚定）

日期：2026-08-29 ｜ 分支：`poc/3dmap-g1` ｜ 前置：G1 已通过（2026-08-29 真机 8/8）
上游方案：`docs/superpowers/specs/2026-08-25-3dmap-mapbox-research.md` §5.3 ｜ **本关含一票否决项**

## 验证什么

角色钉在地理锚点（人民广场 31.2304,121.4737）上，**pan/zoom/旋转/倾角时角色与地图保持视觉锁定**。
一票否决项：快速拖拽/捏合时角色相对地图的撕裂（漂移）量化是否可接受。

## 实现摘要（相对 G1 的变化）

- **单一权威位姿在 Godot**：手势更新 `(center_world, zoom, bearing, pitch)` → 同帧
  a) `map.setCamera(lat,lng,zoom,bearing,pitch)`（jumpTo 无动画）喂地图；
  b) 同一份位姿推导 Godot Camera3D。不再使用 G1 的 `panBy`（地图侧权威已废弃）。
- **世界系**：原点 = 角色锚点，x=东 / -z=北，米制等距近似（城市尺度）；浮动原点重锚为遗留项。
- **相机数学**：`d = (H_逻辑px/2)/tan(fov/2) × 米每逻辑px(lat,zoom)`；
  逻辑 px = 物理 px ÷ pixelRatio（插件新增 `getPixelRatio()` = MapView 密度）；
  米每逻辑px = 40075016.686·cos(lat)/(512·2^zoom)；
  相机位于注视点 heading 反方向仰起 pitch，`look_at(center, heading)`，fov=36.87°。
- **拖拽 = 抓地**：相机射线 ∩ 地面平面，让按下的地面点始终跟在手指下（倾角下精确，
  与 Unity 旧版 _groundPlane 射线方案同理）；近地平线极远命中丢弃（>20d）。
- **角色屏幕等大**：`rigs.scale = d / CHAR_DIST_PER_SCALE`（Pokémon GO 口径，系数产品后定）。
- HUD 每 30 帧对照"权威位姿 vs 地图回读 getCameraInfo()"，做漂移自检。

## 装机验证清单

1. [ ] 冷启动：角色站在人民广场（地图中心），HUD 两行位姿一致（回读≈权威）
2. [ ] **慢速拖拽**：角色跟随地图移动，脚底贴住同一路口/地物，无相对滑动
3. [ ] **快速甩动拖拽**（一票否决项）：录屏逐帧看角色相对地物的瞬时偏移——
   合格线：偏移 ≤ 手指速度 × 1-2 帧（视觉上"跟手不撕裂"）；不合格：角色明显拖影/漂移后回弹
4. [ ] 缩放（按钮与双指捏合）：角色贴地不滑、屏幕大小基本恒定
5. [ ] 旋转 30°×12 次转满一圈：角色绕自身转（可看到背面），脚底不滑
6. [ ] 倾角 0↔70°：角色透视随动、脚底不滑（若滑动 → fov 校准项，见下）
7. [ ] 拖远 5-10 km 再拖回：无累计漂移（等距近似误差可接受）
8. [ ] HUD 两行位姿在交互静止后 1s 内数值一致（桥无丢帧/方向错）

## 已知校准项与退路

- **fov 假设**：Godot 侧用 36.87°（GL JS 相机族默认）。若第 6 项倾角变化时角色滑动，
  首先调 `MAP_FOV_DEG`；终极手段 = 插件挂 no-op custom layer dump `projectionMatrix` 逐元素校准。
- **撕裂不达标**（第 3 项否决）：优化顺序 = ①确认 setCamera 与 Godot 相机同帧提交
  ②试 Choreographer 帧对齐 ③降低手势→渲染的中间延迟；仍不达标 → 方案 A 否决，上会决策
  custom layer / WebView 退路（两者都意味着放弃 Godot 渲染角色，见 spec §6.1）。
- 双指捏合灵敏度、pinch 焦点缩放（目前绕中心缩放）为打磨项。
