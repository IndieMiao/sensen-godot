**为什么 iOS 推送不走 FCM 代投**：那样客户端就得引 Firebase iOS SDK 才能拿 FCM token，
为一条推送通道把整套 Google SDK 装进 App——包体、隐私清单、审核问答都要多担一份。
直连只多一个 p8 密钥。分工写在 `server/README.md`「推送」与 `docs/native-plugins.md`。

### 安卓这边到哪了（2026-09-08 晚补测）

这台机器上有两个 arm64 安卓模拟器（API 37、带 Play services）与 Android Studio 的 JDK，
所以「缺安卓设备」只对真机性能 / 相机类的验证成立，其余可以先在模拟器上推进。实测结论：

| 项 | 结果 |
|---|---|
| 两个新插件的 AAR | 编出来了。踩了两个坑：LiveKit 依赖的 `audioswitch` 只在 JitPack 上（`settings.gradle.kts` 与导出插件的 `_get_android_dependencies_maven_repos` 都要加）；`RemoteAudioTrack` 安卓是 `setVolume(double)` 方法而非 iOS 的 `.volume` 属性 |
| 安卓 debug APK | 导得出（119 MB），清单里三条 `org.godotengine.plugin.v2.*` meta-data 齐全 |
| 装到模拟器 | 三个插件都完成初始化（logcat 的 `GodotPluginRegistry`），应用进到首启年龄门——跑的是社交主线 |
| **16 KB 页对齐** | **不达标，上架硬门槛**。系统弹「This app isn't 16 KB compatible」，点名 `libmapbox-maps.so` 与 `libmapbox-common.so` LOAD segment 未对齐，`libgodot_android.so` 与 `libc++_shared.so` 报 Unknown。要升 Mapbox Android SDK，另两个用 `check_elf_alignment.sh` 复核。已记进 E7（105） |
| QA 步行器 | **还没在安卓上跑通**。adb 没法给进程设环境变量，已加两条路（命令行 `--qa-env=KEY=VALUE`、`user://qa_env.cfg`），文件确实落到了应用目录、内容也对，但走查没启动，原因未查明。这是 QA 工具的问题，不是产品缺陷——下次接手先从这里查 |
| 语音 / 推送真能不能用 | 没验。语音要真 LiveKit 密钥；推送要 `google-services.json` 进导出模板 + Gradle 加 `com.google.gms.google-services` 插件 |

另外：安卓启动会打三行 `No GDExtension library found (android.arm64)` 的报错。安卓侧能力来自 Kotlin 插件、
`.gdextension` 里本就没有 android 条目，而 Godot 强制把注册过的 `.gdextension` 打进包（试过用 exclude_filter
拦，无效），所以这三行去不掉，属正常。

**踩到的坑（会再遇上）**：SPM 下 binaryTarget 的 `.xcframework.zip` 走 URLSession，只认系统网络设置里的
代理、不认环境变量；git 那部分认。于是 xcodebuild 会停在 "Resolve Package Graph"、CPU 0%、几十分钟不动
（实测卡死 36 分钟）。解法是 `tools/ios/prime_spm_cache.sh`，用 curl 下好按 SPM 的命名放进共享缓存，
`setup_ios_g3.sh` 已自动跑一次。

另：iOS 导出目标目录里有注入进去的 `.swift` 就会拒绝再导（「发现意外的文件」），
**改了 GDScript 要重新出包时得先 `rm -rf build/ios/sensen build/ios/sensen.xcodeproj` 再跑 setup**。
