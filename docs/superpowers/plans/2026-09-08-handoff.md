**真机跑出来的两个 bug（都已修）**

1. **安卓选图从来没通过**：Godot 安卓插件按 Kotlin 方法名原样暴露，不做驼峰↔下划线转换。
   photo_picker 的 Kotlin 侧是 `isAvailable` / `pickImages`，GDScript 调的是 `is_available` / `pick_images`，
   于是 `native_available()` 恒 false。一直被记成「缺设备没验」，所以没人发现。
2. **导出失败但看起来像成功**：手工解压安卓构建模板后必须 `touch android/.gdignore`，
   否则导出前的文件系统扫描会把模板 `res/` 里的 `.webp` 也导入一遍生成 `.import` 旁文件，
   Gradle 资源合并直接拒收，而 Godot 只在末尾打一行 export failed——**上一版 APK 还留在原地**。
   我为此白验了两轮（一直在拿旧包做结论）。CI 那一步也补上了这个 touch。

**安卓上跑走查的固定动作**（adb 给不了环境变量，钩子全都得换路子）

```
adb -s <dev> reverse tcp:3101 tcp:3101          # 手机开 VPN 时局域网 IP 会被 tun0 吞掉
printf 'http://127.0.0.1:3101/v1' > server.txt   # Net 只认环境变量或 user://server.txt
adb push server.txt /data/local/tmp/ && adb shell "run-as <pkg> cp /data/local/tmp/server.txt files/"
# qa_env.cfg 同理放进 files/：SENSEN_QA_FLOW=login 等每行一条
```

另外：安卓启动会打三行 `No GDExtension library found (android.arm64)`。安卓侧能力来自 Kotlin 插件、
`.gdextension` 里本就没有 android 条目，而 Godot 强制把注册过的 `.gdextension` 打进包
（试过 exclude_filter，拦不住），所以这三行去不掉，属正常。

**踩到的坑（会再遇上）**：SPM 下 binaryTarget 的 `.xcframework.zip` 走 URLSession，只认系统网络设置里的
代理、不认环境变量；git 那部分认。于是 xcodebuild 会停在 "Resolve Package Graph"、CPU 0%、几十分钟不动
（实测卡死 36 分钟）。解法是 `tools/ios/prime_spm_cache.sh`，用 curl 下好按 SPM 的命名放进共享缓存，
`setup_ios_g3.sh` 已自动跑一次。

另：iOS 导出目标目录里有注入进去的 `.swift` 就会拒绝再导（「发现意外的文件」），
**改了 GDScript 要重新出包时得先 `rm -rf build/ios/sensen build/ios/sensen.xcodeproj` 再跑 setup**。
