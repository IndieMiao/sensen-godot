# D4-b feed —— 实施记录（2026-09-07）

对应 Plane SGODOT-101（D4）第二块，同时给 B3「feed 只读（10-04）」一个最小闭环。

## 1. 范围与规则

- 08-30 调研 §6.4：Must = 图文 + 点赞；Should = 一级评论。无推荐算法（§5.4：推荐算法在中国技术出口
  管制目录内，demo 时间线不做推荐）。
- 可见性照 Follow Feature Requirements §3.2：**关注了作者才看得到作者的动态**，密友与单向关注同一规则；
  作者本人总能看。时间线 = 我 + 我关注的人。
- 图片：只存 R2 对象 key（≤9 张，拒 `..` 与开头 `/`），D4-c 接预签名直传后客户端才拿得到合法 key，
  所以当前客户端只能发纯文字。

## 2. 决策

| 问题 | 决定 | 理由 |
|---|---|---|
| 不可见的帖 | 答 404，不答 403 | 区分「有但不给你看」与「没有」等于泄露存在性；列表接口例外答 403 FOLLOW_REQUIRED，因为资料页本来就知道这个人存在 |
| 删除 | 软删 `deleted_at`；删号硬删 | E1 审核与举报要能回看；账号都没了就没有回看对象 |
| 计数 | `like_count / comment_count` 列在同一事务里增减 | 列表页不能每张卡 COUNT 一次 |
| 幂等 | 发帖带 `idempotency_key`，同作者同 key 重放 200 | 断网重试不能发出两条一样的动态；客户端在重试间保持同一个 key |
| 评论顺序 | 正序（对话顺序），键集分页 | 与时间线相反：评论是读上下文，不是刷新鲜 |
