# D3 IM 服务端核心 —— 实施记录（2026-09-07）

对应 Plane D3（IM 服务端）。08-30 调研 §4.2 默认自建极简版（备选 Tinode）；SSLAUNCH F4 若改判
Tinode，这里的 REST 面与 inbox 事件流可以保留为适配层。

## 1. 决策

| 问题 | 决定 | 理由 |
|---|---|---|
| 存储 | PostgreSQL（JSONB），不引 Mongo | D0「统一 Node + 现有 PG」；Demo 量级下行存储足够，少一套数据库运维 |
| 同步模型 | 会话内 `seq` + 每用户 **inbox 事件流**（用户级单调 `seq`，扇出写） | 客户端 WsClient 只记一个 `last_seq`；断线补拉一条查询；群成员 ≤50 扇出成本可接受 |
| 事件 payload 里的序号 | 叫 `message_seq` / `read_seq`，不叫 `seq` | 同步接口把事件 `seq` 与 payload 展开在同一层，撞名会覆盖（测试抓到） |
| 单聊唯一性 | `dm_pairs (lo, hi)` 主键做并发裁判 | 与账号首登、关注同一套「唯一键让位」手法 |
| 陌生人规则 | 双方都没关注对方时，先开口者在对方回复前只能发一条 | Follow Feature Requirements §3.3；曾互发过不受限 |
| 拉黑 | 不能建单聊、不能发（双向） | E1 双向不可见 |
| 撤回 / 删号 | 撤回软删（内容清空）；删号：本人消息内容清空，单聊整体撤掉，群聊保留 | 对方的会话不该突然缺一段；账号没了单聊没有落脚点 |
| 非成员访问 | 一律 404 | 不暴露别人会话的存在 |

## 2. 服务端（server/）

- `src/http/im.ts`（接口 / 校验 / 视图 / `greetingBlocked` / `LiveHub` / `imAccountModule`）、
  `src/http/memory_im.ts`、`src/db/pg_im.ts`（appendMessage 一个事务：锁会话 → 分配 seq → 写消息 → 扇出）。
- `schema.sql`：conversations / conversation_members / dm_pairs / messages / user_events / user_event_seq。
- 路由见 server/README.md「IM」。文字过 D6 前置审核；图片 key 须在本人前缀下（D4-c）。
- `LiveHub.publish(events)` 是在线推送落点：WS 网关下一步实现；没配时客户端靠 `GET /v1/im/sync` 补拉。
- 测试：`test/http/im.test.ts`（6）、`test/db/im_conformance.test.ts`（3×2，真库跑通，含并发建单聊）。
