## 1. 做了什么

- **`modules/app/app_locale.gd`（class `AppLocale`）**：`SUPPORTED = [en, zh_CN]`；`resolve(saved, os_locale)`（玩家选择优先，否则系统语言 zh* → zh_CN，其余 en）；`apply()` 设 `TranslationServer` 并写 `UiState.locale`；`boot_apply()` 冷启动；`next()` 供设置页循环切换。
- **翻译文件** `locale/en.po`（源语言模板，msgstr 全空，Godot 空 msgstr 回退 msgid）、`locale/zh_CN.po`（49 条，含登录页 / 壳 / 占位页 / Firebase 错误文案 / WsClient 状态名）、`locale/messages.pot`。`project.godot` 注册 `internationalization/locale/translations` 与 `fallback=en`，引擎启动自动加载，运行时直接 `load("*.po")` 得 `Translation`，无导入步骤。
- **抽取工具** `tools/i18n/extract_pot.gd` + 纯函数 `modules/app/i18n_tools.gd`：抽 `tr("…")`、`page_title = "…"`、带 `## i18n` 尾注的行上所有字串（用于 `AppRoutes.TAB_TITLES`、`FirebaseAuth.describe_key()` 这类不经 tr 的 key）；跳过注释行与工具自身；`parse_po` 支持多行续接与转义；`check_po` 报缺失与 `%s/%d` 占位符不一致。
- **`FirebaseAuth.describe()` 改为自带翻译**（静态函数走 `TranslationServer.translate`，先翻译再 `% code`），`describe_key()` 暴露原始 key；登录页不再二次 `tr()`——修掉了"未知错误码先格式化后翻译永远匹配不到"的 bug。
- **`GameUi.theme()`**：Nunito 字体变体加 `fallbacks = [NotoSansSC]`，zh 字形不再缺字。
- **设置页**：「Language: 简体中文 / English」按钮循环切换 → `AppLocale.apply` → `AppRouter.reload_shell()`（新增：清栈后重载壳；Godot 只自动重译场景文件里的文本，代码里 `tr()` 赋值不会自己换）。
- **AppRouter**：启动 `AppLocale.boot_apply()`；**测试进程固定 `en`**——这台开发机是中文系统，注册 zh_CN 翻译后引擎默认 locale 变成 zh_CN，一批英文断言当场变红（见 §3）。
- **im_page**：WsClient 状态名走 `tr()`。

## 2. 关键决定

1. **.po 而不是 CSV**：08-30 §3.1 指定 gettext PO 工作流；Godot 4 原生加载 .po，翻译公司与 SSLAUNCH E10 的校对流程都认 PO。
2. **抽取靠源码扫描而不是编辑器 POT 生成**：编辑器的 POT 生成不能 headless 跑，也抓不到 `describe_key()` 这类间接 key；自写工具 + 守卫测试（"pot 落后于源码就红"）把同步责任放进 CI。
3. **切语言整壳重建**：比给每个页面实现 `NOTIFICATION_TRANSLATION_CHANGED` 便宜得多，占位页阶段没有需要保留的状态；B2/B3 有列表状态后再评估局部重译。

## 3. 踩坑

- **测试进程的 locale 跟着系统走**：注册翻译前 `TranslationServer.translate` 是恒等映射，谁也没注意到 locale 是 zh_CN；注册后 `describe()` 一类文案在测试里全变中文。现在 AppRouter 对测试进程显式 `set_locale("en")`；任何要测 zh 的用例自己切、在 `after_test` 切回。
- 抽取器最早把自己文件注释里的 `tr("…")` 示例抓成了 key「…」——注释行必须跳过，工具文件必须排除。
