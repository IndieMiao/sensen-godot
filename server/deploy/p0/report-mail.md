## 队列接入约定（11-13 开发准备）

每个服务进程仅一个 `ReportOutbox(file, deliveryOrNull)` 写者，和现有 P0 单写者一致。适配器默认关时
传 `null`，队列只入盘不发送；启用时传 `createReportMailer(config)`。调用方定时调 `tick()`，每次最多
尝试一封；并发 tick 共用一次发送。关闭时先 await queue.close()，再 mailer.close()。

权威举报必须先持久化（含只在自有服务器存的名字快照），再调用 `enqueue(reportUUID, publicNotice)`。
队列只投影双方支持码、原因标签、地点/层、时间、渠道，稳定UUID用于幂等；不存姓名、原始ID、IP或凭据。
回调或入队失败后，调用方须能从权威记录重放同一UUID，**不能只靠一次易丢的内存回调**。
客户端原因枚举和channel取值/旧客户端缺字段的映射需先跟后裔确认，不自行从自由文本或未知渠道猜。

默认发送间隔30秒，失败从1分钟指数退避到最多1小时；UTC每日最多200次尝试（含失败），限额/下一次时间
都在SMTP调用前原子写盘，重启不清零。200是开发用保守配置，低于通道2000封/天总上限；不代表独占全部额度，
还须和邮箱验证码的全局额度一起核。时间倒退不会重置预算。读取坏队列直接报固定错误，不静默丢消息；写失败
保留原内存状态和文件，让调用方重试。供应商错误不写日志。

同一UUID重放（含发送成功后）不重复排队；同一UUID携带不同内容拒绝。但SMTP接收成功后，进程崩溃或
本地sent确认写失败时可能重投，**不保证恰好一次**；SMTP接受也不等于最终送达邮箱。
当前没有接生产调度、管理端查询或一年到期清理；sent回执和积压通知的到期处理须随11-16留存模块完成再启用，
按原举报时间到期、不因重试重新计时。状态不写入玩家存档，不改玩家存档版本。
