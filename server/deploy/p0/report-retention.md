# 举报及邮件队列到期物理清理（SGODOT-484）

范围只有当前数据目录的voice_reports.jsonl和report_outbox.json，不删除玩家存档/备份/旧归档，不改变存档版本。
举报期限沿现有REPORT_KEEP_MS（365天），从原举报at起算，等于截止时即到期，不因重试或邮件送达重新计算。
JSONL旧v1原始ID行、新v2含名字快照行都能按有效at清理；未来时间保留，坏JSON/未知kind版本/无合法时间保留并告警计数，
不猜截止、也不把坏行内容写日志。坏行需要管理跟进，不能声称这些无法判断期限的行也已清除。

JSONL每次同步读取→过滤→临时文件→rename，不跨await，避免与本进程append丢写；保留行字节不改。
队列清掉到期pending和sent数据，发送在途结束不会把已删行加回来。预算/重试数据中不含报告载荷的部分保留。
两个文件各自原子，不是假装跨文件事务；中途一个失败可安全重试。原始文件替换失败保留原文件，队列失败保留原内存与文件。
没有生成含过期数据的.bak文件；历史备份按运维生命周期另管。

- `GET /admin/reports/retention`：只读预览计数，无原始ID/名字/内容。
- `POST /admin/reports/retention {apply:true}`：管理鉴权内执行，并记录计数审计；坏行告警不输出原文。
- `deploy-hk.sh --target us reports-retention` 默认预览，`--confirm`显式执行。
- `P0_REPORT_RETENTION=on`：部署获得批准后可开启，起服及每小时物理清理；默认off，不因合代码自动删除。
  邮件开关与留存开关独立，P0_REPORT_MAIL=off也能跑获准留存；这不构造SMTP、不发送邮件。

正式服的开关/清理先报奕星由83执行；本PR只用临时合成文件测试，没有部署或生产删除授权。
12个月未活跃旧号自动清理、历史备份清扫不在本PR。提交前需在获准复演环境验证开启留存后的结果，不能用默认off称已满足政策。
