# 矿洞地下背景 · SGODOT-257

一、二层共用的地下岩体。前沿是浅浮雕土层／岩层和少量枯根、碎石；后侧及两端是带倒角的岩块。离矿洞越远越暗，外缘收回原背景 `#242125`。只含美术资产，接入由周瑜另开 PR，本 PR 不改矿洞、相机、灯光或交互程序。

基线：`farm-dev @ c694788d`，`MineArt.floor_scenery(1/2)` 与 `scenes/p0/p0_mine.gd`。参考为不知火舞提供的 `~/incoming/mine-bg/mine-floor1-current.png`、`231-mine-camera-cmp-1.png`、`231-mine-camera-cmp-3.png`，以及 SGODOT-257 卡片完整规格。

## 摆放与通道

- 单位为米，Godot Y 向上。实例**沿视线朝相机前移 1 m**（接入代码处理：`MineBackdrop.FORWARD_M` × 由 `FarmCamera.PITCH_DEG` / `YAW_DEG` 算出的视线向量；资产本身仍以原点导出），旋转 `(0, 0, 0)`，缩放 `(1, 1, 1)`。网格已经对齐 **俯角 43°、偏航 14.5°**，不要再旋转，也不要随横向平移移动背景。
  - 原因（SGODOT-257 深度扫描，苏烈在 #173 提出，美术总监选定）：`fit_ground_depth` 把 far 按半米取整，并让相机沿视线后退，所以 far 随缩放呈锯齿。在原点时，右端机位捏合越过 1.4（回弹带，最大 1.569）会切掉前缘下方的底部岩层，最差 −0.643 m；360×780 在缩放 1.345 也到 −0.003 m。前移 1 m 后正交画面不变，只有原先被切的地方恢复。
  - **重新导出时不要把这 1 m 加进网格**，否则会前移两次。改动网格后跑 `tests/p0/test_p0_mine_backdrop_depth.gd`（`P0_BACKDROP_DEPTH_FULL=1` 为全密度），它要求可见背景在 far 内至少 0.05 m。
- `COLOR_0.rgb`：三个分量相等的灰度权重，约 **0.420–0.957**。包含层带、倒角、缝隙及左上方受光的明暗；按线性系数读取，不再做一次 sRGB 解码。
- `TEXCOORD_1.x`，即 Godot **`UV2.x`**：渐隐值，0 为楼层套色，1 为原深灰背景。导入压缩可能令 0 附近出现约 `−0.000015`，读取时 `clamp(..., 0, 1)`。`UV2.y` 留空。
- `COLOR_0.a` 恒为 **1**。渐隐是颜色混合，**不使用透明度**。
- 原始 GLB 内的 `KHR_materials_unlit` 材质是灰度数据预览；实际场景须绑定同一个楼层套色材质。

建议楼层色保持卡片规定的起点：

| 楼层 | 输入色（sRGB） | 来源 |
|---|---|---|
| 1 | `(0.39686275, 0.20274510, 0.14450980)`，约 `#653425` | `#B85E43` 压暗 45% |
| 2 | `(0.32352941, 0.30196078, 0.23333333)`，约 `#534D3C` | `#A59A77` 压暗 50% |
| 外缘 | `#242125` | 原 Environment 背景色 |

以下是交接用的材质公式，不是本 PR 的接入实现：

```glsl
// opaque + unshaded + shadows_disabled; floor_tint/void_tint use source_color.
ALBEDO = mix(COLOR.rgb * floor_tint, void_tint, clamp(UV2.x, 0.0, 1.0));
// Do not write ALPHA.
```

实例中 `MineUndergroundBackdrop.cast_shadow` 必须为 `SHADOW_CASTING_SETTING_OFF`；保留无光照、关闭 GI／烘焙、无碰撞。背景不参与 `_walls_box`、`_art_points`、`_art_sides`、角色导航或任何相机取景边界。**不改相机 near/far、不改现有太阳和阴影参数。**

## 为什么不会碰到主体或裁剪面

源网格按两层实际几何在固定相机方向上的投影制作，共用内轮廓包住两层岩壁、底座、梯子、电梯及接触阴影；轮廓外保留抗锯齿保护边。保护区没有背景几何，因此背景不会重新混合主体轮廓的半覆盖像素。

沿相机朝向向量 `N = (0.183116, 0.681998, 0.708058)`，局部浮雕厚度约 **0.276 m**。右侧卡片沿视线前移，最大偏置 **1.10 m**；完整模型的 `dot(P, N)` 范围为 **−6.970811 至 −5.595000 m**。这是为了适配缩放 1.4、最右端机位更紧的远裁剪面；沿视线调整不会改变正交投影中的轮廓和图案。

这是面向镜头的浅浮雕，不是真实可行走的地下悬崖，其世界 Y 包围盒不能用来判断裁剪深度。检查使用原 `FarmCamera.fit_ground_depth`，逐三角形按屏幕矩形裁出可见部分，再验证其深度位于原 near/far 内；屏幕外的左侧片不会误算成右端机位的可见裁剪失败。

## 源文件编辑与导出

在 Blender 打开 `source/mine_backdrop.blend`，编辑 `EDITABLE_RELIEF_PARTS` 集合内的命名部件。保留 `StrataGray` 顶点色、`UVMap` 和 `Fade_UV2` 两套 UV。

在 Text Editor 运行内嵌 **`EXPORT_RUNTIME.py`**：它只复制并合并导出件，输出到同目录上一层的 `mine_backdrop.glb`，随后删除临时合并件并保存有名称的源部件。无需外部脚本、贴图或 Python 包。内嵌 `mesh.json`／制作脚本是 R1 的制作快照；手工编辑后应以当前 `.blend` 和 `EXPORT_RUNTIME.py` 为准，不要用旧快照覆盖编辑。

导出为 glTF Y-up、单位缩放、保留法线、两套 UV、活动顶点色，只导出选择项。随后在 Godot 4.7.2 导入；保留提交的 `.import` UID，LOD、shadow mesh、light baking 均关闭。

## R1 验证与交付

Godot **4.7.2 / Vulkan Mobile / Steam Deck RADV VANGOGH**，原矿洞渲染器、4× MSAA、太阳与环境参数，使用独立本地 QA 用户目录。未连接游戏服务或修改玩家数据。

- 两层 × 缩放 0.8 / 1.0 / 1.4 × 左端 / 中间 / 右端：**18 个机位**。
- 缩放 0.8：360×800、360×840、412×915，每种都检查两层与三个横向位置。与上项重叠后共 **30 个不同视图**。
- 每个视图都有同机位背景开／关原始图、带 HUD 图及主体差异图。包含默认角色、六块矿石、梯子和电梯。角色姿势固定，换机位后等待阴影稳定再捕获。
- 主体遮罩取关闭背景时所有非清屏色像素，不排除岩壁边缘或阴影。当前渲染器将 `#242125` 输出为约 `(36, 34, 36)`，与设定逐通道差 ≤ 1；遮罩使用这个实际清屏值，避免把清屏量化误差算作主体。
- 外缘按完整几何外轮廓投影，检查轮廓内外 2 像素带与 `#242125` 的逐通道差；边缘在屏幕外的视图另以深度范围及画面检查覆盖。

| R1 最终测量 | 结果 |
|---|---|
| 30 个视图的矿洞本体最大逐通道差 | **0**；改变的主体像素 **0** |
| 外缘与 `#242125` 最大逐通道差 | **1 / 255**（要求 ≤ 3） |
| 可见背景到原远裁剪面最小余量 | **0.169672 m** |
| 可见边缘／接缝 | 覆盖拼图已目视检查；无硬边或缺失的背景片 |

接入后的深度扫描（周瑜，SGODOT-257）：缩放按 0.01 步长，从 0.714 扫到 1.569，含回弹带；覆盖取景允许的全部焦点；两层 × 360×800 / 360×780 / 360×781（vivo V2509A）/ 360×840 / 412×915。R1 的 0.169672 m 只测了缩放 0.8 / 1.0 / 1.4 三个点。接入时前移 1 m 后，far 余量与 near 余量见 SGODOT-257 的评论。

验收媒体和逐机位数值表附在 **SGODOT-257**：18 张覆盖拼图、三种屏幕拼图、两层预览、开关／主体差异对比、`verification.json` 和可复查原图包。临时 QA 脚本随原图包留档，不进入运行资产 PR。

这里验证的是目标渲染器下的画面与资产预算；三种屏幕为桌面 SubViewport 渲染，不是 Android 安装包或真机性能报告。最终楼层色由不知火舞看图验收。
